# 运营复盘报告规范

使用[报告模板](templates/运营复盘报告模板.md)固定章节和表头，逐集形成正式报告。保存为`10-社交媒体资料/运营复盘/EPxxx/EPxxx-三平台运营复盘报告-YYYYMMDD.md`，日期对应实际报告命名日期；已有报告不因补充日期自动改名。正文修订按项目版本规则递增，采集快照保留原值，不把后续数据静默写进旧快照。

## 写法与字段

- 头部数据阶段用一句短话；核心结论用无序列表，简要交代主要发现和改进方向。
- 第1章仅平台、账号、发布时间、标题、话题五列；不附作品时长、采集方法或来源清单。
- 第2章固定十二项指标及顺序，保留平台原值。固定章节注为“注：指标保留平台原值，未取得或页面未提供的值记为N/A。”需要解释的字段标“（注N）”，表后无序列表逐条解释，每个编号只对应一条注；多处引用同一解释可以用同号，不同解释必须拆号。
- 全文说明统一用“注”，普通文字，不加斜体、下划线或跳转链接。章末限制说明使用“注：”。
- 第3章每个平台正文用无序列表，写事实与依据事实作出的判断；样本、口径及其他限制放小节末的注。账号活跃时段单独表格，统计对象／周期、可用数据、建议时间与依据分列。
- 第4章时间点表将成片内容与判断对应；“已确认的现象”用无序列表，之后写“结论小结”；“优先验证的原因”用按优先级排列的有序列表，不能把假设写成定论。
- 第5章固定“后续改进建议”，保留建议表，之后分“创作层面的建议”和“内容层面的建议”，写可用于后续作品的总结性建议，不用本集对白拼接示范替代建议。
- 第6章固定“后续数据采集与验证”，只写当前待验证事项、参考值和后续判断；通用采集节点与比较方法留在SOP。
- 第7章固定“报告结论与待跟进事项”，下设“当前结论”“已落实”“待跟进”，均用无序列表；建议尚未执行不能计入已落实。

## 排版与边界

标题、表格、列表及内容板块之间保留一个必要空行，确保Markdown正确渲染；不使用连续空行、空白段或HTML占位符人为撑高版面。粗体标签使用`**标签**：正文`。

报告不写执行原则、返工边界、技能调用、保存路径说明或通用SOP。针对本集的判断限制仍保留为注，不因简洁删掉必要的不确定性。沿用项目方向，不把一次指标表现推成账号上限、平台适配定论或强制改变全剧定位。

固定字段中未发布或未取得的平台数据填N/A并说明，不删除整行制造每次不同的指标表。新平台按已配置平台扩展对应列、小节与账号时段行，仍保留相同指标口径和写法。
