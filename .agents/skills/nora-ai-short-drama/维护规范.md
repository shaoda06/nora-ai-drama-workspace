# 维护规范

版本：v1.105；更新日期：2026-10-16。

本文件只管理 `nora-ai-short-drama` 技能自身及其配套资源的维护，不规定短剧项目的创作内容、制作参数或审批流程。维护时按下方路径读取；普通短剧制作不默认加载。修改本维护规则须依据用户确认，不由agent自行新增分类或另定命名。通用技能维护同时遵循可用的skill-creator指引，用户明确确认的本技能结构优先。

## 维护任务读取路径

修改前读取第1节中与目标文件有关的分类及“规则真源与引用”、第3节的适用校验、第4节归档要求和第5节表述要求。真源索引按本次规则检索；文件命名／移动读第2节及兼容路径，脚本接口读第3.2节，依赖获取／更新读第6节，分发打包读分享边界。未涉及的长表及专项章节不加载；已读且未变化的内容复用。

| 位置 | 职责 |

不新建同义目录；需要新类别时先说明用途并获得用户确认。一个现行文件只维护一份，各处通过链接引用，不复制到多个分类。可填正文在模板目录单独维护，原规范仅保留适用范围、填写要求、审批、保存规则和模板链接，不复制完整正文。七类生图模板只保留生成正文、占位符、生成方式和必要填写说明，不写修订要求或另设修订模板；统一修订规则仅在[提示词规范第2.5节](references/生成规范/Qwen-Image-2.1-提示词规范.md#25-参考图统一修订规则)维护。其他文件通过链接引用；人物、场景、道具记录分别维护。Qwen参考图保留七种核心图片类型；经确认的补充图片另列专用模板，不增加固定种子类别。同一规则的维护与引用按下方“规则真源与引用”执行。场景生成方式与参考输入的真源为[场景专项规范第4.1.1节](references/素材规范/场景资料与参考图规范.md#411-生成方式与参考输入)。固定子情况与补充图片以[提示词规范索引](references/生成规范/Qwen-Image-2.1-提示词规范.md#11-图片类型专用模板索引)为唯一分类索引；条目指定专项生成规则时，生成方式及输入关系由所链接的专项章节维护；未指定专项真源的条目由索引维护。每种子情况一份填写模板，不设置参考案例或待补位置。新增或改变子情况须先获用户确认，同步索引、模板及引用，不临时添加非规定情况或补充说明。文生图／图像编辑两份共用模板只保留共用填写、辅助骨架和输出格式。生图模板只维护可填正文、必要填写说明与格式示意，不要求补全或替换参考案例；项目真实结果、参数、批准依据、失败流水与对照过程保存在项目生成／审阅记录，不回填模板。简短索引、关联字段、初审标准、目录树、命名公式和接口说明保留在规范中；关联字段属于完整模板时只引用其正式定义，不扩出独立模板。后续新增模板仍须获得相应维护授权，不能借模板化自行改变业务规则。工作流JSON不因具有模板性质而再放进“模板”。目录整理不自动授权修改业务规则、模型参数、实际项目资料或远端服务。

主目录只保留现行正式工作流；不再正式使用的旧版、备用及实验工作流移入 `references/comfyui-workflow/非正式工作流/`，不作为常规任务入口。迁移时同步规范链接及校验工具，不保留同一配对的两份可编辑副本。修改前的历史备份仍存入 `references/历史版本/`；项目真实测试副本仍按项目既定位置保存。

### 工作流基准与任务副本

本地 `.workflow.json` 与 `.api.json` 为唯一配套基准，不另维护 `.snapshot.json`。常规执行从基准制作任务副本，不修改基准、不从远端自动覆盖本地基准；只有用户明确要求更新时才备份并同步配对。实际任务请求、参数、任务ID、响应与采用依据继续保存在项目，独立于工作流基准维护。修改工作流文件、配对校验脚本，或调整执行规范中的节点映射、参数与连接要求时，运行离线配对校验，检查相关有效节点、参数、连接及可选输入分支；无关文档修改不触发此项。静态通过不等于服务兼容或执行成功。

### 规则真源与引用

1. **唯一维护入口**：同一条业务规则仅在一个明确章节维护，其他入口保留适用时机、任务特有说明和链接，不复制条件、参数或禁令。模板维护可填正文，执行说明维护技术映射，不另行定义业务选择。
2. **新增与修改**：落笔前先查本节索引及相关现行文件，确定规则归属。已有规则只修改其真源，并核对引用方；新增规则类别或调整归属时，同步下方索引和受影响链接，不为了方便阅读另写一份可编辑规则。
3. **维护交付检查**：将本次规则及同义口径在现行规范、模板、技能入口和工具说明中检索一次，读取命中的相关正文与直接上下游，核对旧条件、重复定义、冲突及流程衔接；不默认通读全部命中文件或递归展开全部链接。只有发现具体依赖问题时继续扩展。修正后复查受影响部分；同一批修改共用一次检查，已通过且未受后续改动影响的检查不重复运行。发现问题时，在授权范围内修正真源和调用说明，将重复定义改为引用，涉及归属变化再同步索引。交付说明实际检查范围、修正与未解决项；链接有效不等于业务衔接通过。

### 1.1 参考文档与工作流程的职责

参考文档解释“是什么、怎么用”：说明概念、方法、适用条件与使用边界，可提供帮助理解和应用的示例；不在文档自身指定短剧流程中的阶段安排。

工作流程规定“什么时候参考、参考后落实什么”：在相关任务或阶段中链接对应参考文档，写明触发条件、参考重点，以及应落实到哪些产出或检查项，不能只有笼统的“参考该文档”。文档自身的用途说明与流程中的调用要求须同时明确，前者不能替代后者；流程通过引用使用方法，不重复复制指南正文。

## 3. 引用同步与校验

1. 操作前明确本次变更范围与完成标准，核对相关源文件、目标路径和引用方，检查其他会话正在产生的改动；以磁盘最新内容为准，不覆盖无关更新。
2. 改名或移动后，同步现行SKILL入口、规范间相对链接、代码／命令中的实际路径和正文标题。跨分类链接从新位置重算；跨技能链接及工作流、脚本路径也要检查，不只替换文件名。
3. 不留第二套可编辑旧规则，不自动批量改写项目资料、既有执行请求、历史文档或定时器配置。检查外部引用并报告；接续者从SKILL现行入口或下表解析旧名。恢复旧定时器前须核对其入口，但不得因本次维护擅自恢复或修改调度。
4. 新增或修改规则时，先按[规则真源与引用](#规则真源与引用)确定维护入口，完成修改后再执行该节的默认收尾复查；按下表选择与变更有关的检查，核对受影响的本地链接、章节锚点和目标文件；同时搜索正文中的章节名、节号及“读取SKILL中的”等非链接指路，确认所指内容确实位于目标章节。普通链接检查不能代替这项语义核对。改名或移动时还须查找并同步现行引用方，检查旧路径残留。提取模板时逐项核对原字段、顺序、正文及必要附表未丢失，检查入口与返回规范的链接，不形成第二份可编辑正文。运行技能校验；其他测试按实际影响选择，不默认执行无关检查。
5. 交付说明实际变更、检查范围与结果；涉及迁移、改名或去重时，补充仍保留的外部旧引用及可恢复位置。

| 变更类型 | 必须检查的范围 |
| --- | --- |
| 仅措辞、排版或说明调整 | 对照原文确认含义及要求未变，核对相关引用；不因文字修改运行工作流或浏览工具测试 |
| 模板、业务规则或目录命名调整 | 核对受影响的上下游规范、字段、路径及引用；按第3.1节判断浏览工具是否需要适配。仅目录整理时确认涉及的工作流与代码内容未变，不以文件移动代替业务验证 |
| 脚本或工作流调整 | 运行受影响功能的现有测试，覆盖相关调用方和失败处理；工作流配对及浏览工具分别按其专项要求检查 |

同一变更涉及多类时合并相关检查；默认收尾复查按[规则真源与引用](#规则真源与引用)执行，深入检查范围按实际依赖确定，不只看文件扩展名。需要对无关主题也作全量逐项检查时，以用户明确要求或改动确实影响全局引用／共用行为为依据。技能维护校验不替代业务审批、运行前核对、防重复提交及其他安全要求。

### 3.1 浏览工具联动检查

修改技能规范或正文模板时，必须检查是否影响[浏览入口的输入格式与解析依赖](references/流程规范/项目浏览入口规范.md#5-输入格式与解析依赖)。项目目录、文件名、编号、字段名、索引表头、记录章节、审批／执行状态及素材引用方式变化均在检查范围；不能只检查链接是否存在。

1. 先按上述输入格式说明判断是否改变解析字段、路径或状态语义；涉及这些变化或无法判定时，再查看相关解析器代码，确定输入解析、页面数据结构、React展示、测试及说明的影响。仅规则读取路径、操作说明或不被解析的正文变化，不要求查看实现或改代码；交付时简述“需要适配／无需适配”及依据。
2. 需要适配时，在同一维护任务内同步规范、解析器、React组件、相关测试和第5节依赖说明；只有受影响的组成部分需要修改，不机械复制规则或逐次重写工具。不通过改写项目审批事实或批量迁移旧资料来迁就解析器。
3. 涉及浏览工具或其输入格式、输出行为时，按[维护检查](references/流程规范/项目浏览入口规范.md#4-维护检查)验证，再核验受影响项目的同步状态及实际条目，核对本次变化对应的条目、状态及入口。仅规范说明变化且不影响解析或现有输出时，无需运行浏览工具测试或重新读取项目，简述判断依据即可。技能更新不自动授权批量修改项目资料。
4. 交付报告影响判断、实际修改、测试结果、项目同步及核验情况；未完成的适配、同步或浏览器验证单列。不将测试通过等同于资料已同步，不将资料同步等同于业务批准。

日常项目推进的刷新责任与时机统一见[交付前同步检查](references/流程规范/项目浏览入口规范.md#交付前同步检查)，本节只管理技能变更的联动，不另立一套项目进度。

### 3.2 固定脚本调用说明

脚本的目标是让agent依据说明直接调用，不通过阅读源码临时设计用法。新增脚本或修改调用接口时，在已有对应规范／工具说明中同步维护用途与使用时机、运行环境、可复制命令、参数含义与默认值（含单位和路径基准）、输出及成功／失败判断，以及实际写入或联网范围；从技能入口或对应任务规范可以找到，不另建重复说明。

命令行工具的 `--help` 应解释可选参数，不只列参数名；测试脚本提供标准测试命令、覆盖范围和结果判断，不必另造命令行接口。维护时按说明验证相关命令及帮助与实现一致。说明缺口在获授权维护时补回说明，不把每次读源码作为常规使用步骤；也不因补说明触发远端生成或增加无关验证。调用与按需查源码的规则统一见[固定脚本调用](SKILL.md#固定脚本调用)。

## 4. 历史归档、去重与读取边界

- 保留内容不同的历史版本。追溯、比较或恢复时才读取；不得用旧规则覆盖现行规则，也不因看到旧参数就恢复旧模板或重跑任务。
- 确认替换现行规则内容前，保存修改前完整内容；纯移动、改名和引用更新不必逐文件制造一套内容相同的历史副本。归档不代表旧版仍有执行效力。
- 后续归档使用 `{当时正式文件名去扩展名}-归档-YYYYMMDD-HHmmss.md`，使用者本机时区精确到秒；同名冲突选择新的实际时间戳，不覆盖。既有历史文件不追溯改名，不重写其旧标题、引用或事实。例外是会被平台注册为技能的历史 `SKILL.md`：保留完整原文，改用普通历史Markdown文件名并同步现行引用；归档目录不保留可发现的技能入口。
- 去重前重新核对完整字节及引用。只有完全相同的副本才可按已获授权范围每组留一份；优先保留已引用版本，无引用时优先保留符合时间戳公式者。近似版本不视为重复，不按“最新”或年龄自动清理。
- 历史去重操作不构成未来删除授权。操作优先可恢复，不删除不同内容的历史版本，完成时说明移走的文件及恢复位置。

## 5. 现行文档的客观表述

技能入口、规则、规范、指南和模板承载已经吸纳、整理后的现行结论，只说明概念方法、适用条件、操作要求、填写方法及检查标准。正文、注释、括注、示例说明、工具说明及画布说明均遵循此口径，不包含知识来源追溯、原帖或原作者观点复述、资料核查经过、开发过程、讨论经过、变更日志、旧新版本对比或某次测试流水；不使用“原帖提出”“按用户某日要求”“此前调整”“本轮新增”等叙事作为规则的组成部分，也不设置此类来源或讨论章节。

现行规则只维护可复用的要求，不记录具体项目进度、任务状态、业务阶段结论、审批结果、故障排查过程或工作轨迹。此类事实按既有目录保存到对应项目资料或执行记录，具体服务的硬件、启动配置和现场状态留在其配置或交接资料中，不复制为通用规范。规则可以规定阶段推进条件和记录方法，不填入某个项目的实际状态。

项目经验需要沉淀为规则时，只提炼有依据的适用条件、操作要求和检查标准，不将个案结论直接扩大为通用要求；实际执行所必需的接口、依赖和兼容要求按其原有入口维护，不因清理业务记录而删除。

可以保留帮助理解规则和方法的示例；示例应能独立阅读，明确展示用法，不承担来源介绍、讨论记录或项目执行流水的职责，不将示例中的题材、参数或情境自动扩大为通用要求。是否设置示例仍遵循对应文件的职责和专项约定，不因此给生图模板新增参考案例或待补位置。

清理此类文字时，将仍有效的要求改写为可独立理解的现行表述，保留适用范围、条件、参数和授权边界，不因移除历史叙述改变业务规则。规则的有效性不依赖读者查阅此前对话。修改前完整内容按第4节归档，现行文件不另附修订经过。

版本号、更新日期、实际仍需使用的兼容路径与格式说明可以保留。依赖获取入口、执行所需的官方接口链接及许可证要求的署名属于使用或合规信息，按既有位置维护，不作为保留知识来源叙述的理由。讨论与资料整理过程不写入现行规则正文，无需为此新增记录目录。项目的生成、审阅、批准和归档事实及其记录字段属于业务资料，不属于应清理的技能开发历史；不删改这些事实，也不移除模板中用于记录它们的字段。历史归档保留原文，不追溯净化。

维护交付前检查受影响文档及引用方，确认规则可独立理解，正文、注释、示例、工具说明及画布说明均不含来源叙述、讨论经过、历史说明或具体项目业务记录；涉及参考文档接入时，同时核对第1.1节的文档职责与流程调用要求。确认模板字段、状态定义、参数和解析接口未被误改；新增规则或模板也按此口径编写。

## 分享边界与本机时间

分享范围为现行 `SKILL.md`、维护规范、被引用的规范和模板、固定工具、配套工作流及 `dependencies/` 中三个ComfyUI适配技能的完整安装内容。排除 `references/历史版本/`、`__pycache__/`、`.DS_Store`、缓存、项目目录与真实工作区配置；历史归档是本地技能开发备份，不是分享附件，保留以便恢复。项目浏览服务、风格库、工作区根目录README／AGENTS和本机FFmpeg环境不随独立技能分享。技能内指向这些工作区资源的链接是按能力使用的外部入口；接收方只有技能目录时，不要求访问不存在的工作区文件，也不把缺少浏览服务当作策划、文本创作或ComfyUI客户端不可用。需要网页浏览／同步、风格库或本地媒体处理时，另提供完整工作区及对应依赖，或明确缺失能力并暂停依赖该能力的操作；不能宣称已同步、已裁剪或已安排监控。项目浏览页及媒体不随技能分享。生图模板不附带项目媒体、请求附件、参考案例或依赖原项目目录的追溯链接，不维护项目进度。

依赖来源统一维护在[本规范第6节](#6-依赖获取与适配资料)的来源表（18个按需依赖技能）；GitHub来源记录仓库及准确技能目录或安装包，`skill-creator` 标注为Codex Desktop自带，三个ComfyUI技能以 `dependencies/` 内适配版为本流程唯一现行入口，不重复复制安装。山音 `screenwriting-master` 为独立安装的按需方法依赖，由本流程按阶段读取，不随本技能分发；使用边界见[依赖模块](references/流程规范/技能依赖与协作规范.md#适用平台与技能依赖)，来源及调用配置见本规范第6节。新增外部依赖默认安装到工作区 `.agents/skills/`，已有可用安装复用；三个随包真源不适用重复安装。维护时不自动改写其他同名安装；保留完整脚本、参考文档与许可证，排除 `state/` 等运行数据。跨技能协作依[依赖模块](references/流程规范/技能依赖与协作规范.md#依赖发现与获取)指定真源，其余按名称发现实际入口，不依赖个人安装路径。更新依赖真源时遵循本规范的归档及相关校验要求，不把个人服务器、项目记录或已安装模型清单写回分发内容。

归档与新记录一律使用运行本技能的使用者本机时区；程序使用带时区的本地时间并在记录中保存偏移。历史时间原文不改写。归档公式对脚本与JSON也适用，保留原扩展名；已有归档不覆盖。

独立分享前核对包内必需入口、模板、工作流、固定脚本及三份随包依赖均可读取；再区分指向工作区资源的外部链接，说明哪些能力需完整工作区。完整工作区维护时核对这些实际外部目标，不用静默忽略失效链接代替检查；不因验证分享边界创建新的依赖清单或版本台账。
