# 维护规范

版本：v1.19；确认日期：2026-09-28。

本文件只管理 `nora-ai-short-drama` 技能自身及其配套资源的维护，不规定短剧项目的创作内容、制作参数或审批流程。修改、扩展、改名、迁移、去重本技能前必须完整读取；普通短剧制作不默认加载。修改本维护规则须依据用户确认，不由agent自行新增分类或另定命名。通用技能维护同时遵循可用的skill-creator指引，用户明确确认的本技能结构优先。

## 1. 目录分类与文件归属

| 位置 | 职责 |
| --- | --- |
| `SKILL.md` | 技能入口、适用边界、按任务选择资料的阅读指引；不要求读完整个分类目录 |
| `维护规范.md` | 本技能目录、命名、引用与历史维护规则 |
| `agents/` | 现有技能界面元数据 |
| `dependencies/` | 三个ComfyUI适配技能的工作区真源，随工作区直接使用；保留必需资源、上游署名、来源版本及许可证，分发不带运行缓存 |
| `scripts/` | 工作流离线配对校验脚本及项目浏览页生成工具，保持既有入口 |
| `references/流程规范/` | 开发流程、会话与进度、逐集内容制作、目录资产管理及项目浏览入口 |
| `references/素材规范/` | 人物参考图初审记录、场景／道具资料及参考图、首帧、参考音视频管理 |
| `references/生成规范/` | 模型提示词规范及ComfyUI执行规范 |
| `references/模板/` | 独立维护、直接填充或调用的正文模板；已确认的正文、任务监控及项目总览HTML模板平铺存放，按对应规范入口读取 |
| `references/comfyui-workflow/` | 当前配套工作流画布与API基准；不维护独立基准快照 |

| `references/历史版本/` | 被替换规范的只读历史备份，不作为默认任务输入 |

不新建同义目录；需要新类别时先说明用途并获得用户确认。一个现行文件只维护一份，各处通过链接引用，不复制到多个分类。可填正文在模板目录单独维护，原规范仅保留适用范围、填写要求、审批、保存规则和模板链接，不复制完整正文。七类生图模板只保留生成正文、占位符、生成方式和必要填写说明，不写修订要求或另设修订模板；统一修订规则仅在[提示词规范第2.5节](references/生成规范/Qwen-Image-2.1-提示词规范.md#25-参考图统一修订规则)维护。其他文件通过链接引用；人物、场景、道具记录分别维护。Qwen参考图按七种图片类型维护专用模板，固定子情况及对应文生图／图生图方式以[提示词规范索引](references/生成规范/Qwen-Image-2.1-提示词规范.md#11-图片类型专用模板索引)为唯一分类依据；每种子情况一份填写模板，不设置参考案例或待补位置。新增或改变子情况须先获用户确认，同步索引、模板及引用，不临时添加非规定情况或补充说明。文生图／图像编辑两份共用模板只保留共用填写、辅助骨架和输出格式。生图模板只维护可填正文、必要填写说明与格式示意，不要求补全或替换参考案例；项目真实结果、参数、批准依据、失败流水与对照过程保存在项目生成／审阅记录，不回填模板。简短索引、关联字段、初审标准、目录树、命名公式和接口说明保留在规范中；关联字段属于完整模板时只引用其正式定义，不扩出独立模板。后续新增模板仍须获得相应维护授权，不能借模板化自行改变业务规则。工作流JSON不因具有模板性质而再放进“模板”。目录整理不自动授权修改业务规则、模型参数、实际项目资料或远端服务。

### 1.1 参考文档与工作流程的职责

参考文档解释“是什么、怎么用”：说明概念、方法、适用条件与使用边界，可提供帮助理解和应用的示例；不在文档自身指定短剧流程中的阶段安排。

工作流程规定“什么时候参考、参考后落实什么”：在相关任务或阶段中链接对应参考文档，写明触发条件、参考重点，以及应落实到哪些产出或检查项，不能只有笼统的“参考该文档”。文档自身的用途说明与流程中的调用要求须同时明确，前者不能替代后者；流程通过引用使用方法，不重复复制指南正文。

## 2. 文件命名与正文标题

- 现行文档按“对象＋用途＋文档类型”命名，不强求长度一致；规则文档以 `规范.md` 结尾，独立可填正文以 `模板.md` 结尾。
- 工具／模型名称与中文用途间统一用 `-`，例如 `ComfyUI-图生图执行规范.md`、`Qwen-Image-2.1-提示词规范.md`。模型标识中的2.1是模型身份，不是规范版本号。
- 现行文件名不带业务排序号、日期或规范版本；已有版本信息在正文维护。文档顶层标题与文件名去扩展名一致；模板中的项目产出标题置于可填正文围栏内，仍保持原产出标题，不把“模板”后缀带入项目文件。
- `SKILL.md`、`README.md`、代码和工作流文件沿用现有约定，不为统一中文规范命名而改动。历史备份保留当时文件名及正文标题，不套用现行标题规则追溯修改。
- 项目浏览页使用 `项目总览模板.html` 作为代码模板、`scripts/build_project_portal.py` 作为生成入口；项目产物固定为根目录 `项目总览.html`。HTML的页面标题由项目资料生成，不套用Markdown顶层标题规则；不把每个项目的生成页面复制回技能模板目录。
- 现行规范和模板以SKILL及对应规范中的链接为入口；兼容路径按第3节对照表解析。新增／变更命名遵循本节，涉及分类调整先确认。

## 3. 引用同步与校验

1. 操作前明确本次变更范围与完成标准，核对相关源文件、目标路径和引用方，检查其他会话正在产生的改动；以磁盘最新内容为准，不覆盖无关更新。
2. 改名或移动后，同步现行SKILL入口、规范间相对链接、代码／命令中的实际路径和正文标题。跨分类链接从新位置重算；跨技能链接及工作流、脚本路径也要检查，不只替换文件名。
3. 不留第二套可编辑旧规则，不自动批量改写项目资料、既有执行请求、历史文档或定时器配置。检查外部引用并报告；接续者从SKILL现行入口或下表解析旧名。恢复旧定时器前须核对其入口，但不得因本次维护擅自恢复或修改调度。
4. 按下表选择与变更有关的检查，核对受影响的本地链接、章节锚点和目标文件；改名或移动时还须查找并同步现行引用方，检查旧路径残留。提取模板时逐项核对原字段、顺序、正文及必要附表未丢失，检查入口与返回规范的链接，不形成第二份可编辑正文。运行技能校验；其他测试按实际影响选择，不默认执行无关检查。
5. 交付说明实际变更、检查范围与结果；涉及迁移、改名或去重时，补充仍保留的外部旧引用及可恢复位置。

| 变更类型 | 必须检查的范围 |
| --- | --- |
| 仅措辞、排版或说明调整 | 对照原文确认含义及要求未变，核对相关引用；不因文字修改运行工作流或浏览工具测试 |
| 模板、业务规则或目录命名调整 | 核对受影响的上下游规范、字段、路径及引用；按第3.1节判断浏览工具是否需要适配。仅目录整理时确认涉及的工作流与代码内容未变，不以文件移动代替业务验证 |
| 脚本或工作流调整 | 运行受影响功能的现有测试，覆盖相关调用方和失败处理；工作流配对及浏览工具分别按其专项要求检查 |

同一变更涉及多类时合并相关检查；检查范围按实际依赖确定，不只看文件扩展名。仅当用户明确要求全量检查，或改动确实影响全局引用／共用行为时，扩大到对应全量检查。技能维护校验不替代业务审批、运行前核对、防重复提交及其他安全要求。

### 3.1 浏览工具联动检查

修改技能规范或正文模板时，必须检查是否影响[浏览入口的输入格式与解析依赖](references/流程规范/项目浏览入口规范.md#5-输入格式与解析依赖)。项目目录、文件名、编号、字段名、索引表头、记录章节、审批／执行状态及素材引用方式变化均在检查范围；不能只检查链接是否存在。

1. 对照实际生成脚本判断影响范围：输入解析、页面数据结构、HTML展示、回归测试及使用说明。仅创作措辞、参数值或不被解析的正文变化，不自动要求改代码；记录“需要适配／无需适配”及简要依据。
2. 需要适配时，在同一维护任务内同步规范、脚本、HTML模板、相关测试和第5节依赖说明；只有受影响的组成部分需要修改，不机械复制规则或逐次重写工具。不通过改写项目审批事实或批量迁移旧资料来迁就解析器。
3. 涉及浏览工具或其输入格式、输出行为时，按[维护检查](references/流程规范/项目浏览入口规范.md#4-维护检查)验证，再按授权范围重建受影响且已接入的项目页面，核对本次变化对应的条目、状态及入口。仅规范说明变化且不影响解析或现有输出时，无需运行浏览工具测试或重建页面，简述判断依据即可。技能更新不自动授权给未接入项目建页或批量刷新其他项目。
4. 交付报告影响判断、实际修改、测试结果、重建项目及核验情况；未完成的适配、生成或浏览器验证单列。不将测试通过等同于页面已重新生成，不将重新生成等同于业务批准。

日常项目推进的刷新责任与时机统一见[交付前同步检查](references/流程规范/项目浏览入口规范.md#交付前同步检查)，本节只管理技能变更的联动，不另立一套项目进度。

### 3.2 固定脚本调用说明

脚本的目标是让agent依据说明直接调用，不通过阅读源码临时设计用法。新增脚本或修改调用接口时，在已有对应规范／工具说明中同步维护用途与使用时机、运行环境、可复制命令、参数含义与默认值（含单位和路径基准）、输出及成功／失败判断，以及实际写入或联网范围；从技能入口或对应任务规范可以找到，不另建重复说明。

命令行工具的 `--help` 应解释可选参数，不只列参数名；测试脚本提供标准测试命令、覆盖范围和结果判断，不必另造命令行接口。维护时按说明验证相关命令及帮助与实现一致。说明缺口在获授权维护时补回说明，不把每次读源码作为常规使用步骤；也不因补说明触发远端生成或增加无关验证。调用与按需查源码的规则统一见[固定脚本调用](SKILL.md#固定脚本调用)。

## 4. 历史归档、去重与读取边界

- 保留内容不同的历史版本。追溯、比较或恢复时才读取；不得用旧规则覆盖现行规则，也不因看到旧参数就恢复旧模板或重跑任务。
- 确认替换现行规则内容前，保存修改前完整内容；纯移动、改名和引用更新不必逐文件制造一套内容相同的历史副本。归档不代表旧版仍有执行效力。
- 后续归档使用 `{当时正式文件名去扩展名}-归档-YYYYMMDD-HHmmss.md`，使用者本机时区精确到秒；同名冲突选择新的实际时间戳，不覆盖。既有历史文件不追溯改名，不重写其旧标题、引用或事实。
- 去重前重新核对完整字节及引用。只有完全相同的副本才可按已获授权范围每组留一份；优先保留已引用版本，无引用时优先保留符合时间戳公式者。近似版本不视为重复，不按“最新”或年龄自动清理。
- 历史去重操作不构成未来删除授权。操作优先可恢复，不删除不同内容的历史版本，完成时说明移走的文件及恢复位置。

## 5. 现行文档的客观表述

技能入口、规则、规范、指南和模板承载已经吸纳、整理后的现行结论，只说明概念方法、适用条件、操作要求、填写方法及检查标准。正文、注释、括注和示例说明均遵循此口径，不包含知识来源追溯、原帖或原作者观点复述、资料核查经过、开发过程、讨论经过、变更日志、旧新版本对比或某次测试流水；不使用“原帖提出”“按用户某日要求”“此前调整”“本轮新增”等叙事作为规则的组成部分，也不设置此类来源或讨论章节。

可以保留帮助理解规则和方法的示例；示例应能独立阅读，明确展示用法，不承担来源介绍、讨论记录或项目执行流水的职责，不将示例中的题材、参数或情境自动扩大为通用要求。是否设置示例仍遵循对应文件的职责和专项约定，不因此给生图模板新增参考案例或待补位置。

清理此类文字时，将仍有效的要求改写为可独立理解的现行表述，保留适用范围、条件、参数和授权边界，不因移除历史叙述改变业务规则。规则的有效性不依赖读者查阅此前对话。修改前完整内容按第4节归档，现行文件不另附修订经过。

版本号、更新日期、实际仍需使用的兼容路径与格式说明可以保留。依赖获取入口、执行所需的官方接口链接及许可证要求的署名属于使用或合规信息，按既有位置维护，不作为保留知识来源叙述的理由。讨论与资料整理过程不写入现行规则正文，无需为此新增记录目录。项目的生成、审阅、批准和归档事实及其记录字段属于业务资料，不属于应清理的技能开发历史；不删改这些事实，也不移除模板中用于记录它们的字段。历史归档保留原文，不追溯净化。

维护交付前检查受影响文档及引用方，确认规则可独立理解，不含来源叙述、讨论经过或历史说明；涉及参考文档接入时，同时核对第1.1节的文档职责与流程调用要求。确认模板字段、状态定义、参数和解析接口未被误改；新增规则或模板也按此口径编写。

## 分享边界与本机时间
