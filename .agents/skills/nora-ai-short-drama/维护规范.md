# 维护规范

版本：v1.137；更新日期：2026-10-24。

本文件管理Nora主控、七个核心业务技能、社交媒体主页视觉专项、视频读取与分析专项、表情拆解专项、三个打戏专项及配套资源的结构维护，不规定短剧项目的创作内容、制作参数或审批流程。维护时按下方路径读取；普通短剧制作不默认加载。修改本维护规则须依据用户确认，不由agent自行新增分类或另定命名。通用技能维护同时遵循可用的skill-creator指引，用户明确确认的本技能结构优先。

## 维护任务读取路径

修改前读取第1节中与目标文件有关的分类及“规则真源与引用”、第3节的适用校验、第4节归档要求和第5节表述要求。真源索引按本次规则检索；文件命名／移动读第2节及兼容路径，脚本接口读第3.2节，依赖获取／更新读第6节，分发打包读分享边界。未涉及的长表及专项章节不加载；已读且未变化的内容复用。修改落地后、交付或继续后续业务前，自动执行[维护落地后的自动复查](#维护落地后的自动复查)，不等待用户另行提醒。

工作流根目录按技术分类：Qwen Image 2.1生成配对放入 `Qwen-image-2-1/`，MiniMax H3生成配对放入 `Minimax-H3/`，图片与视频的超分、插帧配对放入 `后处理综合/`；根目录不散放配对。正式分类包括默认与按条件使用的版本，同名画布与API放在一起。不再正式使用的旧版、备用及实验工作流移入 `references/comfyui-workflow/非正式工作流/`，不作为常规任务入口。目录定位统一由[scripts/workflow_paths.py](scripts/workflow_paths.py)维护，装配、列表、下载和校验复用其分类入口；正式基准按名称定位唯一文件，调用方不拼接技术分类路径。新增技术分类时更新该入口及对应执行规范，不自动递归读取任意子目录。迁移时同步规范链接及校验工具，不保留同一配对的两份可编辑副本。修改前的历史备份仍存入 `references/历史版本/`；真实短剧制作中的任务副本仍按项目既定位置保存。

### 工作流基准与任务副本

用户提供的原始文生图和图生图 `.workflow.json` 只在规定的工作流目录原样保存，禁止修改文件内容或生成修改过的任务画布。配套 `.api.json` 独立维护，任务复制API并按调用说明填写允许修改的字段；不另建snapshot。视频仍使用现行装配入口，收到新的工作流及相应授权后再调整。

不执行画布与API的配对、一致性、来源差异或参数漂移比较，不把这类比较改名保留。用户更新画布时与Agent一起维护执行API和调用说明。维护只运行受影响的API结构、执行参数及调用行为测试；日常准备只保留本次任务参数、接口、素材关联和审批等必要检查。API内部时间线、素材映射与实际任务身份的核对不属于画布与API比较。静态通过不等于服务兼容或生成成功。

真实短剧制作任务的请求、参数、任务ID、响应与采用依据保存在对应项目，不随基准更新改写。获准替换正式文件时先保存修改前内容。可配置的远端产物遵循[输出目录与命名](../nora-generation/references/ComfyUI-服务配置与任务提交规范.md#远端输出目录与命名)；导演台插件的分段保存和缓存目录按原规则处理。

### 规则真源与引用

1. **唯一维护入口**：工作区AGENTS.md保留全局行为、授权及基本目录约定；项目管理、创作制作及技术验证细则归主技能或对应业务技能，单个项目的设定、进度与执行事实仍归该项目资料。入口只链接相应细则，不把业务正文复制为全局规则。同一条业务规则仅在一个明确章节维护，其他入口保留适用时机、任务特有说明和链接，不复制条件、参数或禁令。模板维护可填正文，执行说明维护技术映射，不另行定义业务选择。
2. **新增与修改**：落笔前先查本节索引及相关现行文件，确定规则归属。已有规则只修改其真源，并核对引用方；新增规则类别或调整归属时，同步下方索引和受影响链接，不为了方便阅读另写一份可编辑规则。
3. **维护交付检查**：修改落地后按[维护落地后的自动复查](#维护落地后的自动复查)完成检索、订正及核实；该项是每次维护的默认收尾，不以用户另行要求检查为触发条件。

### 1.1 参考文档与工作流程的职责

参考文档解释“是什么、怎么用”：说明概念、方法、适用条件与使用边界，可提供帮助理解和应用的示例；不在文档自身指定短剧流程中的阶段安排。

工作流程规定“什么时候参考、参考后落实什么”：在相关任务或阶段中链接对应参考文档，写明触发条件、参考重点，以及应落实到哪些产出或检查项，不能只有笼统的“参考该文档”。文档自身的用途说明与流程中的调用要求须同时明确，前者不能替代后者；流程通过引用使用方法，不重复复制指南正文。

## 2. 文件命名与正文标题

- 现行文档按“对象＋用途＋文档类型”命名，不强求长度一致；规则文档以 `规范.md` 结尾，独立可填正文以 `模板.md` 结尾。
- 工具／模型名称与中文用途间统一用 `-`，例如 `ComfyUI-图生图执行规范.md`、`Qwen-Image-2.1-提示词规范.md`。模型标识中的2.1是模型身份，不是规范版本号。
- 现行文件名不带业务排序号、日期或规范版本；已有版本信息在正文维护。文档顶层标题与文件名去扩展名一致；模板中的项目产出标题置于可填正文围栏内，仍保持原产出标题，不把“模板”后缀带入项目文件。
- `SKILL.md`、`README.md`、代码和工作流文件沿用现有约定，不为统一中文规范命名而改动。历史备份保留当时文件名及正文标题，不套用现行标题规则追溯修改。
- 浏览入口使用[浏览服务](../../../工作区浏览服务/README.md)，读取与核验要求见[浏览入口规范](references/流程规范/项目浏览入口规范.md#生成与更新)。项目源文件由服务解析器读取，展示由React组件维护，不维护项目静态HTML生成工具。
- 现行规范和模板以SKILL及对应规范中的链接为入口；兼容路径按第3节对照表解析。新增／变更命名遵循本节，涉及分类调整先确认。

## 3. 引用同步与校验

1. 操作前明确本次变更范围与完成标准，核对相关源文件、目标路径和引用方，检查其他会话正在产生的改动；以磁盘最新内容为准，不覆盖无关更新。
2. 改名或移动后，同步现行SKILL入口、规范间相对链接、代码／命令中的实际路径和正文标题。跨分类链接从新位置重算；跨技能链接及工作流、脚本路径也要检查，不只替换文件名。
3. 不留第二套可编辑旧规则，不自动批量改写项目资料、既有执行请求、历史文档或定时器配置。检查外部引用并报告；接续者从SKILL现行入口或下表解析旧名。恢复旧定时器前须核对其入口，但不得因本次维护擅自恢复或修改调度。
4. 新增或修改规则时，先按[规则真源与引用](#规则真源与引用)确定维护入口，完成修改后自动执行[维护落地后的自动复查](#维护落地后的自动复查)；按下表选择与变更有关的检查，核对受影响的本地链接、章节锚点和目标文件；同时搜索正文中的章节名、节号及“读取SKILL中的”等非链接指路，确认所指内容确实位于目标章节。普通链接检查不能代替这项语义核对。改名或移动时还须查找并同步现行引用方，检查旧路径残留。提取模板时逐项核对原字段、顺序、正文及必要附表未丢失，检查入口与返回规范的链接，不形成第二份可编辑正文。运行技能校验；其他测试按实际影响选择，不默认执行无关检查。
5. 交付说明实际变更、检查范围与结果；涉及迁移、改名或去重时，补充仍保留的外部旧引用及可恢复位置。

| 变更类型 | 必须检查的范围 |
| --- | --- |
| 仅措辞、排版或说明调整 | 对照原文确认含义及要求未变，核对相关引用；不因文字修改运行工作流或浏览工具测试 |
| 模板、业务规则或目录命名调整 | 核对受影响的上下游规范、字段、路径及引用；按第3.1节判断浏览工具是否需要适配。仅目录整理时确认涉及的工作流与代码内容未变，不以文件移动代替业务验证 |
| 脚本或工作流调整 | 运行受影响功能的现有测试，覆盖相关调用方和失败处理；API结构、执行参数及浏览工具分别按适用要求检查 |

同一变更涉及多类时合并相关检查；默认收尾按下方[自动复查](#维护落地后的自动复查)执行，深入检查范围按实际依赖确定，不只看文件扩展名。需要对无关主题也作全量逐项检查时，以用户明确要求或改动确实影响全局引用／共用行为为依据。技能维护校验不替代业务审批、运行前核对、防重复提交及其他安全要求。

### 维护落地后的自动复查

新增、修改、替换、移动或合并本技能及配套资源中的规则、规范、模板、入口或工具说明后，由执行修改的Agent主动完成本节；不等待用户再次要求检查。交付维护结果或继续依赖该修改的后续业务前，须完成适用检查及授权范围内的订正，不能把文件已写入视为维护已完成。

1. **落地内容**：对照本次授权及实际改动，核实要求是否写对、写全、归属唯一；新增内容是否进入现行文件，而非只留在讨论或历史备份中。
2. **旧规则与重复**：检索本次规则的关键词、同义说法和旧条件，读取命中的相关正文及直接上下游，核对相反要求、过期说法、重复定义和流程冲突。同步仍在使用的旧口径；同一规则的重复正文改为指向真源的引用。历史备份和既有执行事实保留，不作为现行规则清理。
3. **引用与可达性**：检查受影响的技能入口、规范、模板及工具说明中的路径、章节锚点、节号和非链接指路，核实目标存在且内容相符。确认实际任务的读取入口会指向新增或调整的规则，并说明何时读取、落实到哪些产出或检查；只有文件存在或链接有效，不等于Agent能在工作时读到并执行。
4. **订正与复核**：发现上述问题，在本次授权范围内同步修正真源、调用方和必要索引，再复查受影响部分，并运行第3节规定的适用校验。不能安全处理或超出授权的问题，说明具体位置、影响和未完成原因，不称为全部检查通过；受该问题阻碍的后续业务暂不推进。
5. **交付与范围**：交付时简述实际检查范围、已修正项、验证结果及真实未解决项；只报告执行过的检查。检查围绕本次变更，同一批修改合并执行一次，未受后续修改影响的已通过项直接复用；只有发现具体依赖问题才扩展，不默认通读全部命中文件、递归展开全部链接或扫描无关主题。不新增独立检查台账或审批步骤，也不据此自动改写真实项目、历史请求或启动生成任务。

### 项目目录整洁与旧结构迁移

获授权维护项目目录，或将既有短片、样片及其他旧结构转为正式项目时，读取[旧结构转为正式项目](references/共用规则/文件版本与工作稿规范.md#旧结构转为正式项目)，将目录归位与引用收尾纳入本次完成范围。项目资料的分类、快照、迁移、授权及完成检查由该规则统一维护；本节不另设归档目录，不将纯规则维护扩展为其他项目的自动整理。

### 技术测试与隔离验证

先按[技术测试资料归属](references/共用规则/文件版本与工作稿规范.md#技术测试资料归属)确定本次用途与保存位置，再选择验证环境。

- 自动化回归或需模拟完整项目结构的验证，使用独立临时工作区；其中可以包含模拟的 `projects/`，但不得指向正式工作区的项目目录，也不将测试项目接入正式服务的项目列表。需保留的结果按[技术测试资料归属](references/共用规则/文件版本与工作稿规范.md#技术测试资料归属)归档。
- 需要验证真实网页、后台或生成链路，也不能为了复用工具或方便浏览而把测试目录放进正式 `projects/`，或把测试素材登记成真实短剧资产。工具受路径限制时，说明限制，按本次授权调整隔离验证方案；无法完成的部分如实标明，不以测试通过代替未执行的验证。修改共用服务仍遵循单独授权要求。

### 3.1 浏览工具联动检查

准备技术测试或浏览器验证时，先执行[技术测试与隔离验证](#技术测试与隔离验证)，再判断本节的联动范围。

修改技能规范或正文模板时，必须检查是否影响[浏览入口的输入格式与解析依赖](references/流程规范/项目浏览入口规范.md#5-输入格式与解析依赖)。项目目录、文件名、编号、字段名、索引表头、记录章节、审批／执行状态及素材引用方式变化均在检查范围；不能只检查链接是否存在。

1. 先按上述输入格式说明判断是否改变解析字段、路径或状态语义；涉及这些变化或无法判定时，再查看相关解析器代码，确定输入解析、页面数据结构、React展示、测试及说明的影响。仅规则读取路径、操作说明或不被解析的正文变化，不要求查看实现或改代码；交付时简述“需要适配／无需适配”及依据。
2. 需要适配时，在同一维护任务内同步规范、解析器、React组件、相关测试和第5节依赖说明；只有受影响的组成部分需要修改，不机械复制规则或逐次重写工具。不通过改写项目审批事实或批量迁移旧资料来迁就解析器。
3. 涉及浏览工具或其输入格式、输出行为时，按[维护检查](references/流程规范/项目浏览入口规范.md#4-维护检查)验证，再核验受影响项目的同步状态及实际条目，核对本次变化对应的条目、状态及入口。仅规范说明变化且不影响解析或现有输出时，无需运行浏览工具测试或重新读取项目，简述判断依据即可。技能更新不自动授权批量修改项目资料。
4. 交付报告影响判断、实际修改、测试结果、项目同步及核验情况；未完成的适配、同步或浏览器验证单列。不将测试通过等同于资料已同步，不将资料同步等同于业务批准。

日常项目推进的刷新责任与时机统一见[交付前同步检查](references/流程规范/项目浏览入口规范.md#交付前同步检查)，本节只管理技能变更的联动，不另立一套项目进度。

### 3.2 固定脚本调用说明

脚本的目标是让agent依据说明直接调用，不通过阅读源码临时设计用法。新增脚本或修改调用接口时，在已有对应规范／工具说明中同步维护用途与使用时机、运行环境、可复制命令、参数含义与默认值（含单位和路径基准）、输出及成功／失败判断，以及实际写入或联网范围；从技能入口或对应任务规范可以找到，不另建重复说明。

命令行工具的 `--help` 应解释可选参数，不只列参数名；测试脚本提供标准测试命令、覆盖范围和结果判断，不必另造命令行接口。维护时按说明验证相关命令及帮助与实现一致。说明缺口在获授权维护时补回说明，不把每次读源码作为常规使用步骤；也不因补说明触发远端生成或增加无关验证。调用与按需查源码的规则统一见[固定脚本调用](SKILL.md#固定脚本调用)。

## 4. 历史归档、去重与读取边界

- 保留内容不同的历史版本。追溯、比较或恢复时才读取；不得用旧规则覆盖现行规则，也不因看到旧参数就恢复旧模板或重跑任务。
- 确认替换现行规则内容前，保存修改前完整内容；纯移动、改名和引用更新不必逐文件制造一套内容相同的历史副本。归档不代表旧版仍有执行效力。
- 后续归档使用 `{当时正式文件名去扩展名}-归档-YYYYMMDD-HHmmss.md`，使用者本机时区精确到秒；同名冲突选择新的实际时间戳，不覆盖。既有历史文件不追溯改名，不重写其旧标题、引用或事实。例外是会被平台注册为技能的历史 `SKILL.md`：保留完整原文，改用普通历史Markdown文件名并同步现行引用；归档目录不保留可发现的技能入口。
- 去重前重新核对完整字节及引用。只有完全相同的副本才可按已获授权范围每组留一份；优先保留已引用版本，无引用时优先保留符合时间戳公式者。近似版本不视为重复，不按“最新”或年龄自动清理。
- 历史去重操作不构成未来删除授权。操作优先可恢复，不删除不同内容的历史版本，完成时说明移走的文件及恢复位置。

## 5. 现行文档的客观表述

技能入口、规则、规范、指南和模板承载已经吸纳、整理后的现行结论，只说明概念方法、适用条件、操作要求、填写方法及检查标准。正文、注释、括注、示例说明、工具说明及画布说明均遵循此口径，不包含知识来源追溯、原帖或原作者观点复述、资料核查经过、开发过程、讨论经过、变更日志、旧新版本对比或某次测试流水；不使用“原帖提出”“按用户某日要求”“此前调整”“本轮新增”等叙事作为规则的组成部分，也不设置此类来源或讨论章节。

现行规则只维护可复用的要求，不记录具体项目进度、任务状态、业务阶段结论、审批结果、故障排查过程或工作轨迹。此类事实按既有目录保存到对应项目资料或执行记录，具体服务的硬件、启动配置和现场状态留在其配置或交接资料中，不复制为通用规范。规则可以规定阶段推进条件和记录方法，不填入某个项目的实际状态。

项目经验需要沉淀为规则时，只提炼有依据的适用条件、操作要求和检查标准，不将个案结论直接扩大为通用要求；实际执行所必需的接口、依赖和兼容要求按其原有入口维护，不因清理业务记录而删除。

[表情参考表](../facial-expression/references/表情参考表.md)保留已获授权的写法验证情况，只记适用写法、已知模型／模式、用途及必要条件下的简短结论。它不承载项目流水或知识来源；实际请求与反馈原话留在原项目记录，更新条件按[反馈复核](../facial-expression/SKILL.md#收到真实反馈后复核)执行。

可以保留帮助理解规则和方法的示例；示例应能独立阅读，明确展示用法，不承担来源介绍、讨论记录或项目执行流水的职责，不将示例中的题材、参数或情境自动扩大为通用要求。是否设置示例仍遵循对应文件的职责和专项约定，不因此给生图模板新增参考案例或待补位置。

清理此类文字时，将仍有效的要求改写为可独立理解的现行表述，保留适用范围、条件、参数和授权边界，不因移除历史叙述改变业务规则。规则的有效性不依赖读者查阅此前对话。修改前完整内容按第4节归档，现行文件不另附修订经过。

版本号、更新日期、实际仍需使用的兼容路径与格式说明可以保留。依赖获取入口、执行所需的官方接口链接及许可证要求的署名属于使用或合规信息，按既有位置维护，不作为保留知识来源叙述的理由。讨论与资料整理过程不写入现行规则正文，无需为此新增记录目录。项目的生成、审阅、批准和归档事实及其记录字段属于业务资料，不属于应清理的技能开发历史；不删改这些事实，也不移除模板中用于记录它们的字段。历史归档保留原文，不追溯净化。

维护交付前检查受影响文档及引用方，确认规则可独立理解，正文、注释、示例、工具说明及画布说明均不含来源叙述、讨论经过、历史说明或具体项目业务记录；涉及参考文档接入时，同时核对第1.1节的文档职责与流程调用要求。确认模板字段、状态定义、参数和解析接口未被误改；新增规则或模板也按此口径编写。

### ComfyUI节点与安装包

获准随技能提供的节点源码目录与ZIP安装包统一放在本技能`dependencies/ComfyUI节点资源/`，不放入工作流目录、项目执行附件或历史目录作为现行依赖入口。项目中已有的测试包、实际部署和执行证据继续保留，不随正式依赖登记迁移或改写。

- 可保存可安装的节点源码目录、ZIP安装包，或同时保存两者。目录与包名使用实际节点名称，不按某个项目、剧集或服务器命名。只保留ZIP时，包内源码为维护入口；两者并存时，源码目录为唯一维护入口，ZIP为对应分发产物，修改后同步打包与测试，不分别编辑两套源码。
- 每个依赖登记实际路径、节点类名、来源及版本依据、许可证、所需原节点／模型、安装验证和回退方法。保留用户要求留存的安装包；包内只带运行代码、必要说明、测试和许可证，不带模型权重、个人凭证、服务配置、缓存或项目素材。
- 安装包属于资源，不是新增技能，不设置`SKILL.md`触发入口。保留原注册类名及安装目录以维持已有画布兼容；工作流转为正式不自动改接口名、升级依赖或重新安装。
- 安装、更新和服务重启仍须有对应授权；优先复用已安装且兼容的版本。缺少节点或模型时如实报错，不自动安装、下载或切换备用算法。验证失败不覆盖原节点，重启不得中断运行或排队任务。

```text
<ComfyUI Python> -X utf8 -B preflight.py --comfy-root <实际ComfyUI根目录> --original-node-dir <实际ComfyUI-VFI目录>
<ComfyUI Python> -X utf8 -B -m unittest discover -s tests -v

```

`preflight.py`只读检查源码接口及已有权重，单元测试不使用GPU，`smoke_test.py`在队列空闲时使用真实CUDA和现有权重，不生成项目视频。三项均退出0后，将独立节点目录复制到实际`custom_nodes/`；目标存在且内容不同则停止，不覆盖。获准空闲重启后，核验原`RIFEInterpolation`和`NoraRIFEInterpolationCutTest`同时注册，后者输出`IMAGE/FLOAT/STRING`。在实际执行记录留存路径、安装版本依据及测试结果，不把静态检查或注册成功记为视频通过审核。

回退时在服务空闲并停止后，仅将本独立节点目录移到`custom_nodes/`之外，再以原方式启动；不在`custom_nodes/`内仅改后缀。停用节点不自动切换替代工作流，不修改历史请求、视频或审批，也不自动重处理。
