# 首帧参考图规范

版本：v1.12；更新日期：2026-09-29。

适用于场次首帧图的制作、复用、初审、审批与记录。每个场次必须准备并采用一张首帧图，依据该场次首个分段的首镜开始状态形成单张完整画面；仅在该首个分段中作为首帧参考。后续分段默认不单独制作首帧图，用户明确提出需要时再讨论例外。“首帧”是参考用途，当前多参考工作流不承诺逐像素硬锁。

## 1. 制作、复用与画面要求

编写或修订首帧提示词时，参考[镜头语言参考指南](../生成规范/镜头语言参考指南.md)的静态表达、构图、观察角度、光影与焦点相关内容，将已确认首镜的开始状态落实为人物站位、视线、取景、注意力中心和清晰区域。只描述开场这一刻，不提前表现后续动作或运镜终点；指南不授权改变分镜，构图有冲突时先修订上游。复用判断沿用下列规则，不因采用新术语自动补图。

- 场次首个分段分镜明确后，为本场确定一张已批准首帧图；已有图完全适用时可选用并记录，无适用图时制作新图。该图在本场仅供首个分段作为首帧参考，不能因后续分段构图相似就自动作为其首帧。
- 首个分段必须实际输入本场已采用首帧图，提示词明确其开场用途；人物、道具及其他参考按实际需要选择，不机械凑齐类型。后续分段是否使用本场首帧图由用户决定，使用时仅参考指定的环境、人物或状态信息，不要求从该图的构图或姿态开始。用户选择在既有分段素材映射中记录，可一次明确多个分段，不重复询问已明确的选择。
- 每个分段（包括首段）除人物、道具参考外，必须实际输入至少一张可用于环境参考的图片：本场首帧图、所在场景图或用户指定且适用于本段的图片。人物、道具参考齐备不能替代环境参考；首段首帧图可兼任环境参考，不为凑数额外加图。必须明确该图提供的环境信息与对应标签，不能只登记而不实际输入。后续段不使用本场首帧图时，必须选用其他环境参考图。
- 景别、机位、站位、视线、遮挡和构图符合首镜；人物身份、人数、服装、发型、伤病、持有物及场景布局、时间天气、光线、道具状态正确。
- 表现开始时刻，不把后续人物、动作结果提前塞进首帧；准备拿杯子不能提前画成已经喝完。使用剧情真实环境，不套用人物资产的白色摄影棚背景。
- 不添加分镜号、提示文字、水印、装饰边框；剧情确需可见的招牌等文字按设定。多视角参考中的同一人物／道具不能被误生成多个主体。
- 完整画面不等于全身照；按首镜取景，特写可只显示脸，画外人物道具不强塞。重要区域缺少依据先补设计，不把随机生成的新设定直接批准为合格。
- 默认16:9、2560×1440、PNG。项目另有画幅先明确固定目标尺寸；视频输出尺寸单独管理，当前工作流比例不严格等于16:9，不能擅自拉伸。必要裁切／适配先明确方法并检查构图。本规范尺寸是制作目标，不扩大实际执行验证范围。
- 图像编辑提示词与执行仍分别读取 [Qwen规范](../生成规范/Qwen-Image-2.1-提示词规范.md) 对应分支和 [图生图说明](../生成规范/ComfyUI-图生图执行规范.md)，不临时改默认技术参数以适配尺寸。

## 2. 目录、命名与版本

以下相对单集根目录：

- 正式图：`04-专用素材/EP编号-C编号-P001-首帧参考图.png`。
- 索引：`04-专用素材/EP编号-素材索引.md`。
- 生成记录：`04-专用素材/EP编号-素材生成记录.md`，整集共一份，不按场次重复建。
- 候选：单集 `其他资料/过程稿/{正式图片名去扩展名}-草稿-v{两位版本}.png`。
- 讨论／审阅：单集 `其他资料/讨论记录/` 与 `其他资料/审阅记录/`，`{正式图片名去扩展名}-讨论记录-{三位序号}.md`、`{正式图片名去扩展名}-审阅记录-{三位序号}.md`。
- 被替代正式图：单集 `其他资料/历史版本/{正式图片名去扩展名}-归档-YYYYMMDD-HHmmss.png`；使用使用者本机时间，重名不得覆盖。

正式图片、素材索引与素材生成记录直接平铺在04根目录，不再按媒体类型、用途、场次或分段建子目录。EP/C/P编号采用固定宽度，文件名按集号、场次、分段、用途排列，便于按名称排序。

新制场次首帧保留EP/C/P001命名，不改成无分段编号的新公式。已有图用于另一场次首段时只引用已有图并登记适用场次，不复制或改名；同场后续分段仅按用户选择作为普通参考。仅替换同一正式图时归档旧版，保留候选及具体批准依据，不丢失历史输入来源。

本集素材索引只登记本目录真实保存的素材：素材编号（首帧用所属分段编号）、类型、正式文件入口、用途说明、来源及生成／处理记录入口、审核／采用状态与具体版本依据。没有使用音视频时不建空关联；项目音视频不复制到本索引成为另一套素材库。每段实际采用何图、以何种用途及标签上传，统一在分段准备与执行映射维护。

## 3. 固定初审与审批

生成候选 → agent技术审查通过 → agent内容审查（非阻塞） → 用户最终审核 → 批准后正式采用。实际查看输出整图和必要局部，输入对照按[输入参考图检查与记录复用](../生成规范/Qwen-Image-2.1-提示词规范.md#24-输入参考图检查与记录复用)执行；逐项填写下表，不以任务成功、尺寸正确或提示词完整代替看图。

| 编号 | 固定检查范围 |
| --- | --- |
| F01 文件规格 | 正常打开，真实尺寸／格式正确，无未经允许的拉伸或裁切 |
| F02 制作依据 | 对应场次首个分段、首镜、开始状态及参考素材具体版本正确；后续分段另制首帧须有用户明确的例外决定 |
| F03 开场构图 | 景别、机位、取景、站位、视线、遮挡符合首镜 |
| F04 人物一致性 | 身份、人数、年龄感、发型、服装及可见身体状态正确 |
| F05 场景与道具 | 空间关系、时间光线、道具结构／状态／持有关系正确 |
| F06 动作与连续性 | 未提前表现后续动作结果，与剧情衔接要求不冲突 |
| F07 画面质量 | 无明显畸变、融合、悬浮、重复主体、异常文字或关键细节模糊 |
| F08 使用适配 | 与目标首镜一致（默认本场首段，例外按用户决定），首帧与环境用途明确；后续普通参考用途不得附加首帧约束，不存在相互矛盾的指令 |

只判断实际可见的内容，画外信息不凭空判定合格；不适用项说明原因。agent只检查既定要求及可识别缺陷，不代替用户另定审美方向。

阶段分工：F01为技术规格，F07中明确画面损坏、异常叠加、严重变形／融合／断裂等归技术审查；F02–F06、F08以及普通内容重复、文字／清晰度偏差归内容审查。同一检查项含两类问题时分别记录，不整体升级为阻塞项。技术异常的准确边界及最多2次重试、1张／3张展示方式统一按[开发流程8.5.1](../流程规范/短剧开发流程规范.md#851-图片有限返修与集中送审)。

技术结论仅“通过／不通过／待确认”，只有明确技术不通过触发额度内重试；无法看图记技术待确认并报告。技术未通过不做内容审查，明确记录“技术审查未通过，未进行内容审查”。技术通过后逐项记录内容“符合／有偏差／待确认／不适用”及依据，内容偏差或依据不足不阻塞最终送审、不自动返修。用户决定正式采用；局部认可不等于整图批准，修改后重新两阶段审查，不继承旧版本结论。

复用未修改的已批准图只补做本次适用性检查，不重复强制审批同一图片；修改后的任何候选重新初审和用户审核，局部认可不代替整图批准。若未实际检查不得写已检查。

## 4. 首帧生成记录模板

使用[首帧参考图生成记录模板](../模板/首帧参考图生成记录模板.md)的两个固定内容章节：当前正式资产、逐次生成记录。只登记已批准资产；索引提供浏览入口，此处提供生成追溯，不另维护各段上传清单。

每次实际提交使用 `生成记录-{三位序号}`，整集首帧任务从001连续递增，不按场次重启。候选v按每个正式图独立递增，与生成序号不同。每条使用模板中的五部分，保存完整实际提示词及输入、参数、执行证据、初审和用户采用依据。

不存在的参数填不适用，未知待补充；不伪造任务ID。失败条目保留，同任务的查询／取回补充原条目；提交结果不明先查原任务，不为序号重发。机器附件存单集 `其他资料/执行附件/`，前缀固定 `EP编号-首帧生成记录-{三位序号}`，后缀用 `-工作流.json`、`-请求.json`、`-上传响应.json`、`-提交响应.json`、`-执行结果.json`，按真实产生保存，无上传不建空响应，不保存凭据。

## 5. 首帧审阅记录模板

使用第2节路径及[首帧参考图审阅记录模板](../模板/首帧参考图审阅记录模板.md)的五个固定章节；同轮补充原记录，新轮递增。按第3节实际检查整图、输入与必要局部，逐项记录F01–F08结论及证据，不适用说明原因。模板中的用户确认仅记录真实决定、具体候选、范围、时间与依据，不以agent初审替代批准。

上游资产或分镜更改后列出受影响首帧及已使用的生成任务，检查后再决定处理，不自动重生成或抹去历史批准。目录更新不自动迁移现有项目。

## 6. 新旧任务衔接

新制作场次执行本规则；已有后续分段首帧图保留，是否用于后续新任务的普通参考由用户决定，不自动删除、改名或撤销历史批准。已提交、已生成任务保留原提示词、输入映射及审批事实，不追溯改写或重生成；尚未提交的新任务按本规则检查。二采仍须复用获批一采的真实执行依据；如新规则要求与该历史依据冲突，先列明并请用户确定处理方式，不擅自更换输入或改写历史。
