# 道具资料与参考图规范

状态：已定稿，经用户确认。  
版本：v1.9。
生效日期：2026-09-30。

涉及道具建卡、三视图制作、状态复用、交付和记录时必须读取本文。七章资料卡正文统一维护在[道具资料卡模板](../模板/道具资料卡模板.md)，填写要求及阶段边界见[开发流程第6节](../流程规范/短剧开发流程规范.md)，本文不另存一套模板。

目录：第1节制作时机与资产身份；第2节目录命名；第3节三视图与状态；第4节交付与审批；第5节生成及审阅记录。

## 1. 制作时机与资产身份

- 通用道具、人物专属道具及已经明确需要的道具，在第五阶段建卡，第七阶段制作已明确需要的基础图。其他状态待实际剧情需要时补充，不预制所有可能状态。
- 单集故事剧本明确后检查所需道具卡、图片及状态是否齐备。新道具先检索索引，确无对应资产再分配 PR 编号、建卡并确认；已有道具补充原卡，需要新状态图时据已批准图片衍生。
- 所有道具卡及正式道具图统一存于项目级 `05-道具资料/`，不区分全剧与集内的保存位置，不因逐集补充而新开会话。不为无须独立设计、记录或保持连续性的普通背景物件机械建卡。
- PR 编号项目内连续、跨集稳定。同一道具状态变化、转交或位置变化沿用编号；剧情中需要区分的原件、伪造件等不同物件分别编号并记录关系。
- 人物专属道具关联人物编号，但仍保存于道具目录，不在人物目录重复维护正式道具资产。
- 逐集引用明确“PR 编号＋状态名＋正式图及具体已批准候选版本”，记录适用场次／分段；不按最新文件猜测。管理信息保留于资料、素材映射和记录，不进入最终 H3 提示词正文；只转写实际画面需求并使用官方素材标签。
- 旧项目继续读取实际有效卡名、图片和审批依据。本规范不自动授权迁移、改名、覆盖或重生成；获准整理后才统一引用，不能建立两份权威资料。

## 2. 固定目录与命名

```text
05-道具资料/
├── 道具索引.md
├── PR001-道具名/
│   ├── PR001-道具名-资料卡.md
│   └── 参考图/
│       ├── PR001-基础-道具参考图.png
│       └── 生成记录.md
└── 其他资料/
    ├── 讨论记录/
    ├── 过程稿/
    ├── 审阅记录/
    ├── 历史版本/
    └── 执行附件/
```

- 索引：`道具索引.md`，固定四列“道具编号、名称、道具类别、资料卡入口”，不复制正文或项目进度。
- 资料卡：`PR{三位编号}-{道具名}-资料卡.md`，版本、日期及确认状态写在文档内。
- 正式图：`{PR编号}-{状态名}-道具参考图.png`，例如 `PR001-基础-道具参考图.png`、`PR001-开启-道具参考图.png`、`PR001-破损-道具参考图.png`。不按视角另拆三个正式文件。
- 状态名在卡内固定登记；首次制作集号、场次及用途记录在生成记录，不强制进入文件名，第七阶段尚无具体制作场次时如实标注。
- 四类过程目录集中在 `05-道具资料/其他资料/`，不在每个 PR 下重复建立。首次产生内容先检查固定路径，存在则复用，缺少则创建；不预建空目录或同义目录。新类型无法归类时先确认并补充规范。

| 类型 | 固定文件名 |
| --- | --- |
| 讨论记录 | `{正式产出名去扩展名}-讨论记录-{三位序号}.md` |
| 草稿／候选 | `{正式产出名去扩展名}-草稿-v{两位版本}.{原扩展名}` |
| 审阅记录 | `{正式产出名去扩展名}-审阅记录-{三位序号}.md` |
| 被替换正式版本 | `{正式产出名去扩展名}-归档-{YYYYMMDD-HHmmss}.{原扩展名}` |

例如候选 `PR001-基础-道具参考图-草稿-v01.png`，资料卡草稿 `PR001-道具名-资料卡-草稿-v01.md`。同一产出的轮次、候选版本分别递增；跨道具讨论关联“道具索引”命名，正文注明涉及资产及版本。

批准后保留原候选，复制为固定正式文件；明确批准替换同一状态的正式图前先归档旧图，再更新正式入口和引用。归档采用使用者本机时区的秒级时间戳，重名时取新时间戳，不覆盖旧档。不同状态可并存，不把其他状态图作为过期版本归档；其余采用规则沿用开发流程的共用约定。

## 3. 三视图与状态规则

### 固定画面规格

- 单张一行三列，从左到右为正面、道具自身右侧90°侧视、背面。依据资料卡明确正面和基准摆放方向，不把右侧解释成画面右方或45°。
- 三格是同一道具、同一状态，展示尺度可比较；结构、材质、配色、纹样及损伤位置一致。对称道具不同视图可以相似，不为制造差异新增结构，也不把同一视图复制三次冒充转面。
- 纯白背景，柔和光照，完整容纳主体与外伸部件、合理留白；浅色、透明或反光材质轮廓仍须可辨。不擅自添加人物、支架、文字、水印、边框或附件，必要的既有标记按确认内容保留。
- 精确尺寸为 **2752×1536，PNG**。采用“16:9”官方推荐尺寸标签，但实际整数比例为 `43:24`；不因此改成严格16:9的另一尺寸。提示词比例元数据使用43:24，像素设置按执行说明，不能只写“2K”。
- 任务副本使用明确宽高，不修改本地基准；有问题记录并讨论调整，不擅自缩放或裁切冒充原生达标。
- 尺寸比例首先通过资料卡和一致展示表达；必须增加持握／参照图才能说明时先确认，不把人物直接加入标准白底三视图。三视图看不清的重要内部细节也先讨论必要补图及命名，不自动增加套图。

### 状态、衍生与复用

- 基础图状态统一名为“基础”，资料卡说明具体含义，如“完整、关闭、未使用”。“基础”和“完好”若指同一视觉状态，不重复登记为两套图片。
- 状态名具体稳定；需要区分损坏程度时明确为“轻微破损”“严重破损”等，不把不同状态反复覆盖成同名“破损”，也不为同一状态创建同义名称。
- 持有人、存放位置或机位变化但道具外观未变，复用既有图。转交等剧情变化仍记卡内状态，但不自动对应新图片。
- 拿起、转动等简单动作由分镜和视频提示词表达，不把逐镜动作都变成新状态图。重要结构、持续外观或关键内容物变化时，先补卡并确认，再按实际需要出图。
- 新状态图依据资料卡形成完整目标提示词，以文生图重新生成，保留未改变的设计描述，不输入已有道具图。内部结构等新可见内容须有确认依据，不能任由模型新增机关。
- 同张三视图只展示一种状态，不混合正面完好、侧面开启、背面破损。损伤在不同视角的位置和程度应相互对应；被遮挡的部分不为展示而移动。
- 首次生成与修订均按[Qwen规范](../生成规范/Qwen-Image-2.1-提示词规范.md)的文生图分支处理，执行读取[文生图说明](../生成规范/ComfyUI-文生图执行规范.md)，不输入旧图作为修改底图。
- 未修改的已批准图在核对适配后可跨集复用，不重新命名或复制另一份正式图，不虚构新生成任务。上传工作副本保留来源映射，不成为新权威资产。

## 4. 交付与审批

按[图片交付与用户审核](../流程规范/短剧开发流程规范.md#851-图片交付与用户审核)完成文件与记录核对后直接展示给用户审核。默认禁止调用看图能力，不执行固定视觉检查清单，不依据agent视觉判断自动重试。看图触发条件与缺少信息时的询问方式执行[看图能力调用边界](../../SKILL.md#看图能力调用边界)。

从资料、生成、操作及批准记录核对资产身份、状态、来源版本、适用场次和输入用途；尺寸、格式、数量及完整性通过文件与执行证据核对。记录中的设计或生成目标不代表实际画面已验证。复用未修改的获批图时依据记录核对适用范围，不重复看图或审批；信息不足先说明并询问，不能猜测。

用户反馈、采用候选、批准范围及时间据实记录；局部认可不等于整图批准，修改后的新候选重新交用户审核。历史审查及批准事实保留。

## 5. 固定生成与审阅记录

### 5.1 生成记录

每个 PR 仅一份 `参考图/生成记录.md`，跨状态与剧集持续维护。使用所链接模板的两章，未知填“待补充”，不适用填“不适用”；正式资产表只列已批准图片。

使用[道具参考图生成记录模板](../模板/道具参考图生成记录模板.md)中的固定正文；本节保留适用范围与填写规则。

生成序号在同一 PR 内从001连续递增，一次实际提交一条，失败保留；同任务状态和审批补原条目，重新提交新增条目。提交结果不明先查原任务，不为编号连续而重发。复用图不新增虚假生成条目，后续用途在记录及逐集引用中补充。

候选版本按正式图片名从v01递增，不与生成序号混用。采用后保留候选；输入关联具体批准候选，旧项目无候选则记录真实留存副本／归档，不编造历史。替换后更新当前资产表，旧任务与原批准事实保留并补充归档入口。

机器附件按实际产生存入 `05-道具资料/其他资料/执行附件/`，使用 `{PR编号}-生成记录-{三位序号}-工作流.json`、`-请求.json`、`-上传响应.json`、`-提交响应.json`、`-执行结果.json`，同任务共享前缀。多图上传响应汇总，不生成空附件，不保存凭据。技术测试使用指定测试目录；模板空JSON不是可提交内容。

### 5.2 审阅记录

位置：`05-道具资料/其他资料/审阅记录/{正式图片名去扩展名}-审阅记录-{三位序号}.md`。每轮五章，同轮补充、新轮递增；用户未审时填写待确认，不能提前写批准。

使用[道具参考图审阅记录模板](../模板/道具参考图审阅记录模板.md)中的固定正文；本节保留适用范围与填写规则。

卡或图修订后检查已生成的衍生图、首帧和视频引用，报告影响后按授权处理，不自动重生成或抹去历史审批。准备阶段按已明确基础图范围验收，逐集按本集实际需求验收，不能以单图通过代替整个阶段完成。
