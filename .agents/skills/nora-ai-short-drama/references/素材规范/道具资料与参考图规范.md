# 道具资料与参考图规范

状态：已定稿，经用户确认。  
版本：v1.25。
生效日期：2026-10-06。

涉及道具建卡、三视图与状态参考图制作、状态复用、交付和记录时必须读取本文。七章资料卡正文统一维护在[道具资料卡模板](../模板/道具资料卡模板.md)，填写要求及阶段边界见[开发流程第6节](../流程规范/短剧开发流程规范.md)，本文不另存一套模板。

目录：第1节制作时机与资产身份；第2节目录命名；第3节三视图与状态；第4节交付与审批；第5节生成及审阅记录。

## 1. 制作时机与资产身份

- 通用道具、人物专属道具及已经明确需要的道具，由05道具资料卡会话建卡，由09道具参考图会话制作已明确需要的基础图。其他状态待实际剧情需要时补充，不预制所有可能状态。
- 单集故事剧本明确后，逐集会话检查所需道具卡、图片及状态是否齐备，将缺项交05补充设计或09制图。新道具先检索索引，确无对应资产再分配 PR 编号、建卡并确认；已有道具补充原卡，需要新状态图时按[统一资产状态规则](../生成规范/Qwen-Image-2.1-提示词规范.md#27-资产状态参考图统一规则)衍生。
- 所有道具卡及正式道具图统一存于项目级 `05-道具资料/`，不区分全剧与集内的保存位置，逐集补充仍回到05与09原职能会话。不为无须独立设计、记录或保持连续性的普通背景物件机械建卡。
- PR 编号项目内连续、跨集稳定。同一道具状态变化、转交或位置变化沿用编号；剧情中需要区分的原件、伪造件等不同物件分别编号并记录关系。
- 人物专属道具关联人物编号，但仍保存于道具目录，不在人物目录重复维护正式道具资产。
- 逐集引用明确“PR 编号＋状态名＋正式图及具体已批准候选版本”，记录适用场次／分段；不按最新文件猜测。管理信息保留于资料、素材映射和记录，不进入最终 H3 提示词正文；只转写实际画面需求并使用官方素材标签。
- 旧项目继续读取实际有效卡名、图片和审批依据。本规范不自动授权迁移、改名、覆盖或重生成；获准整理后才统一引用，不能建立两份权威资料。

## 2. 固定目录与命名

```text
05-道具资料/
├── 道具索引.md
├── PR001-道具名/
│   ├── PR001-道具名-资料卡.md
│   └── 参考图/
│       ├── PR001-基础-道具参考图.png
│       └── 生成记录.md
└── 其他资料/
    ├── 讨论记录/
    ├── 过程稿/
    │   └── 素材/
    ├── 审阅记录/
    ├── 历史版本/
    └── 执行附件/
```

- 索引：`道具索引.md`，固定四列“道具编号、名称、道具类别、资料卡入口”，不复制正文或项目进度。
- 资料卡：`PR{三位编号}-{道具名}-资料卡.md`，版本、日期及确认状态写在文档内。
- 正式图：`{PR编号}-{状态名}-道具参考图.png`，例如 `PR001-基础-道具参考图.png`、`PR001-开启-道具参考图.png`、`PR001-破损-道具参考图.png`。不按视角另拆三个正式文件。
- 状态名在卡内固定登记；首次制作集号、场次及用途记录在生成记录，不强制进入文件名，09制作基础图时尚无具体制作场次则如实标注。
- 四类过程目录集中在 `05-道具资料/其他资料/`，不在每个 PR 下重复建立；过程稿内部按[过程稿文档与素材](../流程规范/短剧开发流程规范.md#过程稿文档与素材)存放。首次产生内容先检查固定路径，存在则复用，缺少则创建；不预建空目录或同义目录。新类型无法归类时先确认并补充规范。

| 类型 | 固定文件名 |
| --- | --- |
| 讨论记录 | `{正式产出名去扩展名}-讨论记录-{三位序号}.md` |
| 草稿／候选 | `{正式产出名去扩展名}-草稿-v{两位版本}.{原扩展名}` |
| 审阅记录 | `{正式产出名去扩展名}-审阅记录-{三位序号}.md` |
| 被替换正式版本 | `{正式产出名去扩展名}-归档-{YYYYMMDD-HHmmss}.{原扩展名}` |

例如候选 `PR001-基础-道具参考图-草稿-v01.png`，资料卡草稿 `PR001-道具名-资料卡-草稿-v01.md`。同一产出的轮次、候选版本分别递增；跨道具讨论关联“道具索引”命名，正文注明涉及资产及版本。

道具三视图的批准后处理及正式保存按[图片超分执行规范](../生成规范/ComfyUI-图片超分执行规范.md)，尺寸按第3节；明确批准替换同一状态的正式图前先归档旧图，再更新正式入口和引用。归档采用使用者本机时区的秒级时间戳，重名时取新时间戳，不覆盖旧档。不同状态可并存，不把其他状态图作为过期版本归档；其余采用规则沿用开发流程的共用约定。

## 3. 三视图与状态规则

### 三视图固定画面规格

基础三视图的生成方式及输入关系读取[Qwen类型索引](../生成规范/Qwen-Image-2.1-提示词规范.md#11-图片类型专用模板索引)，填写[道具三视图模板](../模板/Qwen-Image-2.1-道具三视图提示词模板.md)的对应大类；修订读取[统一修订规则](../生成规范/Qwen-Image-2.1-提示词规范.md#25-参考图统一修订规则)。图生图仍按下方三视图规格展示，不继承输入图的背景或排布。

- 单张一行三列，从左到右为正面、道具自身右侧90°侧视、背面。依据资料卡明确正面和基准摆放方向，不把右侧解释成画面右方或45°。
- 三格是同一道具、同一状态，展示尺度可比较；结构、材质、配色、纹样及损伤位置一致。对称道具不同视图可以相似，不为制造差异新增结构，也不把同一视图复制三次冒充转面。
- 纯白背景，柔和光照，完整容纳主体与外伸部件、合理留白；浅色、透明或反光材质轮廓仍须可辨。不擅自添加人物、支架、文字、水印、边框或附件，必要的既有标记按确认内容保留。
- 原生审批尺寸为 **1376×768，PNG**；用户批准后2倍超分为 **2752×1536，PNG**，核对通过后正式保存。宽高均满足32对齐。采用“16:9”官方推荐尺寸标签，但实际整数比例为 `43:24`；不因此改成严格16:9的另一尺寸。提示词比例元数据使用43:24，像素设置按执行说明，不能只写“2K”。
- 任务副本使用明确宽高，不修改本地基准；有问题记录并讨论调整，不擅自缩放或裁切冒充原生达标。
- 尺寸比例首先通过资料卡和一致展示表达；必须增加持握／参照图才能说明时先确认，不把人物直接加入标准白底三视图。三视图看不清的重要内部细节按下方状态参考图规则明确实际需求，不自动增加套图。

### 虚拟道具基础界面

- 适用于已确认资料卡中没有实体侧边或背壳的虚拟面板。无适用参考图时依据已确认卡文生图；有用户提供并指定的原参考图或用户指定的已批准界面图时可图生图，输入资格与记录读取[Qwen第2.4节](../生成规范/Qwen-Image-2.1-提示词规范.md#24-输入参考图检查与记录复用)。使用[虚拟道具基础界面模板](../模板/Qwen-Image-2.1-虚拟道具基础界面提示词模板.md)内对应大类，不套用实体三视图；已有界面的状态延伸按统一资产状态规则处理。
- 每张仅展示一个已确认状态的单正面界面，完整容纳光幕、边缘和文字，四周合理留白；纯白背景用于独立资产展示，保留资料卡规定的虚拟光层，不添加实体外壳、侧面、背面、人物或场景。
- 基础界面的设计与显示内容按[固定元素与剧情内容](#虚拟界面固定元素与剧情内容)从已确认资料取用。实际镜头与环境结合时依据对应场次需求及已批准图片处理，不在基础界面中预制多状态套图。
- 原生送审为1536×1024、3:2、PNG，每目标1张；用户批准后2倍超分至3072×2048、PNG。任务副本以明确整数宽高设置，宽高满足32对齐；批准后处理按[图片超分执行规范](../生成规范/ComfyUI-图片超分执行规范.md)。
- 沿用本规范的PR编号、卡内状态名、道具参考图命名与生成／审阅记录。属于七类之外的补充图片，种子按[Qwen种子规则](../生成规范/Qwen-Image-2.1-提示词规范.md#26-项目七类图片默认种子)选择，不登记为道具三视图默认种子。
- 制作时按所选分支执行[文生图规范](../生成规范/ComfyUI-文生图执行规范.md)或[图生图规范](../生成规范/ComfyUI-图生图执行规范.md)，修订执行[统一修订规则](../生成规范/Qwen-Image-2.1-提示词规范.md#25-参考图统一修订规则)，新候选重新送审。

### 虚拟界面固定元素与剧情内容

虚拟界面的文字、标记、布局与可用功能来自已确认资料，不提前显示未解锁内容，不凭设计补编奖励或功能。有重复条目或跨镜复用时，在资料卡已有“外观与结构”“道具状态”“连续性约束”中区分固定设计与当次剧情内容：条目前的符号、颜色、大小、对齐和间距，以及出现／点亮方式按选定设计保持；标题、条目名称、数量及结果提示按剧本变化。使用符号时明确同一符号复用，需按类别使用不同图标时先明确对应关系，不让模型逐条随机补出物品图案。

物品列表、到账结果与天赋／能力激活按各自含义布局，不把结果提示补成新物品或改变数量。所用符号由项目设计决定，不统一要求所有项目使用对勾、星星或某种物品图案。

简单符号可先由已确认设计与提示词表达；需要严格复现且文字不足时，再按真实需求明确适用的界面／符号参考或经授权的制作方式，不默认单独制图或新增素材。底板参考只保留其已固定设计，当次文字及显隐动作分别落实到场次分镜与视频提示词；镜头中的关键文字按[画面文字的布局与可读性](../流程规范/逐集内容制作规范.md#画面文字的布局与可读性)表达；显隐过程按[逐集制作规则](../流程规范/逐集内容制作规范.md#显现与消失的过程)表达。是否需要独立卡、补图及审批仍沿本规范第1节与已有专项规范。

### 状态、衍生与复用

道具状态图的共用用途、输入来源、源图保持、修订与衍生记录读取[统一资产状态规则](../生成规范/Qwen-Image-2.1-提示词规范.md#27-资产状态参考图统一规则)；本节只维护道具特有的状态身份、单视角、尺寸与复用要求。

- 基础图状态统一名为“基础”，资料卡说明具体含义，如“完整、关闭、未使用”。“基础”和“完好”若指同一视觉状态，不重复登记为两套图片。
- 状态名具体稳定；需要区分损坏程度时明确为“轻微破损”“严重破损”等，不把不同状态反复覆盖成同名“破损”，也不为同一状态创建同义名称。
- 持有人、存放位置或机位变化但道具外观未变，复用既有图。转交等剧情变化仍记卡内状态，但不自动对应新图片。
- 拿起、转动等简单动作由分镜和视频提示词表达，不把逐镜动作都变成新状态图。重要结构、持续外观或关键内容物变化时，先补卡并确认，再按实际需要出图。
- 道具状态参考图使用[资产状态模板的道具大类](../模板/Qwen-Image-2.1-资产状态参考图提示词模板.md#3-道具状态参考图)。制作前按统一规则选定来源状态和目标状态，并读取资料卡中的相关设计。
- 每张状态参考图仅呈现一个状态、一个最能说明该状态的视角，不拼排多视图，不同时展示变化前后。取景可为整体或必要局部，以清楚展示状态为准；沿用纯白背景与柔和照明，合理留白，不机械要求局部图展示完整道具。
- 依据资料卡、剧情需求与选定源图明确变化部位、保留范围及必要细节。内部结构等新可见内容须有确认依据，不能任由模型新增机关；新视角允许透视及遮挡变化，不要求源图像素位置不变。
- 状态图沿用本规范的状态命名、项目级目录及生成／审阅记录；共用衍生字段按统一资产状态规则填写。
- **生成与送审规格**：统一1024×1024、1:1、PNG，每目标1张单视角图。宽、高均为32的倍数；采用独立方形画布，不继承输入三视图的拼排比例。
- **正式规格与后处理**：正式图为2048×2048、PNG；批准后处理与状态执行[图片超分执行规范](../生成规范/ComfyUI-图片超分执行规范.md)，记录沿用第4节。
- 种子选择、输入避重及记录读取[Qwen种子规则](../生成规范/Qwen-Image-2.1-提示词规范.md#26-项目七类图片默认种子)，本节不另定取值。
- 同张三视图只展示一种状态，不混合正面完好、侧面开启、背面破损。损伤在不同视角的位置和程度应相互对应；被遮挡的部分不为展示而移动。
- 道具基础及状态图按实际分支执行[文生图说明](../生成规范/ComfyUI-文生图执行规范.md)或[图生图说明](../生成规范/ComfyUI-图生图执行规范.md)，修订统一读取[Qwen修订规则](../生成规范/Qwen-Image-2.1-提示词规范.md#25-参考图统一修订规则)。
- 未修改的已批准图在核对适配后可跨集复用，不重新命名或复制另一份正式图，不虚构新生成任务。上传工作副本保留来源映射，不成为新权威资产。

## 4. 交付与审批

本类的交付、文件与记录核对、用户决定及修改后送审执行[图片交付与用户审核](../流程规范/短剧开发流程规范.md#851-图片交付与用户审核)；需要图片内容分析时读取[看图能力调用边界](../../SKILL.md#看图能力调用边界)。

本类核对重点为PR资产、基础／状态图、剧情所需结构与外观状态，以及本次参考用途。

用户采用道具图片后，按最终实际提示词和用户已确认的修改同步道具资料卡，执行[图片状态收尾第2项](../流程规范/短剧开发流程规范.md#852-图片采用替换与归档后的状态收尾)，状态填写与衍生仍按[本规范第3节](#状态衍生与复用)执行。

道具图的批准后处理、异常状态及历史资产边界统一执行[图片超分执行规范](../生成规范/ComfyUI-图片超分执行规范.md)。

用户反馈及采用依据填写下节对应的生成／审阅记录。

## 5. 固定生成与审阅记录

### 5.1 生成记录

每个 PR 仅一份 `参考图/生成记录.md`，跨状态与剧集持续维护。使用所链接模板的两章，未知填“待补充”，不适用填“不适用”；正式资产表只列已批准且完成本类型所需处理与文件核对的正式图片；尺寸与批准后处理按第3节对应类型执行；历史有效正式图保留。

使用[道具参考图生成记录模板](../模板/道具参考图生成记录模板.md)中的固定正文；本节保留适用范围与填写规则。

生成序号以同一PR为计数范围，跨状态与剧集不重启；提交、恢复、纯复用及候选版本计数读取[图片生成条目与候选计数](../流程规范/短剧开发流程规范.md#851-图片交付与用户审核)。批准后子记录及次数读取[超分规范第4节](../生成规范/ComfyUI-图片超分执行规范.md#4-文件核对保存与记录)。

输入关联具体批准候选，旧项目无候选则记录真实留存副本／归档，不编造历史。替换后的资产及引用维护读取[图片状态收尾](../流程规范/短剧开发流程规范.md#852-图片采用替换与归档后的状态收尾)。

机器附件目录为`05-道具资料/其他资料/执行附件/`，前缀为`{PR编号}-生成记录-{三位序号}`；后缀、留存条件及检查时间维护统一执行[精简留档规则](../模板/ComfyUI-任务监控提示词模板.md#执行附件精简留档)。模板空JSON不是可提交内容。

### 5.2 审阅记录
