# 人物参考图初审与记录规范

状态：已定稿。  
版本：v1.21。  
生效日期：2026-09-29。

人物参考图生成、初审、用户审批与记录时必须读取本文，不在每次任务中重新制定清单或记录结构。制作顺序、规格及命名以 [开发流程第8.1节](../流程规范/短剧开发流程规范.md) 为准，实际执行参数读取对应的 [文生图说明](../生成规范/ComfyUI-文生图执行规范.md) 或 [图生图说明](../生成规范/ComfyUI-图生图执行规范.md)。本文专用于人物四类图；场景图必须使用 [场景专项规范](场景资料与参考图规范.md) 的固定目录、初审清单及记录模板，道具图使用 [道具专项规范](道具资料与参考图规范.md) 的固定三视图初审和记录，不套用本人物清单。

## 1. 固定审核顺序与边界

人物四类图均执行[开发流程8.5.1两阶段审查](../流程规范/短剧开发流程规范.md#851-图片有限返修与集中送审)：取回候选 → agent技术审查 → 技术通过后agent内容审查（非阻塞） → 用户最终审核 → 批准后正式保存及供下一步使用。

- 技术审查实际查看整图、各视格及必要局部，以技术规格、明确画面异常及六视图朝向／同列上下内容一致性阻塞；边界、最多2次重试和1张／3张展示规则统一按8.5.1，不在本规范扩大。
- 第2节保留全部核对项目，按下述阶段分工填写。技术不通过时停止内容检查，各内容字段标注“技术审查未通过，未进行内容审查”。技术通过后核对实际输入及既定要求，输入对照按[输入参考图检查与记录复用](../生成规范/Qwen-Image-2.1-提示词规范.md#24-输入参考图检查与记录复用)执行；内容偏差、缺失依据或审美分歧均记录给用户，不触发自动返修。
- agent不替用户选择新的审美方向或批准新设计；内容审查完成即可送审。无法看图记技术待确认，不冒称通过。
- 执行状态、技术结论、内容发现、用户决定分别记录。局部认可不等于整图批准，修改后的候选重新走两阶段；规范维护不自动触发已批准且未修改图片的重审。
- 用户指定的技术测试按明确目标和次数执行，测试结果不自动成为正式素材。

## 2. 固定初审清单

### 2.1 通用检查

阶段分工：下表“文件与规格”及“可见缺陷”中8.5.1定义的画面异常属于技术审查；人物／角色六视图的逐格朝向与同列上下共同可见内容一致性（2.3、2.5）也属于技术审查；其余内容（包括构图、背景、普通清晰度／光照偏差、附加内容及其他专项要求）属于非阻塞内容审查。混合项目分别记录技术异常与内容发现，不因位于同一行就全部阻塞；内容检查中识别到漏检的严重结构异常时回写技术结论及依据。

| 检查项 | 必查内容 |
| --- | --- |
| 文件与规格 | 文件可正常打开；真实宽高、PNG格式、数量符合本次要求；核实是否有未经允许的缩放、拉伸或裁切 |
| 资料依据 | 人物、人物状态、服装状态、资料卡版本、已批准输入正确，没有混用其他年龄、人物或造型 |
| 构图与完整性 | 指定部位完整，留白合理，无意外贴边、截断、遮挡或视图区相互侵入 |
| 背景与光照 | 四类人物相关图片均为纯白背景；曝光正常，深色头发与浅色衣物均可辨认，无严重过曝或阴影遮蔽 |
| 可见缺陷 | 排查明显的五官、肢体、手指和结构畸变，重复部件，融合、断裂、悬浮、异常纹理 |
| 附加内容 | 无擅自增加的文字、水印、装饰、人物、配饰或资料卡未确认的重要设计；必要的已确认服装文字准确保留 |
| 清晰度 | 面容、发型、服装等关键识别信息可辨认；不能只凭像素尺寸认定细节合格 |

### 2.2 人物上半身正面肖像图

- 确定面容身份、年龄感、发型、肤色、颈肩胸可见特征与画风；这些可见特征仍须符合资料卡，但不承担完整身材定型。
- 正面朝向、自然表情；按[开发流程第8.1节](../流程规范/短剧开发流程规范.md#81-人物参考图)检查完整胸部、下缘位于胸下至肚脐之间且肚脐画外，头顶发饰完整、留白合理、双手画外、真实底边硬截断。不能沿用旧下腹至髋部标准；不以完整孕腹等画外体态作为肖像验收条件。历史审核与采用事实保持。
- 按[人物本体提示词片段](../生成规范/Qwen-Image-2.1-提示词规范.md#23-人物本体提示词片段)核对本次年龄分支、规定取景内的人体比例、体态及必要覆盖，遵守该节的适用和验收边界，不另复制提示词正文。达到8.5.1严重变形、融合或断裂边界时才记技术异常，不能仅凭裸体就认定不合规。
- 不擅自改变、删除已确认的辨识特征，不因美化而改变人物定位。

### 2.3 人物多视角参考图

**技术项（阻塞）：**

- 逐格按本次约定的正面／本次冻结提示词指定的侧向／背面检查朝向，任何一格方向错误即技术不通过；按下方上下排关系分别核对，不因上下同时朝错方向就放行。
- 逐列对照全身中的头面、发型发饰、年龄感、肤色、颈肩及共同可见配饰，与上方特写是否统一；明确身份、造型或可见细节不一致即技术不通过。此处仅检查内部一致性，不判断内容是否符合设计要求；两个视格一致但都不符合设定，属于下一阶段的内容发现。尺度、正常透视／遮挡或特写画外部分不作矛盾证据。记录每列结论和具体部位；依据不足记技术待确认。

**完整清单与阶段分工：** 以下朝向及同列上下共同可见内容一致性写入技术章节；对批准输入、资料设定的符合程度、完整性、尺度、跨列其他差异等写入技术通过后的内容章节。

- 延续已批准肖像的身份、头面与可见上半身特征、画风；依据资料卡建立并验收身高比例、整体身材、四肢、站姿及孕态等完整身体状态。不能从肖像画外区域推断体态；肖像未见孕腹不等于非孕。
- 两行三列顺序正确：正面、人物自身右侧90度纯侧面、背面；按[人物模板](../模板/Qwen-Image-2.1-人物六视图提示词模板.md)、[角色模板](../模板/Qwen-Image-2.1-角色六视图提示词模板.md)与本次冻结请求核对。中列右侧朝向镜头、鼻尖与脚尖指向画面右侧；头部、胸膛、骨盆和双脚均为纯侧面，上下同向，不用45度斜面替代。人物自身左右与画面左右分别判断；按可见轮廓与结构核对，正常遮挡不作为部件缺失。历史图片按当时冻结请求审查，不因规则变更自动重审或撤销批准。画格上、下两行高度比为2:5，每行左、中、右三格宽度比为1:1:1，列边界上下对齐；分区比例按内容项记录，朝向及同列内部一致性仍按上述技术项检查。
- 上排为对应头部特写，下排为对应全身；每列头身朝向一致，背面展示后脑、发型和颈部，不转头露脸。
- 六格年龄感、发型、肤色、体型与适用基础着装一致；同一人物的多个视图不变成不同人物。
- 三个全身完整显示头顶至脚底，站姿与展示尺度可比较，不用拉伸改变比例。

### 2.4 服装参考图

主要确定独立衣装设计，包含款式层次、材质配色、纹样、正背结构、鞋履和必要的非头部配饰；适配已确认人物状态与项目画风，不承担人物身份或身材定型。

- 一行两列，左正面、右背面，属于同一套服装。
- 款式、层次、材质、颜色、鞋履和必要的非头部配饰符合资料卡及指定服装状态；画面不包含发冠、发簪、发饰、耳饰等头部配饰。头部配饰误入按内容偏差记录，技术审查边界不变。
- 正背面结构对应，没有凭空增加或遗漏关键部件；鞋履、配饰方向与相应视图对应。
- 不出现真人身体，完整展示服装及所需附件，白色衣物与白底之间仍有可辨轮廓。
- 缺少服装背面等重要设计依据时列为待确认，不能把模型随机补出的设计直接判定为合格。

### 2.5 角色多视角参考图

主要确定已批准本体与衣装结合后的最终穿着效果、贴合遮挡与层次，以及各视角一致性，供后续制作引用；继承身份、体态和画风，不在合成中另行设计。

- 身份、年龄感、发型、肤色及身体比例延续已批准的人物多视角图。
- 服装设计延续已批准的服装图，无基础服残留或其他造型混入。按[角色合成的服装参考与穿戴文字分工](../生成规范/Qwen-Image-2.1-提示词规范.md#4-图像编辑规范与模板)检查：外观、结构和既定位置对照服装图，穿戴层次、贴合及身体遮挡／显露对照补充文字；不把服装图已确定且要求继承的结位、配饰位置按资料卡重复判错。服装输入与文字的差异保留在记录中，不在角色合成中自行改设计。
- 同列上下共同可见的身份、头面、发型发饰、肤色、领口、肩部衣物及配饰等是否一致，和逐格朝向一起按2.3列为技术项；只检查内部一致，不在技术阶段判断衣装设计是否满足资料要求。不同方向的结构对应及其他要求仍逐项核对，按各自阶段记录。
- 穿着关系合理，无明显身体穿透衣物、衣物与皮肤融合等问题。
- 按2.3中排布、朝向、同一人物、全身完整和格间一致性要求检查；不要求采用人物本体图的基础着装。

## 3. 生成记录固定模板

位置：`03-人物资料/CH编号-人物名/参考图/生成记录.md`。每个人物一份，不移入阶段子目录，跨四类图片及人物／服装状态持续维护，不按图片类型新建同义台账。固定两个一级内容章节，不删改字段；不适用填“不适用”，尚无结果填“待补充”，未知信息不编造。

使用[人物参考图生成记录模板](../模板/人物参考图生成记录模板.md)中的固定正文；本节保留适用范围与填写规则。

维护规则：

- 正式图存放层级按[开发流程8.1](../流程规范/短剧开发流程规范.md#固定目录正式命名与过程资产)执行；有阶段目录时，正式文件链接从本生成记录所在的 `参考图/` 指向 `{人物阶段}/{正式文件名}`。目录调整只更新引用，不重置生成编号、候选版本或批准事实。
- 当前正式资产表只登记已批准图片；不同类型及状态分别登记，不列待审候选，不复制人物资料卡正文或项目制作进度。
- 生成条目在同一人物内从001连续递增，不按类型重启。一次实际提交对应一个条目；同一任务的状态、下载及审批补到原条目。重新提交新增条目，失败任务也保留；提交结果不明先查原任务，不能为编号连续而重发。
- 候选版本按正式图片名分别从v01递增，与人物内生成序号不是同一计数。保留完整候选，不因采用而删掉它。
- 实际输入除了正式路径，还关联当时采用的具体候选版本，避免正式文件替换后无法追溯。旧项目无候选版本时链接真实的留存副本或归档，并明确来源现状，不虚构历史版本。
- 替换正式图后更新正式资产表；旧生成条目保留原来源、结果与当时批准事实，可补充旧正式图的归档入口，不篡改旧任务事实。
- 技术测试使用明确指定的测试位置，不混入正式项目资产；本模板中的空JSON只是字段占位，不得作为实际提示词提交。
- 机器执行附件不复制大段进入审阅文档。人物任务固定存于`03-人物资料/其他资料/执行附件/`，使用`{CH编号}-生成记录-{三位序号}-工作流.json`、`-请求.json`、`-上传响应.json`、`-提交响应.json`、`-执行结果.json`；共享相同前缀，按实际产生保存，单次多图上传汇总在该任务的上传响应文件。文生图不生成空上传响应，不保存凭据。

## 4. 审阅记录固定模板

位置：`03-人物资料/其他资料/审阅记录/{正式图片名去扩展名}-审阅记录-{三位序号}.md`。每轮审阅使用固定五章，记录具体候选版本；同一轮补充原记录，新一轮递增。agent按技术、内容两个阶段填写检查结果，用户尚未审核时保持“待确认”，不能先填写批准。技术项目与非阻塞内容项目按第2节分工；技术不通过时内容项目标记未进行，技术通过后完成全部适用内容核对。集中审阅页依次显示技术、内容、用户三个状态；内容完成后用“有内容问题／无内容问题”，技术未通过时用“未进行”，未完成内容检查时用“待审查”，不得误写无问题。

使用[人物参考图审阅记录模板](../模板/人物参考图审阅记录模板.md)中的固定正文；本节保留适用范围与填写规则。

如“脸可以，衣服需要调整”，记录局部认可及待修改内容，不批准整图。上游资产替换后，依据生成记录列出受影响的下游角色图或已有制作引用，检查后再决定处理；不自动重生成、覆盖或抹去历史批准。阶段是否完成仍根据项目要求及实际资产覆盖判断，不以一张图或一批任务通过代替整个阶段完成。
