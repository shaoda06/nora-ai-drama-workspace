# 人物参考图初审与记录规范

状态：已定稿。  
版本：v1.23。
生效日期：2026-10-01。

人物参考图生成、交付、用户审批与记录时必须读取本文，不在每次任务中重新制定清单或记录结构。制作顺序、规格及命名以 [开发流程第8.1节](../流程规范/短剧开发流程规范.md) 为准，实际执行参数读取对应的 [文生图说明](../生成规范/ComfyUI-文生图执行规范.md) 或 [图生图说明](../生成规范/ComfyUI-图生图执行规范.md)。本文专用于人物四类图；场景图必须使用 [场景专项规范](场景资料与参考图规范.md) 的固定目录、交付及记录模板，道具图使用 [道具专项规范](道具资料与参考图规范.md) 的固定三视图交付和记录，不套用本人物清单。

## 1. 固定交付顺序与边界

人物四类图均按[图片交付与用户审核](../流程规范/短剧开发流程规范.md#851-图片交付与用户审核)取回候选、核对文件与记录、展示给用户；批准后正式保存并供下一步使用。默认禁止调用看图能力，不做固定技术视觉或内容初审，不据画面判断自动重试。获准看图的范围及信息不足时的询问方式统一执行[看图能力调用边界](../../SKILL.md#看图能力调用边界)。

## 2. 文件、依据与用户审核

### 2.1 通用核对

从文件和执行记录核对实际尺寸、PNG格式、数量、可解码性、完整性及任务来源；从资料及批准记录核对人物、年龄状态、服装状态与实际输入版本。不要将请求中的外貌、朝向或布局要求当成已验证的输出特征。画面是否符合要求由用户判断，记录真实反馈及决定。

### 2.2 人物上半身正面肖像图

制作目标按[肖像模板](../模板/Qwen-Image-2.1-人物上半身正面肖像提示词模板.md)及资料卡编写。1024×1024原生图交用户审批；批准后按[图片超分执行规范](../生成规范/ComfyUI-图片超分执行规范.md)完成2倍超分，核对2048×2048 PNG后正式保存并作为人物本体六视图的身份来源。不另设默认二次审批；历史适用批准资产保留，不批量补超分。

### 2.3 人物多视角参考图

制作目标按[人物六视图模板](../模板/Qwen-Image-2.1-人物六视图提示词模板.md)及已批准肖像、身体资料编写。朝向、分格及上下共同特征是生成要求，不是agent逐格看图的授权。

### 2.4 服装参考图

制作目标按[服装模板](../模板/Qwen-Image-2.1-服装正背面图提示词模板.md)及已确认服装设计编写；用途、衣装状态与批准版本从记录核对。

### 2.5 角色多视角参考图

制作目标按[角色六视图模板](../模板/Qwen-Image-2.1-角色六视图提示词模板.md)编写。核对已批准人物本体和衣装的输入版本及用途；是否满足穿戴、朝向及身份一致性由用户审核，默认不调用看图能力验证。

规定的批准后2倍超分继承原1024图的批准范围，原图与超分图分别留存且核对来源，不伪称用户重新审核了超分细节；用户要求另审时从其要求。用户要求修改后形成的新候选须重新交用户审核，不继承旧候选批准；复用未修改且适用的获批图不重复审批或看图。历史审查事实保留，不因规则维护重审已批准素材。

## 3. 生成记录固定模板

位置：`03-人物资料/CH编号-人物名/参考图/生成记录.md`。每个人物一份，不移入阶段子目录，跨四类图片及人物／服装状态持续维护，不按图片类型新建同义台账。固定两个一级内容章节，不删改字段；不适用填“不适用”，尚无结果填“待补充”，未知信息不编造。

使用[人物参考图生成记录模板](../模板/人物参考图生成记录模板.md)中的固定正文；本节保留适用范围与填写规则。

维护规则：

- 正式图存放层级按[开发流程8.1](../流程规范/短剧开发流程规范.md#固定目录正式命名与过程资产)执行；有阶段目录时，正式文件链接从本生成记录所在的 `参考图/` 指向 `{人物阶段}/{正式文件名}`。目录调整只更新引用，不重置生成编号、候选版本或批准事实。
- 当前正式资产表只登记已批准图片；不同类型及状态分别登记，不列待审候选，不复制人物资料卡正文或项目制作进度。
- 生成条目在同一人物内从001连续递增，不按类型重启。一次实际提交对应一个条目；同一任务的状态、下载及审批补到原条目。重新提交新增条目，失败任务也保留；提交结果不明先查原任务，不能为编号连续而重发。
- 候选版本按正式图片名分别从v01递增，与人物内生成序号不是同一计数。保留完整候选，不因采用而删掉它。
- 实际输入除了正式路径，还关联当时采用的具体候选版本，避免正式文件替换后无法追溯。旧项目无候选版本时链接真实的留存副本或归档，并明确来源现状，不虚构历史版本。
- 替换正式图后更新正式资产表；旧生成条目保留原来源、结果与当时批准事实，可补充旧正式图的归档入口，不篡改旧任务事实。
- 技术测试使用明确指定的测试位置，不混入正式项目资产；本模板中的空JSON只是字段占位，不得作为实际提示词提交。
- 机器执行附件不复制大段进入审阅文档。人物任务固定存于`03-人物资料/其他资料/执行附件/`，使用`{CH编号}-生成记录-{三位序号}-工作流.json`、`-请求.json`、`-上传响应.json`、`-提交响应.json`、`-执行结果.json`；共享相同前缀，按实际产生保存，单次多图上传汇总在该任务的上传响应文件。文生图不生成空上传响应，不保存凭据。

## 4. 审阅记录固定模板

位置：`03-人物资料/其他资料/审阅记录/{正式图片名去扩展名}-审阅记录-{三位序号}.md`。每轮记录具体候选版本，同轮补充、新轮递增。保存文件核对、展示入口、用户反馈及决定；如有获准看图则记录依据、范围与发现。用户尚未审核时保持待确认，不补填视觉通过。

使用[人物参考图审阅记录模板](../模板/人物参考图审阅记录模板.md)中的固定正文；本节保留适用范围与填写规则。

如“脸可以，衣服需要调整”，记录局部认可及待修改内容，不批准整图。上游资产替换后，依据生成记录列出受影响的下游角色图或已有制作引用，检查后再决定处理；不自动重生成、覆盖或抹去历史批准。阶段是否完成仍根据项目要求及实际资产覆盖判断，不以一张图或一批任务通过代替整个阶段完成。
