# ComfyUI-MiniMaxH3导演包制作规范

版本：v1.4；更新日期：2026-10-11。

适用于将已准备的MiniMax H3导演台任务导出为 `.mmxpack.zip`，供用户在ComfyUI网页画布导入、编辑或测试，以及保存场次一采、二采和后处理定稿。正式定稿留档读取[第5.1节](#51-场次各阶段定稿留档)，流程接续读取[开发流程第二部分第7节](../流程规范/短剧开发流程规范.md#7-生成视频验收与衔接修改)；按需测试导出须有对应授权，不要求每次试生成都额外导出。制作时读取本规范；节点填写和素材容量读取[导演台节点使用规范](ComfyUI-MiniMaxH3导演台节点使用规范.md)，正式参数与处理阶段读取[H3执行规范](ComfyUI-H3视频执行规范.md)。

## 1. 包的用途与范围

导演包携带时间线、公共与各组提示词、引用媒体，以及部分导演台控件。它是任务内容的迁移附件，需与匹配画布一起使用。

| 内容 | 导演包的保存范围 |
| --- | --- |
| 公共与本组正文 | 保存实际时间线中的正文，不另外改写提示词 |
| 素材 | 收集时间线引用的图片、音频、视频及相关模式的媒体；包内采用可移植的相对路径 |
| 分组 | 保存组顺序、ID、时长、计划帧数、位置、段间衔接与运行选择等时间线内容 |
| 编辑状态 | 原生导出保存完整timeline.json，包括其他模式的草稿和编辑工作区 |
| 控件 | 原生导出保存steps、sampler、scheduler、cfg、shift_video、shift_audio、seed、task_type |
| 完整画布 | 不保存全部节点、连线及控件；模型链、外接Refine、SIGMAS、清理开关等由目标画布提供 |
| 模型与缓存 | 不包含UNET、CLIP、VAE及LoRA权重，不包含一采音视频潜变量缓存 |

外接SIGMAS时，包里的steps／scheduler控件不替代实际噪声表。保存或导入导演包不改变处理阶段，不表示已经复用一采或执行二采。

## 2. 制作前准备

以用户指定的场次、分段范围或已保存任务为来源，先核对以下内容：

1. **来源与版本**：找到对应画布/API及素材映射，确定实际导演台节点ID、组与EP/C/P映射。复现已提交任务时使用其冻结输入，不用已修改的最新准备稿替代。批准依据和处理阶段继续按H3执行规范维护；技术测试可使用明确获授权的测试输入，不补写内容批准。
2. **正文与标签**：核对公共正文、本组正文、实际图片／音频／视频顺序和标签。编号、容量、公共区与本组的合并关系按[导演台第2–4节](ComfyUI-MiniMaxH3导演台节点使用规范.md#2-素材排序与编号)检查，不因打包重排标签或删掉必要素材。
3. **时间线同步**：按[导演台第5节](ComfyUI-MiniMaxH3导演台节点使用规范.md#5-时长帧数与编辑状态同步)核对根时间线、对应编辑工作区、画布与API。组ID、正文、素材、时长、帧数、衔接和选择状态须对应，不能保留一份会在网页重新打开时恢复旧内容的草稿。
4. **素材所在服务**：确定这些真实媒体路径所在的ComfyUI地址；不能把另一端的上传路径直接用于导出。离线API文件只提供引用信息，素材仍须在所选服务可读。

从网页当前编辑内容制作时先完成保存；固定工具只读取保存的API，不读取浏览器未保存的编辑。原生导出会保留时间线中的其他模式草稿，交付前核对其是否属于本任务；不将无关项目媒体随草稿带入包。

## 3. 包内结构与素材标号

包内目录及文件名使用ASCII字符；外层ZIP可使用中文任务名。下例假设公共区有3张图片，本组首张为Picture 4；扩展名按实际格式保存。

```text
pack.json
timeline.json
shared_params/
  shared_params.json
  Picture1.png
  Picture2.png
  Picture3.png
asset_groups/
  01/
    group.json
    Picture4.png
  02/
    group.json
source_video/                 # 有源视频时使用
extra/                        # 原生导出收集的其他引用媒体，如编辑工作区副本
```

| 文件或目录 | 用途 |
| --- | --- |
| pack.json | format为`minimax-h3-director-pack`，固定工具支持formatVersion=1；另存任务类型、部分控件及output设置 |
| timeline.json | 完整时间线和编辑工作区；原生导出须保留 |
| shared_params/shared_params.json | 公共正文、开关与公共素材引用 |
| asset_groups/01、02等 | 按原始组序存放；group.json保存该组正文及相关字段，媒体存于所属组目录 |
| source_video、extra | 有对应媒体时由原生导出保存，不将其自动计作新增活动素材 |

`PictureN`、`AudioN`、`VideoN`按各自模态的绝对标签命名。本组素材从公共区之后顺延，不在每组重置为1；不同组可以在各自目录使用相同的本组标签号，不表示它们共享同一文件。组目录序号不是P编号，具体对应关系记录在来源映射中。没有本组新增媒体的组仍保留group.json。

原生导出可能为编辑工作区保留媒体副本，接口fileCount不能直接当作去重后素材数量。核对有效素材时分别检查公共区、各组与草稿引用，不按ZIP文件总数补造标签。

符合原生结构的外部转换包可以没有timeline.json，由导入接口根据公共与分组文件组装时间线；本工作区固定工具使用原生导出，不以精简转换包替代完整时间线。格式与接口见[原生导演包接口](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director#导演包剧本--素材)。

## 4. 导出与文件核对

Agent导出复用[固定工具export-pack](../comfyui-scripts/README.md#export-pack从保存的api导出原生导演包)，命令、参数、响应及错误说明由该README维护。传入已核对的服务地址、API文件、真实导演台ID、新包路径及导出响应路径；不另写通信代码或自行拼装ZIP。用户在网页直接导出时使用原生导出功能，并核对当前编辑内容已同步。

固定工具先预检缺失素材，再请求原生导出。缺失项未解决时停止，报告真实路径及归属，不用其他图片、预览或旧结果填补。接口异常、坏包或传输失败按工具错误处理，不记作视频生成失败，也不自动提交生成或反复重试。

导出完成后核对：

- 文件实际存在，传输字节数、ZIP完整性、原生格式标识及版本有效；保留工具返回的传输信息。
- 公共与各组正文、组序、ID、时长、计划帧数、衔接、选择状态、尺寸、帧率及种子与指定来源一致。
- 公共与各组媒体路径在包内可对应，素材index和正文标签一致；根时间线与编辑工作区对应持久化内容一致。
- 未将模型链、外部SIGMAS、Refine或一采缓存的存在写成“包已携带”。

上述检查是文件与输入身份核对，不解码审片，也不替代人工内容审核。需要验证导入兼容性时，可在隔离目录做离线导入核对；该结果单独记录，不等同于网页实际导入通过。

## 5. 保存与交付

正式制作的定稿包、配对画布及保存范围执行[第5.1节](#51-场次各阶段定稿留档)。导出响应、汇总准备API及来源记录按[共同证据归属](../流程规范/逐集目录与资产管理规范.md#多组任务的共同证据与状态)留在既有执行附件，不另存一份定稿包或配对画布。

单独获授权的测试导出沿用任务准备／执行附件或既有技术测试目录，文件名沿用本任务附件前缀，添加 `-导演包.mmxpack.zip` 与 `-导演包-导出响应.json`；测试包不登记为阶段定稿，也不要求从定稿目录复制一份。再次导出使用新的明确版本或序号，保留已有包；导出本身不增加生成R编号。源画布/API和原素材映射保留，不能用包取代生成记录。

在既有准备或执行记录注明来源文件与版本、导出时间及服务地址、实际导演台ID、组与P映射、公共／本组标签、包与响应入口、文件完整性和缺失检查结论。记录当次事实，不另建同一任务的进度台账。

交付提供可下载包、匹配画布和简短导入说明。无需用户解压后逐张上传；素材随包导入。通用规范不保存真实项目媒体、服务器地址、任务ID或单次测试流水。

### 5.1 场次各阶段定稿留档

一采、二采、后处理分别在当前场次该阶段全部分段的最终版本经用户明确批准采用后留档，不等待其他场次，也不将局部批准当作整场批准。一采留档在进入二采前完成，二采留档在进入后处理前完成，后处理留档在场次收尾前完成。只处理已经获批的阶段；批准和导出不授权重新生成视频、切换执行阶段或清理缓存。

每个场次每个阶段依据各段的获批来源整理一份整场汇总工程，再原生导出一个该阶段的整场定稿导演包，并保存同版本的两项附件：

- **导演包**：`EP编号-C编号-阶段名定稿-导演包.mmxpack.zip`，阶段名填写一采、二采或后处理；按分镜顺序包含本场全部P段在该阶段最终采用版本的正文、素材、时长、衔接与包内配置。汇总工程的根时间线和编辑工作区保持一致，不夹带未采用版本或其他批次的历史整场草稿。不另造一种配置文件格式。
- **已配置画布**：`EP编号-C编号-阶段名定稿.workflow.json`，保存与该阶段整场定稿包配对的已配置节点、连线、模型链、SIGMAS、控件及导演台内容，不能用空白画布或通用基准代替。由多个执行来源整理时明确标注为整场汇总工程，不声称它是某一次实际执行的原始画布。

一采、二采按该阶段获批任务的实际配置汇总；后处理的正文与素材沿获批后处理文件的来源追溯，配对画布保留该阶段实际超分／插帧节点、参数及输入关联。导演包未携带的处理设置由配对画布保存，不将另一阶段的包和画布直接改名当作本阶段定稿。

定稿包与配对画布只保存到[逐集目录规范第4节](../流程规范/逐集目录与资产管理规范.md#4-视频执行输出审核与采用)规定的对应阶段定稿目录，不在执行附件、其他阶段或另一套正式目录重复保存。导出时将包的目标直接指定为该定稿位置，导出响应及汇总准备API按既有执行附件和共同证据归属留存；实际来源画布仍作为原任务证据保留，与新整理的配对定稿画布分别记录用途。在既有记录中逐P关联该阶段获批版本、实际来源API／画布、素材映射、任务ID、种子及批准依据，并登记整场包与画布的配对入口。原始请求和记录保持完整；核对整场包覆盖全部已获批P段且每段只出现一次，正文、素材标签、时长和配置与其获批来源对应。原生包内路径与服务端路径可不同，按素材映射核对对应关系。

分批执行或局部返修产生多个获批来源时，仍汇总为一个整场定稿包，历史来源工程用于追溯，不按来源批次分别导出多个场次定稿包。汇总只在新建的任务API／画布副本中进行，不改写来源文件，不重新生成视频；重排组序或重映射素材标签后核对其语义和实际媒体对应不变。缺少来源画布时依据其实际API与配套画布恢复并注明依据；来源无法确定时记录缺项，不猜填。

不同来源的公共设置、种子或其他控件存在差异时，按节点实际能力核对整场工程能否准确表达。无法在同一包及配对画布中保留必要配置时，说明具体冲突和受影响P段，待用户确定处理方式；不静默统一参数，也不自行拆成多套定稿包。未解决前不登记整场定稿留档完成。

这两项附件用于以后打开、调整和重新测试该场该阶段内容，不携带或恢复一采潜变量缓存。二采仍按各获批来源的原始组序、P映射和缓存接续，整场汇总工程不作为二采缓存命中的依据。后续编辑使用副本；新版本按现有版本规则另存，保留原定稿附件及批准事实。包和配对画布均已导出、文件核对通过且记录入口可用后，才登记该阶段定稿留档完成；留档缺项不改变视频已获批的事实，问题在既有记录中注明并处理。

## 6. 网页导入与测试

1. 在ComfyUI网页打开匹配画布，保留原文件并另存测试副本；在导演台面板选择“导入导演包”，选取整个 `.mmxpack.zip`。
2. 导入将媒体写入目标服务的 `input/minimax_director_packs/`，替换当前导演台时间线并更新部分控件。检查缺失提示，以及公共区、本组区、素材标签、正文、时长、组序、衔接、尺寸、帧率、种子和运行选择。
3. 重新打开相应分组，核对编辑工作区与根时间线内容；检查外接模型链、Refine、SIGMAS、清理开关及其他未由包恢复的参数，按目标测试阶段填写。
4. 导入沿用目标画布的导演台ID，不携带来源服务的一采潜变量。另存画布文件不隔离同一ID的缓存；新批次或续做原批次按[导演台缓存规则](ComfyUI-MiniMaxH3导演台节点使用规范.md#75-缓存检查与清理接口)确定实际范围和来源。

导出或导入授权不附带Queue、清缓存、重新一采、二采或后处理授权。只有当前任务已有相应执行授权且准备条件满足时才接续生成；仅交付包时不自动运行。

## 7. 完成状态与问题记录

分别记录“导出及文件核对”“离线导入核对”“网页导入测试”“生成测试”的实际结果，没有执行的项目写未执行。用户确认导演包测试成功时，记录其确认及适用包；未明确生成阶段和结果时，不据此登记视频生成、性能问题修复或内容获批。

发现素材缺失、正文或编号错位、编辑状态不一致、控件恢复不完整时，记录具体包、来源和问题位置，修正准备资料后按授权另导出新版本；已有包及历史依据不覆盖。
