版本：v1.23；更新日期：2026-10-03。此版本号仅用于本文档，不维护工作流业务版本。制作顺序及审批依赖读取[开发流程第二部分第7节](../流程规范/短剧开发流程规范.md#7-生成视频验收与衔接修改)。

状态：三套本地配对基准可离线校验；实际服务的运行条件由使用者准备，静态一致性不代表远端执行或内容通过。

提示词与制作资料使用 [逐集剧本与分段制作规范](../流程规范/逐集内容制作规范.md)，H3 格式调用 `h3-prompt-writing`（从已发现的依赖技能目录读取）。本说明只管理具体工作流的输入、执行和记录，不授权生成之外的服务器改动。目录、任务R编号、候选／选定及记录模板必须同时遵循 [逐集目录与资产管理规范](../流程规范/逐集目录与资产管理规范.md)：05只保存生成前准备，06保存全部实际执行、输出和视频审核。

视频结果的取回展示、用户人工审核及决定记录统一执行[视频结果人工审核](../流程规范/逐集目录与资产管理规范.md#视频结果人工审核)；场次及整集成片的收尾同时读取该目录规范第5节。

## 0. 制作策略与工作流配置

制作顺序及审批边界以 [开发流程第二部分第 7 节](../流程规范/短剧开发流程规范.md#7-生成视频验收与衔接修改) 为准。当前本地基准如下：

| 工作流 | 当前设置与用途 |
| --- | --- |
| Nora-MiniMaxH3-多参考视频-仅一采 | 节点 264 正式保存一采视频，`save_output=true`，24fps，用于方向与大致内容审核 |
| Nora-MiniMaxH3-多参考视频-仅二采 | 重新计算一采后继续二采，不输出一采视频；节点 283 为 1.5，节点 214 正式保存，24fps |
| Nora-RTX-AusBoss-切镜保护超分插帧 | 每个获批二采片段单独处理；节点1为1800×1040/ULTRA，节点12为RAFT光流切镜保护插帧，目标60fps；节点16使用12返回的实际fps并保留原音轨，最后再合并 |

获批一采的提示词、素材及顺序、模型、完整参数和实际种子须留存。二采复用共同配置重新计算，再执行既定二采分支；不要求画面逐帧一致。前端randomize显示的下一次种子不是获批种子，API必须写入获批实际数值；缓存命中按真实记录说明。

各阶段保存独立候选和人工决定，不覆盖已批准来源。执行成功不构成后续批量生成授权。后处理沿既定参数执行，出现问题先记录，不自动改阈值或切回其他方法。

## 1. 当前固定基准与任务副本

本地 `.workflow.json`（画布）与 `.api.json`（执行）是同一工作流的配套唯一基准；不维护独立 `.snapshot.json`。画布保留节点、开关、布局和关闭分支；API保留正式输出依赖及可选参考加载器。未经用户明确要求，不修改基准、不从远端自动替换、不向远端发布。用户要求更新时先归档旧文件，同步有效节点、参数和连接；不要求两种JSON逐字相同。

| 阶段 | 画布 JSON | API JSON | API 节点数（含可选加载器） |
| --- | --- | --- | --- |
| 仅一采 | [画布](../comfyui-workflow/Nora-MiniMaxH3-多参考视频-仅一采.workflow.json) | [API](../comfyui-workflow/Nora-MiniMaxH3-多参考视频-仅一采.api.json) | 36（21＋15） |
| 仅二采 | [画布](../comfyui-workflow/Nora-MiniMaxH3-多参考视频-仅二采.workflow.json) | [API](../comfyui-workflow/Nora-MiniMaxH3-多参考视频-仅二采.api.json) | 41（26＋15） |
| 切镜保护超分插帧 | [画布](../comfyui-workflow/Nora-RTX-AusBoss-切镜保护超分插帧.workflow.json) | [API](../comfyui-workflow/Nora-RTX-AusBoss-切镜保护超分插帧.api.json) | 5 |

H3基准API的15个可选加载器暂未接入265。各加载器 `_meta.nora_optional_reference` 保留目标节点、输入名和输出槽；映射直接由画布推导，元数据不代替实际连接。任务副本只保留本次选中的加载器、填写真实上传路径并接线，**删除所有未选加载器**，防止空占位素材进入请求。该机制保留9图／3音频／3视频的可选能力，不等于允许同时使用15份素材；总量及模式限制仍按第3节。

API由保存画布离线展开子图及Set/Get、Reroute，连接覆盖控件默认值，旁路关闭分支并剔除前端管理／预览字段，不冒称浏览器原生导出。两份H3共同的一采节点保持一致，二采仍计算一采但不输出一采成片。

本地配对的检查范围、调用命令及测试入口见[离线配对校验与回归测试](#11-离线配对校验与回归测试)，无需为调用读取脚本源码。

运行环境由使用者准备，默认项目配置的服务可以支持携带的工作流。AusBoss使用 `optical flow (requires cached RAFT weights)`；具体参数和连接按第2节维护。若实际缺少节点、模型或缓存权重，报告错误，不自动安装、替换方法或改参数。

**基准不可原样提交。** 提示词、加载素材及输出命名为占位样例；任务副本必须替换。后处理 `6.inputs.file` 填本次获批二采实际路径；输出前缀按第2.1节填实际编号。预览占位不作为结果依据，取回只认本次实际响应。每次读取基准的文件名及SHA-256可写入本次执行记录；完整实际API请求、参数、任务ID、服务地址与响应继续保存于项目06。

连接地址读取当前项目根目录 `comfyui-config.json` 的 `remote-url`，显式传给固定工具。缺少配置按技能入口询问，不沿用旧请求或其他项目地址。

### 1.1 离线配对校验与回归测试

[workflow_baselines.py](../../scripts/workflow_baselines.py) 使用Python 3.9及以上标准库；用于修改配套工作流、配对校验脚本，或执行规范的节点／参数／连接要求后进行离线检查，不是每次生成的前置动作。不连接服务器、不依赖节点库存、不写入基准。

以下命令将安装路径替换为实际绝对路径，可在任意工作目录调用：

```sh
python3 -B "/技能实际安装目录/nora-ai-short-drama/scripts/workflow_baselines.py"
```

唯一业务参数 `--directory "/待检查工作流目录"` 可选，默认是脚本所属技能的 `references/comfyui-workflow/`，不是当前工作目录；显式相对路径按当前工作目录解析。目录直接包含同名的 `名称.workflow.json` 和 `名称.api.json`，不递归扫描。此工具针对本技能配套工作流及其副本，不是任意ComfyUI工作流的通用校验器。使用普通Python模式，不加 `-O`，以保留校验断言。

输出为每套配对一行JSON，随后一行 `PASS: ...` 文本，不是单个完整JSON文档。字段：`workflow` 为工作流名，`nodes` 为API节点数，`optional_references` 为可选参考节点数，`reference_combinations` 为已检查的参考数量组合数。当前完整基准应有8条结果，两套H3各检查147种合法数量组合。退出0表示已扫描配对通过；非零时读取错误定位缺失文件、参数／连接不一致等问题，不自动覆盖基准。空目录也可能退出0，须核对实际输出的工作流是否覆盖本次目标，不能只看PASS。此检查不证明远端兼容、模型存在、权重可加载或素材时长合法。

修改校验脚本后运行[回归测试](../../scripts/test_workflow_baselines.py)：

```sh
python3 -B -m unittest discover -s "/技能实际安装目录/nora-ai-short-drama/scripts" -p "test_workflow_baselines.py" -v
```

测试使用标准库，读取随包基准，在临时目录制造错误样本，不修改正式基准、不调用远端。覆盖8套配对和参考分支、API参数及图片超分倍率漂移、缺少参考加载器、断链及通信工具的本机时区时间戳。退出0且报告OK表示测试通过；FAIL／ERROR或非零表示未通过，跳过项按测试报告说明，不计作已验证。此测试只在维护相关工具时调用，不加入日常生成循环。

## 2. 参数边界

除第 0 节已确认的工作流配置外，常规任务配置限定为参考素材上传／启用／对应连接，以及：

| 内容 | API 位置 | 处理 |
| --- | --- | --- |
| 完整 H3 提示词 | `263.inputs.text` | 每次填写对应分段的完整实际模型正文，不提交模板说明文字、文档外壳或路径表；二采复制获批一采请求中的正文 |
| 请求时长（秒） | `259.inputs.value` | 每次按对应分段填写已确认实际请求秒数，规划段长读取[逐集内容制作规范第1节](../流程规范/逐集内容制作规范.md#1-层级编号与时长)；模板10秒不是所有片段的固定值；二采复用获批一采的实际值 |
| 一采种子策略／二采复用种子 | `256.inputs.noise_seed` | 按本节[种子策略](#场次基准种子与实际任务种子)设置并保存实际数值 |
| 后处理输入视频 | `6.inputs.file` | 每次替换为本次获批二采分段上传后或已核实可复用的实际远端路径，不能直接使用模板占位样例 |
| 输出前缀 | 一采`264.inputs.filename_prefix`／二采`214.inputs.filename_prefix`／后处理`16.inputs.filename_prefix` | 按第2.1节公式填本次实际项目代号、EP/C/P/R编号及阶段；不同阶段使用各自本次R号，不复制来源任务前缀 |

其余保持**本地工作流保存值**，不是节点出厂值。不要自行改模型、LoRA、分辨率、参考图尺寸策略、采样设置、二采倍率、帧率或输出格式，也不擅自添加视频原声连接。输出前缀仅按批准公式填实际任务值，不临时发明另一套命名；取回后的文件名仍按逐集目录规范保存。

固定值包括：模型／VAE／LoRA、Euler／Beta及12步中的一采8步和二采4步、1.5倍二采、H.264 MP4／yuv420p／CRF19；后处理1800×1040／ULTRA、RAFT光流、阈值0.15／批次1／目标60fps，以及源fps、返回fps和原音轨连接。用户未明确授权改变时保持不变。一采采用16:9选择项、0.5MP和32对齐，输出使用节点计算的非严格16:9像素尺寸，不擅自裁切或改成精确16:9。后处理目标用于保持当前1440×832输入比例，不是标准1920×1080，不自动套用到其他画幅。


259 通过 250 的原始表达式转换成帧数，再接入 265.length：

```text
max(5, round(a * 24)) + (5 - (max(5, round(a * 24)) % 17)) % 17
```

保留表达式和连接，不手填覆盖 265.length。请求 10 秒按该公式为 243 帧、名义约 10.125 秒；请求 15 秒为 362 帧、名义约 15.083 秒。这是静态推算，非实测结果。记录请求秒数、计算帧数及真实输出时长；如交付要求严格不超过 15 秒，先明确时长／剪辑方案，不默默裁掉内容或改变公式。

### 场次基准种子与实际任务种子

- **同场次首次一采。** 准备当前场次首批获授权任务时，先查06已有执行记录中是否已登记场次基准种子；已有则沿用，没有则采用用户指定值，未指定时生成一次节点允许范围内、可精确序列化的整数种子并保存。同一EP/C内各段首次一采默认使用该值，不按片段强制刷新，也不把模板示例值当作项目基准。
- **对比与探索。** 修改提示词、需要比较修改效果时，默认保留所比较任务的实际种子；希望探索另一版结果时，为该段新任务刷新种子并记录目的。返修不自动等于换种子，目的不明时先确认。某段探索换种子不改写本场基准、其他段任务或已批准结果；不强制重新生成其他段。所有新生成仍须在用户授权范围内，不自动重试。
- **记录位置。** 场次基准值及首次建立依据保存在本场首个准备执行的一采任务的`输入映射.json`，在该段`生成记录.md`引用；后续段映射引用这一固定任务入口，同时记录本次实际种子及“场次基准／保留对比／刷新探索／用户指定”等来源。实际值在提交前写入API、请求和执行记录，不在05维护运行台账，不另建种子管理文件。恢复时先读取已有记录，不能因换会话重建场次种子。
- **二采严格复用。** 一采获批后，从该段被批准任务的真实请求读取种子及共同参数，精确复用；该段若探索过新种子，应使用获批的新值，而不是一律回退场次基准。不得在二采随机替换种子。
- **API与界面。** 256画布当前保存`control_after_generate=randomize`，API模板中的84781009642919仅为示例；API不会自动刷新。通过界面执行时，在任务副本中填入并固定本次种子，防止前端randomize改变共用或保留的值；探索时也先明确新数值并保存，再执行。不能到批准时才读取前端已变化的种子。画布／API基准的保存参数按第1节管理。
- **边界。** 任务恢复、监控和重新取回不刷新种子、不重新提交。用户明确指定的种子方案优先，并记录依据；旧测试请求与审批不追溯改写。共用种子只减少一个变化因素，不保证人物、音色或跨段一致性；仍使用已批准参考素材和明确的状态约束，不将固定种子视为优于随机种子的效果保证。

### 2.1 已批准的输出前缀公式

三份工作流统一使用：`Nora/{项目代号}/{EP编号}-{C编号}-{P编号}-{R编号}-{处理阶段}`。

| 本地工作流 | 保存节点 | 模板中的默认前缀 |
| --- | --- | --- |
| Nora-MiniMaxH3-多参考视频-仅一采 | 264 | `Nora/{项目代号}/{EP编号}-{C编号}-{P编号}-{R编号}-一采` |
| Nora-MiniMaxH3-多参考视频-仅二采 | 214 | `Nora/{项目代号}/{EP编号}-{C编号}-{P编号}-{R编号}-二采` |
| Nora-RTX-AusBoss-切镜保护超分插帧 | 16 | `Nora/{项目代号}/{EP编号}-{C编号}-{P编号}-{R编号}-后处理` |

- 花括号是任务准备时由agent替换的占位符，不是ComfyUI自动展开语法；提交前逐项检查已全部替换。
- EP/C/P/R填完整编号，如`EP001-C001-P003-R002`，不重复加字母。R按该分段三阶段实际执行序号递增，不是工作流版本，也不是阶段固定编号；重取同一任务不分配新R。
- 项目代号使用项目已有确认的稳定值，同一服务上不同项目不得混用。值必须是单个安全路径段，不包含路径分隔符、`..`、控制字符、Windows文件名禁用字符或格式替换表达式；不安全时先确认安全代号，不自行改项目名称。
- 前缀相对于ComfyUI输出目录，使用`/`分层，不加`.mp4`扩展名，不填本机绝对路径。例：`Nora/项目代号/EP001-C001-P003-R002-二采`。
- 远端保存节点可能追加计数或音轨后缀，以真实返回的filename／subfolder／type取回，不自行拼接预测下载地址。与本地规范文件名的对应写入执行记录。
- 新规则只用于后续新任务；不改写已提交请求、已有视频文件名或历史批准。三个本地文件组随名称同步改名，历史引用中的原名仍表示当时事实，不自动迁移项目执行目录。

## 3. 参考素材限制与槽位

一采／二采的首帧、每段环境参考及后段复用条件读取[首帧规范第1节](../素材规范/首帧参考图规范.md#1-制作复用与画面要求)，历史任务衔接读取[第6节](../素材规范/首帧参考图规范.md#6-新旧任务衔接)。提交前按下方映射核对图片文件、具体版本、用途、Picture标签及265图像连接。后处理输入视频沿原规则，不另加图片。其他素材按需开启，不用的关闭。每次按本段提示词映射启用所需参考分支并上传对应实际素材；若复用已上传文件，先核对实际路径与素材身份并记录，不用示例或空路径占位。界面开关 307／308／309 分别筛选参考图像／音频／视频组。API执行必须反映实际连接，不仅修改界面开关属性。

| 类型 | 上限 | 附加约束 |
| --- | --- | --- |
| 图片 | 9 张 | 与其他素材合计最多 12 个 |
| 独立音频 | 3 段 | 总长 ≤15 秒，必须搭配图片或视频 |
| 视频 | 3 段 | 各 2–15 秒，总长 ≤15 秒 |

音频与视频的总时长分别计算；混合素材不能同时用满 9+3+3。计数限制不能替代实际媒体时长检查。

当前基准按下表连续映射；完整节点对象从配套API的对应加载器读取，映射使用其 `_meta.nora_optional_reference`，不重新猜测节点参数：

| 提示词素材标签 | 加载器 ID（依次） | 节点265输入（依次） | 文件输入字段 |
| --- | --- | --- | --- |
| Picture 1–9 | 51、49、50、43、19、23、199、200、201 | `ref_images.ref_image_0` 至 `ref_images.ref_image_8` | `image` |
| Audio 1–3 | 48、14、15 | `ref_audios.ref_audio_0` 至 `ref_audios.ref_audio_2` | `audio` |
| Video 1–3 | 27、25、26 | `ref_videos.ref_video_0` 至 `ref_videos.ref_video_2` | `video` |

三类均连接加载器第 0 个输出。素材标签从 1 开始，API 槽位从 0 开始；`<Subject N>` 和 `(Sx)` 不作为加载槽位编号。

1. 先确定每段标签、实际文件、来源版本、用途及输入槽位；图片身份、用途及视觉信息按生成／操作／批准等记录核对，遵守[看图能力调用边界](../../SKILL.md#看图能力调用边界)，记录不足先询问，不因每段准备而重看图片；核对视频内容／帧率与时长、听辨音频及复用方式。不能检查的内容明确标注，不臆测。
2. 结合 `comfyui-api`，通过 [固定工具](../comfyui-scripts/README.md) 的upload上传到本次独立输入位置，避免覆盖既有文件。上传与取回成功仅证明文件传输，不证明H3音视频参考条件或加载器兼容；须按实际节点要求核对文件类型、加载方式及参考条件。
3. 保存上传响应中的实际文件名、子目录和类型；加载器填写真实 input 相对路径，不填写 Mac 绝对路径，也不根据上传完成顺序重排标签。
4. 在任务副本保留选中的可选加载器，删除未选加载器，只替换选中节点的文件字段；读取其 `_meta.nora_optional_reference`，在 `265.inputs` 添加该条 `input`，值为 `[加载器节点ID, output_slot]`。用 1、2…连续标签及 0、1…连续槽位。
5. 未使用参考分支保持不接入；移除任务副本中不再使用的加载器与对应输入，不用空路径、重复图片或示例文件占位。
6. 提交前逐条核对“提示词标签 → 本地文件及版本 → 上传返回路径 → 加载器 → 265 槽位”；不以文件名排序代替映射。

当前视频加载器 `force_rate=0` 保留源帧率，而 265 的视频参考说明要求 24 fps。先核对实际素材与输出帧序列；不兼容时说明影响，另确认素材处理方式，不自行改默认加载参数。视频原声端口当前未连接，输入有声视频不等于声音已参与条件；需要声音时按独立音频方案与限额准备，新增原声连接须另行确认。

## 4. 提交、恢复与结果取回

本节四类通信操作必须使用 [固定工具](../comfyui-scripts/README.md) 的upload／submit／status／download，结合comfyui-api技能，不新写单次执行脚本。agent准备最终API JSON和业务记录；工具不改工作流、不决定种子或审批。submit的record-dir指向本次既定执行目录，request-name／response-name分别设为`请求.json`／`提交响应.json`，attempt-name设为`提交尝试.json`；后者只用于防重与恢复，不另建管理目录。其他响应用result按需保存至相应技术附件。已有请求不可让工具覆盖，提交前不要预建与工具输出同名的请求文件；冻结API等其余资料仍由agent准备。同一逻辑提交保持证据路径不变。

仅在用户要求执行生成或明确技术测试时提交，不因写提示词或更新技能而执行。

1. **记录本次依据。** 按[逐集目录规范的执行快照](../流程规范/逐集目录与资产管理规范.md#执行快照)冻结本次API、完整提示词、请求、输入映射及上传响应；保存基准标识、提示词版本、请求时长、实际种子、来源获批任务及测试范围。任务目录、R计数与二采历史依据按该规范维护。
2. **提交前校验。** 按[执行前检查与复用](../../SKILL.md#执行前检查与复用)使用comfyui-inventory的有效库存或补查能力依据，逐任务检查节点、模型选项、动态输入与输出类型；核对默认参数未被意外改动、参考数量／时长合法、素材路径有效。种子策略、音视频加载／帧率等环节按本次输入范围及已有验证依据逐项核对，不把文件上传通过等同于全能力通过。
3. **只提交一次。** 保存唯一 client ID，`POST /prompt` 后立即保存 prompt ID。响应不明先查队列和历史，不重复 POST。
4. **跟踪真实状态。** 遵循 `comfyui-api` 查询对应历史；历史为空不能认定成功或失败。恢复中断任务先根据已保存 ID 查询原任务，不能因换会话重新提交。定时跟进必须使用 [ComfyUI任务监控提示词模板](../模板/ComfyUI-任务监控提示词模板.md)，只填本批真实任务字段，不现场重写执行规则。失败时用 `comfyui-troubleshooter` 定位，不自动重启、清队列或更换模型。
5. **按实际输出取回。** 当前仅一采工作流的 264、仅二采工作流的 214、后处理的 16 均为正式保存输出。根据返回的实际文件字段、subfolder、type 取回，不能把画布历史预览或其他处理阶段片段当本次结果；若工具不能直接预览远端媒体，按应用允许的方式展示，不为绕过显示限制下载。
6. **保存新候选。** 按[视频文件与候选流转](../流程规范/逐集目录与资产管理规范.md#视频文件与候选流转)保存本次真实输出，记录保存节点、远端文件信息、实际入口及来源任务；技术测试存于用户指定位置。

## 5. 人工审核与轻量记录

分段记录使用[逐集目录规范第4节](../流程规范/逐集目录与资产管理规范.md#分段生成记录)所链接模板，填写真实参数、任务与采用依据。场次及整集的目录、计数、说明、合成输入与帧率读取[第5节](../流程规范/逐集目录与资产管理规范.md#5-场次与整集成片)，本文件不重复维护业务记录结构。

结果交付及客观异常按[视频结果人工审核](../流程规范/逐集目录与资产管理规范.md#视频结果人工审核)执行，使用本处理阶段的审阅记录保存人工决定；候选与选定按目录规范第4节流转。

用户提出某镜头问题时，按其意见定位所属分段及受影响资料，在授权范围内处理；重生成后将整段重新交用户人工审核，并提示可能影响相邻段的衔接，不自行复审相邻视频。修订上游分镜时同步受影响提示词与素材。场次及整集成片同样只由用户人工审核，合成前的输入清单与执行核对、合成后的取回展示和记录均按目录规范第5节处理；不把候选片段数量或分段全部获批等同于整集完成。

参考组合、多场次组织及后处理输入的验证范围以实际测试记录为准；需要测试时单独记录。未经实测的输入组合、硬首帧控制、参考声音直接复用和自动随机化均不得写成已验证能力。
