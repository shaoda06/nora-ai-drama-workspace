# ComfyUI-H3视频执行规范

版本：v1.65；更新日期：2026-10-13。

本规范管理视频工作流的填写、执行与记录。制作顺序及审批读取[开发流程第二部分第7节](../流程规范/短剧开发流程规范.md#7-生成视频验收与衔接修改)，后处理与其他视频修改的阶段归属读取[阶段与当前版本修改](../流程规范/短剧开发流程规范.md#视频阶段与当前版本修改)；提示词正文读取[逐集内容制作规范](../流程规范/逐集内容制作规范.md)及 `h3-prompt-writing`。准备资料、实际任务和人工审核按[逐集目录规范](../流程规范/逐集目录与资产管理规范.md)保存，不把技术成功写成内容获批。

## 0. 制作策略与工作流配置

视频生成的唯一默认入口为“Minimax-H3-导演台-视频生成-标准版”；去油版仅在用户明确指定该工作流时使用，不因画面观感或内容判断自动切换。两版均为“一采确认与二采”配套工作流，独立“仅一采”“仅二采”不作为现行入口。正式生成使用原生MiniMax H3导演台，一采与二采通过同一画布分轮执行，输入模式默认为r2v / Ref2VA。准备或修改节点内容时按[导演台任务阅读路径](ComfyUI-MiniMaxH3导演台节点使用规范.md#任务阅读路径)选读，覆盖本次组与P映射、素材、正文、时间线及执行所需条件。

| 工作流 | 当前用途 |
| --- | --- |
| Minimax-H3-导演台-视频生成-标准版 | 正式默认视频生成，不加载节点128；502为导演台，407为Refine；首次只一采，人工确认后再次执行二采；默认分段导出，403报告驱动执行 |
| Minimax-H3-导演台-视频生成-去油版 | 用户明确指定时使用；保留节点128 Mystic LoRA，用于角色去油；其余参数及审核流程与标准版一致 |
| Nora-MiniMaxH3-多参考视频-SelfLift-备用 | 备用，不接入默认制作流程；单次渐进采样直接输出高清，不能中途送审低清 |
| Nora-MiniMaxH3-多参考视频-仅一采 | 旧版保留，仅供追溯和恢复，不作为默认视频生成入口 |
| Nora-MiniMaxH3-多参考视频-仅二采 | 旧版保留，仅供追溯和恢复，不与正式导演台画布混用，不默认执行 |
| Nora-RTX-AusBoss-切镜保护超分插帧 | 正式后处理；按[开发流程的整场后处理安排](../流程规范/短剧开发流程规范.md#7-生成视频验收与衔接修改)逐段输入选定二采，先插帧后超分；固定参数与连接见[第2节](#2-参数边界) |

一采参数和工作流确认不等于具体视频获批，也不授权下一批任务。二采与后处理仍需指定获批来源和对应执行授权；正式一采保持1024×576，二采目标为1536×864；Refine设置与执行端条件见第2节。

### 1.1 离线配对校验与回归测试

[workflow_baselines.py](../../scripts/workflow_baselines.py) 使用Python 3.9及以上标准库，修改配套文件或节点映射后调用：

```sh
python3 -B "/技能实际安装目录/nora-ai-short-drama/scripts/workflow_baselines.py"
```

可选 `--directory "/待检查工作流目录"`，扫描指定目录及其直属 `非正式工作流/`，不扫描其他子目录。默认检查该技能的 `references/comfyui-workflow/`；直接指定非正式目录时只检查其中配对。普通任务准备无需重跑整套检查。不使用 `-O`。

输出每套配对一行JSON和PASS；退出0后还须核对实际覆盖了目标。当前主目录6套、非正式目录5套，共11套配对；标准版为19个API节点，执行输出包含403报告、504一采保存及506二采保存；去油版为16个API节点，以403报告为执行输出入口，校验实际控件保存值、固定种子的画布控制值、全部启用的执行节点（含预览输出）、子图内被外部输入覆盖的控件保存值，以及公共正文、尺寸、总帧数、根时间线与编辑工作区的对应持久化内容、选择状态。工作区可以是原生序列化后的精简快照，不要求与根对象完整相等，比较范围读取[导演台状态同步规范](ComfyUI-MiniMaxH3导演台节点使用规范.md#5-时长帧数与编辑状态同步)。保留二采的15个可选加载器检查147种合法参考数量组合。不同结构的一采与二采不以同号节点强行比较，也不据静态通过宣称两者已可衔接。

修改校验工具后运行：

```sh
python3 -B -m unittest discover -s "/技能实际安装目录/nora-ai-short-drama/scripts" -p "test_workflow_baselines.py" -v
```

## 2. 参数边界

两版一采确认与二采的固定生成设置如下；用户未明确改变时沿用基准保存值，不用节点出厂值替代：

| 项目 | 节点及固定值 |
| --- | --- |
| 模型 | 192：minimax_h3_hybrid_fl2va_ref2va_b25-49-int8.safetensors，weight_dtype=default |
| 通用Sage | 406：PathchSageAttentionKJ，auto，allow_compile=false，启用 |
| H3专用Sage | 58：MiniMaxH3MemoryEfficientSageAttentionPatch，启用 |
| LoRA | 两版均保留53：minimax_h3_turbo_v4_step600_ema_pruned_comfyui.safetensors，1.0；仅去油版加载128：MysticXXX_MMH3-V1.safetensors，0.5；标准版没有128节点 |
| TE | 405：0.08 / 0.1 / 0.9 / mcs=2 / device=auto / mode=8-step LoRA，启用 |
| 编码器 | 38：qwen3vl_32b_minimax_h3_int8_convrot.safetensors，type=minimax，device=default |
| 视频 / 音频VAE | 36：minimax_h3_video_vae_int8_convrot.safetensors；37：minimax_h3_audio_vae_fp32.safetensors |
| 尺寸及帧率 | 502控件、timeline根字段及output统一1024×576、24fps；output为fixed尺寸模式、严格16:9、32对齐，实际约0.59MP（megapixels控件为0.6）；ref_max_size / refMaxSize=864；各组refImageSize="1536"，限制参考图片最长边1536 |
| 采样 | Euler，CFG=1；261为Beta12步，289按8分割；前段SIGMAS连502，一采噪声表末尾归零后实际报告9步；后段SIGMAS连407，二采4步。502的steps/scheduler显示不覆盖外部SIGMAS |
| Shift | 502 shift_video=12，shift_audio=3 |
| 性能控件 | clear_vram_between_segments=true，precise_segment_memory=true；clear_vram_before_refine=true，clear_vram_before_face_refine=false，cache_frames_codec=ffv1（缓存画面采用FFV1无损压缩，不改变MP4导出） |

| 二采模型分块 | 408：MiniMaxLowVRAMAttention，head_chunks=4；409：MiniMaxChunkFeedForward，chunks=4、seq_threshold=4096；只接二采模型支路 |

标准版模型链为192 → 406 → 58 → 53 → 405；去油版为192 → 406 → 58 → 128 → 53 → 405。两版除128节点及其连接外，生成参数和时间线一致；405直接接261和502；二采独立支路为405 → 408 → 409 → 407.refine_model。执行端须提供上述两个分块节点及对应参数接口，不用Refine的时间／空间分块开关替代模型分块。58接管H3主干注意力；通用节点的加入不表示叠加两次加速。`allow_compile`仅允许参与编译，不是节点总开关；`disabled`直接传递模型。407连接502.refine；没有SelfLift、FaceRefine或语义桥连接。一采实际9步加二采4步，不能把调度器显示12步登记成两轮实际总步数。

Refine当前实现始终跟随一采比例，以 `megapixels × 1024²` 计算像素量，再将宽高对齐32；仅填写width/height不会覆盖这一计算。1024×576配合megapixels=1.265625得到1536×864，两阶段均为严格16:9。画布保存的MP数值与API一致。

参考图片尺寸由各组 `refImageSize="1536"` 控制，保持原比例；该设置与生成画布尺寸及 `ref_max_size / refMaxSize` 分开，不通过修改后者替代。正式基准各组与output回退值均保存1536；准备、新增、复制或导入任务分组时逐组落实，并同步根时间线及对应编辑工作区。插件“新增分组”会生成自己的尺寸值，不能宣称仅修改基准JSON就改变了插件默认行为；手动画布可复制已设1536的组，新增空组则须选择1536。

执行端的清理实现须在模型GC／卸载前清空动态显存预取队列，按阶段保留／卸载模型，并支持 `precise_segment_memory`。精确调度按模型权重大小与物理内存总量的比例选择策略，不是按当前内存占用率决定。节点缺少所需接口时报告兼容性问题，不静默删掉参数、覆盖插件或更改启动配置。

基准更新及版本选择用于后续获授权任务，不自动改写已有任务副本、请求或批准来源。已有一采的二采接续沿用原工作流版本，不自动切换标准版或去油版；需要切换时先核对模型链与缓存影响。参考图策略属于一采缓存输入；已有一采接续二采时按[制作变更时的缓存保护](ComfyUI-MiniMaxH3导演台节点使用规范.md#751-制作变更时的缓存保护)及第5节保留来源配置并核对缓存，不套用新基准导致重新一采。

后处理准备与提交前按[开发流程第二部分第7节](../流程规范/短剧开发流程规范.md#7-生成视频验收与衔接修改)核对整场开始条件、指定来源及执行授权；每个后处理任务使用该P选定的二采原文件，先在源视频尺寸下插帧到60fps，再超分，固定输出1920×1080、60fps。节点12为RAFT光流、target_fps=60、scene_cut_threshold=0.15、batch_size=1；节点1为target dimensions、width=1920、height=1080、quality=ULTRA。画面连接为7.images → 12.frames → 1.images → 16.images；12.source_fps连接7.fps的源视频实际帧率，16.frame_rate连接12.fps的插帧返回帧率，16.audio连接7.audio的源视频原音轨。保持播放速度和音画同步，不用改变播放帧率代替插帧。任务完成后按[任务监控规范](../流程规范/ComfyUI-任务监控规范.md)取回全部成果，核对实际尺寸、帧率、时长及来源，再交用户人工审核。插件使用已安装且接口兼容的版本，不固定或自动升级版本；缺少节点、模型或RAFT缓存权重时报告实际错误，不安装或替换方法。

任务中的素材、公共／本组正文、时长与编辑状态按[导演台节点使用规范第2–5节](ComfyUI-MiniMaxH3导演台节点使用规范.md#2-素材排序与编号)填写；实际种子按下节保存到502的seed，画布control_after_generate固定为fixed。逐组导出使用导演台报告的实际路径并按组与P映射归位。精简基准只使用分段导出，不依赖外接视频保存节点；分段交付与本集收尾读取[逐集目录规范第5节](../流程规范/逐集目录与资产管理规范.md#5-分段交付与本集完成)。明确改用全部导出时须在任务副本补齐对应的视频保存连接，不能只改exportMode后声称已保存合并视频。

### 场次基准种子与实际任务种子

同一EP/C首次一采先查已有场次基准种子；没有时采用用户指定值，未指定则生成一次允许范围内且可精确序列化的整数。后续同场首次一采沿用。返修必须沿用被返修来源任务的实际种子；新增R编号、修改提示词或素材、选择部分分段均不换种子。对照默认保留实际种子；需要探索其他种子时，明确为另行获授权的探索范围，不把换种子作为常规返修步骤，不改写历史批准。

场次基准和来源在本场首个任务的 `输入映射.json` 保存，后续记录引用该入口并记录本次实际值；不另建种子台账。每次导演台提交只有一个全局seed，作用于该批实际运行的各组；选择运行不会自动创建分组独立种子。一轮生成七组时，七组使用同一实际种子；选择其中三组时，这三组仍共用该任务的seed。画布control_after_generate保持fixed，不在轮次结束后自动随机或递增。另行探索改变全局种子时，说明其他组后续缓存匹配也受影响；历史获批来源确有不同实际种子时按各自来源核对，不用一个值覆盖历史。恢复查询不换种子、不重复提交。画布/API内7503308486466147是示例，不能直接当作其他项目的场次基准；不得在执行后读取前端下一次种子冒充本次实际值。

请求时长、17k+5帧格及时间线同步按[导演台节点使用规范第5节](ComfyUI-MiniMaxH3导演台节点使用规范.md#5-时长帧数与编辑状态同步)处理；保存请求秒数、计划帧数和真实输出时长，严格时长要求需明确方案，不默默裁切或变速。

标准版的预览与保存接线：502.images_pre_refine（槽位6）→503 CreateVideo→504 SaveVideo；502.images（槽位0）→505 CreateVideo→506 SaveVideo。两条CreateVideo均连接502.audio（槽位1）和502.fps（槽位2），使用8位sRGB；SaveVideo使用MP4／H.264，分别保存到相对output目录的`Nora/Director/FirstPass`、`Nora/Director/SecondPass`前缀，提供播放预览和下载。前缀为通用辅助输出标识，不代表项目成果身份或采用状态。

首次一采确认时最终images口被阻断，只能由504保存一采；人工批准后沿用同一任务副本、缓存名、导演台节点ID、实际种子和一采输入再次执行，命中一采缓存后执行二采，由506保存二采。二采轮可能同时输出一采对照视频，不能把504的对照文件登记为新一采或二采成果。缓存缺失或不匹配按[来源保护与恢复](ComfyUI-MiniMaxH3导演台节点使用规范.md#75-缓存检查与清理接口)处理，不改关闭确认来绕过审批。

默认segments导出时，外接保存仅用于最后实际运行组的辅助预览，完整逐组文件仍由403最终报告驱动后台取回；不替代逐组P映射。明确使用all导出时，两条保存分支接收相应阶段的合并画面，保存为合并视频，不能当作所有P的独立文件。任务完成后再取回全部预期成果。

### 2.1 已批准的输出前缀公式

R的分配、阶段转换及同配置补做读取[视频修订编号与执行过程](../流程规范/逐集目录与资产管理规范.md#视频修订编号与执行过程)，不由任务ID或提交次数分配新R。

采用 `Nora/{项目代号}/{EP编号}-{C编号}-{P编号}-{R编号}-{处理阶段}`。当前正式分段工作流使用导演台原生导出文件名，取回后按组与P映射归位；本公式用于标准版504／506的实际任务输出前缀、需要外接保存的任务副本、兼容仅一采264、独立二采214及后处理16，分别填对应处理阶段。花括号由agent替换，不是ComfyUI自动展开语法；不同任务和阶段使用实际编号，不覆盖既有结果。

项目代号为已有稳定且安全的单个路径段；不包含路径分隔符、`..`、控制字符或Windows文件名禁用字符。前缀相对ComfyUI输出目录，不加扩展名，不用本机绝对路径。下载只认任务返回的filename/subfolder/type。

多组任务的共同证据位置、任务状态与各P输出记录读取[多组任务的共同证据与状态](../流程规范/逐集目录与资产管理规范.md#多组任务的共同证据与状态)；合并文件不冒充每个P的独立输出。正式场次/整集保存与计数按逐集目录规范；已有用户明确指定的技术测试位置可沿用。不因导演台一次导出多组就自行创建一套正式目录或计数规则。

## 3. 参考素材限制与槽位

素材的制作、批准及用途按[首帧规范](../素材规范/首帧参考图规范.md)和[逐集内容制作规范](../流程规范/逐集内容制作规范.md#6-分段视频提示词文档)核对，不以导演台上传替代素材批准。

参考素材的数量、混合总量与音视频时长统一读取[导演台节点使用规范第2.4节](ComfyUI-MiniMaxH3导演台节点使用规范.md#24-公共与本组的数量和时长限制)，准备阶段按每组实际合并输入核对。公共／本组排序、顺延编号、API同号覆盖与实际字段读取该规范第2–3节。

准备任务副本时，对照[场次分镜的参考输入规划](../流程规范/逐集内容制作规范.md#参考输入规划与分段可执行性)和05计划素材映射，将容量结论落实到本次各组的真实输入；超限或未知项解决前不提交该任务。整场提交与同场分批选择读取[开发流程第二部分第7节](../流程规范/短剧开发流程规范.md#7-生成视频验收与衔接修改)。按该流程分批时，将P范围、公共素材方案及跨批衔接方式落实到既有输入映射；分别按[节点缓存规范](ComfyUI-MiniMaxH3导演台节点使用规范.md#75-缓存检查与清理接口)分配并保持批次身份，不假定独立任务会自动继承上一批尾帧或缓存。

既有二采使用265的可选外部加载器时，以其画布映射与 `_meta.nora_optional_reference` 为准，填写实际文件并接入目标槽位，删除所有未用加载器。保留结构不等于已获新二采执行授权。

## 4. 提交、恢复与结果取回

服务配置、选端与恢复地址执行[项目ComfyUI配置](../流程规范/ComfyUI-服务配置与任务提交规范.md#项目-comfyui-配置)。新任务的准备与入队按[服务与任务提交入口](../流程规范/生成任务读取规范.md#comfyui服务与任务提交)执行，不向远端发布基准。已有后台任务按[查询与结果处理入口](../流程规范/生成任务读取规范.md#进度查询与结果处理)选择[状态查询](../comfyui-scripts/README.md#后台状态查询)、[通知确认](../comfyui-scripts/README.md#后台通知确认)或[取回重试](../comfyui-scripts/README.md#后台取回重试)，无需加载上传、提交或完整comfyui-api说明。

1. **准备**：从正式基准制作本次副本，替换全部业务占位符，保存组与EP/C/P映射、获批资料版本、完整模型正文、实际素材、种子和输出范围。冻结任务按[逐集目录规范第4节](../流程规范/逐集目录与资产管理规范.md#4-视频执行输出审核与采用)保存，05不维护运行流水。
2. **核对**：按[执行前检查与复用](../流程规范/ComfyUI-服务配置与任务提交规范.md#执行前检查与复用)使用有效库存或补查节点定义；按实际选择检查标准版19个或去油版16个有效节点、实际模型及参数、素材身份和数量/时长、标签、时间线与输出位置；按[模型提示词长度规则](../流程规范/逐集内容制作规范.md#模型提示词长度)核对各分段最终正文并记录结果；内容与格式分别核对、分别记录结论，语言适配读取[语言与命名](../流程规范/逐集内容制作规范.md#h3模型正文的语言与命名)，检查要求及结论留存直达[模型正文的内容核对](../流程规范/逐集内容制作规范.md#模型正文的内容核对)，资料包的其他交付项按[交付核对](../流程规范/逐集内容制作规范.md#交付核对)执行。不能用UI注册或上传成功证明全组合可运行。
3. **入队**：本次生成获授权后通过统一入口登记，保存本地任务ID。Agent提供工作流、素材绑定、输入映射及成果保存路径；后台轮到任务时上传，在POST前按[生成版本的资料关联](../流程规范/逐集目录与资产管理规范.md#生成版本的资料关联)冻结当次资料，保存实际地址与远端ID。参数见[视频资料自动保存](../comfyui-scripts/README.md#视频资料自动保存)。
4. **跟进**：后台按[任务监控规范](../流程规范/ComfyUI-任务监控规范.md)监听、重连及核对，Agent不另开定时器。收到结果通知后先确认收到，再读取记录；失败从具体失败阶段复查，不自动安装、重启、清队列或替换模型。

   原ID丢失时执行[故障后的视频接续](../流程规范/ComfyUI-任务监控规范.md#51-后端故障后的视频接续)，保留证据和已有文件，核对状态与来源缓存，不自动补做。
5. **取回**：默认分段导出按导演台报告中的本轮运行目录和逐组文件核对，按[逐组输出规范](ComfyUI-MiniMaxH3导演台节点使用规范.md#731-导出方式与逐组文件)区分一采、二采及P映射，403报告为逐组文件依据。明确采用全部导出时须核对本任务实际接入的保存节点；旧版仅一采认264、独立二采认214，后处理认16。只用本任务真实文件身份，不把旧预览作为结果。缺少完整逐组文件时报输出异常，不把执行成功当作全部交付。
6. **交付**：后台成功后将最终文件保存到指定候选路径，按[成果保存与已有文件](../流程规范/逐集目录与资产管理规范.md#成果保存与已有文件)保留已有文件与记录。Agent按[精简收尾](../流程规范/ComfyUI-任务监控规范.md#视频完成通知后的精简收尾)维护必要业务状态并交用户人工审核；成功生成和保存均不等于内容获批。

## 5. 人工审核与轻量记录

执行、候选/选定、人工审阅及场次/整集交付统一按[逐集目录规范](../流程规范/逐集目录与资产管理规范.md)维护，不另建运行台账。结果只由用户人工审核，不进行agent内容初审、自动重生成或未经批准切换处理阶段。

获批一采的缓存保存及二采前的来源恢复执行[导演台第7.5.2节](ComfyUI-MiniMaxH3导演台节点使用规范.md#752-获批一采缓存的本地保存与恢复)。一采、二采及后处理的获批收尾执行[场次各阶段定稿留档](ComfyUI-MiniMaxH3导演包制作规范.md#51-场次各阶段定稿留档)，按开发流程接续下一环节；定稿包与画布留档不替代下文的一采来源和缓存核对。

正式画布407.confirm_first_pass保持开启。一采与二采共用工作流不合并制作阶段；按开发流程的整场审批顺序推进，分别保存两阶段任务ID、输出及用户决定。首次执行只生成一采；用户批准后，沿用同一任务副本、缓存名、导演台节点ID、实际种子与一采输入再次执行。逐一核对本轮选中组与获批一采的缓存匹配，命中后只做二采；缓存缺失或不匹配时先说明，不把重新一采冒充二采。局部返修与不同获批输入的分轮执行按[返修选择运行操作](ComfyUI-MiniMaxH3导演台节点使用规范.md#711-返修选择运行操作)处理。Refine参数可按已批准二采方案调整；清理缓存按[节点缓存操作](ComfyUI-MiniMaxH3导演台节点使用规范.md#75-缓存检查与清理接口)执行，不在两轮之间自动清理。
