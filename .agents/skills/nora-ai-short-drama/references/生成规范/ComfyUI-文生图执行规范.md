# ComfyUI-文生图执行规范

状态：现行执行规范。  
版本：v1.32。
更新日期：2026-10-02。
用途：使用本地工作流副本配置参数、提交远端 ComfyUI、取回图片并完成验收记录。当前参数映射适用于 Qwen Image 2.1 普通版工作流。

提示词编写另见 [Qwen Image 2.1 提示词规范与模板](Qwen-Image-2.1-提示词规范.md)，并依其[接入与适配](Qwen-Image-2.1-提示词规范.md#13-qwen-image-2-1-prompter接入与适配)使用qwen-image-2-1-prompter的T2I分支。本文件只接收该规范第 3 节的文生图两字段结果，不处理图像编辑的 `ratio_follow`，不重复规定提示词写法。

场景任务先按[场景生成规则](../素材规范/场景资料与参考图规范.md#411-生成方式与参考输入)确定分支；仅所选文生图任务执行本文。

场景图任务必须先读取 [场景资料与场次参考图规范](../素材规范/场景资料与参考图规范.md)，核实场次需求和已确认资料卡；使用固定生成／审阅记录模板进行文件核对及用户审核，完成文件与记录核对后提交用户最终审核。场景任务原始附件存入 `04-场景资料/其他资料/执行附件/`，正式图及生成记录位于对应 SC 的 `参考图/`；不沿用人物白底或人物专项清单。图片像素及节点映射按本文规定执行。

道具三视图任务必须读取 [道具资料与参考图规范](../素材规范/道具资料与参考图规范.md)，使用白底单张三视图及固定生成／审阅模板；完成文件与记录核对后交用户最终审核。正式图及生成记录位于对应 PR 的 `参考图/`，机器附件位于 `05-道具资料/其他资料/执行附件/`。制作规格读取该专项规范；节点设置按下表执行并核验真实输出。

制作、修订和结果核对按[Qwen参考图生成与修订的七项约定](Qwen-Image-2.1-提示词规范.md#22-qwen参考图生成与修订的七项约定)执行；工具选型见[技能入口](../../SKILL.md#当前参考图生成选型)。候选先交用户审核；修订按[参考图统一修订规则](Qwen-Image-2.1-提示词规范.md#25-参考图统一修订规则)执行。

道具状态参考图使用图生图，按[道具专项规范](../素材规范/道具资料与参考图规范.md)及[图生图执行规范](ComfyUI-图生图执行规范.md)执行，不套用本文三视图分支。

## 1. 输入与工作流文件

执行前取得两类信息：

- 提示词结果：`rewritten_prompt` 与 `wh_ratio`。用户明确要求直接使用原文时，按用户要求处理并记录。
- 运行要求：目标像素宽高、图片数量、输出格式、保存位置，以及项目类别默认种子、已确定的CFG或采样步数等；种子取值统一按提示词规范第2.6节执行。

本地基准文件：

| 文件 | 用途 |
| --- | --- |
| [普通画布版](../comfyui-workflow/Qwen2.1-文生图-普通版.workflow.json) | 保留节点布局与子工作流，供可视化检查和后续修改 |
| [API 执行版](../comfyui-workflow/Qwen2.1-文生图-普通版.api.json) | 已展开子工作流，供程序配置参数并提交执行 |

**基准文件不可直接提交。** 两个导出版本保留1024×1024方图配置和占位提示词，不是当前参考图任务的成品配置。每次必须在任务副本中替换为本次实际提示词、比例、像素规模和输出前缀，并核对数量及采样参数；不得沿用示例内容直接生成。

每次从 API 基准文件创建任务副本，保存本次实际参数。提交副本不会自动改写本地基准或远端保存的工作流；只有用户要求保存配置时，才更新相应基准文件。

当前模型组合为主模型 `qwen_image_2.1_int8_convrot.safetensors`、编码器 `qwen3vl_8b_bf16.safetensors`、VAE `qwen_image_2.1_vae_bf16.safetensors`。除非用户明确要求，不更换该组合。执行前按[执行前检查与复用](../../SKILL.md#执行前检查与复用)使用comfyui-inventory的有效库存或刷新后核对节点与对应加载器选项，不能仅凭文件名推断兼容性。

## 2. 提示词与参数映射

| 信息 | 当前工作流中的位置 | 处理方式 |
| --- | --- | --- |
| 正向提示词 | `459:452.inputs.prompt` | 提取 `rewritten_prompt` 的值，不把整个 JSON 当作提示词 |
| 反向提示词 | `459:452.inputs.negative_prompt` | 默认沿用本次已确定设置；需要单独编写时明确记录 |
| 宽高比 | `13.inputs.aspect_ratio` | 按第 3 节将 `wh_ratio` 映射为节点实际比例选项 |
| 像素规模 | `13.inputs.megapixels` | 根据目标宽高计算，并核对对齐后的结果 |
| 对齐倍数 | `13.inputs.multiple` | 当前基准为 `32`；场景审批尺寸任务副本按第3节保持 `32` |
| 图片数量 | `459:456.inputs.batch_size` | 按本次请求设置，当前基准为 `1` |
| 种子 | `459:458.inputs.seed` | 按[项目七类图片默认种子](Qwen-Image-2.1-提示词规范.md#26-项目七类图片默认种子)按核心类别或补充图片分支选值，作为运行参数记录 |
| CFG、步数 | `459:458.inputs.cfg`、`459:458.inputs.steps` | 当前基准为 `1` 和 `25`，按本次要求沿用或调整 |
| 文件名前缀 | `461.inputs.filename_prefix` | 为本次任务使用可辨认的前缀 |
| 输出格式 | `461.inputs.format` 及其关联字段 | 当前基准为 PNG；格式变更时同步检查关联字段 |

节点编号属于当前模板。工作流重新导出或调整结构后，应重新核对映射，不能假定编号永久不变。

官方增强器工具的输出记录中，`negative_prompt` 固定为空；这不代表 ComfyUI 没有反向提示词输入。当前工作流使用标准 KSampler，CFG 为 `1` 时，反向条件不发挥常规引导作用。修改 CFG 属于采样参数调整，应与提示词改写分开记录。

## 3. 分辨率设置

人物四类图片及道具三视图使用明确整数宽高，不能仅把比例标签传给比例选择器：人物六视图与服装图审批尺寸均为1152×864、4:3。肖像、服装和道具三视图的首次生成及修订，在任务副本中将 `459:456.inputs.width`、`height` 的节点13连接替换为下表整数，保留batch_size及其他采样设置；记录该任务节点13不决定画布。图生图仅用于固定索引允许的类型，不因修订而将文生图类型切换为图生图。

| 用途 | 明确宽×高 | wh_ratio | 设置方式 |
| --- | --- | --- | --- |
| 人物上半身正面肖像审批图（含画风样例） | 1024×1024 | `1:1` | width=1024、height=1024 |
| 服装正背面审批图 | 1152×864 | `4:3` | width=1152、height=864 |
| 道具三视图审批图 | 1376×768 | `43:24` | width=1376、height=768 |

本表维护原生生成尺寸的技术映射；批准后处理与正式保存统一执行[图片超分执行规范](ComfyUI-图片超分执行规范.md)。画风样例仅共用1024×1024生成规格；认可后保留原图，不执行超分，按[定位画风验证流程](../流程规范/短剧开发流程规范.md#项目画风展开示例验证与复用)保存。

道具“16:9”为近似推荐标签，实际宽高比例43:24，不能用16:9选择器推算替代以上整数画布。场景审批图使用以下ResolutionSelector任务配置，并核对实际输出尺寸：

| 用途 | 目标宽×高 | wh_ratio | 比例选项 | megapixels | multiple |
| --- | --- | --- | --- | --- | --- |
| 场景审批图 | 1536×864 | `16:9` | `16:9 (Widescreen)` | `1.265625` | `32` |

节点13使用 `megapixels × 1024 × 1024` 计算目标像素量再对齐宽高，公式为 `宽 × 高 ÷ (1024 × 1024)`。历史单次测试不保证其他任务的原生输出规格。所有新任务按[执行前检查与复用](../../SKILL.md#执行前检查与复用)核对目标值符合节点限制；能力依据满足复用条件时无需重新查询，生成后读取真实宽高；规格失败时记录偏差并讨论修正，不私自放大或裁切冒充达标。其他比例不直接假定为选择器选项。

只修改目标尺寸时，不需要同时修改 CFG。比较提示词时沿用该图片类型的项目默认种子，优先固定尺寸和其他采样参数；修改 CFG、尺寸或模型时，在记录中单独说明。

## 4. 执行流程

监控与恢复必须读取 [ComfyUI任务监控提示词模板](../模板/ComfyUI-任务监控提示词模板.md)，执行任务填写区、共用规则及图片分支。计数、检查间隔、双向切换、恢复和通知规则统一由该模板维护。图片文件核对与用户批准按本图片用途的专项规范执行，获授权修改按[图片交付与用户审核](../流程规范/短剧开发流程规范.md#851-图片交付与用户审核)执行；不因队列生成跳过审批依赖或提交下一步任务。

本节的提交、单轮查询和下载必须使用 [固定通信工具](../comfyui-scripts/README.md) 的submit／status／download，并结合comfyui-api技能。不为每次任务编写HTTP执行脚本；agent先配置最终API JSON，再交工具提交。业务附件位置和文件名由agent按既有规则通过参数指定，附件留存执行[精简留档规则](../模板/ComfyUI-任务监控提示词模板.md#执行附件精简留档)；程序不做图像初审或批准。

1. **读取本地模板。** 创建任务副本，保存本次完整提示词和生成要求。
2. **配置并检查参数。** 按上述映射填写提示词、比例、尺寸、种子及其他已确定参数。按[执行前检查与复用](../../SKILL.md#执行前检查与复用)使用有效库存或刷新能力依据，逐任务核对目标尺寸、图片数量、节点、模型及输入连线。
3. **连接远端服务。** 从当前项目 `comfyui-config.json` 读取 `remote-url` 并显式传给固定工具，检查服务状态。
4. **提交一次任务。** 通过 `POST /prompt` 提交 API 工作流，将其作为请求的 `prompt` 字段，取得并保存 `prompt_id`。提交结果不确定时，先查队列或历史，避免重复生成。
5. **跟踪执行。** 使用任务编号查询 `/history/{prompt_id}`，或监听 WebSocket 进度。历史暂为空时结合队列判断；历史有记录时仍须核对成功、失败或中断状态。
6. **取回图片。** 任务成功后，按输出节点返回的文件名、子目录和类型，通过 `/view` 下载至本次指定位置。
7. **交付并记录。** 通过文件与执行证据核对真实尺寸、格式、数量、可解码性、来源和版本，按图片专项生成／审阅模板保存候选并直接展示给用户审核。默认不看图、不做视觉初审、不自动重试；异常如实报告，处理按[图片交付规则](../流程规范/短剧开发流程规范.md#851-图片交付与用户审核)。

远端服务接口的详细调用方法由 `comfyui-api` 技能负责。本文件保留当前工作流的使用方式与验收要求。

## 5. 检查与验收

### 提交前

- 提示词已按对应规范完成，或已明确采用用户原文；不存在未替换的占位符或基准中的无关示例提示词。
- `wh_ratio`与目标像素一致；使用明确整数画布时核对宽高，使用选择器时再核对节点比例；像素规格不依靠提示词中的清晰度用词实现。
- 节点、模型、连接和输出格式配置可用；任务副本包含本次完整参数。
- 目标数量和保存位置明确，基准文件与本次副本可以区分。
- 已按[种子规则](Qwen-Image-2.1-提示词规范.md#26-项目七类图片默认种子)核对本任务适用分支及实际取值，保存选择依据。

### 生成后

- 通过文件读取实际尺寸、格式、数量及可解码性，按执行记录核对输出来源；图片内容直接交用户判断。
- 分开记录执行状态、文件核对结果和用户决定；看图仅在明确允许时记录依据、范围及发现。附件位置沿图片专项规范，不另建重复记录。
- 若需要修改，明确是提示词、参数还是编辑任务；记录本次变化，避免同时调整太多因素而无法比较。
- 保存实际提交正文、反向提示词、任务编号、模型、种子、CFG、步数、目标与真实尺寸、输出路径及验收结果。

完成标准：本次任务状态清楚，图片及记录已保存，真实规格及用户审核状态已向用户说明。

## 本地配套基准

服务地址从项目 `comfyui-config.json` 读取。每种工作流的 `.workflow.json` 与 `.api.json` 是同一工作流的配套唯一基准；未经用户明确要求不修改、不从远端自动替换。普通版仍为默认；保存的越狱版仅在用户明确要求时使用，其配套API同名可读，不把名称视为运行或内容效果保证。执行从本地API复制任务副本，只填写已授权的提示词、素材和参数；所有占位提示词与素材必须替换。真实请求、参数、任务ID及响应仍保留在项目。
