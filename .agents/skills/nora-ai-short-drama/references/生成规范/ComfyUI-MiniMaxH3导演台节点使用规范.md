# ComfyUI-MiniMaxH3导演台节点使用规范

版本：v1.19；更新日期：2026-10-07。

用于填写、修改和检查 `MiniMaxH3Director` 节点的网页画布与API任务副本。接口说明入口为[节点仓库](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director)。正式基准、固定生成参数、种子策略、执行授权和输出命名读取[H3执行规范](ComfyUI-H3视频执行规范.md)；模型正文及中文参考版读取[逐集内容制作规范第6节](../流程规范/逐集内容制作规范.md#6-分段视频提示词文档)及 `h3-prompt-writing`。本文件不复制这两类规则。

## 1. 节点与任务结构

当前正式一采确认与二采画布中的导演台为502，节点类型是 `MiniMaxH3Director`。任务副本以真实节点类型和连接为依据，不能仅凭标题辨认节点。常规使用原生r2v素材组，不额外连接 `r2v_groups`；外部组一旦接入，会优先于网页素材组，不能一边填写原生组、一边以为两边会自动合并。

本工作区采用一个素材组对应一个项目P分段的编排方式，组内可包含多个Shot；这是项目制作约定，节点本身只识别素材组，不要求使用EP/C/P编号。`segments[]` 的数组顺序就是组顺序；每个组保留独立id，并在既有输入映射中记录对应EP/C/P。移动、复制或删除组后同步检查分镜顺序、时长、提示词、连续开关和输出范围，不把组显示序号当作永久P编号。

| 区域 | 用途 | 时间线字段 |
| --- | --- | --- |
| 公共参数区 | 每组共同使用的素材和主体定义 | `global` |
| 本组区 | 当前P独有的素材、镜头动作、对白与声音描述 | `segments[i]` |
| 输出与衔接区 | 画布规格、音频模式、连续设置与导出范围 | `output` |
| 模式编辑状态 | 再次打开画布时恢复公共区、各组及选择状态 | `batchWorkspaces.r2v` |

使用公共素材时，明确将 `global.commonEnabled` 设为true。折叠公共区只改变展示，不等于关闭公共参数。关闭公共参数后，不把仍保留在global中的素材计入本组实际输入；不能假定本组原有槽位和提示词会自动恢复成从1开始。

### 1.1 视频模式与输入条件

| task_type | 输入用途 | 模型类别 |
| --- | --- | --- |
| t2v | 文本生成音视频，无硬首尾帧 | FL2VA |
| i2v | 图片引导生成，使用该模式的图像输入 | FL2VA |
| fl2v | 首帧、尾帧或首尾帧；空组可只写文本 | FL2VA |
| r2v | 多张图片、视频与音频作为参考素材，使用公共／本组素材区 | Ref2VA |
| v2v | 对源视频时间轴的对应片段进行编辑，源片段绑定Video 1 | Ref2VA |
| rv2v | 源视频编辑，同时加入参考图片与音频 | Ref2VA |

正式任务沿用H3执行规范中的r2v与已确认模型组合。此表说明节点能力，不授权切换模式、换模型或重做素材；i2v／fl2v的硬首尾帧和r2v的普通参考图片不能互相替代。公共／本组容量规则适用r2v，不机械套到首尾帧或源视频时间轴。

## 2. 素材排序与编号

### 2.1 三种编号各自独立

图片用 `<Picture N>`，独立音频用 `<Audio N>`，视频用 `<Video N>`。三者各自从1开始，不能把图片、音频、视频混成一条编号序列。文件数据中的 `index` 从0开始，对应模型标签N＝index＋1。

同一种素材按有效 `index` 从小到大排序，不按文件名、上传完成时间或数组存放顺序排序。新任务按本次计划先确定公共素材顺序，再确定本组素材顺序；同模态连续填写，不为空素材预留编号。人物、场景、道具的先后采用本次已有映射，不额外规定某类必须排第一。

### 2.2 公共在前，本组顺延

开启公共参数后，每种媒体的本组起始位置分别计算：

```text
offset = 公共区该媒体最后一个已填槽位的index + 1
公共区没有该媒体时，offset = 0
本组第j份素材（j从1开始）的index = offset + j - 1
本组第j份素材的模型标签序号 = offset + j
```

这里取的是**最大已填index＋1**，不是数组长度或文件数量。公共图片只有index 0、2时，本组从index 3／Picture 4开始，不从Picture 3开始。既有空位不在接续任务中静默压缩；确需重排时同步检查所有受影响提示词和映射。

公共区连续放3张图片时，各组的本组图片都从Picture 4开始。第2组不接着第1组的最后一张图编号；各组分别与同一公共区合并。

| 所在位置 | 素材用途示意 | index | 模型标签 |
| --- | --- | ---: | --- |
| 公共区 | 人物甲 | 0 | `<Picture 1>` |
| 公共区 | 人物乙 | 1 | `<Picture 2>` |
| 公共区 | 共用环境 | 2 | `<Picture 3>` |
| 第1组本组区 | 本段开场构图 | 3 | `<Picture 4>` |
| 第1组本组区 | 本段道具状态 | 4 | `<Picture 5>` |
| 第2组本组区 | 另一段的独有道具状态 | 3 | `<Picture 4>` |

上表中两组的Picture 4可以是不同文件；公共正文只能统一定义共同含义的标签，本组正文解释该组独有图片的用途。不能在公共正文中把仅第1组使用的Picture 4定义成所有组共同使用的文件。

音频、视频同理：公共区有1段音频，本组独立音频从Audio 2开始；公共区没有视频，本组视频仍从Video 1开始。图片数量不会影响音频或视频的起号。

### 2.3 网页顺延与API填写的区别

网页根据公共区的已填槽位显示本组可用槽位。启用公共参数或公共素材扩展时，界面会尝试把冲突的本组槽位移到公共区之后：全部冲突时整体顺延，部分冲突时移到可用的后续槽位。空间不足时无法保留所有条目，不能把界面调整当作素材已完整保留的证明。

这种调整针对素材index，不构成提示词标签已同步改写的保证。先确定公共区，再上传或填写本组；公共区增删、换位或开关变化后，逐组核对最终槽位、实际文件和正文标签。出现素材丢失或容量不足时调整本次素材计划，不提交被截掉的输入。

直接填写API或离线修改画布时，**主动计算并写入绝对index**。不能给公共区写index 0、1、2，同时给本组新图又写index 0，并期待服务器自动把新图追加到Picture 4。

服务端的合并是按index建立映射，再按index排序；同模态同index时本组覆盖公共。它不会替直接API调用完成网页的顺延操作。常规新增本组素材按上一节顺延，不用碰撞实现追加。只有确实需要替换公共素材、且正文和映射已同步明确时，才使用覆盖；保存后还需确认网页没有将该条目顺延成另一槽位。

### 2.4 公共与本组的数量和时长限制

以下限制适用于原生r2v / Ref2VA素材组。公共区与每个本组共用容量；先确定公共素材，再按剩余容量填写各组。技术槽位说明见[素材组界面](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/web/js/minimax_image_batch.js)，模型输入规格见[H3输入规格](https://github.com/MiniMax-AI/MiniMax-H3#model-variants-and-input-specifications)。

**限制对象**：12份限制的是每个分段实际送入Ref2VA的参考输入，不是整个场次的上传总数，也不是一次Queue包含的全部组的文件总数。全场次可上传和分配超过12份素材，只要每组的公共＋本组实际输入分别符合下列限制。

| 素材所在位置 | 是否计入当前组额度 |
| --- | --- |
| 已上传到服务器，但未填入当前组或启用的公共区 | 不计入 |
| 其他组的本组素材 | 不计入 |
| 已启用公共区中的有效素材 | 计入每组；公共区不是供提示词按需挑选的素材库 |
| 当前组已填入的有效素材 | 计入当前组，即使提示词未写它的标签 |

节点按素材字段合并公共与本组输入，再将参考媒体送入模型，不根据提示词出现了几个Picture／Video／Audio标签筛选输入。要使一份素材不进入某组，将其从该组输入中移除；仅部分组需要的素材放到对应本组，不放进启用的公共区。服务器仍可保留已上传文件，无需删除源文件。合并及传入方式见[组输入构建](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/director/gen_timeline.py)和[Ref2VA输入编码](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_minimax_h3.py)。

| 媒体 | 公共区单项最多 | 无公共素材时本组单项最多 | 公共参数开启后本组可新增槽位 | 每组公共＋本组合并上限 |
| --- | ---: | ---: | --- | ---: |
| 图片 | 9张 | 9张 | 9－图片offset | 9张 |
| 视频 | 3段 | 3段 | 3－视频offset | 3段 |
| 独立音频 | 3段 | 3段 | 3－音频offset | 3段 |

offset按第2.2节计算。公共素材连续编号时，offset等于该类公共素材数量；公共槽位有空缺时，仍取最大已填index＋1，空缺不增加本组的追加空间。例如公共图片仅占Picture 1、Picture 9，本组也没有可顺延的图片槽位。公共参数关闭时三种offset均为0，global中保留的素材不计入实际输入。

表中是各媒体单项上限，不能同时填满三列。每个组还须同时满足：

- **混合数量**：每个分段实际合并的图片数＋视频数＋独立音频数≤12；启用的公共区本身也不得超过12份，因为它的素材会进入每组。新增本组素材的总量不超过12－启用的公共素材总量，并同时受各媒体剩余槽位约束。9张图片＋3段视频已满额，不能再加入独立音频。
- **视频时长**：每段2–15秒；本组实际使用的公共视频与本组视频总时长≤15秒。
- **独立音频时长**：每段2–15秒；本组实际使用的公共音频与本组音频总时长≤15秒，且须搭配图片或视频。音频与视频总时长分别计算，不共用同一个15秒额度。

数量按每组实际输入的有效槽位核对，不按服务器input目录中的文件数量或整个导演台所有组的文件数量计算。同一文件重复填入不同槽位仍占用对应槽位，不靠文件去重减免额度。公共素材在每组内计一次；各组本组素材不互相累占额度。视频自带音轨不作为额外上传的独立Audio文件计数，若再将其提取并填入独立音频槽，则另占独立音频额度。

**连续编号示例**：公共区放4张图片、1段视频、1段独立音频，共6份。每个组的单项剩余槽位分别为5张图片、2段视频、2段音频，但三者新增总量最多6份；新增5张图片＋1段视频可达到12份，再加1段音频就超额。若公共视频为10秒，该组新增视频总时长最多5秒；公共音频的时长另算。各组都按这套公共素材独立计算。

**全场超过12份的示例**：公共区6份（4张图片、1段视频、1段独立音频），三个组各自再放5份不同素材（3张图片、1段视频、1段独立音频）。全场共21份不同文件；每组只接收公共6份＋本组5份＝11份，分别为7张图片、2段视频、2段独立音频，因此数量符合限制。各组仍须分别满足音视频时长限制。其他两组的本组素材不会进入当前组；21份不会被一次性合并成某一段的参考输入。

公共素材占满某类槽位时，本组该类新增数量为0；需要不同的本组素材时，调整公共／本组安排并同步标签，不填入超范围index或依赖界面、服务端自动截掉输入。数量上限是可用边界，不要求填满；只有该批所有分段都需要的素材才放公共区，仅部分分段需要的素材分别引用在这些分段的本组区，避免无关公共素材占用每组容量。

**素材安排与超限处理**：先保留每段必需的参考输入，去掉无关或重复用途的输入，将仅部分组需要的素材移到对应本组；不为凑数量删除必需环境图、首段首帧或剧情所需的身份／状态依据。公共区只放该批每组都需要的素材，调整后重新核对所有受影响组的数量、时长、槽位与标签。资源份数按拟输入文件和槽位计算，不按出场人物或资产种类计算。

公共区适用于该批所有组；调整公共素材后须重新核对每组的实际合并输入。仅把同一个超限组放入另一次Queue不会减少它的输入，提示词不提标签或节点截断也不能作为容量通过的依据。场次提交与分批选择读取[开发流程第二部分第7节](../流程规范/短剧开发流程规范.md#7-生成视频验收与衔接修改)；素材安排后仍超限、需要细分生成段时，执行[参考输入规划与分段可执行性](../流程规范/逐集内容制作规范.md#参考输入规划与分段可执行性)。

### 2.5 合并后的核对

每个组分别列清“模型标签 → 公共或本组 → 实际文件及版本 → 用途”。沿用既有05计划映射和[逐集目录规范第4节](../流程规范/逐集目录与资产管理规范.md#4-视频执行输出审核与采用)中的实际输入映射，不另造素材排序台账。按第2.4节逐组核对有效槽位、混合数量及音视频时长，再核对正文中的标签；上传成功或网页能显示槽位不等于输入已经符合全部限制。

公共素材变更会影响所有引用它的组；本组素材变更只检查本组及确实受影响的后续衔接。公共主体定义、英文正文、中文参考版和实际输入都使用同一映射，不以仍存在的旧标签、预览缩略图或文件名证明素材正确。

## 3. 原生素材字段与上传路径

| 媒体 | 公共字段 | 本组字段 | 文件身份字段 |
| --- | --- | --- | --- |
| 图片 | `global.refs[]` | `segments[i].refs[]` | index、imageFile、fileName、type、subfolder |
| 独立音频 | `global.refAudios[]` | `segments[i].refAudios[]` | index、audioFile、fileName、type、subfolder |
| 视频 | `global.refVideos[]` | `segments[i].refVideos[]` | index、videoFile、fileName、type、subfolder |

按服务端已安装接口和原生导出状态填写完整媒体记录，不新增自定义媒体键。文件字段使用上传后真实input相对路径；保留响应中的name/subfolder/type，避免漏掉子目录或重复拼接子目录，不传客户端绝对路径。通过[固定通信工具](../comfyui-scripts/README.md)上传，已有远端文件经身份和路径核对可复用。

图片、视频和音频的预览字段只服务界面；实际文件字段不能为空。删除不用的媒体条目，不留只有缩略图、空文件名或旧文件名的占位条目。`referenceVideo` 是既有单视频兼容字段，不与本次明确的 `refVideos` 槽位同时留存另一份未核对视频。

r2v中的普通Picture提供视觉参考，不是i2v／fl2v的硬首帧。首段与后段的首帧用途读取[首帧规范](../素材规范/首帧参考图规范.md)，不要仅靠写“第一帧完全一致”改变输入模式。视频自带音轨与独立Audio槽是不同输入，计数按第2.4节，参考用途按[音视频规范第4节](../素材规范/参考音视频管理规范.md#4-分段使用边界)确定。

### 3.1 音频参考与输出模式

`output.audioMode`决定输出视频的音频来源，参考Audio素材则参与生成条件；上传参考音频与选择输出原声是两件事。

| audioMode | 输出行为 | 使用要求 |
| --- | --- | --- |
| generate | 优先使用模型生成、解码的音频；适用任务在生成音频为空时可回退到原声来源 | 正式一采沿用此模式；模型正文的参考用途按音视频规范第4节填写 |
| source | v2v／rv2v取对应源片段原声；r2v没有源视频时间轴时，取本组实际合并输入中的第一条可用独立参考音频 | 使用原声须获明确授权；模型正文的参考／复用用途按音视频规范第4节填写 |
| mute | 输出静音 | 明确要求静音时使用，不能据无输出声音声称参考音频未参与条件 |

r2v的source逐组选择原声，公共音频也属于本组的合并输入；不能仅在提示词中指定另一个Audio标签就改变“第一条可用音频”的选择。某组没有可用原声时，该组输出静音，不借用另一组的音频。原声输出按该段实际帧数裁切或补齐时长，并进行输出格式归一化，不能视为文件字节完全不变。generate产生空音频时，检查报告与实际来源，不把回退的原声登记成模型新生成声音。接口行为见[音频输出实现](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/director/audio_export.py)。

音频槽可以选择音频文件，也可以从视频中提取首条音轨；提取后实际填写的是生成的音频文件，不因此占用Video槽。核对上传响应中的真实路径，不能继续把原视频路径写到audioFile。技术接口可提取不等于获得加工授权；是否可处理及入库执行[音视频管理规范的入库规则](../素材规范/参考音视频管理规范.md)，声音选用与模型正文按该规范第3、4节接续。

## 4. 公共提示词与本组提示词

| 内容 | 保存位置 |
| --- | --- |
| `subject_definitions`标题及共同素材／主体定义 | `global.prompt`，与导演台控件/API的 `global_prompt` 一致 |
| 不带章节标题的本段素材／主体定义续写，随后接其余五节正文 | `segments[i].prompt` |

公共参数开启时，节点把“公共正文＋空行＋本组正文”拼接为本组实际提示词，不是本组正文替换公共正文。公共区以 `subject_definitions:` 开头，本组开头接续本段独有素材／主体的定义，不重复该标题或共同定义，再依次填写summary、retention_analysis、detailed_description、overall_soundscape、non_diegetic_music。没有本段独有定义时，本组直接从summary开始。拼接后共同定义与本段定义属于同一个subject_definitions章节，整段符合Ref2VA六节格式。六节格式和这种拆分属于本工作区的填写约定；导演台接口只拼接字符串，不检查章节名称或内容归属。

公共素材的适用范围按[第2.4节](#24-公共与本组的数量和时长限制)确定。仅部分分段需要的同一文件分别引用在这些分段的本组区，其定义也随素材写在本组开头；首段独用的开场图不放公共区。素材及定义一起归位，不能只移动素材而保留不适用的公共定义。编号按[第2.2节](#22-公共在前本组顺延)逐组对应，不接续上一组的本组编号。

素材／主体定义客观说明标签所指对象、参考用途及需保留的主要特征，不代写剧情动作或状态变化，不无差别照搬整张参考图的背景、排版或陈列。本段独有开场图可说明图中状态，并限定其参考镜头；开门等后续动作仍写入逐镜正文。公共定义只写各段共同成立的身份、外形或空间结构，不写开关门、作物生长、持有物、姿态、情绪等随剧情变化的过程。每段的起始状态、变化时点及结束状态主要写在本组detailed_description，summary与retention_analysis与之对应；不在前段复制后续段才发生的状态，也不以“变化后保持”概括整场后复制到每段。当前段已经成立的状态明确写出，不只引用其他段。新增主体、场景状态或声音信息仍依据获批资料整理，不因技术拆分改写剧情。主体与说话者编号的含义和分配读取逐集内容规范。

没有共同素材和定义时关闭公共参数，由每个本组独立填写subject_definitions标题及后五节，不保留空的公共正文。

按逐集内容规范保留完整英文模型正文及中文参考版；实际填写导演台时拆到上述两处，并核对拼接后的完整正文。模型正文的内容边界沿用该规范。网页的 `@` 素材选择最终对应官方标签；直接填写API时使用明确的 `<Picture N>`／`<Audio N>`／`<Video N>`。

拼接后的完整正文执行[模型提示词长度规则](../流程规范/逐集内容制作规范.md#模型提示词长度)。填写完成及公共／本组正文变化后，逐组检查实际拼接字符串：subject_definitions标题只出现一次，后五节顺序正确，标签与实际素材对应，定义及各节的当前状态、变化时点和结束结果一致；在既有准备／执行记录注明计数结果。不能仅检查本组输入框，或仅凭六节齐全认定状态正确。

## 5. 时长、帧数与编辑状态同步

每组 `durationSec` 对应本P获批请求时长。按当前24fps的H3帧格换算：

```text
frameCount = max(5, round(durationSec * 24))
             + (5 - (max(5, round(durationSec * 24)) % 17)) % 17
```

10秒对应243帧，15秒对应362帧。`length` 与frameCount一致；第一组start为0，后续start为前面各组frameCount之和；根totalFrames及导演台的total_frames为全部组frameCount之和。根durationSec保留原生界面的字段语义，不用它代替各组durationSec或真实输出时长；输出时长以本次文件的实际帧数和fps核对。

修改后同步核对：

| 数据 | 一致性要求 |
| --- | --- |
| 画布控件／API | width、height、frame_rate、ref_max_size、total_frames与时间线相应字段匹配 |
| 时间线根字段 | width、height、frameRate、refMaxSize、totalFrames |
| output | 宽高与当前实际画布规格匹配，其他生成参数按正式基准 |
| 根global与segments | 本次真实正文、素材、顺序、时长和衔接设置 |
| `batchWorkspaces.r2v.globalCommon` | 公共开关、折叠状态、prompt、refs、refAudios、refVideos及存在的t2vCommon，与global对应字段一致 |
| `batchWorkspaces.r2v.segments` | 组顺序、id、正文、素材、时长、帧数、衔接与其他持久化业务字段一致 |
| 选择状态 | 根与工作区中的editMode、selectedIndex、runSelectEnabled、runSelection相符；原生导出省略字段时，按界面默认值核对，selectedIndex默认为0 |

编辑工作区是经原生序列化整理后的业务快照，不是根对象的完整复制。globalCommon不必包含global的taskType、genImage、referenceVideo等模式根字段；素材预览数据可以被删除，type、subfolder、空图像字段等可以按接口补默认值，null首尾帧可以被省略。比较对应持久化内容，不要求两份原始JSON对象完全相等，也不能为追求相等把根专有字段强塞进工作区。未知字段不擅自删除；实际序列化格式见[网页编辑状态实现](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/web/js/minimax_timeline.js)。

只修改根segments而保留工作区旧正文，会使重新打开画布时恢复出另一套内容。修改画布的 `widgets_values_named` 与对应 `widgets_values` 时保持同值；API的timeline_data使用JSON序列化得到的字符串，不拼接转义。删除无关旧预览、旧报告及生成缓存引用，不把它们当作本次结果。离线配对校验检查对应公共内容、分组内容和选择状态，能接受原生快照的精简形式；不能用忽略业务字段的方法规避内容不同步。

实际种子填写导演台的seed，设置及复用读取[种子策略](ComfyUI-H3视频执行规范.md#场次基准种子与实际任务种子)。模板里的三组、时长、id和种子均为填写样例，不限制其他任务的组数。

## 6. 段间引导与重绘

| 设置 | 含义 |
| --- | --- |
| `output.continuityEnabled` | 总开关；关闭时不启用段间运动上下文 |
| `segments[i].continuityFromPrev` | 本组是否引用前一组；同时受总开关约束，首组没有前组 |
| `output.continuityOverlapFrames` | 取前段末尾上下文的范围，可选5、22、39、56帧 |
| `output.continuityMode=guide` | 将前段尾部音视频作为固定上下文前缀，引导后段，生成后处理该前缀 |
| `output.continuityMode=continue` | 将前段尾部写入后段初始音视频潜变量，并用噪声遮罩控制接缝区域的重新采样 |
| `output.continuityRedraw` | continue的上下文重绘幅度；不是整段有多少百分比被重做，guide不由此值控制 |
| `output.continuityKeepTail` | 保留帧格对齐后可用的尾部范围；最终帧数与时长按执行报告、实际文件记录 |

正式默认值读取[H3参数边界](ComfyUI-H3视频执行规范.md#2-参数边界)。首组明确不引用前组；后组按分镜判断是否延续同一状态，正常计划切镜不必自动关闭衔接，明确时间、地点或剧情状态跳变则逐组选择。引导与continue是两种一采衔接方式，不等于外接Refine二采。

开启总开关但本组未引用前组，不会得到该组的尾部衔接；只上传共同参考图也不等于启用了段间引导。上下文长度不是最终视频固定增加的时长，不能靠手工累加它填写交付时长。

### 6.1 局部返修时的前后衔接

开启衔接且本组引用前组时，节点可读取同一导演台前一组的磁盘缓存，即使前组本轮没有重新采样。返修P002时，可用P001的已采用结果引导P002；它不是同时约束P002与P003的双向衔接。已有P003不会因P002重生成而自动更新，新的P002与旧P003是否接得上由用户人工审核，不能根据共用参考图或缓存匹配直接判断。

提交前在既有输入映射中核对前组缓存对应的具体版本及批准依据。节点为恢复衔接可能读取旧缓存，缓存存在不等于它就是当前采用版本；前组没有可用缓存时可能跳过引导，按实际报告记录，不冒称已接续。需要恢复前组缓存或重新生成前组时，按相应授权处理。

命中一采缓存并直接执行二采时，节点保留该一采已有的上下文，不根据刚修改的前组重新建立衔接。前组变化后是否需要重做后组一采，仍依据用户反馈和对应获批来源决定。衔接处理还可能裁去前组尾部并重新写入其缓存或导出MP4；“未选组没有重新采样”不保证其导出文件字节与时长完全不变。取回核对见[运行中取回与收尾](#732-运行中逐段取回与收尾)，返修操作见[返修选择运行](#711-返修选择运行操作)。

## 7. 运行范围、缓存与输出

### 7.1 选择运行与缓存

默认运行本次全部组，关闭选择运行。局部运行明确选中的组与P映射；选择运行只限定本轮处理哪些组，不表示强制重做一采。正式确认模式下，选中组命中一采缓存时进入二采；不匹配时重做该组一采并等待确认。返修选择运行按第7.1.1节操作，衔接边界按第6.1节核对，不用旧预览声称未选组也重新生成了。

| 未选组的情况 | 全部导出时的行为 |
| --- | --- |
| 有可用缓存 | 可将缓存加入合并结果，该组没有重新采样 |
| v2v／rv2v无缓存，但有可用源片段 | 可直接填入源画面，该组没有重新采样 |
| r2v等生成组无缓存，且无可用源片段 | 跳过该组，不加入合并；报告列出skipped／omitted from merge |

因此“全部导出”不保证一定包含原计划的全部组。交付时核对报告中的缓存复用、源片段直通、缺失组以及实际帧数；缺失组需在获授权后执行，不能用空画面或另一段结果补成完整场次。选择运行及合并行为见[执行实现](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/director/executor_core.py)。

### 7.1.1 返修选择运行操作

1. **落实本轮范围**：先按[同场反馈的返修范围与提交](../流程规范/短剧开发流程规范.md#同场反馈的返修范围与提交)确定本轮P清单，再将镜头或时间点对应到组内Shot，按[制作返修的上游归属](../流程规范/逐集内容制作规范.md#制作返修的上游归属)维护剧本、分镜、提示词或素材。修改生成输入时同步既有准备资料、实际任务副本及中文参考版，历史请求不改写。
2. **确认缓存保护与时间线**：提交前执行[制作变更时的缓存保护](#751-制作变更时的缓存保护)。原结构内返修保留完整时间线及各组原始位置与id，仅开启需返修组的选择运行，按第5节同步根时间线、编辑工作区及画布/API的选择状态；未返修组不加入本轮采样范围。拆分、插入、删减或重排采用该节确定的隔离方案，不把新播放顺序直接写入仍需保留缓存的旧导演台。
3. **核对将执行的阶段**：先比较选中组的一采缓存与本次输入。提示词、参考路径等一采输入改变后，该组重新一采；输入不变且缓存匹配时，再次执行会做二采，不会自动“换一次运气”。原输入不变但要求强制重做一采时，先明确实际重生成方案及缓存影响范围，再按授权执行；不把网页节点级清理按钮当作单组清理。缓存判定、ID和清理范围只在[第7.5节](#75-缓存检查与清理接口)维护。
4. **核对输入及扩散影响**：实际seed按[种子策略](ComfyUI-H3视频执行规范.md#场次基准种子与实际任务种子)填写。公共提示词、公共素材和共同参数的变化可能影响多组，不声称只改了本组。替换参考文件内容时使用对应新版本的真实路径，不能覆盖原路径后假定缓存必然失配。被引用前组及返修后组的衔接按[第6.1节](#61-局部返修时的前后衔接)处理；没有新反馈或相应授权，不自动扩大到后续分段。
5. **审核并接续二采**：取回本轮实际返修结果，记录新任务ID、各P的R编号和对旧版本的替代关系；送审安排及整场审批顺序按开发流程执行。二采分别依据当前获批一采的冻结输入；历史获批来源存在不同实际种子或共同参数时，不能用一套全局值宣称全部缓存匹配，按各自获批快照明确执行方案。未匹配组先处理来源问题，不让二采批次意外重新一采。

例如原时间线为七组，本轮范围确定为P001、P002、P005：保留七组原位置与id，同步这三组正文，根时间线及编辑工作区均填写runSelectEnabled=true、runSelection=[0,1,4]。按第6.1节核对实际前组缓存及相邻段影响，不将未选组的旧输出登记为本轮新结果。

### 7.2 采样输入

当前正式一采的model、video_vae、audio_vae、clip及外部SIGMAS按基准接线。外部SIGMAS已连接时，以外部噪声表为准，内部steps／scheduler不替代它；sampler、CFG与Shift仍有作用，不因外部SIGMAS接入而忽略这些控件。节点出厂参数不是项目已批准参数。

### 7.3 输出端口

端口按实际节点类型与接口核对，不仅凭相似的IMAGE类型接线。

| 输出序号 | 端口 | 内容与启用条件 |
| ---: | --- | --- |
| 0 | images | 最终生成画面；连接并执行Refine时为处理后的画面，首次确认等待时可能被阻断 |
| 1 | audio | 按audioMode得到的输出音频，合成时与对应画面匹配 |
| 2 | fps | 实际输出帧率 |
| 3 | frame_count | 实际输出帧数，用于核对时长与输出范围 |
| 4 | source_images | 原时间轴画面，受export_source_images控制；不是一采结果 |
| 5 | report | 分组计划、运行与输出情况，含跳过、复用及异常说明 |
| 6 | images_pre_refine | Refine前的一采画面，用于与二采比较或首次确认 |
| 7 | images_pre_face_refine | 修脸前画面；需连接并启用FaceRefine，同时启用export_pre_face_refine |

source_images解码失败时可能出现灰色占位，同时报告说明失败，不能将其作为生成结果。视频合成使用真实images、audio和fps；实际保存节点及命名读取H3执行规范，不使用预览URL或旧缓存作结果。一个合并视频包含多组时，在既有执行记录保留完整组序与P范围，不冒充每个P的独立输出。端口定义见[导演台节点接口](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/nodes/director.py)。

### 7.3.1 导出方式与逐组文件

`output.exportMode`控制导出范围，不改变逐组采样的方式；选择运行决定哪些组参与本轮生成，两者分别核对。

| exportMode | 行为 | 取回依据 |
| --- | --- | --- |
| all（全部导出） | 合并实际可用的各组画面、音频；未选组可能复用缓存或源画面 | 外接保存节点返回的真实文件及报告中的完整组序；不将合并文件冒充独立P |
| segments（分段导出） | 按组增量保存完整MP4，不在内存拼成整场；外接images/images_pre_refine只携带最后一个实际运行组的完整画面 | 本轮报告中的逐组MP4路径、运行目录及组序映射；外接保存节点只作末段辅助，不代表全部组 |

分段文件写入`output/minimax_seg_export/{本轮运行目录}/`。目录名称由服务端实际执行生成，以本任务报告的值为准，不用本机时间猜测。`seg_0000.mp4`对应时间线第1组，后续按原始组序编号；`_pre.mp4`表示Refine前一采，`_pN.mp4`表示第N轮精修，`_facepre.mp4`表示修脸前。首次确认只一采时，使用报告标识的实际一采文件，不能仅因没有`_pre`后缀就登记成二采。

二采执行时可同时保存最终与一采对照文件；按本轮报告和Refine是否真正执行区分阶段。选择运行时未选组不自动补入分段交付；第6.1节的衔接裁尾可能更新前组导出，须按实际报告区分改写与重新采样。旧缓存、预览缩略图和外接末段视频不能证明全组完成。插件内部MP4编码失败可能不使生成任务失败，必须核对报告中的成功路径与缺失项。路径只出现在报告而没有对应history媒体条目时，核对其属于本轮output目录后按真实相对subfolder/filename/type取回；路径缺失或归属不明时先报告，不猜文件名。磁盘分段缓存目录不是正式导出目录。

接口实现见[逐组MP4保存](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/director/segment_mp4_export.py)和[输出范围处理](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/director/executor_core.py)。

### 7.3.2 运行中逐段取回与收尾

默认分段导出时，导演台逐组生成并保存MP4，可在整轮任务仍运行时取回已经保存的分段，不必等最后一组。适用范围仅限原生分段MP4；全部导出的合并文件及其他保存节点仍等任务成功返回实际输出。取回方式继续使用[固定工具](../comfyui-scripts/README.md)的status／download，不新增提交或下一阶段执行。

1. **确认本轮身份**：沿用既有执行记录，绑定服务地址、prompt_id、导演台节点ID、原始组序与P、处理阶段，以及服务端实际运行目录。查询history／queue仍按监控模板执行；history为空但任务正在运行，不等于没有已经保存的分段。
2. **确认完整文件已保存**：仅依据本轮真实的逐组MP4保存成功事件及路径，不能以采样结束、实时预览、进度条或缓存存在代替。可在服务端提供时有限只读查询`/internal/logs/raw`，核对`segment mp4 run dir`与`segment #... mp4 saved`事件；该补充入口不替代status，也不是通用的逐段文件清单接口。日志没有prompt_id时，结合本轮执行时间、当前导演台及运行目录确认归属；混有其他任务且无法对应时等待终态报告，不按最新目录或猜测文件名取回。保存失败或临时文件不计入可取回结果。
3. **取回并展示已知分段**：按[取回路径与下载参数](#733-取回路径与下载参数)获取真实output相对subfolder、filename和type，再调用download。下载成功先落执行附件，再立即按[运行中分段文件留存](../流程规范/逐集目录与资产管理规范.md#运行中分段文件留存)移入候选，填写本段取回核对状态及文件对应关系，使网页可读取，不等整轮完成。任务状态按[共同证据与状态规则](../流程规范/逐集目录与资产管理规范.md#多组任务的共同证据与状态)维护，未确认项记未知，不将部分结果写成全场完成。保存必要的首次取回依据，普通无变化轮询不新增JSON。
4. **识别后续改写**：第6.1节的衔接处理可能在后组运行时改写前组文件；提前保存成功只证明当时该版本已生成，不证明它就是终态版本。版本留存与批准关系读取上述目录规范，下一阶段条件读取[开发流程第二部分第7节](../流程规范/短剧开发流程规范.md#7-生成视频验收与衔接修改)。
5. **结束后核对最终输出**：任务结束时按403报告及真实逐组文件确认本轮运行目录、组序、阶段、缺失项及衔接改写情况；将最终文件身份与提前取回依据对照，记录未变、已改写或仍不能确认。依据核对结论执行上述目录规范的文件复用、终态取回与送审规则。取回失败独立记作交付问题，不把它改写为生成失败。
6. **区分局部成果与整轮状态**：后段失败或任务被终止，不抹去前面已经明确保存、取回的分段，但也不将整轮登记成功。核对已知输出和问题后报告，按现有监控规则收尾；没有逐组保存证据时仍等终态，不能承诺所有任务都能提前取回。

保存与后续裁尾实现见[逐组MP4保存](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/director/segment_mp4_export.py)及[执行与衔接处理](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/director/executor_core.py)。本节不授权增加Agent视频初审、自动返修或改动已提交请求。

### 7.3.3 取回路径与下载参数

取回涉及两条不同路径：执行端已保存的MP4是远端来源，本机保存位置是下载目标。导演台磁盘缓存中的潜变量不作为视频取回来源。

- **任务仍在运行**：按第7.3.2节获取并绑定本轮真实保存事件、运行目录与逐组MP4路径。status不会自动从导演台运行日志生成完整的逐组文件清单；没有可对应的保存路径时等待终态报告，不用计划文件名代替实际输出。
- **任务已经结束**：读取本任务终态history中403报告展示节点返回的实际逐组MP4路径，并核对阶段和P映射。403是当前基准的报告展示节点，不是视频保存节点；任务副本使用其他report展示节点时按实际连线核对。报告缺失且无可绑定的逐组保存依据时说明缺口，不能以末段预览代替逐组输出。若history已有媒体文件字段，使用该输出真实的filename／subfolder／type。
- **绝对路径转换**：先核对执行端真实output根目录，将实际MP4路径换算为该根目录内的相对路径。最后一个路径组件作为filename，其父目录作为subfolder，type为output；子目录分隔符可统一成`/`。无法确认output根目录或路径不属于它时，不猜测换算。服务地址仍用该任务实际提交端，不使用本机地址或当前项目配置覆盖。

下面仅示范路径拆分。假设已核对远端output根目录为`D:\ComfyUI\output`，实际报告返回：

```text
D:\ComfyUI\output\minimax_seg_export\20261005_120000\seg_0000_pre.mp4
```

| download参数 | 从该示例得到的值 |
| --- | --- |
| `--filename` | `seg_0000_pre.mp4` |
| `--subfolder` | `minimax_seg_export/20261005_120000` |
| `--type` | `output` |
| `--url` | 该任务实际提交的ComfyUI服务地址 |
| `--output` | [运行中分段文件留存](../流程规范/逐集目录与资产管理规范.md#运行中分段文件留存)或正式候选规则规定的本机绝对文件路径 |

调用方式读取[固定工具download说明](../comfyui-scripts/README.md#download明确指定文件)。不要将远端盘符路径传入subfolder，不将`output/`再次加在subfolder前，也不把远端缓存目录、浏览器预览URL或本机保存路径当作来源。记录实际远端与本地文件对应关系；例子的盘符、目录名和时间均不是固定配置。

### 7.4 可选扩展与激活条件

扩展的正式启用状态读取H3执行规范；接口存在不等于启用。新增连接须有对应方案和执行授权，控件名称出现refine不代表已接入二采。

| 扩展 | 实际作用与条件 |
| --- | --- |
| Refine：refine | 连接refine后进行同尺寸精修采样；passes可重复精修 |
| Refine：upscale | 放大到目标画布后再采样；放大方式与二采噪声表须明确，passes不代表每轮重复放大 |
| Refine：latent_upscale | 放大H3潜变量，不进行第二次采样；不能登记成二采 |
| Refine：confirm_first_pass | 首次Queue输出images_pre_refine，并阻断主images下游；再次Queue命中对应一采缓存后继续二采。再次执行仍需授权，缓存不匹配时不声称已沿用一采 |
| SelfLift | 接入selflift，使一采采用低清前缀、潜变量提升、高清收尾；使用Euler，仍是一采扩展 |
| FaceRefine | 接入face_refine后进行局部修脸采样并合回；修脸前输出还受独立开关控制 |
| Semantic Bridge | 接入semantic_bridge改写条件token；蒸馏目标为FL2VA，r2v／v2v／rv2v是强制兼容，不视为已验证质量提升，不串联两座桥 |

Refine的skip_fl2v可使首尾帧组跳过二采；采用混合模式或fl2v时检查实际设置与报告，不能仅凭连了Refine就声称每组都完成二采。扩展接入不自动改变工作流正式状态；二采倍率、模型、参数及与现行一采的衔接继续按H3执行规范确认。

### 7.5 缓存检查与清理接口

Refine面板的“清理缓存”按钮找到其相连的导演台，向`POST /minimax/director/clear_segment_cache`发送JSON：`{"node_id":"实际导演台ID","kind":"all"}`。传导演台ID，不传Refine节点ID；任务副本以真实连线为准。按钮不属于采样控件，API图中没有对应布尔开关。

一采缓存逐组比较已有元数据与当前一采输入：组序与帧范围、实际拼接提示词、参考素材路径及标签、尺寸与帧率、参考图策略、段间衔接设置、种子、CFG、采样器、Shift、噪声表，以及已接入的SelfLift和Semantic Bridge参数。须同时存在该组的一采元数据与音视频潜变量文件；同一个种子或单独保留MP4不够。Refine的二采参数不属于一采指纹，可在保持一采来源不变时调整已授权的二采方案。

导演台节点ID是画布节点的id，并作为ComfyUI的隐藏UNIQUE_ID传入节点；不是每次提交产生的prompt_id，也不是画布文件名或工作流UUID。网页新建节点时由ComfyUI分配编号，离线制作画布时由制作者指定并同步API键及连接。保存、重新打开或复制整个画布文件保留其中编号；另建或复制粘贴节点通常重新分配。编号只要求在当前画布中唯一，不保证不同画布之间唯一。

制作新批次任务副本时，为导演台分配与该远端仍需保留缓存的其他批次不同的编号，依据既有任务记录及目标端缓存核对，不直接重复套用基准编号。同步画布节点id、API键和所有关联连接，并在既有输入映射中记录实际服务地址、导演台节点ID及组与P映射，不新增编号台账。同一来源接续一采、原结构内返修或二采时保留该编号及原始组位置；制作变更需要保护旧来源时按[缓存保护](#751-制作变更时的缓存保护)确定隔离方案。每轮prompt_id分别记录，不能仅据新任务ID另换导演台编号，也不能换执行端后默认原缓存已迁移。

缓存位于执行端output/minimax_seg_cache/{node_id}/，本地画布不携带这些潜变量文件。每个节点编号与组位置只有对应缓存槽，重新生成会替换该槽旧缓存；删减时间线会清理已不存在组位置的缓存。改名或另存画布不隔离缓存；正常重启并保留同一输出目录时可继续使用磁盘缓存，不等于内存缓存仍在。独立导出MP4、实际任务画布与输入映射按项目目录规则留存，缓存不作为永久版本库。

缓存先按服务端和导演台节点ID定位，再按组匹配；删除下游辅助保存节点不改变一采来源，改导演台ID则会切换缓存目录。Refine面板“重新检查”通过上述只读接口返回cached_count、matched_count、diff_keys与can_confirm_refine。外接SIGMAS的网页检查不重算实际张量，执行时仍会比较实际噪声表；不能仅靠面板绿字证明整个模型链相同。模型、编码器及LoRA权重未完整纳入这套指纹，变更这些生成条件时仍核对一采来源，不直接据匹配结果复用。真正跳过一采以执行报告中的“命中一采缓存，跳过一采，开始二采”为准；未匹配组不能登记为二采完成。

| kind | 删除范围 |
| --- | --- |
| first_pass | 该导演台节点的`seg_XXXX.pre.*`一采缓存 |
| final | 除`.pre.*`之外的成片及音频等缓存 |
| all | 该节点全部一采与成片缓存；网页按钮使用此值 |

目标为服务端`output/minimax_seg_cache/{node_id}/`，不是释放显存，不清理全部ComfyUI缓存，也不删除外接保存视频或`minimax_seg_export`中的独立导出文件。不同画布使用相同导演台ID时共享该缓存范围，不能按网页标题推断只影响当前场次。

Agent可以在用户明确要求并确定服务端、导演台ID及删除范围后调用该补充接口，检查响应中的removed与kind并如实记录；仅询问用途、监控任务或批准二采不构成删除授权。不为验证接口试删，不在仍需一采缓存的两轮之间自动清理。清一采或全部缓存后，确认二采无法沿用已删除的一采；重新生成仍须相应授权。与清理接口分开的`POST /minimax/director/first_pass_cache_status`用于只读比较现有缓存和当前输入，不将查询成功或缓存存在当作用户批准。

接口说明见[缓存请求处理](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/director/http_routes.py)和[缓存清理实现](https://github.com/AIMixer/ComfyUI_MiniMaxH3_Director/blob/main/director/segment_cache.py)。

### 7.5.1 制作变更时的缓存保护

一采已产生后，拆分、插入、删减、重排、修改段长或返修输入，均先判断是否会覆盖仍需使用的缓存。保护范围包括待审核的一采、已批准且仍需二采的一采，以及后续衔接仍要读取的具体版本；不能等整场定稿或导出导演包时才保护。二采完成不自动授权清理来源缓存，清理仍按第7.5节处理。

按实际服务及导演台ID查找既有任务记录中仍需保留的来源，不只查看当前画布或当前P。在既有工作稿及输入映射中说明受影响P、来源R、实际服务、导演台ID、原始组位置与帧范围、后续用途及保护方案。区分项目播放顺序与来源任务的执行组序；P编号未变、未选中或MP4已留存，均不能代替缓存保护。除选中组覆盖外，还须考虑时间线删减及前后衔接改写，不只检查本轮runSelection。

- **原结构内返修**：沿用原服务、导演台ID及完整原组序，先确认被替换的缓存不再需要保留。若旧版本仍待比较、仍是获批二采来源或衔接来源，新返修使用隔离副本，不能以返修授权默认为可牺牲旧来源。
- **拆分或改变时间线结构**：只要原导演台还有需保护的缓存，新结构使用同一服务上另一个已核对未占用的导演台ID，保留旧导演台及原完整配置供旧来源接续。同步新副本的画布/API节点与连接、完整新组序及P映射，选择本轮获授权的新增／返修组；未变化段的二采仍从各自获批来源快照和原缓存接续，不因统一播放顺序而全部重生成。
- **隔离后的阶段与衔接**：新ID不会自动取得旧ID的潜变量。提交前只读检查目标缓存，明确本轮将执行一采还是二采。需要前组引导时按第6.1节解决来源；没有可用前组缓存，不把旧MP4冒充潜变量，也不擅自关闭衔接、改成独立起点或重生成前组。保护方案无法满足已确认内容时，说明具体缺项、受影响段及额外生成成本，取得处理方向后再提交该范围。
- **二采接续**：按每段获批一采的原服务、导演台ID、完整组序、输入和实际模型链准备；分别核对选中缓存，不能为与新时间线一致而改组位置或改ID。匹配失效时先保留现有文件与证据并处理来源问题，不把二采授权当作重新一采授权。审批顺序仍按[开发流程第7节](../流程规范/短剧开发流程规范.md#7-生成视频验收与衔接修改)，不为抢救缓存提前执行尚未满足审批条件的下一阶段。

默认保护方式是保留原缓存目录并隔离后续写入，不宣称已完成潜变量备份或迁移。当前固定通信工具没有潜变量备份／恢复命令；MP4、导演包及画布均不能代替潜变量。确需另行备份或迁移时，先核实执行端实际能力、元数据及音视频潜变量的完整范围、对应输入和恢复验证方式，按相应授权处理；未经验证的复制或改目录名不能作为可恢复依据。不在任务仍写入时复制、替换或清理该缓存，也不为保护缓存中断活动任务。

提交前确认保护方案已落实，涉及的旧来源仍可按其快照只读核对；本轮结束后复核仍需接续的受影响来源，记录实际保留、失配或缺失。已有来源确实损失时如实报告，不假称能够从导演包恢复，不自动追加生成。规则维护不改写已经接受的任务或历史输入。

## 8. 导演包导入导出

需要将已准备任务导出为导演包，或在网页导入、测试导演包时，读取[导演包制作规范](ComfyUI-MiniMaxH3导演包制作规范.md)。按其中要求准备来源与素材、核对包内容、保存附件及交付匹配画布；包结构、制作方法和导入检查由该规范统一维护。

## 9. 填写完成检查

1. 核对任务模式、原生组输入和公共参数开关；明确组与P映射。
2. 按第2节计算各模态的公共与本组绝对index，逐组核对真实文件、最终标签和合并后容量。
3. 核对公共正文与各组正文拼接后，和对应获批英文正文及中文参考版一致，并完成[模型提示词长度检查](../流程规范/逐集内容制作规范.md#模型提示词长度)。
4. 同步时长、帧数、根时间线、r2v工作区持久化内容和画布/API控件；检查选择运行、继承前组及实际音频来源。
5. 按H3执行规范核对固定参数、实际种子、输出范围和本次授权，再交付画布或提交任务。填写检查不自动触发生成。
