# ComfyUI-图片超分执行规范

版本：v1.0；更新日期：2026-10-01。

用于人物正面半身图及复用该流程的男女画风样例：先生成1024×1024审批图，用户批准具体版本后，以该图执行一次2倍超分，取得2048×2048 PNG。超分是获批图的后处理，不重新生成提示词，不调用Qwen采样，不裁切、拉伸或换图；人物和角色六视图等其他类型不自动套用。

## 1. 触发与输入

- 先在原生成／审阅记录确认用户已批准的1024×1024具体版本，核对实际文件、来源和可解码性。用户批准即接续本规范的超分，无需再问一次执行许可；尚未批准、仅部分认可或未明确版本时不提交。
- 输入必须是被批准的审批原图；不使用另一张同人物图或中间预览。沿用已有上传响应或通过固定工具上传，使用真实返回路径。原1024图与其请求、批准记录完整保留。
- 历史已批准的其他尺寸资产保留，不批量补超分、不因规格变化撤销批准。明确技术测试可以使用指定测试输入，测试结果不登记为正式人物资产。
- 读取项目`comfyui-config.json`中的服务地址；按[库存技能](../../dependencies/comfyui-inventory/SKILL.md)核对节点与参数。没有可用节点或出现执行异常时报告，不安装依赖、不切换放大器、不自动重提。

## 2. 配套工作流与参数

本地[画布基准](../comfyui-workflow/Nora-RTX-图片2倍超分.workflow.json)和[API基准](../comfyui-workflow/Nora-RTX-图片2倍超分.api.json)配套维护。每次复制API任务副本，替换输入路径及输出前缀，不改写基准或远端保存的工作流。

| 节点 | 类名与输入 | 固定要求 |
| --- | --- | --- |
| 2 | `LoadImage.inputs.image` | 被批准的1024×1024原图的真实上传路径 |
| 1 | `RTXVideoSuperResolution.inputs.images` | `["2", 0]` |
| 1 | `resize_type` | `scale by multiplier` |
| 1 | `resize_type.scale` | `2`，动态参数完整键名不可改为`scale` |
| 1 | `quality` | `ULTRA` |
| 3 | `SaveImage.inputs.images` | `["1", 0]` |
| 3 | `filename_prefix` | 本任务唯一可辨认的超分前缀 |

正式输出节点为3，PNG数量1，2048×2048、1:1。画布中的ImageCompare只用于人工操作时对照，不属于API正式输出或自动看图环节。没有提示词、种子、CFG或采样步数，记录为不适用，不伪造扩散模型参数。

## 3. 执行与恢复

使用[固定通信工具](../comfyui-scripts/README.md)的upload、submit、status、download；不另写通信客户端或一键重试循环。以下命令中的工具路径、服务地址、文件和编号须替换为实际值：

```sh
python3 /实际技能目录/references/comfyui-scripts/comfyui_client.py upload --url 'http://实际服务:8188' --file '/实际目录/获批审批图.png' --subfolder '本任务输入目录' --result '/实际附件目录/生成前缀-超分-001-上传响应.json'
```

从本地API基准复制任务副本，把上传响应的`data.input_path`写入节点2的`image`，把本任务前缀写入节点3的`filename_prefix`，保存为`生成前缀-超分-001-工作流.json`，核对第2节参数及连线后提交一次：

```sh
python3 /实际技能目录/references/comfyui-scripts/comfyui_client.py submit --url 'http://实际服务:8188' --workflow '/实际附件目录/生成前缀-超分-001-工作流.json' --record-dir '/实际附件目录' --attempt-name '生成前缀-超分-001-提交尝试.json' --request-name '生成前缀-超分-001-请求.json' --response-name '生成前缀-超分-001-提交响应.json' --result '/实际附件目录/生成前缀-超分-001-提交摘要.json'
python3 /实际技能目录/references/comfyui-scripts/comfyui_client.py status --url 'http://实际服务:8188' --timeout 25 --prompt-id '真实ID' --result '/实际附件目录/生成前缀-超分-001-执行结果-001.json'
```

查询新快照递增末尾序号。按照[图片监控规则](../模板/ComfyUI-任务监控提示词模板.md)动态计数：1—5项会话5秒轮询，超过5项5分钟定时；切换前按规则暂停同批定时器。用户审批期间不查询已终态生图任务；超分提交后只查询自己的真实ID。成功必须同时具备completed=true、status_str=success和节点3的一张正式PNG输出。

```sh
python3 /实际技能目录/references/comfyui-scripts/comfyui_client.py download --url 'http://实际服务:8188' --filename '节点3实际文件名.png' --subfolder '实际子目录' --type output --output '/实际过程稿目录/原候选名去扩展名-超分-001.png' --result '/实际附件目录/生成前缀-超分-001-下载响应.json'
```

已有提交证据或文件时核对并复用，不覆盖或换编号绕过防重。接口故障、执行失败、下载失败、规格不符时保留原批准事实，记“已批准，超分异常，未正式保存”，处理原任务并报告；没有新授权不重新POST。下载失败不重跑超分。停止查询不等于超分完成。

## 4. 文件核对、保存与记录

核对实际2048×2048、PNG、数量1、可解码性及来源：工作流确为批准的1024图→节点1两倍→节点3，核对真实请求、history、上传及下载响应。默认不调用看图能力，不宣称细节或身份的视觉保真已经验证。需要视觉分析时按[看图边界](../../SKILL.md#看图能力调用边界)取得明确授权。

超分不增加第二轮默认画面审批。文件与记录核对通过后，将2048结果作为已批准版本的正式交付文件并展示；批准依据仍指向原1024审批图，记录“批准后2倍超分”，不能伪称用户另行审核了超分细节。若用户要求再审超分结果则先送审。超分尚未完成时不将1024图冒充2048正式图，不替换旧正式文件，不开始依赖该正式肖像的六视图制作。

人物资产沿用[人物生成／审阅模板](../素材规范/人物参考图初审与记录规范.md)：原生成条目保留1024输出、参数及用户批准，在同条目补充超分子记录。子记录依次编号`超分-001`等，实际超分提交次数与原生图次数分开，不重置历史、不为后处理另算一次Qwen生成。机器附件沿用原生成前缀，例如`CH编号-生成记录-NNN-超分-001-*`，候选超分文件为`{原候选名去扩展名}-超分-001.png`，仍在规定的`其他资料/过程稿/`。当前正式表登记2048文件，采用版本写原候选版本及超分编号，审阅入口指向原批准记录；正式文件名和层级不变。按[采用后收尾](../流程规范/短剧开发流程规范.md#852-图片采用替换与归档后的状态收尾)同步引用及浏览页。

画风样例执行相同批准后超分流程，但文件与子记录仍留在`00-项目定位/其他资料/`对应分类；由定位链接2048样例和1024批准依据，不登记为项目人物，不更换固定模特描述或画风正文。

## 5. 维护验证

修改配套工作流或节点映射时，在技能目录执行离线配对校验及回归：

```sh
python3 scripts/workflow_baselines.py
python3 -B -m unittest discover -s scripts -p 'test_workflow_baselines.py' -v
```

校验应包含本图片超分配对，执行节点为2、1、3；静态通过不证明服务端执行成功。实际验证须使用明确的技术测试输入，保存请求、结果和真实尺寸，不修改业务批准或自动替换项目资产。
