# 故事大纲模板

使用前读取[短剧开发流程规范](../流程规范/短剧开发流程规范.md)的第一部分第4节及适用的共用规则；命名、保存位置、填写要求与审批以该规范为准。本文件只维护可填正文，不替代规范。

保持六章名称、顺序及第六章的三个固定小节。下方围栏内是产出正文，填写时使用产出标题，不将本模板文件名作为项目产出名。

头部执行[正式内容文档的共用头部](../流程规范/短剧开发流程规范.md#正式内容文档的共用头部)，文档状态按对应流程填写；正文的固定章节与业务编号保持。

```markdown
# 故事大纲

- 项目名称或代号：{{当前项目实际名称或代号}}
- 文档版本：{{当前文档版本号}}
- 更新日期：{{YYYY-MM-DD}}
- 确认状态：{{按对应流程填写当前文档的实际状态}}
- 确认范围：{{当前文档已确认内容及待决边界；尚未确认时如实填写}}
- 确认依据：{{实际审阅或决定记录的简短链接；未确认写“尚未确认”}}

## 1. 全剧故事主线

连贯讲清从开端到结局的完整故事，突出事件之间的因果关系，而不是宣传式简介。
将上一阶段的结局方向展开为具体的结局事件与人物结果。

## 2. 故事阶段与重大转折

按剧情自然划分阶段，分别说明阶段目标、冲突、关键事件、重大转折和结束状态。
不强制固定幕数，不提前逐集拆解。

## 3. 主要人物作用与变化

明确主要人物承担的剧情作用、关键选择及前后变化，不提前填写完整人物资料卡。

## 4. 重要人物关系发展

说明关系如何建立、变化或破裂，以及推动这些变化的具体事件，不只列静态关系。

## 5. 关键秘密与伏笔安排

明确关键秘密的真相、铺垫，以及揭示或回收的大致剧情位置。
尚未分集时不强行指定集号；没有相关内容时据实说明，不为填充章节强造秘密。

## 6. 补充说明

### 6.1 剧情说明

集中说明理解全局故事所需的跨章节边界、原稿对应和关联资料；属于前五章的剧情直接写回对应章节，不在这里重复全文。

### 6.2 核对与采用

简要写明当前核对结论、已采用范围和依据链接；完整核对过程、历次修改和旧决定保存在工作稿或历史版本。

### 6.3 待落实事项

只列当前仍需确认或在后续阶段落实的事项，注明对应阶段或资料入口；已解决的更新为当前结论，过程保留在工作稿。没有待落实事项时写“无”。
```
