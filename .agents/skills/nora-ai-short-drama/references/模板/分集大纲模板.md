# 分集大纲模板

使用前读取[短剧开发流程规范](../流程规范/短剧开发流程规范.md)的第一部分第7节及适用的共用规则；命名、保存位置、填写要求与审批以该规范为准。本文件只维护可填正文，不替代规范。

保持七个业务章节及固定字段；最终集按既有规则收束。 下方围栏内是产出正文，填写时使用产出标题，不将本模板文件名作为项目产出名。

头部执行[正式内容文档的共用头部](../共用规则/文件版本与工作稿规范.md#正式内容文档的共用头部)，文档状态按[分集大纲填写规则](../../../short-drama-develop/references/分集大纲规范.md#单集分集大纲填写规则)选择；正文的固定章节与业务编号保持。

## 章节职责

填写与补充统一执行[固定结构与补充写法](../共用规则/文件版本与工作稿规范.md#固定结构与补充写法)。下表说明固定正文各部分的分工，填写时不复制本表。

| 章节或区域 | 内容与写法 |
| --- | --- |
| 1. 本集定位 | 写本集在全剧中的任务和主要推进。 |
| 2. 前文承接与开场 | 从前集结束状态接到本集开场，首集写开篇依据。 |
| 3. 本集剧情概要 | 按因果顺序写本集主要事件，不提前写逐镜头脚本。 |
| 4. 涉及人物、场景与关键道具 | 列实际涉及的角色、场景和关键道具及其用途。 |
| 5. 伏笔与信息变化 | 区分新铺设、推进、揭示或回收的信息。 |
| 6. 本集结束状态 | 写剧情结束时人物、关系、已知信息和物品等实际状态。 |
| 7. 结尾吸引点或全剧收束 | 非最终集写继续观看的吸引点，最终集写全剧收束；不在此追加编制信息。 |
| 其他补充（按需启用） | 固定放在上述正文之后；只写已有章节无法容纳的事项，采用下方三项条目，不记录修改流水。 |

```markdown
# EP编号｜分集大纲

- 项目名称或代号：{{当前项目实际名称或代号}}
- 文档版本：{{当前文档版本号}}
- 更新日期：{{YYYY-MM-DD}}
- 确认状态：{{从分集大纲填写规则中选择一个简短状态}}
- 确认范围：{{当前文档已确认内容及待决边界；尚未确认时如实填写}}
- 确认依据：{{实际审阅或决定记录的简短链接；未确认写“尚未确认”}}

## 1. 本集定位

- 集号：
- 所属故事阶段：
- 一句话概要：
- 本集在全剧中的作用：

## 2. 前文承接与开场

- 承接的前文事件或状态：
- 开场发生的事情：

第一集填写故事的初始处境与开篇事件，不虚构前集内容。

## 3. 本集剧情概要

按实际叙事顺序，连贯描述本集主要事件、冲突、
人物选择、转折及结果，体现事件之间的因果关系。

不展开完整故事剧本、对白、镜号或视频生成分段。

## 4. 涉及人物、场景与关键道具

- 主要人物：编号、姓名及必要状态
- 主要场景：名称及适用状态；已有 SC 编号时引用，未进入逐集制作的地点不要求提前编号建卡
- 关键道具：编号、名称及必要的持有、使用或外观状态

引用已有资料卡，不复制完整设定。
确需新增而尚未建立资料的内容，明确标注待补充。

## 5. 伏笔与信息变化

- 本集新铺设的伏笔：
- 本集推进或回收的伏笔：
- 人物与观众获知的关键信息：

按实际剧情填写；没有相关内容时填“无”。

## 6. 本集结束状态

- 人物目标或处境的变化：
- 重要人物关系的变化：
- 影响后续承接的场景、道具或信息状态：
- 尚未解决、需要后续承接的问题：

只记录影响后续剧情的变化，不重复整集概要。

## 7. 结尾吸引点或全剧收束

- 结尾呈现的事件或信息：
- 对观众形成的期待：

最终集改为说明主要矛盾、人物结果及主题如何收束，
不强行制造下一集钩子。

## 其他补充

无。确有未被以上章节覆盖的事项时，按以下三项逐条填写；填写后删除本提示。

- 事项：<简短名称>
- 内容与适用范围：<当前需要补充的事实、说明及所指对象>
- 依据与当前状态：<实际来源入口；已确定／待确认／待落实，以及尚需处理的内容>

```
