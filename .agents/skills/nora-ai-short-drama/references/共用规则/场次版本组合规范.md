# 场次版本组合规范

<a id="版本组合规范"></a>

<a id="场次修改轮次"></a>
### 修改轮次

修改轮次表示一次集中修改形成的完整单集版本组合，按项目／EP分别计数；同一集所有场次、分段共用编号。一批可只修改部分场次，每场也可只修改部分P，未改内容明确沿用基轮。一批只登记一轮，可分多个任务执行；保存、上传、故障重试、结果到达、采用及切换预览不新增轮次。界面继续显示“第N轮”。

旧记录保留原编号、归属、文档副本、请求及人工决定，日常登记不迁移、不补造整集历史。用户明确授权拆分片头片尾方案时，按[多套独立方案与场次](../流程规范/逐集目录与资产管理规范.md#多套独立方案与场次)保留原始证据、记录身份映射，并新增迁移后的完整组合；不将其追记成历史生成轮次。首次单集登记接该集已有最大修改轮次加一；完全无记录才从1开始。首次基线取各场最新已登记的完整组合，不能按各P最大R、文件修改时间或执行缓存拼接。旧场次JSON只读追溯，不再追加新修改。

一采、二采和后处理共用本集轮次序列。共同剧本、各场分镜保留各自文档版本；各EP／C／P／阶段的R独立计数，不为对齐轮次或阶段重做。允许同轮混合阶段及R。批准一采本身不增轮，含二采或后处理的新组合另行登记；文稿确认、轮次登记、生成授权和视频采用分别记录。

本批方案确定、送审或准备执行时，按[模板](../模板/场次修改轮次模板.md)调用[登记工具](../comfyui-scripts/README.md#场次修改轮次登记)，一次提交所有改动场次。唯一新组合文件为本集`其他资料/工作稿/EP编号-修改轮次.json`。每轮保存共同剧本、有序完整场次映射、各场分镜引用、完整P顺序、计划时长和阶段／R。全部场次须覆盖该版剧本，按其顺序排列；新增场次须给完整方案，删去的场次仍在旧轮次中保留。工具留存准确文档副本，未变内容复用，不引用会继续编辑的当前文件。

局部修改指定`base_round`，`scenes`中只列改动场次，其余沿用基轮。场内局部修改使用完整`segment_changes`条目，只替换对应P，未改P的阶段／R及计划时长保持。首次从旧记录局部接入，在该场条目填写原场次`base_round`。新增、删除、重排或重新划分P须给该场完整`segments`，不让局部替换推算关系。多场同批不得分开登记成多轮；并行登记同一集以独占锁阻止重复编号，失败后核对已登记结果再重试，不覆盖他人批次。

播放组合与导演台执行时间线分别维护。轮次文件决定各场播放顺序、阶段／R和计划时长；执行映射`segments`对应API原组位置，`selected_indices`只限定该任务执行、冻结和回写范围。未选中组可因缓存或接续保留旧参数，不表示播放采用，不据此改写组合或其他分段。

新视频任务必须引用已登记的单集轮次。输入映射保留兼容字段名`scene_modification_round`，值为本批共同编号，`scene`仍是该任务实际EP／C。准备检查从该轮取对应场次，核对共同剧本、该场分镜、实际选中P的阶段／R及计划时长，不要求未选中缓存组相同。已登记旧任务恢复继续读取原场次轮次，不改原请求、准备凭据或归属；旧场次轮次不能用于新任务准备。

生成与成片时长分别记录：组合`duration`为播放时长，映射`duration_seconds`为模型请求；不同时显式填写`playback_duration_seconds`，并在生成说明写明采用区间与余量用途。分别核对成片与组合、请求与API，请求不得短于成片；未填新字段的既有同长任务保持原检查。

已登记轮次不因编辑或回片改变版本指向。提示词、素材、配置、媒体与人工决定继续按原EP／C／P／阶段／R读取；同一R可供多轮引用，不复制或回写旧资料。新增其他轮次不改变旧任务已引用的组合。视频未生成、失败或未取回时保留该轮身份及可用资料，明确缺项，不跳过或顶替。旧批准只适用于原对象及范围。

网页选择、历史版本联动与连播执行[轮次展示](../流程规范/项目浏览入口规范.md#场次修改轮次展示)。登记不提交任务、不表示采用，也不授予生成或处理权限。
