# ComfyUI-任务监控规范

版本：v1.11；确认日期：2026-10-10。

本规范维护后台监控、完成后取回、异常接续、消息通知和技术留档。入队、自动调度及按钮语义的唯一规则入口为[服务配置与任务提交规范](ComfyUI-服务配置与任务提交规范.md)。Agent负责准备、收到结果后的业务收尾和人工审核接续。

## 1. 监控方式与间隔

统一入口先登记本地任务，再由浏览服务后台上传、提交和监控。普通生成不使用Agent会话轮询、heartbeat或legacy直提交。服务未启动或缺少真实Codex上下文时报告具体缺项并修复接入，不静默切换模式。

后台为每个配置地址维持常驻只读WS。连接及重连后先读取queue，收到队列变化时立即刷新，并每30秒补查。已接受任务按原服务地址、原prompt ID核对history／queue；WS提供执行开始、当前节点、采样步数及完成／失败事件。任务监听断线后每5秒重连，心跳每20秒、回应超时20秒；节点观察连接按立即、1、2、5、10、30秒退避，之后每30秒继续，不限次数。断线不等于生成失败。

### 1.1 待提交跟进方式与间隔

本地等待由后台调度。Agent入队成功后保存本地任务ID，不留在会话中等空位，不另设定时任务。查询用户主动关心的进度时，使用browser_tasks.py status读取最新后台状态和实际更新时间。

## 2. 留档与收尾

### 执行附件精简留档

沿用本次既定执行附件，不另造任务目录。后台写入提交尝试、完整实际请求、上传／提交／下载响应、终态执行结果，以及后台任务状态.json、后台过程记录.json。过程记录按阶段追加时间、结果、原因、尝试次数及相关证据和文件位置；普通每步采样不落一份JSON。任务摘要随状态更新。SQLite保存任务、完整入队资料、顺序、暂停状态、阶段事件和通知批次；project内JSON方便Agent复查，不能据手工改JSON更改调度状态。

保留失败前的成功上传和成功下载，重试引用原凭据；记录取回失败与生成失败的区别。后台不改写人工决定、提示词、审批、项目工作稿或候选采用状态；Agent依据技术记录维护这些业务事实。请求、原始响应和旧文件不得覆盖或删除以绕过防重复。

### 2.1 定时器命名状态与提示词

新后台任务不创建Agent监控定时器。现有旧定时器和历史资料不因本次维护批量修改；获授权接续时先核对任务是否已交给后台，避免并行监控和重复提交。结果处理正文使用[任务监控提示词模板](../模板/ComfyUI-任务监控提示词模板.md)。

## 3. 跟进与通知

后台只在成果全部保存、明确失败或需要处理的问题出现时唤醒来源会话。预检查导致暂停、提交被拒绝、提交结果不明、远端ID丢失和取回失败均带具体失败阶段。排队、普通采样、取回中和暂时断线只更新网页；网页手动暂停、恢复、排序或取消不额外唤醒。

### 3.1 异常检查与连接恢复

- 提交前发现素材缺失、绑定不匹配或冻结资料冲突：暂停，写明原因并通知，其他独立任务继续。
- 请求发出后结果不明：进入历史“提交结果待核对”，保存原请求，不自动重发。
- 明确生成失败：历史“生成失败”，保留远端错误节点、类型、错误正文和终态证据，不下载预览冒充成果。
- 生成成功但下载失败或缺少预期输出：历史“取回失败”，保留已保存文件；Agent使用原本地ID请求retry-collection，只重试取回，不重新生成。
- 重连成功后由后台先查queue，再按已接受的原ID查history。仍在队列就继续监控；明确终态就恢复收尾；两次查询均无原任务时进入历史“状态待核对”，不自动重发。主节点已确认空闲时其他独立任务继续。
- 后台重启恢复本地顺序与暂停状态；准备中但尚未POST的任务重新准备。提交中先读取原提交响应；取得原ID继续监控，没有明确接受结果时标为待核对。取回中使用已经保存的终态结果继续下载。

### 3.2 汇报规范

通知包含通知批次ID、本地任务ID、项目与标题、远端ID、当前结果、失败阶段和原因、已保存成果与缺项、记录入口及下一步。Agent先调用browser_tasks.py ack确认收到，再读取记录处理业务收尾；保存成果不等于用户批准。

同一来源会话的多条未发送通知合为一条，逐项列结果，不跨会话合并。同一任务未发送的旧问题被最新结果替代，说明此前问题已经恢复，完整经过仍保留。会话忙时每15秒检查，不可连接时每30秒重试。已发送或送达不明的批次不重复合入新消息；发送结果不明时每30秒检查是否收到确认，不盲目重发。通知等待不阻塞队列和取回。

### 3.3 故障补做授权与额度

第一版后台不自动重新生成，Agent也不因断线、history为空或下载失败安排新生成。需重新生成时说明原任务证据、失败范围和当前所需执行授权，取得授权后创建新的执行，保留与旧任务关系；R、阶段、审批及缓存要求沿用相关媒体规范。重试取回使用原任务，不另占一次生成。

## 4. 图片处理

后台完成后按照登记的输出节点、output_key、index选择真实filename／subfolder／type，保存到Agent明确指定的本机路径。Agent读取下载证据，按图片用途核对文件、尺寸、数量及版本后交用户审核；默认不调用看图能力、不自动重生成。图片用途和批准后超分按[图片交付与用户审核](短剧开发流程规范.md#851-图片交付与用户审核)及专项规范执行。

## 5. 视频处理

所有视频都在生成成功后取回。原生导演台按[完成后分段取回](../生成规范/ComfyUI-MiniMaxH3导演台节点使用规范.md#732-完成后分段取回)读取最终报告、原始组序和阶段，映射到入队前指定的本机目标；合并导出及后处理按实际保存节点输出。运行中不下载、不展示提前版，不查询日志寻找片段。网页不再区分“取回版／完成版”。

文件留存及已有文件处理按[成果保存与已有文件](逐集目录与资产管理规范.md#成果保存与已有文件)。Agent收到结果后按[视频结果人工审核](逐集目录与资产管理规范.md#视频结果人工审核)维护业务记录、展示候选和用户决定；部分取回不冒称全部完成。下一阶段仍按[开发流程第7节](短剧开发流程规范.md#7-生成视频验收与衔接修改)的实际审批顺序推进。

### 5.1 后端故障后的视频接续

由后台执行第3.1节的原ID核对。原ID丢失时保留已有本机文件和证据，进入状态待核对，不扫描猜测远端目录、不将潜变量缓存当成MP4成果、不把原执行登记成功。Agent从记录复查所缺成果与来源缓存，向用户说明可接续范围；新的返修／二采仍核对实际执行地址、原导演台节点和获批输入，不自动改投备用端、清缓存或重做一采。

## 6. 执行核对

- 入队资料、真实来源会话、本地ID及成果保存目标明确，后台接管后没有同任务Agent轮询或heartbeat。
- POST、防重复和断线核对记录完整；未知结果没有自动重发。
- 成果选择依据是本任务真实终态报告或输出节点；成功下载凭据与目标文件对应。
- 生成失败、取回失败、状态待核对与人工批准分开，通知收到确认后按真实状态处理。
