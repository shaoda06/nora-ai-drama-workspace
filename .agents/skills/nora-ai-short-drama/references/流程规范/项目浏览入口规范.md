# 项目浏览入口规范

版本：v1.134；确认日期：2026-10-09。

使用工作区根目录[工作区浏览服务](../../../../../工作区浏览服务/README.md)，从工作区首页选择项目。正式文件、资料卡、项目进度及审阅／生成记录仍是依据；服务解析源文件，使用React组件展示内容和批准状态。仅对用户明确输入的视频修改意见提供独立保存，不改写执行、审核或创作正文，不代替原有保存、审核与进度维护。

## 1. 使用与读取范围

| 本次任务 | 读取范围 |
| --- | --- |
| 仅讨论、查询现有资料 | 使用已有源文件；不写项目资料、不执行同步核验 |
| 新增／修改项目资料、取回候选、记录用户决定 | [交付前同步检查](#交付前同步检查)；仅检查时间更新按该节例外处理 |
| 核对文档链接写法 | [通用文本与链接](#通用文本与链接) |
| 修改模板、目录、字段或解析器 | [输入格式与解析依赖](#5-输入格式与解析依赖)及[维护检查](#4-维护检查) |
| 修改页面展示或交互 | [组件与页面实现](../../../../../工作区浏览服务/docs/组件与页面实现.md#项目页面展示要求)及受影响的实现章节 |

## 2. 展示规则入口

项目标签、资产列表、预览、视频工作区、颜色和组件交互在浏览服务[项目页面展示要求](../../../../../工作区浏览服务/docs/组件与页面实现.md#项目页面展示要求)维护，本规范不另存展示规则。页面读取真实资料，不以候选、文件存在或执行成功推断批准；普通项目填写沿用对应规范和模板。

主技能经本表可以找到全部组成部分；业务规则保留在对应规范，不复制进脚本使用说明。服务由用户双击启动，持续运行至用户停止或关机，不设开机自启。页面打开期间每5秒查询一次变化；后端比较路径、修改时间与大小，在后台重新解析发生变化的项目。正在阅读的文档提示有新版本，由用户选择切换；标签、搜索、展开目录及正在打开的媒体保持，整页不自动重载。首次打开大项目需完成一次解析，更新时间依据读取结果，不把请求发起当作同步完成。服务停机时不承诺后台同步，下次打开重新读取。失败时保留上次完整结果并记录错误原因；页面打开期间每隔30秒重试，文件再次变化时可提前重试。读取前后内容发生变化时放弃本次结果，保留一致性检查。详细模块和测试记录见服务目录。

- 服务自动发现 `projects/` 中的项目目录，不创建项目文件。正式内容、审阅记录与项目进度先按原规范更新，再核验服务读取的实际条目。
- 原文件链接按原Markdown位置解析，已收录的Markdown可页内阅读；未收录链接仍指向原文件，不将历史失效链接伪装为已修复。
- 不把界面示意、QA截图或临时测试文件放入创作资产目录，页面示意不构成故事资料或批准事实。
- 项目静态HTML不作为现行入口或交付物，不再生成。已授权退场的项目根目录 `项目总览.html` 压缩保存到本项目 `99-综合资料/项目总览-退役-YYYYMMDD-HHmmss.zip`，保留原HTML文件名，验证可完整解压后移除原入口；压缩包不包含源素材，恢复时将HTML放回原项目根目录。未获授权的既有文件不自动归档或删除。旧工具源码由Git历史恢复，现行目录不留第二套工具。

#### 交付前同步检查

适用于使用浏览入口且本次获授权写入的项目。责任人是本轮实际修改文件、取回素材或维护记录的agent，包括主控、阶段、逐集会话及获授权的监控唤醒；不能假定其他会话会补核验。服务自动更新不免除源资料维护与条目核验。

1. **触发。** 本轮新增／修改创作正文、资料卡、索引、素材、生成／审阅记录、采用关系、项目进度，或经授权移动／归档文件导致入口变化，均须同步。形成待审草稿或候选就触发，不等用户批准、阶段完成或整集完成。保存用户批准／不采用等决定后再次同步，不让页面保留旧状态。
2. **时机。** 先完成本轮源资料、关联引用及必要进度维护；涉及图片处置时，按适用情形先完成[开发流程8.5.2状态收尾](短剧开发流程规范.md#852-图片采用替换与归档后的状态收尾)。由服务重新读取本次变更，在送审、交付或交接前完成核验。无实质变化轮询仅更新既有任务的最近检查时间时，不执行本节完整浏览条目核验；服务可继续自动读取该变化。纯讨论与只读查询不写项目资料，发现滞后只报告。
3. **核验。** 检查对应项目 `/api/projects/{项目名}/status` 的 `revision`、`updated`、`updating` 与 `error`，并核对相关栏目或资产接口的实际条目；读取仍在进行中或存在错误时不能称为完成。须核对本次条目、状态原文、目标编号、生成编号、候选文件及链接。本批收录数量和待审数量以本批清单为准，不以历史全库总数替代；送审及处置含义读取[开发流程8.5.1](短剧开发流程规范.md#851-图片交付与用户审核)及[8.5.2](短剧开发流程规范.md#852-图片采用替换与归档后的状态收尾)；页面仅将明确“待确认／待审核”的实际候选计入待审，未送审、已采用、不采用或已关闭条目不计入。采用／关闭后核对旧候选不再计入、比较候选与下游引用保留、监控摘要同步；历史审核原文仍可追溯。文件存在、HTTP成功或进程成功均不足以代替条目核验。
4. **异常。** 如同步失败、并发写入、解析警告涉及本轮变更或条目缺失，先报告真实问题、提供原文件入口；不得把旧页面数据称为已同步，也不在页面内手工补造状态。并发问题先读取最新文件，再核验服务重试后的读取结果，不用循环覆盖解决。工具适配超出本轮权限时明确待处理事项；刷新失败不撤销已完成的创作或审批事实。
5. **交付。** 简要说明“浏览入口已同步”及入口；不能同步时说明“源资料已保存，浏览入口未同步”的原因。本地审阅页及用于审阅的项目浏览页按[开发流程基本约定](短剧开发流程规范.md#基本约定)免除agent页面排版视觉检查，不将该免检项列为交付缺口。文件、链接、页面数据核验及同步要求保留；服务页由后端检测并读取变更。涉及交互功能检查时仍如实说明实际验证范围，不将未执行的检查记作已通过。

同步是已有交付流程的检查项，不新建第二份进度表、审批台账或刷新任务系统，也不修改视频仅人工审核、图片核对文件与记录后直接由用户审核的既定分工。技能本身更新触发的适配与重建判断见[维护规范](../../维护规范.md#31-浏览工具联动检查)。

## 4. 维护检查

修改解析器或页面组件后，在[浏览服务目录](../../../../../工作区浏览服务/README.md#开发命令)运行相关测试。检查缺少正式文件、状态来源、相对链接、原内容保留、HTML转义及路径安全。页面维护检查标签切换、正文、折叠文件列表、页内阅读与返回／关闭；排版检查按[开发流程基本约定](短剧开发流程规范.md#基本约定)执行。浏览器受限时如实说明未完成项，不能用脚本通过代替交互验证。

```sh
# 在工作区浏览服务目录执行；测试只使用临时资料。
python -X utf8 -B -m unittest discover -s tests -v
pnpm --dir frontend build
```

解析回归须覆盖人物索引、场景资料和逐集导航同时存在的组合，防止不同标签的数据互相覆盖。同步测试覆盖失败保留旧数据、无文件变化时重试、文件修正后提前重试及错误日志。构建不代替实际浏览器验证。

Windows与Mac共用相同工具及测试。Windows环境的Python命令可使用`python`，保留`-X utf8`以正确读取中文测试资料。符号链接安全测试在有创建权限时执行；仅遇到Windows错误1314（缺少创建符号链接权限）时明确标为跳过，其他错误仍使测试失败。跳过不代表该项安全检查通过，不改变解析器的路径安全检查。

浏览入口按上述规则补齐。后续按实际反馈调整，新业务规则或资产变更仍需相应授权。技能修改仍遵循[维护规范](../../维护规范.md)，不覆盖其他会话的新要求。

## 5. 输入格式与解析依赖

辅助目录从阶段 `其他资料/` 读取，人物、场景、道具详情“相关记录”对应此目录的三类文件，并按资产编号筛选；完整制作记录链接对应 `其他资料/工作稿/{CH／SC／PR编号}-参考图-工作稿.md`，未迁移对象仍读取原 `参考图/生成记录.md`。无辅助文件不创建目录；未迁移项目兼容原阶段直属分类目录，按实际路径各展示一次。候选与审阅仍按生成记录聚合图片，不将执行附件混入候选。

项目级历史统一通过“历史版本”栏目读取根目录 `历史版本/`。根目录 `其他资料/` 不生成顶层标签或栏目，阶段及单集 `其他资料/` 仍按各自规则展示。项目级归档位置与触发条件读取[归档与版本留存](短剧开发流程规范.md#归档与版本留存)；浏览工具不自动迁移旧文件。

源文档标题至第一个正文二级标题之间的完整内容生成 `headerHtml`，供网页文档信息组件读取；额外字段及旧说明不丢失，不以六项为数量上限。解析器保留 `summaryHtml`、`introHtml` 作为源文档头部数据。制作规格属于完整正文，不从正文推断头部字段。进度表解析允许表头、分隔行及数据行之间存在空行，不把分隔行算作阶段，遇到表格后的正文停止。

正式内容文档的输入使用[共用头部](短剧开发流程规范.md#正式内容文档的共用头部)及各自模板。主旨与简介填写方法见[简介文件填写要求](短剧开发流程规范.md#简介文件填写要求)。解析器从独立列表项读取文档版本、更新日期和确认状态；网页服务统一使用完整headerHtml。不从自由说明推断范围或批准。阅读边界保留完整文字，正文按实际Markdown标题关联；页面展示读取浏览服务[栏目展示规则](../../../../../工作区浏览服务/docs/组件与页面实现.md#各栏目展示)。

视频模型正文从“提交给模型的完整提示词”章节提取；兼容历史章节名“提交给节点263的完整提示词”。两者均关联对应中文参考版，不因节点编号变化丢失既有视频的提示词展示。

项目定位读取[项目基本定位模板](../模板/项目基本定位模板.md)规定的字段与小节。名称读取“项目名称或代号”，兼容旧“项目名称”；确认状态、确认范围和确认依据分别展示。正式画幅直接展示字段值，不从自由说明中提取比例，按定位模板展示项目统一画幅及其确认状态、待确认事项和依据。语言正文按“画风与美术实现正文”下的“中文／英文”四级标题关联，同版本适配的状态、范围和依据随对应语言保留；没有英文不生成译文。

项目定位中的独立图片行 `![说明](相对路径)` 仅关联项目内PNG／JPEG／WebP。“已确认画风样例”下的“男性样例／女性样例”四级标题分别关联原图及模板规定的四项字段，标题锚点沿用原小节名称。缺少独立分辨率字段时不从自由说明或文件名推断；兼容旧男女样例段落。图片批准依据读取源文档，不从候选目录自动选图。布局及字段展示读取浏览服务[文档显示与集中审阅](../../../../../工作区浏览服务/docs/组件与页面实现.md#文档显示与集中审阅)。

本节记录当前工具的接口依赖，供agent维护及格式适配使用；不是新的业务模板，也不授权修改原审批记录。正式填写仍以[开发流程](短剧开发流程规范.md)、[进度规范](会话与进度管理规范.md)、[逐集目录规范](逐集目录与资产管理规范.md)及各自链接的专项模板为准。业务结构调整后须同时核对本节和实际代码；不因工具支持某种旧格式就取消业务要求。

### 通用文本与链接

- 输入文档为UTF-8（可带BOM）的Markdown，支持LF与Windows CRLF换行；仅在解析时统一换行，不改写源文件，源文件校验仍依据原始字节。正文支持常用标题、段落、列表、表格、引用与代码块；原始HTML按文本转义，不执行任意内嵌HTML。浏览工具不是完整Markdown扩展语法引擎。
- 页面数据的目录键及文档键统一为相对于项目根目录的正斜杠路径，Windows与Mac保持同一格式；磁盘访问仍使用运行系统的路径规则。
- 头部字段与正文内同名字段按其实际位置区分；字段值、原文及链接在解析数据中保留，显示样式见浏览服务[文档显示与集中审阅](../../../../../工作区浏览服务/docs/组件与页面实现.md#文档显示与集中审阅)。
- 已有文档中的独立标记 `——编制信息——` 及其后正文保持完整；代码块内同名文字不触发特殊解析，源Markdown不改写。显示方式见浏览服务[文档显示与集中审阅](../../../../../工作区浏览服务/docs/组件与页面实现.md#文档显示与集中审阅)。
- 附件类型在生成器中统一识别，过程文件列表与目录浏览共享类型信息；JSON／TXT／LOG快照独立存入`textPreviews`，不作为Markdown解析，也不用于推断审批状态。预览限制与回退读取浏览服务[统一文件预览与原文件入口](../../../../../工作区浏览服务/docs/组件与页面实现.md#统一文件预览与原文件入口)。新增附件类型须同步生成器、预览分支和回归测试。
- 抽取字段采用单行 `- 字段名：值`（也接受英文冒号）；字段名须准确，包括空格。通用元信息为“文档版本、更新日期、确认状态”，可选“阅读边界”。只把同义词放入正文、加粗字段名或任意换行，不保证可抽取；正式内容文档的必填字段缺失时如实提示缺项，不推断。生成、审阅等执行或记录型文档沿用专用模板，不要求整份文档填写“确认状态”；通用文件列表及预览读取实际填写的文档状态，不把逐条图片审批状态当作整份文档状态。文件列表读不到状态时显示灰色“未知”，仅作界面占位，不写回源文件、不代表审批结论；文档预览仍不为不适用的字段补出统一确认状态。
- 一级标题用于文档标题，首个二级标题前为前置说明；网页服务按实际二至六级标题形成章节导航。正文措辞与段落可变化，受专项解析依赖的记录标题不得随意改名。
- 项目Markdown中的本地文件入口（资料卡、输入参考、输出候选、正式文件、生成／审阅记录、请求响应及批准依据）使用实际Markdown相对链接，不只写裸文件名。路径以**链接所在Markdown文件的目录**为基准，不以项目根目录、生成后的HTML或当前工作目录为基准；链接解析后须指向项目内实际文件，章节入口可附 `#锚点`。
- 当前解析器不接受本地绝对路径，即使文件位于同一项目内也不接受；不要在上述链接目标中写 `/Users/...`、`C:\...`、`file://...` 或以 `/` 开头的项目路径。相对路径使用 `/` 分隔。外部网页可保留真实HTTP／HTTPS引用，但不作为本地素材入口或自动媒体预览。
- 区分文档链接与执行路径：对话中展示本地图片及提供可点击文件入口仍使用绝对路径；工具参数、工作流输入和执行清单中的实际路径字段按各自执行规范保留，不为符合文档链接规则改写已提交请求或机器记录。HTML生成器负责将Markdown相对链接转换到页面所在位置，填写者不提前改成页面路径。
- 表格使用明确表头、分隔行及完整单行数据行，列数须与表头一致；除进度表要求固定顺序外，以下索引按列名读取，可含额外列。

### 参考图关联与状态

人物、场景、道具的正式参考图和候选与审阅分别共用同一独立组件，沿用人物资料的三列槽位布局；少图不拉宽，窄屏随可用宽度换行。正式卡片统一显示采用版本、状态、适用范围及生成记录，来源等完整信息保留在记录正文。候选按图片类型默认折叠，每张图独立成卡，同类型倒序排列；当前正式资产中已有实际文件、明确批准且能关联到具体生成记录的图片，不再重复进入候选区，入口及分类数量同步排除。正式表未写生成编号时，候选明确为已采用且与实际正式资产关联同一批准记录，也不重复展示；不将候选版本号当生成编号。仅获批而未正式保存的候选继续保留。原生成、审阅和历史记录不删除。

审核、留存与适用性的含义及填写规则统一见[图片交付与用户审核](短剧开发流程规范.md#851-图片交付与用户审核)。页面分别展示“审核结果”“留存用途”“当前制作适用性”，目录自动发现只影响收录，不影响批准；只有明确批准且未明确标记不适用／待核对的图片可作封面。未识别的原审批文字完整保留，提示“审核结果待核对”，不把解析失败表述为质量不通过。新记录结论使用固定值；既有明确的不通过、不采用或修改后再审直接显示真实结果，不显示格式错误通知。

服装、场景、道具状态参考图按[统一资产状态规则](../生成规范/Qwen-Image-2.1-提示词规范.md#27-资产状态参考图统一规则)沿用原CH／SC／PR目录和同一生成记录；服装仍按“服装参考图”及服装状态展示，场景按既有视图与状态展示，道具按状态名展示。虚拟道具基础界面沿用PR目录及记录。保留正式文件、具体候选版本及来源字段；规格与批准后处理读取对应资产规范，浏览工具仅展示实际记录，不维护尺寸与处理规则。

场景和道具的正式图片展示以各自资产目录下 `参考图/` 中直接存放的PNG／JPG／JPEG／WebP文件为准；解析器每次读取自动扫描此目录中的图片，不要求先登记当前正式资产表。排除隐藏文件、非图片、子目录及越界链接，不扫描候选、历史或执行附件目录。有登记记录时优先保留其元数据及审批原文，以文件路径去重；无记录的图片显示“审核结果未记录”，留存用途与当前制作适用性分别标明未记录／待核对，未记载的版本、来源不编造。场景按编号和EP-C文件名识别环境图，场次环境图在正式页置顶，平面及其他图片在其下展示；未知名称仍显示原文件名。人物参考图保持原登记方式。更新目录后，等待服务后台读取并核对条目；浏览器本身不扫描磁盘。

各人物／场景／道具所属阶段的 `其他资料/工作稿/{CH／SC／PR编号}-参考图-工作稿.md` 为图片元数据来源；未迁移对象兼容卡同目录下的 `参考图/生成记录.md`，同一对象存在工作稿时只读工作稿；场景和道具同时自动收录正式目录中的图片，链接须指向项目内实际媒体。正式图片允许平铺或位于 `参考图/{人物阶段}/`。人物阶段选项取资料卡 `## 3. 外貌与基础造型` 内的 `### 3.N 阶段名`，按正文顺序与正式文件直接父目录匹配；仅展示有登记资产的阶段。旧项目未迁移时继续显示平铺资产，不因资料卡有多个标题自动改动路径或制造阶段标签。当前图片预览识别PNG／JPG／JPEG／WebP；其他类型不因存在就当作有效封面。

候选数据中的 `pending` 与 `pendingLabel` 由同一用户状态前缀生成：仅明确“待确认／待审核”计数，后者保留这两个标签的区别。列表总数、阶段与类型分组计数及定位目标共用此依据；不从渲染后的HTML或历史看图结论反推状态。

改变状态词、批准结论或这些章节结构时，检查 `field`、`phase_rows`、`table_records`、`build_data` 和 `status_markup` 等解析逻辑，以及React组件的相应显示逻辑和服务测试。

当前并非所有格式不匹配都会导致读取失败或产生警告：索引表头、编号、候选结构不匹配可能表现为条目未收录、空列表或“未记录”；输出候选使用不支持的本地绝对链接时，整条候选可能被跳过，`warnings` 仍为空。出现缺项时先核对源记录的字段、链接基准、目标存在性及规定目录归属；填写错误应修正源记录再核验，不在页面手工补条目，也不为接受错误写法擅自放宽解析限制。因此维护后必须用代表性输入核对预期条目，不能以接口成功作为兼容性充分证据；发现规范已改而解析未适配时，应修复工具或报告缺口，不修改项目真实内容来掩盖问题。已有源文档校验值仅用于已读取文档，不证明目录新增项、媒体或所有外部变化都被检测。

审批解析依赖：审阅第四章“结论／决定”提供审核结果，第五章“留存用途”“当前制作适用性”分别提供用途和适用范围；缺少字段如实显示未记录，不从文件目录补造。三个维度分别展示，适用性字段中明确“不适用／待核对”时不选作当前封面。

现行过程分类按[工作稿管理规则](短剧开发流程规范.md#工作稿管理规则)读取。页面展示工作稿、历史版本和执行附件；讨论记录、过程稿和审阅记录仅在旧目录实际存在时作为兼容分类显示，不据浏览生成动作迁移资料。旧项目保持真实入口和批准事实；同一对象存在新工作稿时不回退读取旧生成记录补状态。
