# ComfyUI-服务配置与任务提交规范

版本：v1.6；确认日期：2026-10-10。

本规范维护项目ComfyUI配置、能力核对、选端、提交接续、任务地址绑定及固定通信要求；具体工作流、模型参数、审批与监控策略仍由对应专项规范维护。按当前任务读取：

- 初始化项目或调整服务地址：读取[项目配置](#项目-comfyui-配置)。
- 准备或提交新任务：读取[执行前检查](#执行前检查与复用)、[选端与提交](#新任务的选端与提交)、[任务显示标题](#任务显示标题)及[固定工具](#固定通信工具与证据)，再按实际媒体类型进入执行规范。
- 推进已授权待提交任务：读取[待提交推进](#已授权待提交任务的推进)及其链接的监控方式。
- 查询、取回或恢复已提交任务：读取[地址与恢复](#已提交任务的地址与恢复)、[固定工具](#固定通信工具与证据)及任务监控规范，不重新选端或提交。

## 项目 ComfyUI 配置

本节是项目服务配置、主节点提交和任务地址绑定的唯一规则入口。每个项目独立维护根目录 `comfyui-config.json`，不跨项目继承。配置只保存有序地址列表：

```json
{
  "remote-urls": ["http://127.0.0.1:8188"]
}
```

`remote-urls` 为非空HTTP／HTTPS地址数组，第一项为主节点，其余为备用节点。地址不重复，不含凭据、查询参数或片段。所有类型的新任务都提交到主节点；备用节点保留连接监控和队列查看，不自动接收分流任务。主节点不可用时停止本次提交，不改投备用节点。网页手动转交功能尚未实现。

初始化检查已有配置：合法则复用，不擅自覆盖；缺少时询问实际服务地址或有序地址列表，并告知默认地址 `http://127.0.0.1:8188`。用户确认默认地址后才使用上述内容；未回答不视为同意。`127.0.0.1` 指执行脚本的机器。配置不保存时区、模型、节点、库存或运行状态。只含 `remote-url` 的旧配置按单主节点解释；获授权整理时转为上述格式并完整保留实际地址，不在运行时自动改写其他项目。

## 新任务的选端与提交

所有会话的新任务使用[统一分配与提交入口](../comfyui-scripts/README.md#nora统一分配与提交)，所有类型均提交到项目主节点。先完成当前执行授权、审批依赖及主节点能力／素材核对，再逐个调用；不直接绕过入口向各端批量提交。

完整工作区使用统一入口默认的browser模式，将主节点上传及资料关联完成后的任务交给浏览服务提交和监控；调用前按[接入参数](../comfyui-scripts/README.md#浏览服务监控接入)准备明确的成果取回映射；原生H3分段导出同时登记分段计划及已核实output根目录，继续引用既有输入映射，不另建P编号台账。确认目标会话获准接收分段、改写、终态及问题通知。后台监控及未具备服务条件时的显式legacy模式统一遵循[监控方式](ComfyUI-任务监控规范.md#1-监控方式与间隔)。浏览服务接管不改变本规范的主节点提交、授权及防重复提交条件。

统一入口不根据远端运行或等待数量拦截提交，不读取其他任务的工作流判断占用。远端排队由ComfyUI处理；每次调用仅执行本次获授权提交，不等待空位、不循环重试。未提交资料不等于后台本地队列；本地队列调度及按钮业务尚未接入，不声称后台会自动提交。

一采、返修及二采须满足执行地址与导演台节点ID的缓存接续要求。旧一采在备用端执行时，新增返修或二采仍须核对主节点的来源缓存及输入是否具备；未具备时停止，不照搬其他节点的路径，不把MP4当作潜变量缓存。阶段、来源及缓存核对统一执行[H3人工审核与接续](../生成规范/ComfyUI-H3视频执行规范.md#5-人工审核与轻量记录)及[导演台缓存规范](../生成规范/ComfyUI-MiniMaxH3导演台节点使用规范.md#75-缓存检查与清理接口)。同一地址不证明节点ID、具体版本和生成输入匹配。

统一入口以本技能 `state/comfyui-dispatch.lock` 的操作系统文件锁串行完成必要上传与一次提交；锁仅协调使用同一技能安装的本机进程，不控制其他机器或ComfyUI网页手动提交。参考素材在主节点实际上传或核对已有路径后才提交，不照搬其他节点的上传路径。一次POST开始后不因错误或超时重发，防重复及异常核对沿用固定通信工具。主节点提交不改变工作流、模型、参数或制作／审批顺序；二采类型不代表二采方案已经批准可执行。

### 任务显示标题

Agent准备提交时，按 `{对象编号} · {简短任务描述}` 编写标题，并显式传入统一入口的 `--task-title`。对象编号采用项目已有编号：整场任务使用EP/C编号，单段任务使用完整EP/C/P编号，资产任务使用对应人物、场景或道具编号；不为标题新增编号。描述说明本次具体要做什么，例如 `EP002-C001 · 首次生成`、`EP002-C001-P003 · 返修动作`、`CH001 · 调整发型`。

标题不重复卡片顶部的项目名及图片生成、图片超分、视频一采、视频二采、视频后处理这五种任务类型，不把排队、执行或下载状态写进标题。标题由Agent提交时确定；脚本及网页保留提交值，不随执行阶段改名。工具未填写标题时采用执行记录目录名的兼容默认值，不代替Agent按本节填写标题的责任。执行记录、文件名称和生成序号继续遵循对应制作规范，不由显示标题改写。

## 已授权待提交任务的推进

尚未提交的已授权任务保留在原会话既有任务清单或生成记录中，保存准备资料入口、授权范围、任务类型、未提交原因及最近检查时间；不另建调度台账，不填虚构prompt ID，不计为远端排队或失败。等待审核、等待执行授权、缓存问题及提交结果不明分别处理。

主节点不可达、能力或素材不具备时停止本次提交，如实记录原因。取消旧的等待门槛和定时查空位提交规则，不自动改投备用节点，不通过heartbeat循环提交。原会话接到继续执行的指令后，按[待提交跟进方式与间隔](ComfyUI-任务监控规范.md#11-待提交跟进方式与间隔)核对资料与原授权再处理；提交证据已存在时先核对原任务，不换目录重提。取得真实ID后才转入已提交监控。已提交任务的连接恢复继续按监控规范执行。

## 已提交任务的地址与恢复

任务在现有执行记录中绑定实际服务地址、任务ID及对应提交证据；实际地址及能力核对注明于既有生成／执行记录，不另维护一份调度状态库。查询、取回和恢复优先读取该任务提交尝试中的真实地址，再显式传给固定工具的 `--url`；不从当前地址列表第一项覆盖旧任务地址。旧记录缺少地址时核对当时请求、上传或响应依据，无法确定先沟通，不猜测。

调整地址顺序或备用列表只影响新任务，不取消、移动或重提旧任务；原备用端任务继续按提交时的实际地址跟踪。停止监控不等于取消生成。对已提交任务服务不可达、提交状态不明或失败的处理执行[监控与异常规则](ComfyUI-任务监控规范.md)，不自动更换执行地址。

## 执行前检查与复用

随包inventory的缓存由使用时生成，不包含在分发包中；缓存位置按[技能入口指定的](../../SKILL.md#依赖发现与获取) `comfyui-inventory` 真源入口读取，不能假定在相邻的 `comfyui-api` 目录。项目执行地址仍以本规范的项目配置为准，显式传入工具，依赖自身的默认地址不能覆盖项目配置。

本节适用于文生图、图生图及H3一采／二采／后处理；复用的是服务能力依据，不是上一任务的提交结论。不同远端的库存分别指定保存位置并核对source_url，不用同一个缓存反复覆盖后当作多端能力证明；具体刷新仍使用inventory的现有--output参数。

- **能力依据可复用。** 读取 `comfyui-inventory` 的已有库存，核对 `source_url`、`last_updated`、`complete` 和 `errors`。来源与本次主节点一致、完整且满足该技能的时效要求，没有已知环境变化，并覆盖本次所需节点、模型及接口定义时，直接据此核对任务，不为每张图或每段视频重复刷新。新会话也可复用满足条件的已有库存，不只凭会话记忆或旧任务成功结论。
- **按触发条件重查。** 库存缺失、过期、不完整、服务地址变化、已知节点／模型／接口更新、依赖缺失或与工作流冲突，以及用户要求刷新时，按inventory规则刷新。工作流新增／更换依赖、扩展动态输入或切换处理阶段时，先核对变化涉及的能力；已有有效库存覆盖且一致则复用，否则只读补查相关定义，按inventory规则需要刷新库存时执行。接口、加载或类型错误使相关旧结论失效，按实际错误核对，不因普通画面初审失败全量刷新。
- **逐任务仍须核对。** 每次读取本项目服务配置，核对主节点上的本次API节点、模型选择、必填输入、连接与输出类型，并检查实际素材及版本、上传路径、标签顺序、参数范围、数量／尺寸／时长、输出位置、执行授权与审批依赖。依赖未变也不能跳过这份任务副本检查；返修及批次内各任务同样执行。
- **不复用瞬时状态。** 连通性、当前队列、任务进展和可用显存不由旧库存证明；连接、监控及异常处理继续按comfyui-api和固定监控模板执行。缓存刷新失败如实报告，不把旧缓存当作实时核对成功，不自动重提任务或修改服务器。
- **沿用已有记录。** 在现有生成／执行记录中注明使用的库存入口、核对时间及复用／补查结论，不新增缓存服务、哈希门槛、独立预检台账或工具代码。能力核对不证明权重必可加载、资源必够用或画面质量通过；输出仍按既有验收和审批规则处理。

## 固定通信工具与证据

所有ComfyUI执行、查询与取回同时读取 `comfyui-api` 和[固定工具说明](../comfyui-scripts/README.md)，新任务按本规范提交到主节点；通信复用 `references/comfyui-scripts/comfyui_client.py` 的upload／submit／status／download，不逐任务重写通信代码，不使用会重写审批状态的旧执行器，也不修改comfyui-api技能本身。工具故障或缺口先报告并集中修复；额外只读核对按相关技能处理，不静默另写临时替代工具。

agent准备最终API JSON、素材顺序、参数和保存路径；脚本只负责通信和技术证据，不决定业务参数、审核或候选／选定，不内置监控调度。每次逻辑提交沿用固定证据位置，保留“提交尝试”附件；提交不明先核对，不换目录绕过防重。附件沿用现行命名，不另建管理体系。
