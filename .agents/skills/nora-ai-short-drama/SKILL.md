# Nora AI 连续短剧创作

使用本技能统一 AI 连续短剧项目的创作流程、目录、命名、资料模板和交付方式。安装位置与项目工作区由使用者确定；独立技能与完整工作区的能力边界见下方依赖入口。

## 技能维护

修改、扩展或整理本技能及配套资源前，完整读取[维护规范](维护规范.md)，使用 `skill-creator`；维护规范只管理技能本身，普通短剧任务无需默认读取。修改维护规范须依据用户确认。

当前任务从本文件进入现行规范，按任务读取，不加载整个目录。`references/历史版本/` 仅用于追溯、比较或恢复；旧路径失效时查维护规范中的对照表。不因技能更新自动迁移项目、改写历史或恢复定时任务。

## 适用平台与技能依赖

本技能的创作规则、模板与配套ComfyUI客户端可独立分享。完整工作区另外提供FFmpeg初始化说明、项目浏览服务和风格库；使用这些能力时才需要相应工作区资源。其他平台还须提供会话与监控能力，缺失时说明受影响操作，不宣称已安排跟进。分享清单与外部资源边界见[分享边界](维护规范.md#分享边界与本机时间)。

### 外部技能协作与规则优先级

在平台约束内，本流程按以下顺序处理规则冲突：

1. 用户当前明确要求及实际授权范围。
2. 适用的工作区／项目指令，以及项目已确认的剧情、人物、风格与规格。
3. 本技能现行规范及固定模板；同一规则从其唯一维护入口读取。
4. 外部技能在本次任务范围内适用的方法与建议。
5. 未被上述依据规定的通用写作建议。

用户要求改变已确认的核心剧情、人物或视觉方向时，沿用本流程的影响说明与确认要求；已有明确授权则按其范围处理。同层冲突先核对规则真源与具体适用范围，仍不能判断时说明冲突及影响，由用户决定。真实模型、接口和素材容量限制属于执行条件，不能靠规则优先级绕过。

外部技能提到的其他技能或转交流程不自动加入本流程。已登记技能按本入口的任务条件选用；未登记项先核对当前任务是否确需及与本流程的关系，按依赖发现规则处理，不因外部推荐递归加载、安装技能或新增制作与审批阶段。

创作补充技能只提供本次所需的方法，不替代本地模板、编号、目录、审批或媒体执行流程；具体适配读取[编剧与对白方法](references/流程规范/逐集内容制作规范.md#编剧补充与表达润色)、[分镜方法](references/流程规范/逐集内容制作规范.md#分镜方法补充)及[文本审查方法](references/流程规范/逐集内容制作规范.md#文本审查的方法补充)。外部推荐不自动授权安装、转交任务或新增审批。

上述创作补充技能的阶段调用时机由开发流程的[全剧准备](references/流程规范/短剧开发流程规范.md#第一部分全剧准备)、[逐集制作第3步](references/流程规范/短剧开发流程规范.md#3-扩写本集故事剧本并明确场次需求)、[第4步](references/流程规范/短剧开发流程规范.md#4-整理场次分镜并划分视频生成分段)及[文本交付前自检](references/流程规范/短剧开发流程规范.md#文本交付前的自检与订正)维护；具体用法分别见[编剧补充与表达润色](references/流程规范/逐集内容制作规范.md#编剧补充与表达润色)、[分镜方法补充](references/流程规范/逐集内容制作规范.md#分镜方法补充)及[文本审查的方法补充](references/流程规范/逐集内容制作规范.md#文本审查的方法补充)。按名称发现并读取实际安装入口，不能只写“已参考”；缺少方法补充技能时如实说明受影响的方法，不声称已用，也不阻塞本流程已有的创作能力。

### 辅助技能的条件调用

各阶段按当前任务及下方条件选择技能。命中时读取实际安装入口的 `SKILL.md` 及本次所需参考，再将方法落实到获授权的产出或检查；本会话已读取且版本未变的内容可以复用。仅列出技能名称、安装成功或阅读完毕，不等于已经完成应用。交付创作或维护成果时，在既有编写依据、执行记录或交付说明中简述实际采用的技能及落实内容，不新建技能调用台账；未实际使用不声称已用，纯查询及无变化监控仍遵循原通知要求。

| 技能 | 条件 |
| --- | --- |
| `stop-that-shit` | 明确调用，或维护中需要判断额外机制、范围扩大、反复验证的必要性 |
| `stss` | 决策方案中存在防御性赘述，或用户明确要求处理 |
| `find-skills` | 用户寻找技能，或核对已有能力后仍缺少本次专用能力 |
| `vercel-react-best-practices` | 本次实际开发或审阅React／Next.js工具 |
| `fastapi` | 本次实际开发或审阅FastAPI后端 |

命中后按名称读取实际技能，并选读[工程适配说明](维护规范.md#辅助技能的工程适配)；普通创作不加载开发技能，不为使用技能改换技术栈。

### 依赖发现与获取

项目画风无论来自名称、图片或风格库，均按[项目画风展开、示例验证与复用](references/流程规范/短剧开发流程规范.md#项目画风展开示例验证与复用)转换为具体美术实现，制定、保存及生产引用前执行该入口的正文内容边界检查，经用户确认后保存唯一正文，并通过图片／视频模板固定引用；不把风格名称当作完整实现。

工作区的 `krea2-style-library` 是独立的可选画风辅助工具，不计入上述流程依赖。确定项目视觉风格时，按[视觉风格选择与记录](references/流程规范/短剧开发流程规范.md#视觉风格选择与记录)主动介绍其用途及访问方式；实际使用时按名称发现并读取该技能，提供真实浏览入口。用户可不使用风格库；工具或资源缺失不阻塞定位，不自动安装、更新资源或切换生成模型。

1. 三个ComfyUI技能以本文件依赖表链接的 `dependencies/{技能名}/SKILL.md` 为本流程唯一现行入口；它们随工作区提供，不再次复制安装，不因发现全局同名版本切换。关联脚本和参考资料均从所选入口解析。同名旧安装需要整理时先比较并保存独有内容，未经授权不删除其他位置的安装。平台未自动列出嵌套技能时，按表中明确路径读取；若平台不支持该方式，报告能力限制，不静默创建另一套可编辑真源。
2. 其他依赖先从当前平台按名称发现并读取实际入口，已有可用安装则复用，不自动覆盖或升级；需要查找缺少的专用技能时，按[辅助技能的条件调用](#辅助技能的条件调用)使用 `find-skills`。缺失且本次任务需要时按[获取来源](维护规范.md#6-依赖获取与适配资料)取得完整技能目录及必需资源；许可证位于仓库根目录时也须保留。以 `.skill` 包发布的解包取得技能目录。不要安装仓库内无关技能或Hook。
3. 除非用户明确指定其他安装范围或目录，新增依赖默认安装到当前工作区 `.agents/skills/{技能名}/`。工作区指包含工作区级 `AGENTS.md`、`projects/` 和主技能的根目录，不是某部短剧的项目目录；有多重工作区且归属不明时先确认。随包真源不适用重复安装。安装后核对入口可读取及平台发现状态；山音采用仅显式调用策略。
4. Codex Desktop的 `skill-creator` 使用内置入口；其他平台若无此技能，说明技能维护阶段缺少依赖。来源不可访问或安装能力缺失时，说明具体缺项及受影响操作。方法补充技能缺失不阻塞本流程已有的创作能力；缺少技术执行能力时停止依赖该能力的操作，无关策划可继续；未实际读取或应用的技能不得声称已用。按需补齐依赖，不要求项目初始化时安装所有技能。依赖获取不授权安装ComfyUI节点、模型或更改服务器，也不等于ComfyUI已具备运行条件。

使用者须提供支持配套工作流的ComfyUI环境；本技能不安装模型、节点或服务端依赖。保留执行规范要求的只读核对；错误如实报告，不自动替换模型、修改服务环境或用远端工作流覆盖本地基准。

## 使用流程

1. 确认项目、本次范围及主控／阶段会话身份。新项目发起会话作为主控；已有明确阶段任务的会话直接承担该阶段，不额外开一次会话。
2. 初始化、阶段安排、进度查询和接续时，读取[会话与进度管理规范](references/流程规范/会话与进度管理规范.md)；会话职责、编号、命名、[剧名或代号确定后的创建提醒](references/流程规范/会话与进度管理规范.md#剧名或代号确定后的会话创建提醒)及并行条件统一由该规范维护。
3. 创作、评审或修改项目内容前，读取项目局部指令、项目进度、已有定位及核心设定，再按任务读取相关大纲、资料卡、剧集与素材；已有用户原稿时，同时执行[原稿读取、复用与确认](references/流程规范/短剧开发流程规范.md#用户原稿的读取复用与确认)。读取[开发流程](references/流程规范/短剧开发流程规范.md)的基本约定、当前阶段完整章节及命名存放规则；关联修改再读取对应章节，不加载全剧全部文件和历史会话。纯概念讨论可直接回答。
4. 按下表进入本次相关章节；创建或修改正文时完整读取对应模板，纯查询、讨论和仅恢复既有任务不加载无关模板。规范管理填写、审批和存放，模板提供固定正文；不能凭记忆重建字段。资料卡字段不得删除、改名或调换，未知填“待确认”，不适用填“不适用”，项目特有内容写“其他备注”。不提交未替换占位符。
5. 只讨论或评审时不修改文件；创建或修改时维护关联资料。不提前制作未获授权的阶段内容。与已有设定冲突或改变核心方向时，先说明影响并由用户决定。其他项目资料不作为本项目的设定、资产或审批依据。
6. 正式文件使用规定名称与路径；各阶段辅助资料统一归入 `其他资料/`，按工作稿、历史版本和执行附件分类，具体职责见[开发流程](references/流程规范/短剧开发流程规范.md#正式产出与非正式文档)。过程文档按固定分类按需建目录，不另建同义目录。提示词编写与生成执行分开：仅要求提示词时交付提示词，不触发生图或视频生成。

## 固定脚本调用

固定脚本用于直接复用既有执行能力，agent只准备本次参数和任务数据，不重新设计已有工具已覆盖的调用流程。调用说明入口：[ComfyUI通信](references/comfyui-scripts/README.md)、[库存刷新](dependencies/comfyui-inventory/SKILL.md#connection-and-refresh)（本流程使用依赖表指定的工作区真源）、[工作流校验与测试](references/生成规范/ComfyUI-H3视频执行规范.md#11-离线配对校验与回归测试)、[项目浏览工具与测试](references/流程规范/项目浏览入口规范.md#工具组成与阅读入口)。

日常调用以“脚本调用说明应足以支持直接执行”为行为基调，而不只是脚本维护要求。已有固定脚本且说明足够时，agent默认按说明准备参数并直接执行，不为了泛化的“先确认一下”额外读源码，也不重新设计已有工具覆盖的实现。参数不明确时按需查看 `--help`，不要求每次重复读取帮助。仅在说明存在具体缺口、行为与说明不符、执行异常或需要修改脚本时，查看与问题相关的代码，不默认通读完整实现。日常检查聚焦本次任务参数、执行授权及返回结果，既有安全和验收要求保持不变。

## 看图能力调用边界

- **默认禁止调用看图能力。** 图片身份、用途、人物／服装／场景／道具状态及版本，优先依据生成、操作、资料、审批等已有记录确定；记录中的生成目标不等于实际画面已符合目标，不补写未经查看或用户确认的视觉结论。
- **只允许两类触发。** 当前有效工作流规范明确指出该具体任务需要调用看图能力；或用户明确要求查看图片内容，例如针对图片说“你看一下”“检查一下这个图片的内容”。仅询问进度、读取规则、要求生成、上传或展示图片不构成看图授权。笼统的“检查素材”“保证一致性”和依赖技能的无条件看图建议不构成本流程的独立例外。
- **缺少视觉信息先询问。** 说明缺少哪项信息、涉及哪张图及为何影响当前任务，询问用户是否需要且允许查看，收到明确许可后再调用；等待时继续不依赖该信息的工作，不猜测、不把未回答视为允许，也不能通过自行增写规范制造授权。
- **查看限定于授权问题。** 只查看该任务涉及的图片及确有必要的局部，不扩展为全套审查；已有授权仍适用且信息足够时不重复询问或重复查看。生成新图、换批次、换会话、恢复监控、复用、归档、登记采用本身都不触发看图。规范规定的例外只适用于其明确范围，例如用户选定风格后的预览分析，不延伸到常规生成结果。
- **展示与看图区分。** 向用户提供图片、原图链接或审阅页不要求先将图片送入视觉模型。文件取回、可解码性、尺寸、格式、数量、来源／版本核对可以通过文件与记录完成；不得借裁图、拼图、截图或其他视觉接口绕过本边界。图片默认直接交用户审核，不做固定技术视觉审查、内容审查或据此自动重试。记录与交付按[开发流程8.5.1](references/流程规范/短剧开发流程规范.md#851-图片交付与用户审核)。

## 完成标准

本轮涉及图片处置时，按[状态收尾检查](references/流程规范/短剧开发流程规范.md#852-图片采用替换与归档后的状态收尾)中的适用情形完成关联维护，再同步浏览入口；触发范围及检查项由该节统一维护。
