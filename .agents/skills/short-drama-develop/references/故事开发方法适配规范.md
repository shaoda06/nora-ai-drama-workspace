# 故事开发方法适配规范

### 故事开发的方法补充

在定位、主旨简介、故事大纲或分集大纲中，新写或实质性修订故事方向、主线、人物长线或分集结构前，由本技能按下表选择当前阶段及具体问题所需的参考资料；仅调整错字、格式、记录或局部表达时不因本节加载。以当前任务输入、已有原稿及已确认的上游为依据，不因安装技能重做已完成阶段。

| 当前阶段 | 参考重点与正文落实位置 |
| --- | --- |
| [项目基本定位](项目定位与画风规范.md#1-确定项目基本定位) | 按需读其 `references/story-craft.md`、`references/genre-cards.md`；将目标受众、题材的观看兴趣和情绪取向落实到定位既有章节。方向未定时比较真正不同的故事机制，已有方向时直接深化；不提前写全剧大纲。 |
| [主旨与简介](主旨简介与世界观规范.md#3-主旨与简介) | 以 `references/story-craft.md` 梳理主角目标、阻力、代价与反复能获得的回报；有穿越、重生或系统等前提装置时，按需读 `references/premise-devices.md`，把已采用的规则与限制写入世界观、核心设定和主要矛盾。结局承诺与故事简介仍按七章模板填写。 |
| [故事大纲](故事大纲规范.md#4-故事大纲) | 按问题读 `references/story-craft.md`、`references/serial-character-and-memory.md`；改编取舍读 `references/adaptation-craft.md`，中段机制重复读 `references/mechanism-loop.md`。将冲突如何持续并升级、人物选择与代价、关系变化及铺垫兑现写入大纲对应章节；原稿保留、压缩、调序或新增的依据归入既有工作稿，不另建故事引擎文件。 |
| [分集大纲](分集大纲规范.md#7-分集大纲) | 读 `references/episode-design.md`；按问题选读 `references/reveal-reversal-payoff.md` 或 `references/genre-and-hook-playbook.md`。将本集进入状态、主要行动与进展、结果和下集承接落实到逐集七章大纲，索引只保留既定定位信息。接续已有多集整稿时，按需读 `references/multi-episode-intake.md` 的实际边界判断与分批回读方法，再执行[原稿接续](../../nora-ai-short-drama/references/共用规则/创作定位与原稿规范.md#用户原稿的读取复用与确认)和[已有剧集拆分](分集大纲规范.md#已有剧集的拆分与后续集号调整)。 |

协作优先级执行[技能入口](../../nora-ai-short-drama/SKILL.md#外部技能协作与规则优先级)。只吸收开发方法，沿用本流程正式路径、模板、工作稿、确认及关联同步；不自动创建外部的 `输入/`、`项目开发/`、`short-drama.json`、简报、引擎、分集JSONL或节奏档案，不把其发布工具和整稿索引脚本直接用于本流程文件。需要外部脚本时先明确输入输出及适配范围，不以安装成功认定脚本已兼容现有格式。

外部题材卡、首集候选数量、节奏默认值、钩子和单集回报建议只辅助判断，不变成本流程的配额或完成门槛。既有[单集分集大纲填写规则](分集大纲规范.md#单集分集大纲填写规则)允许停在持续行动的关键节点，必要的声音交代与直接表达仍按[台词设计规则](../../short-drama-write/references/对白与表演修订规范.md#台词设计节奏与统计)保留；不能借方法补充强制反转、删减因果解释或改写已确认的核心人物与剧情。改编缺项与实质变化沿用原稿接续的授权规则，未安装其他上游技能不阻塞当前可完成的开发任务。

完成当前任务时，将实际采用的方法、原稿依据及取舍落实到现有正文和工作稿；按原阶段的完成判断检查，再交给后续人物资料、分集规划或逐集剧本。不另设开发报告、独立审查、审批阶段或技能调用台账。
