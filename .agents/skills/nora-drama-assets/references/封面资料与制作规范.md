# 封面资料与制作规范

## 1. 用途与制作

封面用于项目展示、片头、介绍或视频发布；按实际需求制作系列通用或单集专用封面。由资产设计负责画面、文案、排版和素材依据，生成执行负责调用、结果登记及规格处理；不新增独立制作阶段。

启用选择与已有项目的接续执行[定位阶段的可选安排](../../short-drama-develop/references/项目定位与画风规范.md#封面与片头片尾的可选安排)，专项会话与进度登记执行[配套接续](../../nora-ai-short-drama/references/流程规范/会话与进度管理规范.md#可选配套的会话与进度接续)。

按需讨论用途、文案、比例和目标尺寸，需求已清楚时直接制作。默认使用内置Imagegen，Qwen Image 2.1为备用；能力选择与切换沿[统一入口](../../nora-ai-short-drama/SKILL.md#当前参考图生成选型)，不重复定义。封面不新增项目固定种子类别。Qwen备用生图遵守现有32像素对齐接口约束，例如横版1536×1152、竖版1152×1536；这些是候选请求尺寸，正式成品仍按本次已定目标处理。

不设固定封面生图提示词模板。根据本次目标自由组织完整实际提示词，写清文案原文、画面与排版、参考图逐张用途和保留／变化范围，沿用项目已确认画风、人物及服装。保存实际提示词与真实输入，修改和重新生成沿[共用源图规则](图片提示词规范.md#参考图统一修订规则)。用户选定某图并指定据此延展时，记录该源图、版本和范围；新横竖版分别送审，不继承源图批准。

### 成套交付

封面默认以套组制作和交付，每套包含一个横版和一个竖版。只有用户明确要求不需要其中某一版时，才按单版交付，并记录省略的版式及用户依据；先制作或先批准其中一版，不代表另一版无需制作。同套使用共同的画面设计、人物、文案及视觉风格，按横竖比例调整排版；用户明确要求的差异按实际记录。

套组名称固定表示同一用途，例如“系列通用”或“EP002”，不随平台、方案名称或改图轮次变化。同一用途下的每个平台及版式登记固定封面编号，方案和修改进入该封面的修订轮次，不因换风格另建对象。每张图片仍保留真实候选文件版本、生成、批准及处理记录。同套缺少尚需交付的版式时，如实记为未完成；已获批单张的状态保留，不因整套未完成而撤销。套组完成按本次所选平台逐一核对；扣除用户明确省略的版式后，所有仍需交付的成品均已获批且规格达标，才记为本套交付完成。

## 2. 平台选择、规格与后处理

### 平台字段与多选

成品必须绑定适用平台。固定使用以下字段和写法；平台与系列通用／单集专用的适用范围分别记录，不互相代替。

| 字段 | 固定填写方式 |
| --- | --- |
| 封面编号 | 项目内固定编号COV001起；登记后不复用或随文件名变更，横竖版各有一个编号；适配多平台且共用同一设计与文件时可绑定多个平台 |
| 套组名称 | 同一用途的横竖版共用固定名称，例如“系列通用”或“EP002”；平台单独登记，方案名称放在轮次名称中 |
| 修订轮次 | R001起；一次用户反馈或新方案为一轮，同一轮的抽卡与故障恢复记录可以共用轮次；横竖同步修改时使用相同轮次，仅改单版时不为另一版伪造新记录 |
| 轮次名称 | 简短说明本轮变化，如“初稿”“视线调整”“配色整合”；不使用原始文件名作为页面标题 |
| 目标平台 | 本批制作的平台选择，允许多选；平台标准名称为“通用”“抖音”“快手”“小红书”，后续平台按其正式中文名称补充，不使用别名或缩写 |
| 适用平台 | 每条成品实际适配的平台；单平台填标准名称，多平台用顿号连接，如“抖音、快手”，按抖音、快手、小红书的顺序填写，其他平台依本批选择顺序追加 |
| 版式 | “横版”或“竖版” |
| 规格依据 | 对应平台及版式的依据，区分平台要求、工作区交付预设和用户指定规格；引用核实依据时注明链接及适用日期 |

“通用”表示不针对具体发布平台，按明确用途及目标规格交付，不表示已经适配全部平台。“通用”单独选择，不与具体平台混选；具体平台可以同时选择多个。不明确目标平台时先询问，不自动填通用或沿用上次平台。需要用户选择时优先使用可多选的选项弹窗；弹窗仅支持单选时，用同一问题接收顿号分隔的全部平台，不将多平台需求压成单选。已有明确选择直接沿用。

### 封面对象与版本归属

封面索引的当前表逐项登记固定“封面编号”，即使尚无正式图也先登记对象及目标规格，成品和原图尚不存在时如实填待处理／待生成。生成前明确编号、修订轮次、轮次名称；Imagegen及Qwen的新请求均在fields填写，工具检查编号存在且用途、平台和版式与索引一致。同一对象后续沿用其正式图片身份及候选命名，不因修改风格重新从v01建立另一个对象。

页面按平台和用途展示横竖各一张对象卡片，优先预览当前正式版；没有正式版时展示最新候选。新版候选不自动替换正式版，有待确认更新时给出提示。详情按轮次从新到旧列出候选及执行记录；同轮多次生成是候选／执行附件，不平铺成独立封面。原生图及本地缩放、裁切或超分后的成品属于同一轮，尺寸处理不新增设计版本。历史成品引用本轮保留的处理输出或归档文件，不能引用会被新采用覆盖的当前正式路径。

旧记录缺少编号或轮次时，在同一封面索引的“历史归属补录”表按生成记录逐项关联。只补经旧请求、修改链或原采用索引核实的归属，保留原执行清单、提示词、生成编号及批准原文。没有明确归属的资料留在“待归类资料”，不按文件名相似、文件版本号或比例猜测。不得把制作时未登记的平台追写成历史真实发布平台；补录表示当前图库的版本归属。

### 规格确定与成品处理

按以下顺序处理每批封面：

1. 确定套组名称、适用范围、目标平台及用户明确省略的版式。每个目标平台默认需要横版和竖版。
2. 以本规范的统一交付预设确定横竖版目标宽高、比例和格式；通用及各目标平台均以此为默认起点。逐平台核对实际发布入口，明确需要其他规格或用户另有要求时再适配；未核实的官方限制如实注明，不将工作区预设或用户指定值标为官方要求。
3. 先确定共同设计，再制作横竖版和所需平台延展。平台之间画面、排版、宽高、比例及格式完全相同，且分别满足各平台已确认要求时，可共用同一成品文件，索引一条记录列出全部适用平台，无需重复生成或复制。任一项不同则分别处理和登记；仅同属一个套组不能推定文件可共用。
4. 以各成品已定目标执行下方后处理，保留原图和实际处理记录。比例变化需要重新排版或明显改变构图时按修订处理，不能仅凭尺寸达标视为完成。
5. 按实际适用平台及版式逐项核对成品与批准依据，再更新索引、工作稿及套组待办。某平台尚未确认规格或尚缺一版时保留对应未完成项，不影响其他已完成成品的真实状态。

每个封面在制作时注明适用平台、用途、规格依据、目标宽高、比例和格式。

### 平台官方口径与适用入口

核实日期：2026-10-25。所有尺寸按宽×高填写。封面图片、视频内容画幅、列表卡片、商品主图和直播封面是不同对象，不互相代用规格；官方推荐比例与上传接口的强制限制分别记录。

| 平台及入口 | 官方资料中的横竖比例口径 | 像素尺寸口径与适用边界 | 官方依据 |
| --- | --- | --- | --- |
| 快手普通作品发布接口 | 封面参数未列出统一的横版／竖版比例 | 该页未规定封面固定宽高或最低像素；不能据此声称任意像素均可上传，也不将其他接口的尺寸限制移用于手机投稿 | [创建视频—发布视频](https://open.kuaishou.com/platformDocs/openAbility/contentManagement/createAVideo) |
| 快手小程序内容Feed卡片 | 补充分发封面字段包括ratio43（4:3）、ratio34（3:4）、ratio169（16:9）、ratio916（9:16）；主cover字段另标为比例任意 | 未给出固定像素宽高；该接口单张不超过10M，支持JPG／PNG／WEBP。这是第三方资源卡片接口规格，不等于普通作品或所有客户端必须提交四张封面 | [Feed卡片内容类接口](https://open.kuaishou.com/docs/develop/IndustrySolutions/createAnInterface.html) |
| 小红书商家课程：笔记封面展示建议 | 推荐竖版3:4；该处没有给出统一横版封面比例 | 未列出封面固定像素或最低像素；这是官方课程的制作建议，不是所有账号的强制上传限制 | [电商学习中心：商品笔记课程，第5.3.3节](https://school.xiaohongshu.com/lesson/normal/af0fe7e97bb0433fac9da5d1df52b07f) |
| 小红书商家课程：视频笔记封面建议 | 视频笔记段落推荐横版16:9／竖版9:16 | 未列出对应固定像素或最低像素；与同页3:4笔记封面展示建议分别保留适用场景，不合并成一个全站强制比例 | [同课程：视频笔记段落](https://school.xiaohongshu.com/lesson/normal/af0fe7e97bb0433fac9da5d1df52b07f) |

普通手机投稿端的统一封面像素下限、裁切方式及文件大小限制，未由上表资料完整确认；使用时按目标账号的实际发布入口或更新后的官方说明核对。没有明确依据时填写“未核实”，不将网上常见的1080像素、1242像素、3MB或5MB等数值标为平台统一硬性要求。

### 工作区选用的交付预设

默认每套只制作以下横竖两版，适用于“通用”及抖音、快手、小红书等目标平台的初始交付。比例和像素均为工作区制作选择，不代表各平台统一强制要求；默认交付PNG。已有用户指定规格优先沿用。

| 默认版式 | 比例 | 交付尺寸 |
| --- | --- | --- |
| 横版 | 4:3 | 1440×1080 |
| 竖版 | 3:4 | 1080×1440 |

其他比例仅在实际发布入口明确需要或用户指定时适配，不按平台名称自动另做一套。例如入口需要16:9横版或9:16竖版时，可选1920×1080或1080×1920；这两组像素仍是工作区自选尺寸，入口另有明确像素、格式或文件大小限制时按其要求处理。官方列出的可选比例或推荐比例，不自动成为本批必须交付的规格。

首次用于某个平台时，在实际发布环节核对封面上传预览、列表或主页裁切效果，确认标题、人脸和关键信息完整；只有入口需要时再从保留的原图适配，必要时重新排版。

规格依据固定区分“比例依据”和“交付像素依据”：分别注明官方强制／官方推荐／工作区预设／用户指定；引用官方要求或建议时附对应官方链接、适用入口和核实日期，入口裁切或上传未验证时如实注明。文件达到交付预设不等于已验证所有平台入口的显示效果。

平台预设更新不自动改变已采用封面、用户指定规格或历史批准。已有4:3／3:4等组合可以保留为其明确用途或用户指定规格；新增平台用途或改动现有画面时，再按本次授权适配，不批量裁切、扩图或重写原记录。

生成原图完整保留，真实尺寸以文件为准，不把请求比例或文件名当作实际规格。候选送审与用户决定沿[图片交付规则](核心参考图制作规范.md#851-图片交付与用户审核)。

后处理只用于使分辨率、尺寸和比例达到本次目标；明确目标宽高后，沿[图片后处理的方式选择](../../nora-generation/references/ComfyUI-图片超分执行规范.md#指定尺寸处理的方式选择)处理，Qwen备用封面同样适用，不套用其他资产的固定2倍要求。不为尺寸处理重新生图。裁切按本次用户授权执行，明显改变构图的裁切、补画或扩图作为修订处理。

用户批准的是具体原图。后处理完成后核对实际宽高、比例、格式和可解码性，记录原图、处理方式、结果及批准依据，再登记正式成品。原图与成品都保留，不把“画面已批准”写成“成品规格已达标”。项目原有不超分约定不免除目标尺寸和比例核对。

## 3. 项目级保存与记录

`10-封面资料/` 的建立时机执行[配套目录初始化](../../nora-ai-short-drama/references/共用规则/项目初始化规范.md#2-创建项目目录)，制作时复用已有根目录。下列索引、正式封面和过程资料分类首次有对应内容时建立，不预填空白文件。系列通用封面在项目内集中保存，单集专用图在套组名称和索引标注EP编号；用途不限定为发布。

```text
10-封面资料/
├── 封面索引.md
├── 正式封面/
│   └── {套组名称}-{平台标记}-{横版或竖版}封面.png
└── 其他资料/
    ├── 工作稿/
    │   ├── 封面制作-工作稿.md
    │   └── 素材/
    ├── 执行附件/
    └── 历史版本/
```

正式文件名如 `系列通用-抖音-横版封面.png`、`EP002-通用-竖版封面.png`。多平台共用文件的平台标记按适用平台顺序用加号连接，如 `系列通用-抖音+快手-横版封面.png`；平台字段仍使用顿号，不以文件名代替平台登记。候选使用 `{正式名去扩展名}-候选-vNN.png`，放工作稿素材目录；同名修改版本递增。同一用途的不同方案放在原封面对象的不同轮次，轮次名称写明方案区别；只有用户明确要求另存为独立用途时另建封面对象，不覆盖原对象。既有正式图及候选不因规则变更自动改名；获授权整理时保留原文件、历史记录及路径对应。

索引按[封面索引模板](../../nora-ai-short-drama/references/模板/封面索引模板.md)维护套组名称、逐项适用平台、当前成品、采用原图、范围、目标规格、规格依据、实际版本与批准／处理入口。索引封面名称写为“{套组名称} · {适用平台} · {版式}封面”；页面卡片简写“横版封面／竖版封面”，详细归属、文件名及记录放到详情。工作稿按[封面制作工作稿模板](../../nora-ai-short-drama/references/模板/封面制作工作稿模板.md)记录生成、讨论、审阅和规格处理；这是记录格式，不是提示词模板。通用与单集封面共用本项目的一个工作稿，生成序号持续递增。

实际提示词、调用清单及响应归执行附件，候选原图归工作稿素材。用户采用后保留源图及批准记录，正式成品放正式封面目录；替换、旧候选结束及历史留存沿[状态收尾](核心参考图制作规范.md#852-图片采用替换与归档后的状态收尾)。

旧资料迁移先留存完整原状及路径对照，再更新现行链接；既有请求、响应和历史批准事实保持原字节，不追溯改写执行参数。旧入口提供新位置和原状留存入口，避免并行维护两份当前工作稿。

## 4. 固定工具与浏览入口

Imagegen沿[固定交接工具](../../nora-ai-short-drama/references/comfyui-scripts/README.md#imagegen子代理交接与固定收尾)，使用 `kind:封面`、本项目封面工作稿及本次自由编写的 `prompt`。Qwen备用沿现有统一装配入口使用同一登记类型；只保留模型接口必需格式，不新增封面提示词模板。规格处理按上方方式选择；需要RTX放大时沿原后处理入队入口，本地处理直接保存实际处理记录。两种方式均关联采用原图和明确目标尺寸，结果在原生成条目补处理记录。交接本批实际图片时，将套组名称、适用平台和版式写入工作稿任务信息及现有工具的 `fields`，目标尺寸按该张已定规格填写；多平台选择不自动授权额外生图次数。

浏览页读取封面索引、工作稿及真实图片尺寸，提供“封面资料”栏目：对象卡片、当前正式版、最新候选、按轮次折叠的版本记录，以及待归类资料。原图与成品的查看／下载跟在对应条目后面，执行记录挂在所属轮次中。不从文件存在或目录位置推定采用批准。项目资料变更及工具结果的核验沿[交付同步](../../nora-ai-short-drama/references/流程规范/项目浏览入口规范.md#交付前同步检查)。
