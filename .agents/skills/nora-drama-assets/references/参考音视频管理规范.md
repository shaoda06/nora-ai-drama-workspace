# 参考音视频管理规范

版本：v1.17；更新日期：2026-10-24。

参考音频、参考视频属于项目级可复用素材，不绑定首次使用的剧集，不放单集 `04-专用素材/` 或在05建立正式副本。项目根目录固定使用 `07-参考音频/`、`08-参考视频/`，随项目初始化建立；内部目录按本节及第2节的实际入库需要建立，不增加会话阶段或预制全剧素材。

音频原素材保存、正式素材制作及生成使用统一执行[音频入库与取样](#21-音频原素材与正式素材流程)。参考视频仅接收符合当前参考输入要求、可以直接使用的素材，不存放待加工视频，不以入库任务主动裁剪、提取音轨、转码或另建加工版本；发现无法直接使用时说明问题并按实际授权处理。用户要求读取或分析视频内容时，按下节处理分析副本。

### 视频内容分析与正式入库

用户要求读取视频讲解、整理字幕或分析表演、动作、构图时，调用[视频读取与分析](../../video-study/SKILL.md)；字幕、转写、抽帧与证据区分由该技能统一维护。仅入库、查进度或生成结果通知不自动调用。

分析所需的临时音轨和图片帧使用系统临时目录，原视频不变，不自动登记RA／RV或作为正式生成参考。已有项目参考视频的持久分析结论写入本库既有工作稿，必要转写与图片证据归其`其他资料/执行附件/`；未入库的教学或共用视频按[资料归属](../../nora-ai-short-drama/references/共用规则/文件版本与工作稿规范.md#综合资料存放规则)保存，不为分析强行入库。分析完成不等于素材已批准采用，后续入库及正式取样仍沿本规范对应分支。

索引与被替换素材的必要旧版保存于本库 `其他资料/历史版本/`，不放项目根目录历史版本。实际执行产生的命令、日志与响应归本库 `其他资料/执行附件/`；分段视频生成任务的音视频上传证据仍归该次视频任务，不在本库重复留存。尚无执行证据时不为凑目录创建空附件。原素材与正式素材仍按本规范专用位置保存，不移入工作稿素材；试切输出仍按[本地取样与核对](#23-本地取样与核对)使用系统临时目录，不将参考视频库扩展为视频加工目录。

## 2. 编号、文件与索引

### 2.1 音频原素材与正式素材流程

1. **入库前检查**：先读取用户提供音频的实测时长、实际格式及可解码性，按[导演台第2.4节的模型输入限制](../../nora-generation/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#24-公共与本组的数量和时长限制)核对单条音频下限。低于模型下限时，明确告知用户素材过短、不能使用及所需最低时长，结束该素材入库；不保存到项目的原素材或正式素材目录，不创建RA入库条目。不能读取时长或解码时说明问题，待核对后再入库；不删除用户提供的源文件。
2. **保存合格原素材**：通过前置检查的用户音频，原封不动保存到 `07-参考音频/原素材/`，保留用户文件名、格式和完整内容，登记人物／声源、来源和使用授权；原素材不另分配素材编号、不覆盖外部原文件。同名且内容不同的文件不得覆盖，先明确保留名称。原素材仅作来源与加工依据，不能作为生成参考输入。
3. **制作正式素材**：已通过入库检查且不超过4秒（含4秒）的用户素材可直接复制为正式素材，保留实际时长。超过4秒时，选取一段连续声音，以4秒为目标裁剪另存。人物声音优先选择音色清楚、无其他人声覆盖的区间，环境或物件声选取体现目标声音的区间；不要求包含完整一句台词，也不要求精确为4.000秒。输出稍短但达到模型下限即可；按4秒目标裁剪后常见编码填充或毫秒级偏差不要求反复裁剪、转码，实际模型下限与容量仍须满足。不补静音、循环、拉伸或拼接凑长度。既有用户授权覆盖的入库／取样任务按本流程裁剪，无需对规定的裁剪再次请求许可；纯规则整理或只读检查不自动触发实际加工。其他降噪、变声、混音、从视频提取音轨等处理须有相应授权。
取样的本地命令与核对步骤见[本地取样与核对](#23-本地取样与核对)。

4. **核对与保存**：核对裁剪起止位置（直接复制时记未裁剪）、输出实测时长满足模型下限与容量、格式与完整可解码性，并实际听辨目标声音是否适合作参考。不以是否精确等于4秒作为通过条件，不因允许较短素材而补写不存在的时长。不能听辨时如实记录限制，不能写声音内容核对通过。原素材保留；仅符合文件与声音用途要求的结果保存到 `07-参考音频/正式素材/`。
5. **登记与引用**：正式素材按第2.2节命名。索引记录原素材入口、实际截取起止位置、正式素材入口及版本、实测时长、核对与用户决定；沿第3、4节更新人物关联及分段输入。正式素材尚未完成时，文件入口填“待制作”，来源列可链接原素材，不用原素材链接冒充正式文件。

现有素材检查先核对来源、时长及当前适用性；旧目录中的音频不因已有编号或过去入库而成为符合本规则的正式输入。迁移、改名与加工按本次实际授权处理；保留历史文件、原请求及批准事实，维护当前引用与迁移说明，不改写已提交任务。

### 2.2 命名与索引

- 音频原素材沿用户文件名保存，不套RA命名公式；正式音频使用固定三段式：`RA{三位编号}-{对象名称}-{参考用途}.{实际扩展名}`，例如 `RA001-林舟-说话音色.wav`。对象写具体人物或声源，不用“女主”等泛称；用途写音色、环境声或具体物件声。需要区分声音状态时写入用途段，例如“幼年说话音色”；不再添加秒数、“取样”或“完整音频”后缀。
- 视频沿用 `RV{三位编号}-{简短名称}.{实际扩展名}`，例如 `RV001-缓慢环绕运镜.mp4`。
- RA、RV分别在全项目从001连续编号，不在各分类内重启，不加EP前缀。原素材不额外占用RA编号；既有RA素材在获授权规范化其来源与正式取样时保留原身份，原留存版本和替换关系由索引追溯，不因加工重排已有编号。首次使用集号、来源及适用范围写入索引。
- 扩展名对应实际格式，不以改后缀冒充处理；音频原文件的格式保持，正式裁剪输出只做必要的编码，不自动附加其他声音处理。跨集复用不重命名或复制正式素材。
- 在索引保留来源及使用授权说明；参考视频库不承担原始视频暂存或加工管理。

两份索引统一使用以下列，实际类型写对应音频或视频：

| 编号 | 名称 | 分类 | 文件入口 | 参考用途与适用范围 | 来源及使用授权说明 | 实测时长 | 审核／采用状态及版本依据 |
| --- | --- | --- | --- | --- | --- | --- | --- |

音频索引的“文件入口”只链接正式素材；原素材、取样区间和来源核对依据写在“来源及使用授权说明”，当前处理结果、采用状态与具体工作稿依据链接写在“审核／采用状态及版本依据”，完整过程按[过程资料规则](#11-过程资料与历史版本)维护。只有原素材且尚无正式结果时可使用既有／计划RA条目说明待制作，不将计划编号记为正式文件已存在。不编造授权、实测或审批。索引不维护各分段上传槽位、模型标签或项目制作进度。

### 2.3 本地取样与核对

执行第2.1节已获授权的音频取样时，使用本机已记录的FFmpeg和Python调用路径；FFmpeg依赖的初始化与运行规则统一见[工作区README](../../../../README.md#ffmpeg初始化与运行)。以下为PowerShell调用，路径须为本次真实绝对路径，起点与长度单位均为秒。原素材只读；试切输出使用系统临时目录，不另建项目加工目录。

1. **确定区间**：用户已指定区间时使用该区间；未指定时结合试听选择。静音检测可辅助定位低音量停顿，不能识别人声身份、判断字音完整性或代替试听。记录起点、终点和拟取时长，不把检测参数或某份素材的区间作为通用固定值。
2. **裁剪输出**：只截取所选连续区间，裁剪输出为WAV、PCM 16位；保留源采样率和声道数，不默认降噪、变声、调音量、补静音或混音。使用`-n`避免覆盖已有结果，失败时停止该项，不把不完整文件记为通过。

```powershell
$taskFfmpeg = '<FFmpeg可执行文件的绝对路径>'
$taskPython = '<Python可执行文件的绝对路径>'
$taskAudioSource = '<原素材音频的绝对路径>'
$taskAudioStart = '<已选起点秒数>'
$taskAudioLength = '<已选连续区间的秒数>'
$taskAudioOutput = Join-Path ([System.IO.Path]::GetTempPath()) ('nora-audio-' + [guid]::NewGuid().ToString() + '.wav')
& $taskFfmpeg -hide_banner -nostdin -n -ss $taskAudioStart -i $taskAudioSource -t $taskAudioLength -map 0:a:0 -vn -c:a pcm_s16le $taskAudioOutput
if ($LASTEXITCODE -ne 0) { throw '裁剪失败，停止该项入库。' }
```

`-ss`为起点，`-t`为截取长度而不是终点；终点等于起点加长度。`-map 0:a:0`选取该音频文件的第一条音轨，`-vn`不输出视频；不能借此处理未获授权的视频音轨。

3. **文件核对**：读取WAV帧数、采样率、声道数及实际时长，再完整解码。正常退出、完整解码无错误和时长符合第2.1节条件才算文件核对通过；PCM／WAV的时长按帧数除以采样率计算，不以播放器显示的整数时长代替实测。

```powershell
& $taskPython -X utf8 -c "import sys,wave; w=wave.open(sys.argv[1], 'rb'); print('seconds=', w.getnframes()/w.getframerate(), 'rate=', w.getframerate(), 'channels=', w.getnchannels(), 'bytes_per_sample=', w.getsampwidth()); w.close()" $taskAudioOutput
if ($LASTEXITCODE -ne 0) { throw '读取裁剪文件失败，停止该项入库。' }
& $taskFfmpeg -hide_banner -nostdin -i $taskAudioOutput -map 0:a:0 -f null -
if ($LASTEXITCODE -ne 0) { throw '完整解码失败，停止该项入库。' }
```

4. **声音核对与正式保存**：按第2.1节试听核对；不能听辨时提供实际试切文件供用户试听，记录真实结论，不以技术检查代替声音内容核对。核对完成后，将同一试切文件按第2.2节命名复制到正式素材目录，不再次转码；已有同名正式文件时沿其实际版本和替换授权处理，不覆盖。只在保存成功后更新索引及人物／分段引用。未完成声音核对的试切文件不列为正式就绪；原素材和用户源文件保持。

## 3. 人物声音的可选关联

人物卡第五章的可选声音关联使用[人物资料卡模板](../../nora-ai-short-drama/references/模板/人物资料卡模板.md)中的固定字段，本节维护关联条件和素材管理，不另复制字段。“可选”指人物尚无参考音色时不强制创建，不表示已有适用的正式参考音色后可以任意省略。

确有多个声音状态才重复关联条目；人物卡保留正式文件引用及用途，来源／审核／版本详情按第2节在音频索引中维护。用户已指定声音来源但正式取样未完成时，记录“声音来源已指定，正式素材待制作”，关联索引说明，不将原素材绑定为可用于生成的参考音频。

文字设定与音频明显冲突先确认方向，不静默替换设定。模型标签、槽位和执行参数不进入人物资料卡，分段的实际用途按第4节处理。

已有用户确认采用、适用于当前人物状态的正式参考音色时，按每个生成分段的实际声音安排逐人物判断，只有以下两种处理：

- **本段发声，必须带**：包括开口对白、画外对白（VO）、心理独白（OS）及其他人物发声；对应正式参考音色必须进入本段实际参考输入，不能只在提示词中写“音色一致”或Audio标签代替输入。
- **本段不发声，禁止带**：即使人物出镜、在本集或同场其他分段有台词，也不得将其参考音色放入本段实际输入。

判断范围是当前分段，不按整集或整场统一携带。只有该批每个分段都需要的同一人物音色才可放公共区；只在部分分段发声时放入对应本组，不能让公共区将音色带入人物不发声的组。是否进入模型以公共＋本组实际合并输入为准，提示词不引用标签不等于排除该素材。

跨段发声沿用同一已选、适用且可追溯的正式声音来源；多个声音状态按人物卡的适用范围选择，不擅自替换。将音色特征与本句情绪、语速及播报方式分别描述，不把语气改变自动当作声音身份改变。人物对白和OS没有明确变声设定时沿同一音色，口型及声源性质按[心理独白与开口对白的切换](../../short-drama-storyboard/references/场次分镜制作规范.md#心理独白与开口对白的切换)处理。

尚无实际声音来源时，人物卡填写“暂未关联”，不为填表强制生成音频，不阻塞人物资料卡完成。确有待补声音需求时，在场次分镜既有参考输入规划写明人物、声音用途、计划份数及待提供／制作的事项；未知时长如实保留，不编造编号、文件或采用事实，不把需求记成已加入音频。不将尚无参考音色与已有参考音色但漏带混为一谈。

应带音色缺失、未就绪、适用状态不明或容量超限时，在既有准备／提交前检查中列明并先解决，不能省略、换用其他音色或将本段标为可直接提交。数量、时长及公共／本组安排按[导演台容量与超限处理](../../nora-generation/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#24-公共与本组的数量和时长限制)核对；需要调整分段时按[参考输入规划与分段可执行性](../../short-drama-storyboard/references/视频分段规划规范.md#参考输入规划与分段可执行性)处理。

用户已选正式素材后，按第2节登记并关联人物卡的既有声音字段；分段准备与执行引用按第4节落实。取样制作按[音频入库流程](#21-音频原素材与正式素材流程)及实际授权执行。

## 4. 分段使用边界

05准备文档说明本段实际拟采用的素材、版本与用途；按[第3节的逐段音色输入规则](#3-人物声音的可选关联)，将本段人物的发声情况、对应音色及纳入／排除结果记录在既有“主体与声音对应”和“提交前检查”中，准备完成时对照公共＋本组实际输入检查漏带和多带；提交时复用未变的准备结论，由工具核验实际绑定。既有执行附件中的实际输入映射记录真实上传返回路径和输入顺序，见[逐集目录与资产管理规范](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md)。RA／RV是项目资产编号，不等于H3的Audio／Video标签，每段按实际选用独立映射。

启用参考音频时，实际输入必须是第2节已核对的正式素材；原素材、旧目录完整音频及待制作条目不能上传作参考。执行前实际听辨／查看所选素材，按[导演台第2.4节](../../nora-generation/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#24-公共与本组的数量和时长限制)核对每组数量与音视频时长，按其第3节核对媒体字段、上传路径及[输出音频模式](../../nora-generation/references/ComfyUI-MiniMaxH3导演台节点使用规范.md#31-音频参考与输出模式)；其他执行规格与流程读取[H3执行规范](../../nora-generation/references/ComfyUI-H3视频执行规范.md)。项目素材要求与模型技术限制分别核对，模型能接收某文件不代表该文件符合正式入库规则。

准备模型正文时，按[逐集制作规范第6节](../../nora-video-prompts/references/视频提示词制作规范.md#6-分段视频提示词文档)读取官方参考模式指南，明确音频是音色／节奏参考还是经授权复用的原声，将用途及对应人物写入05计划映射，执行记录保存实际输入和输出音频来源。参考用途、原词处理和Audio／Subject／Sx绑定以该官方指南为准；输出模式不替代参考用途说明。声景与配乐按[逐集制作规范](../../short-drama-storyboard/references/场次分镜制作规范.md#声景与配乐)执行。

本规范不授权搜索、采购、生成、上传或批量迁移素材；按用户实际任务执行。获准整理旧项目时同步人物声音关联及受影响引用，保留来源和批准事实，不自动改名其他项目文件。
