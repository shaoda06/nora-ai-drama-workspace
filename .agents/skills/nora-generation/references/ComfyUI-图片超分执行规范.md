# ComfyUI-图片超分执行规范

版本：v1.26；更新日期：2026-10-20。

适用于需超分的生产图片：人物正面半身图、服装正背面图、道具三视图、资产状态参考图（服装／场景／道具）、虚拟道具基础界面、场景参考图、首帧参考图及新生成的剧集专用参考图。本规范所列类型的新生成及修订候选先以对应低分辨率原生生成并送审，用户批准具体版本后，以该审批原图执行一次2倍超分，核对正式尺寸后保存。超分是获批图的后处理，不重新生成提示词，不调用Qwen采样，不裁切、拉伸或换图；修改后的新候选须重新审批。

| 图片类型 | 送审／正式尺寸及比例的规则入口 |
| --- | --- |
| 人物半身、人物六视图、服装正背面、角色六视图 | [人物专项规则](../../nora-drama-assets/references/人物参考图制作与记录规范.md#2-规格背景与布局) |
| 道具三视图、道具状态参考图、虚拟道具基础界面 | [道具规范第3节](../../nora-drama-assets/references/道具资料与参考图规范.md#3-三视图与状态规则) |
| 场景参考图 | [场景规范第4节](../../nora-drama-assets/references/场景资料与参考图规范.md#41-画面要求) |
| 资产状态参考图 | [统一资产状态规则的对应规格入口](../../nora-drama-assets/references/Qwen-Image-2.1-提示词规范.md#27-资产状态参考图统一规则) |
| 新生成的剧集专用参考图 | [集内素材规则](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#21-剧集专用参考图) |
| 首帧参考图 | [首帧规范第1节](../../short-drama-storyboard/references/首帧参考图规范.md#1-制作复用与画面要求)，区分新生成与已有图／视频取帧来源；仅对该入口要求超分的图执行本规范 |

2倍指宽、高各为输入的2倍，总像素为4倍，画幅比例保持不变。新任务先核对本类型送审尺寸和节点约束，取回后核对真实输出；不将节点可填写的尺寸视为已经实测成功。不将高分辨率旧图缩小再放大冒充低分辨率原生生成。

人物本体六视图与穿衣角色六视图的规格及直接原图保存要求读取[人物专项规则](../../nora-drama-assets/references/人物参考图制作与记录规范.md#2-规格背景与布局)，不进入本超分流程。画风验证样例保留原图作为风格依据，不进入资产超分流程。导入的剧集专用参考图按其专项规则记录实际处理，不因本规范要求补做生成或超分。

## 1. 触发与输入

- 先在原生成／审阅记录确认用户已批准的对应审批尺寸具体版本，核对实际文件、来源和可解码性。用户批准即接续本规范的超分，无需再问一次执行许可；尚未批准、仅部分认可或未明确版本时不提交。
- 输入必须是被批准的审批原图；不使用另一张同人物／同道具／同场景的其他图或中间预览。已有远端素材按原凭据核对，本轮新素材交后台上传并使用实际返回路径。审批原图与其请求、批准记录完整保留。
- 历史已批准的其他尺寸资产保留，不批量补超分、不因规格变化撤销批准。明确技术测试可以使用指定测试输入，测试结果不登记为正式资产。
- 按[工作区选端及任务地址规则](ComfyUI-服务配置与任务提交规范.md#工作区-comfyui-配置)选择新任务服务或恢复原任务；准备检查与远端能力诊断按[执行前检查与复用](ComfyUI-服务配置与任务提交规范.md#执行前检查与复用)执行，不将库存查询作为常规任务步骤。节点缺失或执行异常时保留实际错误，不自动安装依赖、切换放大器或重提；获授权的节点部署沿用[节点与安装包规则](../../nora-ai-short-drama/维护规范.md#comfyui节点与安装包)。

## 2. 配套工作流与参数

本地[画布基准](../../nora-ai-short-drama/references/comfyui-workflow/后处理综合/Nora-RTX-图片2倍超分.workflow.json)和[API基准](../../nora-ai-short-drama/references/comfyui-workflow/后处理综合/Nora-RTX-图片2倍超分.api.json)配套维护。每次复制API任务副本，替换输入路径及输出前缀，不改写基准或远端保存的工作流。

| 节点 | 类名与输入 | 固定要求 |
| --- | --- | --- |
| 2 | `LoadImage.inputs.image` | 被批准的审批原图的真实上传路径 |
| 1 | `RTXVideoSuperResolution.inputs.images` | `["2", 0]` |
| 1 | `resize_type` | `scale by multiplier` |
| 1 | `resize_type.scale` | `2`，动态参数完整键名不可改为`scale` |
| 1 | `quality` | `ULTRA` |
| 1 | 共用必填输入 | 按[RTX节点共用必填输入](#rtx节点共用必填输入)显式填写，不能省略远端标为必填的默认参数 |
| 3 | `SaveImage.inputs.images` | `["1", 0]` |
| 3 | `filename_prefix` | 本任务唯一可辨认的超分前缀 |

正式输出节点为3，PNG数量1，实际宽高分别为批准输入的2倍，符合上表对应正式尺寸和比例。画布中的ImageCompare只用于人工操作时对照，不属于API正式输出或自动看图环节。没有提示词、种子、CFG或采样步数，记录为不适用，不伪造扩散模型参数。

### RTX节点共用必填输入

图片超分和视频后处理使用 `RTXVideoSuperResolution` 时，任务API明确填写 `strength=1.0`、`image_encoding="8-bit RGB"`；画布的命名控件与位置控件同步保存这两个值。前者为处理强度，后者为SDK像素编码；它们不能因远端提供默认值而从API省略。尺寸、缩放方式、质量和帧率仍按各自图片／视频执行规范填写。

现行图片与视频工作流的配对基准均保存这些字段。固定 `--prepare-only` 入口和离线配对工具检查已知必填输入及取值；缺字段时在本地停止，不上传、不生成，也不由工具自动补值。准备报告复用与节点接口差异的处理见[服务配置与任务提交规范](ComfyUI-服务配置与任务提交规范.md#远端能力与错误返回)。已生成任务的原请求、参数和批准记录保留，不因维护基准而改写。

## 3. 执行与恢复

新任务使用[统一入队入口](../../nora-ai-short-drama/references/comfyui-scripts/README.md#nora统一分配与提交)，任务类型image-upscale。Agent在[任务清单](../../nora-ai-short-drama/references/comfyui-scripts/README.md#一次装配与批量入队)提供已批准原图、原批准章节、正式目标及必要适用内容；工具装配API／画布、节点2的image上传绑定、节点3的一张PNG成果映射及本机候选目标，不由Agent手工逐份填写；超分附件沿用原前缀追加超分序号，不另建调度目录。后台上传批准原图、按队列提交并留存真实路径、请求、远端ID和响应。

工具在提交前自动准备[图片收尾计划](../../nora-ai-short-drama/references/comfyui-scripts/README.md#图片及超分收尾计划)，关联批准输入、原批准章节、正式路径及正式资产表和关联入口的更新。入队成功汇报数量即结束本轮，不补ID、进度或查网页。后台按[监控规范第4节](ComfyUI-任务监控规范.md#4-图片处理)完成下载、下节规格与来源核对、正式保存和网页同步后再通知。Agent收到通知只调用report并直接展示结果，不重复检查或补常规记录。下载失败使用browser_tasks.py retry-collection请求原任务只重试取回，不重新超分。生成失败、状态未知及提交不明均保留原批准事实，不自动再POST。

预期输出为节点3的一张正式PNG，本机候选按原候选名追加超分序号保存，下载凭据位于原执行附件。后台只按已批准原图及收尾计划完成正式采用；需要替换已有正式图时必须提供归档入口，不覆盖历史文件。异常报告保留真实完成范围，未完成正式保存时不记已采用；原批准事实不因技术异常撤销，下载完成不等于正式收尾完成。

## 4. 文件核对、保存与记录

原生成条目的当前采用字段与批准依据保留在原处，填写格式读取[开发流程8.5.1](../../nora-drama-assets/references/核心参考图制作规范.md#851-图片交付与用户审核)。批准后尚未完成时保留批准；等待、处理中和异常写入执行结果及原因与依据。完成规定核对及正式保存后更新采用状态，原因与依据记录“批准后2倍超分”，关联审批原图、超分子记录及正式文件。未送审、待确认及候选结束状态读取[开发流程8.5.1、8.5.2](../../nora-drama-assets/references/核心参考图制作规范.md#851-图片交付与用户审核)，不因后处理改写用户决定。

由后台核对实际宽高符合准备计划及上表对应正式尺寸、PNG、数量1、可解码性及来源：工作流确为批准的审批原图→节点1两倍→节点3，复用已接受任务及终态成果关联，核对实际请求、上传及下载响应。正常通知后Agent直接使用报告，不重复读取这些证据。默认不调用看图能力，不宣称细节或身份的视觉保真已经验证。需要视觉分析时按[看图边界](../../nora-ai-short-drama/SKILL.md#看图能力调用边界)取得明确授权。

超分不增加第二轮默认画面审批。文件与记录核对通过后，将对应正式尺寸结果作为已批准版本的正式交付文件并展示；批准依据仍指向审批原图，记录“批准后2倍超分”，不能伪称用户另行审核了超分细节。若用户要求再审超分结果则先送审。超分尚未完成时不将审批原图冒充正式尺寸图，不替换旧正式文件，不开始依赖该新正式图的下游制作。

人物、道具、场景及首帧分别沿用[人物](../../nora-drama-assets/references/人物参考图制作与记录规范.md)、[道具](../../nora-drama-assets/references/道具资料与参考图规范.md)、[场景](../../nora-drama-assets/references/场景资料与参考图规范.md)及[首帧](../../short-drama-storyboard/references/首帧参考图规范.md)中的生成／审阅模板：原生成条目保留审批原图、参数及用户批准，在同条目补充超分子记录。子记录依次编号`超分-001`等，实际超分提交次数与原生图次数分开，不重置历史、不为后处理另算一次Qwen生成。机器附件沿用对应资产专项规范规定的原生成前缀，追加`-超分-001-*`，不在此另定义各类型的原生附件命名；候选超分文件为`{原候选名去扩展名}-超分-001.png`，存放位置按[工作稿管理规则](../../nora-ai-short-drama/references/共用规则/文件版本与工作稿规范.md#工作稿管理规则)执行。当前正式表登记对应正式尺寸文件，采用版本写原候选版本及超分编号，审阅入口指向原批准记录；正式文件名和层级不变。按[采用后收尾](../../nora-drama-assets/references/核心参考图制作规范.md#852-图片采用替换与归档后的状态收尾)同步引用及浏览页。

画风验证样例的保存及展示读取[定位画风验证流程](../../short-drama-develop/references/项目定位与画风规范.md#项目画风展开示例验证与复用)，本规范不另维护样例尺寸。

## 5. 维护验证

修改配套工作流或节点映射时，在技能目录执行离线配对校验及回归：

```sh
python3 scripts/workflow_baselines.py
python3 -B -m unittest discover -s scripts -p 'test_workflow_baselines.py' -v
```

校验应包含本图片超分配对，执行节点为2、1、3；静态通过不证明服务端执行成功。实际验证须使用明确的技术测试输入，保存请求、结果和真实尺寸，不修改业务批准或自动替换项目资产。
