# ComfyUI-H3视频执行规范

版本：v1.100；更新日期：2026-10-25。

本规范管理视频工作流的填写、执行与记录。制作顺序及审批读取[开发流程第二部分第7节](视频阶段与返修执行规范.md#7-生成视频验收与衔接修改)，后处理与其他视频修改的阶段归属读取[阶段与当前版本修改](视频阶段与返修执行规范.md#视频阶段与当前版本修改)；提示词正文读取[视频提示词制作规范](../../nora-video-prompts/references/视频提示词制作规范.md#6-分段视频提示词文档)及 `h3-prompt-writing`。准备资料、实际任务和人工审核按[逐集目录规范](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md)保存，不把技术成功写成内容获批。

## 0. 制作策略与工作流配置

视频生成的默认入口为“Minimax-H3-导演台-视频生成-标准版”，使用同一画布的四种配置；按[配置及横竖屏表](#标准版四种配置与生成前询问)设置LoRA、采样步数、尺寸、Refine参数及对应后处理分支，并按“一采确认与二采”分轮执行。正式生成使用原生MiniMax H3导演台，一采与二采通过同一画布分轮执行，输入模式默认为r2v / Ref2VA。准备或修改节点内容时按[导演台任务阅读路径](ComfyUI-MiniMaxH3导演台节点使用规范.md#任务阅读路径)选读，覆盖本次组与P映射、素材、正文、时间线及执行所需条件。

| 工作流 | 当前用途 |
| --- | --- |
| Minimax-H3-导演台-视频生成-标准版 | 正式默认多功能画布，DMAD与343常开，Mystic和打戏组按本次选项启用；502为导演台，407为Refine；首次只一采，人工确认后再次执行二采；默认分段导出，403报告驱动执行 |
| RTX-RIFE-自动切镜保护超分插帧 | 文戏配置1、2的后处理：逐段输入选定二采，先插帧再超分；横竖屏目标按[后处理交付规格](#后处理交付规格)填写；制作开始条件见[整场后处理安排](视频阶段与返修执行规范.md#7-生成视频验收与衔接修改) |
| RIFE-自动切镜保护裁切 | 打戏配置3、4的后处理：逐段输入对应尺寸的选定二采，先插帧再按短边方向两侧各裁4像素；横竖屏裁切位置按[后处理交付规格](#后处理交付规格)填写；制作开始条件同上 |

标准版生成前先按[四种配置与生成前询问](#标准版四种配置与生成前询问)确定本次有效配置。一采参数和工作流确认不等于具体视频获批，也不授权下一批任务。二采与后处理仍需指定获批来源和对应执行授权；各阶段尺寸、Refine设置与执行端条件见第2节。

## 1. 当前固定基准与任务副本

工作流基准与任务副本的维护边界统一读取[维护规范](../../nora-ai-short-drama/维护规范.md#工作流基准与任务副本)。正式与非正式文件的目录归属按[维护规范第1节](../../nora-ai-short-drama/维护规范.md#1-目录分类与文件归属)执行。画布保留UI布局、导演台公共/本组编辑状态及说明；API只保留正式输出所需的服务端依赖。标准版节点标题使用“中文解释名｜英文原名”，英文原名保留节点实际类型名（例如`二采前馈分块｜MiniMaxChunkFeedForward`）；标题不写节点编号、权重、步数、块数、尺寸、设备或开关状态等实际配置，参数保留在控件与执行规则中。API的`_meta.title`沿用同一格式，实际节点ID及类型标识不改。

### 1.1 离线API检查与回归测试

[workflow_baselines.py](../../nora-ai-short-drama/scripts/workflow_baselines.py)使用Python 3.9及以上标准库，只读取API，检查必要输出、连接引用、RTX必填参数、后处理链路及API内部导演台时间线和编辑状态。不读取画布，不做画布与API一致性或差异比较。

```sh
python3 -B /实际技能目录/scripts/workflow_baselines.py
python3 -B -m unittest discover -s /实际技能目录/scripts -p test_workflow_baselines.py -v
```

可选`--directory /待检查目录`，扫描其中API及统一目录入口登记的直属分类，不递归扫描其他目录。默认覆盖5份正式API，非正式目录当前为空；每份输出一行JSON，成功输出PASS并退出0。空目录也可返回成功，须确认目标有被覆盖。修改API或相关脚本时运行；普通提交不重复跑整套测试。不使用`-O`。

后处理报告列出宽高、目标帧率和编码参数；低于交付建议只提示，不强制改写用户已确认目标。正式RIFE同时检查随包ZIP的必需文件、完整性和Python语法，不加载模型、不运行GPU。测试不连接远端，不证明实际生成或用户批准。

### 1.2 任务参数来源与准备提交

执行责任见[视频执行分工](ComfyUI-服务配置与任务提交规范.md#视频执行分工)。新建首次一采的内容准备从第1节对应的现行本地 `.workflow.json` 基准配置本次内容画布；通过[任务清单入口](../../nora-ai-short-drama/references/comfyui-scripts/README.md#一次装配与批量入队)由工具导出配套API、装配上传／成果映射、执行检查并入队，不由Agent平行编辑两份技术副本；不是从空白重建节点、凭记忆重写固定参数，或直接提交含样例内容的基准。固定生成参数以第2节及配套基准保存值为准，不以远端节点出厂默认值、网页临时显示值或旧项目副本替代。

任务清单从本次指定内容画布导出实际API；旧式逐项入口读取`--workflow`指向的最终API副本。两者不自动加载最新基准、填补未授权配置或升级旧任务。后台按上传绑定将真实素材路径同步到受影响的API／画布字段后提交；其余已准备的生成配置沿用任务副本。准备报告复用、入队及执行时点核验读取[执行前检查与复用](ComfyUI-服务配置与任务提交规范.md#执行前检查与复用)，不在提交阶段增设人工逐项复查。基准变更不追溯更新已准备、入队或已提交任务；确需变更尚未提交的登记任务时按[准备检查与提交复用](../../nora-ai-short-drama/references/comfyui-scripts/README.md#准备检查与提交复用)显式重新准备，已有提交证据的任务不重写或重发。

标准版画布完整接线为192 → 331 → 53 → 128 → 342 → 344 → 345 → 343 → 405，默认将128、342、344、345旁路，实际执行链为192 → 331 → 53 → 343 → 405。LoRA、采样步数、生成尺寸与后处理按下节选择，其他生成参数和时间线保持不变；405直接接261和502；二采独立支路为405 → 408 → 409 → 407.refine_model。执行端须提供上述两个分块节点及对应参数接口，不用Refine的时间／空间分块开关替代模型分块。331选择完整注意力计算后端，一采与二采均沿用Kitchen；不串接Sage补丁或332稀疏注意力。407连接502.refine；没有SelfLift、FaceRefine或语义桥连接。两轮实际步数按外部SIGMAS及一采补零后的结果记录，不能把261显示的总步数登记成两轮实际总步数。

Refine先按一采比例及 `megapixels × 1024²` 计算目标宽高，再分别对齐32；仅填写width/height不会覆盖这一计算。一采1024×576时，MP=1.265625得到1536×864，MP=1.9921875得到1920×1088；竖屏576×1024使用相同MP分别得到864×1536和1088×1920。任务副本同时填写MP与目标宽高，执行依据是实际API中的MP；不要只改宽高控件。打戏二采受32对齐影响，比例略偏离16:9／9:16，后处理按短边方向裁掉8像素得到标准画幅；不拉伸二采原片，也不改写一采缓存。

参考图片尺寸由各组 `refImageSize="1536"` 控制，保持原比例；该设置与生成画布尺寸及 `ref_max_size / refMaxSize` 分开，不通过修改后者替代。正式基准各组与output回退值均保存1536；准备、新增、复制或导入任务分组时逐组落实，并同步根时间线及对应编辑工作区。插件“新增分组”会生成自己的尺寸值，不能宣称仅修改基准JSON就改变了插件默认行为；手动画布可复制已设1536的组，新增空组则须选择1536。

执行端的清理实现须在模型GC／卸载前清空动态显存预取队列，按阶段保留／卸载模型，并支持 `precise_segment_memory`。精确调度按模型权重大小与物理内存总量的比例选择策略，不是按当前内存占用率决定。节点缺少所需接口时报告兼容性问题，不静默删掉参数、覆盖插件或更改启动配置。

基准更新及版本选择用于后续获授权任务，不自动改写已有任务副本、请求或批准来源。已有一采的二采接续沿用原工作流版本和原一采尺寸，不自动改用当前基准或其他LoRA配置；需要切换时先核对模型链与缓存影响。参考图策略属于一采缓存输入；已有一采接续二采时按[制作变更时的缓存保护](ComfyUI-MiniMaxH3导演台节点使用规范.md#751-制作变更时的缓存保护)及第5节保留来源配置并核对缓存，不套用新基准导致重新一采。不同分辨率的一采即使使用同一种子也可能产生不同构图和动作，既有内容批准不自动转用于另一尺寸的新结果。

### 标准版四种配置与生成前询问

### 后处理交付规格

后处理推荐分辨率不低于1080P、帧率30fps；横屏16:9基准为1920×1080，竖屏9:16对应1080×1920，其他画幅按实际比例选择，不拉伸凑尺寸。这是制作建议及基准默认值，不是所有平台的硬性门槛；其他明确选定的规格可用于实际任务。平台发布入口、合同或项目另有已确认要求时，记录其依据并采用对应值，不把支持的最高帧率当作最低要求，也不默认把所有视频补到60fps。

视频码率12～16Mbps可作为1080P交付的推荐参考，不作强制区间或最低值。实际码率还受帧率、画面复杂度、编码器及质量设置影响。基准使用H.264、CRF 19按画质编码，不保证成品落在该区间；只有本次交付确需限定码率时，才按已确认要求配置码率控制。准备记录区分平台硬性要求、推荐参数与实际选定目标；结果记录区分视频轨平均码率与含音频、封装的文件总平均码率，注明测量来源，不把推荐值填写为实测结果。

源文件已满足本次选定规格时，无需仅为套用基准再次插帧或超分；需要处理时保持原播放时长及音画同步，并保留真实切镜，不跨切镜生成混合过渡。任务副本按实际画幅与交付目标调整，画布和API同步；基准更新不改写历史任务、视频、审批或采用记录，不构成重新处理的授权。

后处理准备与提交前按[开发流程第二部分第7节](视频阶段与返修执行规范.md#7-生成视频验收与衔接修改)核对整场开始条件、指定来源及执行授权；每个后处理任务使用该P选定的二采原文件。配置1、2选用RTX-RIFE超分基准，配置3、4选用RIFE裁切基准，方向与目标按上表；不能把裁切配置当作全部视频的默认后处理。两种基准均先在源视频尺寸下以RIFE插帧到30fps。节点12为`NoraRIFEInterpolationCutTest`，使用已安装的原`RIFEInterpolation`及已有`flownet.pkl`；节点包与安装验证统一见[节点与安装包](../../nora-ai-short-drama/维护规范.md#comfyui节点与安装包)，固定接口名不因正式使用而改变。默认`target_fps=30`、`scale=1.0`、`scene_cut_threshold=0.15`、`batch_size=1`、`use_fp16=true`。节点在内部用64×64 RGB相邻帧差异检测切镜，按整段目标时间表将跨切点的插值改为源帧保持，其余位置使用原模型；不按手填切点拆片，不跨切镜混合，也不按镜头分别四舍五入帧数。阈值0表示关闭保护，仅在本次任务明确选择时填写；闪光、快速运动和相近构图可能影响检测；结果按[后处理自动采用](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#后处理自动采用)处理，用户反馈具体问题时再按实际授权返修。

文戏RTX-RIFE基准节点1为`RTXVideoSuperResolution`，使用`target dimensions`、横屏`width=1920,height=1080`／竖屏`width=1080,height=1920`、`quality=ULTRA`，显式填写[RTX共用必填输入](ComfyUI-图片超分执行规范.md#rtx节点共用必填输入)。画面连接为`7.images → 12.images → 1.images → 16.images`。打戏RIFE裁切基准节点1为`ImageCrop`，画面连接为`7.images → 12.images → 1.image → 16.images`，按上表填写裁切位置及目标宽高，不接RTX、不缩放、不拉伸；只用于对应横／竖屏打戏二采尺寸，历史或其他尺寸来源另行确认处理，不能默认裁切到所选交付尺寸。

两种基准均将`12.source_fps`连接`7.fps`，`16.frame_rate`连接`12.fps`，`16.audio`直接连接`7.audio`原音轨，`trim_to_audio=false`。源帧率到目标帧率的整数帧量化可有不足一帧差异，不用修改播放速度代替插帧；默认H.264／yuv420p／CRF 19。任务完成后按[任务监控规范](ComfyUI-任务监控规范.md)取回成果，由后台核对尺寸、帧率、时长、码率和来源，再按[后处理自动采用](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#后处理自动采用)录入并补全记录后汇报。安装或模型缺失时报告实际错误，不自动下载、升级或替换方法。

节点16的`VHS_VideoCombine`画布控件`widgets_values`使用按字段名保存的对象，不使用位置列表；任务副本修改输出身份时保留对象格式。编码设置为`format=video/h264-mp4`、`pix_fmt=yuv420p`、`crf=19`、`save_metadata=true`、`trim_to_audio=false`、`pingpong=false`、`save_output=true`，API按同名输入填写。手工导入画布后，输出名称中的编号占位符须替换为本次实际身份；源视频、目标尺寸和插帧设置按本次已确认要求填写。

正式工作流更新不修改历史任务副本、视频、审批或采用记录，不自动重新处理其他视频。

### 场次基准种子与实际任务种子

同一EP/C首次一采先查已有场次基准种子；没有时采用用户指定值，未指定则生成一次允许范围内且可精确序列化的整数。后续同场首次一采沿用。内容返修默认沿用来源任务的实际种子，便于比较提示词、素材或时间安排的修改效果；新增R编号或选择部分分段本身不触发换种子。固定种子用于控制随机因素，不保证保留原构图、表演或动作，也不保证正确执行修改后的提示词。

**主动建议换种子尝试的条件**：在处理用户反馈、制定一采返修方案时，出现下列情况应主动提出，不等用户先提种子：

- 已对照该次冻结请求，确认相关描述清楚、参考输入无冲突、动作时间与构图可见范围合理，但用户反馈仍有漏动作、表演不合适等生成偏差，建议保持方案不变、更换少量种子作对照。
- 根据用户反馈及既有记录，同类问题连续返修仍存在，重新判断原因，并将换种子列为备选；发现文本、素材、时间或配置的明确问题时先处理，不以换种子代替修正，也不只反复叠加同义措辞。

提出建议时说明具体问题、已核对的依据、推荐候选数量及P范围，不将疑点说成种子已被证实有问题，不承诺换种子必然修好。沿用用户已有的明确选择和执行授权；尚未覆盖换种子或追加候选时，先确认该范围。仅换种子的对照保持提示词、素材顺序、时长和其他生成配置不变，保存各次实际种子与来源；候选完成后交用户审核，不自动追加尝试。不要求每次返修都先跑固定种子、再跑新种子两轮，也不因正常结果通知触发主动审片或生成。

上述选择用于新的一采返修；获批一采接续二采仍保持其来源种子，不以换种子绕过缓存问题。换种子的修订编号及留存按[视频修订编号规则](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#视频修订编号与执行过程)处理，不改写场次基准、历史请求或批准事实。

场次基准和来源在本场首个任务的 `输入映射.json` 保存，后续记录引用该入口并记录本次实际值；不另建种子台账。每次导演台提交只有一个全局seed，作用于该批实际运行的各组；选择运行不会自动创建分组独立种子。一轮生成七组时，七组使用同一实际种子；选择其中三组时，这三组仍共用该任务的seed。画布control_after_generate保持fixed，不在轮次结束后自动随机或递增。另行探索改变全局种子时，说明其他组后续缓存匹配也受影响；历史获批来源确有不同实际种子时按各自来源核对，不用一个值覆盖历史。恢复查询及故障恢复保持原任务种子，不因查询重复提交。画布/API内7503308486466147是示例，不能直接当作其他项目的场次基准；不得在执行后读取前端下一次种子冒充本次实际值。

请求时长、17k+5帧格及时间线同步按[导演台节点使用规范第5节](ComfyUI-MiniMaxH3导演台节点使用规范.md#5-时长帧数与编辑状态同步)处理；保存请求秒数、计划帧数和真实输出时长，严格时长要求需明确方案，不默默裁切或变速。

标准版的预览与保存接线：502.images_pre_refine（槽位6）→503 CreateVideo→504 SaveVideo；502.images（槽位0）→505 CreateVideo→506 SaveVideo。两条CreateVideo均连接502.audio（槽位1）和502.fps（槽位2），使用8位sRGB；SaveVideo使用MP4／H.264，任务中分别使用[远端输出目录](ComfyUI-服务配置与任务提交规范.md#远端输出目录与命名)的项目辅助预览前缀，提供播放预览和下载，不代表全部分段成果或采用状态。

首次一采确认时最终images口被阻断，只能由504保存一采；人工批准后沿用同一任务副本、缓存名、导演台节点ID、实际种子和一采输入再次执行，命中一采缓存后执行二采，由506保存二采。二采轮可能同时输出一采对照视频，不能把504的对照文件登记为新一采或二采成果。缓存缺失或不匹配按[远端缓存复用与缺失处理](ComfyUI-MiniMaxH3导演台节点使用规范.md#752-获批一采缓存的远端复用)处理，不改关闭确认来绕过审批。

默认segments导出时，外接保存仅用于最后实际运行组的辅助预览，完整逐组文件仍由403最终报告驱动后台取回；不替代逐组P映射。明确使用all导出时，两条保存分支接收相应阶段的合并画面，保存为合并视频，不能当作所有P的独立文件。任务完成后再取回全部预期成果。

### 2.1 已批准的输出前缀公式

R的分配、阶段转换、失败恢复及完整结果后的再次生成读取[视频修订编号与执行过程](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#视频修订编号与执行过程)，不由任务ID或提交次数分配新R。

可配置保存节点统一按[远端输出目录与命名](ComfyUI-服务配置与任务提交规范.md#远端输出目录与命名)填写，包括标准版504／506辅助预览、需要外接保存的任务、历史任务副本中的264／214及后处理16。导演台插件内部的分段保存和缓存目录保持其原有规则，不由外接前缀控制。下载只认实际返回的filename/subfolder/type。

多组任务的共同证据位置、任务状态与各P输出记录读取[多组任务的共同证据与状态](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#多组任务的共同证据与状态)；合并文件不冒充每个P的独立输出。正式场次/整集保存与计数按逐集目录规范；已有用户明确指定的技术测试位置可沿用。不因导演台一次导出多组就自行创建一套正式目录或计数规则。

既有二采使用265的可选外部加载器时，以其画布映射与 `_meta.nora_optional_reference` 为准，填写实际文件并接入目标槽位，删除所有未用加载器。保留结构不等于已获新二采执行授权。

## 4. 提交、恢复与结果取回

服务配置、选端与恢复地址执行[工作区ComfyUI配置](ComfyUI-服务配置与任务提交规范.md#工作区-comfyui-配置)。新任务的准备与入队按[服务与任务提交入口](ComfyUI服务与任务提交规范.md#comfyui服务与任务提交)执行，不向远端发布基准。已有后台任务按[查询与结果处理入口](进度查询与结果处理规范.md#进度查询与结果处理)选择[状态查询](../../nora-ai-short-drama/references/comfyui-scripts/README.md#后台状态查询)、[通知确认](../../nora-ai-short-drama/references/comfyui-scripts/README.md#后台通知确认)或[取回重试](../../nora-ai-short-drama/references/comfyui-scripts/README.md#后台取回重试)，无需加载上传、提交或完整comfyui-api说明。

1. **准备**：内容已备时，工具从指定内容画布制作任务副本并自动建立分段阶段技术条目；内容尚未准备时先从正式基准配置当前内容，替换全部业务占位符，保存组与EP/C/P映射、获批资料版本、完整模型正文、实际素材、种子和输出范围。冻结任务按[逐集目录规范第4节](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#4-视频执行输出审核与采用)保存，05不维护运行流水。
2. **准备核对**：内容合理性由Agent在准备阶段完成，可程序判断的格式和执行条件调用工具生成报告；按[执行前检查与复用](ComfyUI-服务配置与任务提交规范.md#执行前检查与复用)复用本地工具报告，不预查远端节点／模型能力；由工具按所选标准版配置检查19／20／22／23个节点的API结构、素材身份和数量/时长、标签、时间线与输出位置；按[模型提示词长度规则](../../nora-video-prompts/references/视频提示词制作规范.md#模型提示词长度)核对各分段最终正文并记录结果；内容与格式分别核对、分别记录结论，语言适配读取[语言与命名](../../nora-video-prompts/references/视频提示词制作规范.md#h3模型正文的语言与命名)，检查要求及结论留存直达[模型正文的内容核对](../../nora-video-prompts/references/视频提示词制作规范.md#模型正文的内容核对)，资料包的其他交付项按[交付核对](../../short-drama-review/references/交付核对规范.md#交付核对)执行。不能用UI注册或上传成功证明全组合可运行。
3. **入队**：本次生成获授权后直接使用已核对资料通过统一入口登记，不重新通读内容或手工重跑技术检查；登记只做必要边界校验并保存本地任务ID；轮到执行时由工具统一比较准备依据并复用未变结论，上传后只核对实际改写的素材绑定，不比较画布与API，具体边界按[执行前检查与复用](ComfyUI-服务配置与任务提交规范.md#执行前检查与复用)执行。Agent只提交已备内容及语义映射；脚本导出API、装配绑定和成果目标、自动维护执行条目；后台轮到任务时上传，在POST前按[生成版本的资料关联](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#生成版本的资料关联)冻结当次资料，保存实际地址与远端ID。参数见[视频资料自动保存](../../nora-ai-short-drama/references/comfyui-scripts/README.md#视频资料自动保存)。
4. **跟进**：后台按[任务监控规范](ComfyUI-任务监控规范.md)监听、重连及核对，Agent不另开定时器。收到结果通知后只调用report，在同次读取中确认收到，直接汇报数量和审核入口；不再读常规记录或补写；失败从具体失败阶段复查，不自动安装、重启、清队列或替换模型。

   原ID丢失时执行[故障后的视频接续](ComfyUI-任务监控规范.md#51-后端故障后的视频接续)，保留证据和已有文件，核对状态与来源缓存，不自动补做。
5. **取回**：由后台执行。默认分段导出按导演台报告中的本轮运行目录和逐组文件核对，按[逐组输出规范](ComfyUI-MiniMaxH3导演台节点使用规范.md#731-导出方式与逐组文件)区分一采、二采及P映射，403报告为逐组文件依据。明确采用全部导出时须核对本任务实际接入的保存节点；历史独立一采任务认264、独立二采任务认214，后处理认16。只用本任务真实文件身份，不把旧预览作为结果。缺少完整逐组文件时报输出异常，不把执行成功当作全部交付。
6. **交付**：后台成功后将最终文件保存到指定候选路径，按[成果保存与已有文件](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#成果保存与已有文件)保留已有文件与记录。后台按[精简收尾](ComfyUI-任务监控规范.md#视频完成通知后的精简收尾)自动登记待审和核验网页后再通知，Agent读取现成报告直接汇报并交用户人工审核；成功生成和保存均不等于内容获批。

实际送入模型的文字限制执行[视频生成全程无字幕](../../nora-ai-short-drama/references/共用规则/画面文字与字幕规范.md#视频生成全程无字幕)；字幕问题的修订优先级及获授权的省略例外按[提示词对照](../../nora-ai-short-drama/references/共用规则/画面文字与字幕规范.md#生成字幕问题的提示词对照)处理，准备核对覆盖本次方案的完整正文与中文参考版，不以格式通过代替结果要求。

## 5. 人工审核与轻量记录

执行、候选/选定、人工审阅及场次/整集交付统一按[逐集目录规范](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md)维护，不另建运行台账。结果只由用户人工审核，不进行agent内容初审、自动重生成或未经批准切换处理阶段。

获批一采的远端缓存复用执行[导演台第7.5.2节](ComfyUI-MiniMaxH3导演台节点使用规范.md#752-获批一采缓存的远端复用)。一采、二采明确获批后，以及后处理满足[自动采用](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#后处理自动采用)条件时，走[一次收尾入口](../../nora-ai-short-drama/references/comfyui-scripts/README.md#视频批准的一次收尾)，依据报告及实际授权接续下一环节；只有一采、二采按规定导出定稿包与配对画布，后处理直接完成采用与业务收尾。定稿留档不替代下文的一采来源和缓存核对。

正式画布407.confirm_first_pass保持开启。一采与二采共用工作流不合并制作阶段；按开发流程的整场审批顺序推进，分别保存两阶段任务ID、输出及用户决定。首次执行只生成一采；用户批准后，沿用同一任务副本、缓存名、导演台节点ID、实际种子与一采输入再次执行。逐一核对本轮选中组与获批一采的缓存匹配，命中后只做二采；缓存缺失或不匹配时先说明，不把重新一采冒充二采。局部返修与不同获批输入的分轮执行按[返修选择运行操作](ComfyUI-MiniMaxH3导演台节点使用规范.md#711-返修选择运行操作)处理。Refine参数可按已批准二采方案调整；清理缓存按[节点缓存操作](ComfyUI-MiniMaxH3导演台节点使用规范.md#75-缓存检查与清理接口)执行，不在两轮之间自动清理。
