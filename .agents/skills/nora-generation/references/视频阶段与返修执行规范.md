# 视频阶段与返修执行规范

### 7. 生成视频、验收与衔接修改

根据场次资料包执行[ComfyUI-H3规范](ComfyUI-H3视频执行规范.md)：入队前核对参数、素材、种子、输入映射和成果保存路径，统一交后台排队、提交和任务完成后取回全部成果；跟进与异常接续读取[监控规范](ComfyUI-任务监控规范.md)。

一采、二采、返修及后处理在实际提交前先按[任务组提交范围](ComfyUI-服务配置与任务提交规范.md#任务组提交范围)汇总本次可同时入队的对象；下文的场次、导演台组和来源分批用于执行与审核，不决定通知组边界。

一采、二采及后处理统一按[任务完成后取回全部成果](ComfyUI-任务监控规范.md#2-留档与收尾)执行，再进入[视频结果处理](进度查询与结果处理规范.md#正常视频结果)，保留P、R和处理阶段。导演台最终报告与文件对应关系按[成果映射](ComfyUI-MiniMaxH3导演台节点使用规范.md#732-任务完成后取回全部成果)核对；留存、网页审核及对话通知方式按[视频结果人工审核](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#视频结果人工审核)。

#### 视频阶段与当前版本修改

视频“后处理”包括常规规格处理和按交付用途确定的定制处理。常规项目为超分、插帧及[H3交付配置](ComfyUI-H3视频执行规范.md#后处理交付规格)规定的画幅适配；定制项目可包括去绿／抠像、制作透明通道、导出适配剪辑软件的格式等。执行项目以本次制作方案、明确用途及已有授权为准，不要求每个任务全部执行，也不因“做后处理”自行增加未明确的内容修改。

准备时在既有生成方案或执行记录中写清源二采身份、常规及定制项目、执行顺序、目标规格、各交付文件用途及授权依据。现有工作流只承担其实际支持的项目；定制处理未包含在工作流中时，使用已具备的适用工具接续，并在同一任务记录保存输入输出、实际命令／参数、技术结果及未完成项。不得把超分插帧完成视为全部定制交付完成；各文件角色、产物清单及最终交付登记按[同轮次后处理产物](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#同轮次后处理产物)，采用按[后处理自动采用](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#后处理自动采用)，完成汇报按[后处理完成汇报](ComfyUI-任务监控规范.md#后处理完成汇报)。

独立修订一采／二采的音轨、字幕、调色、裁剪或制作合成预览，仍归来源阶段，不因使用FFmpeg、抠像或转换格式就变为正式后处理。已列入正式后处理方案并获授权的定制项目归后处理；改变原片内容或节奏的动作仍须符合[剪辑授权](#整段生成与剪辑授权)，不能以扩充后处理范围代替具体许可。对一采静音或抠像所得预览仍为一采衍生；已完成后处理的视频再作修改，保留后处理阶段归属。修改形成新R的条件及来源关联按[视频修订编号规则](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#视频修订编号与执行过程)执行。

独立版本修订前明确具体来源文件、修改范围及执行授权；原视频及当时批准事实保留，修订结果作为该阶段的新候选重新交用户审核。修改改变剧情、镜头、分段范围或时长时，按[制作返修的上游归属](../../nora-ai-short-drama/references/共用规则/制作返修与完整重做规范.md#制作返修的上游归属)同步相关正文与衔接，不只改视频文件。修订结果获批后才替换该阶段当前采用文件，按实际影响核对下游输入；不得将仅静音等修改视为已经完成超分插帧，或将本次修改自动套用于之后新生成的视频。进入二采仍需核对指定获批一采的生成快照与缓存来源，修改后媒体文件的批准不替代这项核对。

片头、片尾的视频修订、标题合成及后处理，先核对[片头片尾的时长与剪辑授权](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#片头片尾的时长与剪辑授权)，按实际许可确定处理范围与时长，再执行本节的阶段及候选规则。

#### 整段生成与剪辑授权

本节适用于正集、片头和片尾的一采、二采、返修及其预览交付。以已确认的P段为生成和审阅单位，不把整集强制合成一段；模型的多组选择运行仍按本规范执行。

1. **默认整段返修。** 修改P段时，先将本轮修改要求和保留内容落实到该P完整的模型提示词及中文参考版，再按获授权阶段生成该P的新整段结果，交付本轮实际生成的整段供审。不能只生成局部后自行拼入旧片，也不能从多个完整版本里择取镜头替换后当作新生成原片交付。
2. **保留效果的含义。** “保留上一版表情”“其他镜头不变”“沿用某版效果”等要求，默认指在完整提示词及实际参考输入中保持对应内容，不构成截取或复用旧视频片段的授权。新原片出现变化时如实说明，由用户审看；不为达到表面上的保持不变而自动替换旧片段。单纯整理提示词、保留效果的要求不另行授权生成。
3. **剪辑须有具体许可。** 截取、旧片替换、多源拼接、调倍速、倒放、插入定格，以及其他改变原片内容或节奏的操作，均须有用户针对具体对象和动作的明确许可。提出剪辑方案时写清来源版本、采用区间及时间处理，已有明确授权直接执行；“再生成一版”“做完整预览”“沿用效果”或后处理授权本身不包含这些动作。旧版做过某项操作，也不自动延续到新版本。
4. **标题叠加不扩大底片修改范围。** 用户授权叠加标题、字幕或角标时，只执行明确的文字内容及动效；保持所用底片的画面顺序、播放速度、连续动作和自然结束时长。调整文字层不授权压缩、延长定格或拼接人物／广告画面。字幕内容及模型正文仍按既有文字规范执行；后处理项目及阶段归属按[视频阶段与当前版本修改](#视频阶段与当前版本修改)执行。
5. **交付标识与来源。** 在既有生成／审阅记录及交付说明中，明确写出实际阶段和“模型生成原片”“标题叠加预览”或“剪辑合成版”，提供对应原片入口；模型原片只指该次任务直接输出。标题叠加预览注明底片身份，剪辑合成版注明各来源、区间、倍速及定格；处理后的版本不只用“一采／二采／完整预览”隐去剪辑。来源关系写入现有输入映射和执行记录，不另建交付台账。

获授权剪辑后的候选、采用、二采接续及定稿留档，继续按现有实际来源规则核对；合成文件的批准不产生新的模型任务身份或潜变量缓存。技术限制、生成不稳定、时长不足或留档缺项均不构成自行改变制作方式的许可。片头片尾可用时长按其专项规则合理延长，不能为凑旧时长擅自加速或补定格。

#### 场次制作循环

生成与后处理以场次为循环单位，按分镜索引顺序推进，不增加会话阶段；整集剧本、分镜及素材准备仍按前述步骤执行。下述审批是进入下一环节的前提，不自动扩大用户的执行授权：

以下按场次组织执行及阶段准入；用户交付时机统一读取[整轮汇总规则](ComfyUI-任务监控规范.md#3-跟进与通知)，不以单场执行结束决定整轮汇报。

1. **当前场次分段一采与统一审核。** 默认将当前场次全部分段作为一个导演台多组任务提交一采。逐组容量与素材安排按[导演台第2.4节](ComfyUI-MiniMaxH3导演台节点使用规范.md#24-公共与本组的数量和时长限制)核对；不同段必需的公共素材方案无法合在一批时，在同一场次内分批，明确各批P范围、公共素材方案与跨批衔接，不仅因全场素材总数超过限制而拆场次。每批仍须逐组符合输入限制，单段超限按[分镜的参考输入规划与分段可执行性](../../short-drama-storyboard/references/视频分段规划规范.md#参考输入规划与分段可执行性)处理。任务参数、种子及依据按H3规范第0–3节保存，多组共同证据按[多组任务的共同证据与状态](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#多组任务的共同证据与状态)归属。全部批次收尾后统一送审；未获批段按用户意见及授权处理，不将局部批准当作整场批准。
2. **当前场次分段二采与统一审核。** 按[场次各阶段定稿留档](ComfyUI-MiniMaxH3导演包制作规范.md#51-场次各阶段定稿留档)完成该场一采定稿包与配对画布留档后，按[获批一采缓存的远端复用规则](ComfyUI-MiniMaxH3导演台节点使用规范.md#752-获批一采缓存的远端复用)核对来源及远端缓存，再依据各段获批一采快照，保持各一采批次的原始组序、P映射及缓存来源，按H3规范第0、2节执行二采。每批执行终态核对，全部批次收尾后按上述网页交付方式统一交用户人工审核；二采执行不必等待其他场次的一采完成；交付时机按上述整轮规则处理。
3. **当前场次统一安排后处理与自动采用。** 当前场次所有二采批次完成终态文件核对，且全部分段的最终二采版本均经用户明确批准采用后，按[场次各阶段定稿留档](ComfyUI-MiniMaxH3导演包制作规范.md#51-场次各阶段定稿留档)完成该场二采定稿包与配对画布留档，再进入该场后处理。按分镜索引核对本场全部P对应的选定二采文件及既有生成／审阅记录中的批准依据；仍有待审、返修、未采用或文件版本未确定的分段时，不因其他段已采用而提前后处理。再按[H3规范第0节的工作流用途](ComfyUI-H3视频执行规范.md#0-制作策略与工作流配置)、[后处理交付规格](ComfyUI-H3视频执行规范.md#后处理交付规格)及[第2节的参数边界](ComfyUI-H3视频执行规范.md#2-参数边界)核对方案、选定交付目标与实际输入，区分推荐值及已确认的交付要求；准备齐备且已获本轮执行授权后，统一安排本场各段独立后处理，不先合并场次或整集。保留二采原文件；结果到达后进入[后处理自动采用](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#后处理自动采用)。统一安排以场次为范围，不要求把整场帧装入一个任务，也不授权自动重试。用户已授权常规整集后处理时，复用[已采用二采后处理清单装配入口](../../nora-ai-short-drama/references/comfyui-scripts/README.md#从已采用二采生成后处理清单)，从已完成批准报告和本轮组合自动准备逐段来源与画布，再交固定提交入口；不手工重复拆来源或逐段填字段。
4. **当前场次收尾与下一场。** 按[逐集目录规范第5节](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#5-分段交付与本集完成)完成本场分段交付与记录，再进入下一个场次，循环执行上述步骤；仍在本集会话内完成，不按场次新建会话。制作流程不设置场次合成、整集合成或对应的成片审批环节。
5. **本集分段交付与收尾。** 本集所有场次完成后，按该规范第5节核对本集交付范围与完成条件，交付各场次已采用的后处理分段及其播放顺序，再执行[完集复盘与经验维护](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#完集复盘与经验维护)，完成后说明下一集入口。
- 各处理阶段的结果判断与记录按[视频结果人工审核](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#视频结果人工审核)执行。
- 采用收尾执行[采用记录与依据](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#视频采用记录与批准依据)；按对应收尾报告及实际授权接续上述阶段。
- 视频返修按下方[同场反馈的返修范围与提交](#同场反馈的返修范围与提交)确定本轮范围，再按[制作返修的上游归属](../../nora-ai-short-drama/references/共用规则/制作返修与完整重做规范.md#制作返修的上游归属)维护对应内容；导演台配置、缓存与衔接执行[返修选择运行操作](ComfyUI-MiniMaxH3导演台节点使用规范.md#711-返修选择运行操作)。
- 获授权处理用户指出的构图、运镜、光影或焦点问题时，按[视觉表达方法](../../short-drama-storyboard/references/视觉表达方法规范.md#视觉表达方法)参考镜头语言方法，修订对应文本或参考图；不将指南用作agent主动审核视频、自动返修或重生成的授权。
- 问题来自人物、场景或道具资料卡时，先修改对应资料卡，再继续后续剧集。若促使剧情发生变化，同步检查后续分集大纲。

### 同场反馈的返修范围与提交

处理用户已指出的问题时，先按[问题参考](../../nora-ai-short-drama/references/共用规则/制作问题与解决方案参考.md)检索现象并核对适用条件，将可用方法落实到返修方案；处理结果按[经验维护](../../nora-ai-short-drama/references/流程规范/逐集目录与资产管理规范.md#完集复盘与经验维护)记录与归并，不扩大重生成授权。

同一轮场次反馈先按[完整重做的范围与完成要求](../../nora-ai-short-drama/references/共用规则/制作返修与完整重做规范.md#完整重做的范围与完成要求)确定本轮是完整重做还是局部返修，再汇总该范围内的问题。局部返修将单镜问题对应到所属P，核对修改对相邻段、共同素材与公共参数的影响，再统一修改分镜、提示词和任务配置；完整重做先依据对应剧本重建整场／整集分镜及新分段规划，再据新分镜重写受影响提示词，不按用户举例的旧P缩小范围或叠加旧稿补丁。可能需要超出用户指定范围时，说明影响及原因，按相应授权处理；文本重做范围不代替实际重生成授权。

制作中需要拆分或改变分段组织时，先按[制作中拆段的必要性与影响](../../short-drama-storyboard/references/视频分段规划规范.md#制作中拆段的必要性与影响)落实方案，再按[制作变更时的缓存保护](ComfyUI-MiniMaxH3导演台节点使用规范.md#751-制作变更时的缓存保护)同步执行副本的时间线与组映射，不改变整场各环节的审批顺序。

局部返修装配前先落实[执行快照与素材路径](ComfyUI-MiniMaxH3导演台节点使用规范.md#611-局部返修的执行快照与素材路径)。本轮返修段准备及确认齐备、取得执行授权后，按来源批次保留各自完整时间线，使用导演台选择运行将本轮需要返修的组统一提交，按分镜播放顺序安排。例如七段中P001、P002、P005需修改且可在同批安全执行时，同轮选择这三组；不默认把已汇总的范围拆成三次单段生成。存在原批次身份、素材容量或获批来源兼容性等实际限制时，沿本节既有分批条件明确方案，不把逐段准备或审核当作逐段提交的理由。

只有用户明确要求“只单独生成／重生成P某段”等独立生成范围，才从本轮已汇总的返修段中单独执行该段。“一段一段改”“逐段讨论”“先看第一段”不构成单段生成要求，也不扩大执行授权。仅一段需要返修时，按本轮汇总范围执行，不追加无问题分段。

制定一采返修方案时，按[场次基准种子与实际任务种子](ComfyUI-H3视频执行规范.md#场次基准种子与实际任务种子)判断沿用或主动建议换种子，实际值也按该节保存；前后组缓存及衔接执行[导演台第6.1节](ComfyUI-MiniMaxH3导演台节点使用规范.md#61-局部返修时的前后衔接)。同轮提交不证明与未返修相邻段自然接上；本轮结果取回并完成终态核对后统一交用户人工审核，说明具体相邻段影响，不进行agent内容初审或自动采用。
