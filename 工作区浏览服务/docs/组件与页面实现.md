场次页面的说明与异常统一使用公共MessagePanel，位于分段导航及视频准备进度下、画质／版本控件上；宽屏模式同样保留。自动切轮与未登记版本提示、连播异常、上集末段说明、分段顺序说明及轮次资料问题在同一框内逐条显示。视频准备数量不放入公共框，沿用独立的两侧细线、居中灰字样式，失败详情复用PointerTooltip；普通模式显示在分段条下方，宽屏模式按原规则隐藏。切到场次分镜或分镜修改时，公共区域只保留适用于当前标签的信息；无消息时不显示框体。普通信息、警告及错误使用统一行样式，错误保留alert语义，操作按钮与消息同行、窄屏换行。

## 1. 页面怎样生成

当前服务采用 React＋TypeScript 前端、FastAPI 后端。Vite将前端打包，FastAPI同时提供前端文件和数据接口；React Router使用 `#/` 路由切换页面。项目、风格库、开发记录按需加载，TanStack Query负责请求、缓存和定时检查。

浏览器读取数据接口后，由React组件渲染。项目资料仍保存在原目录，后端共用 `backend/parsers/project.py` 解析Markdown、资产记录和素材路径，不另建内容数据库。API按当前栏目、资产和文档返回数据；项目首次只解析定位和进度，栏目及单集详情在进入时解析并缓存。Krea2通过适配层沿用原资源及更新程序。开发记录直接读取本服务 `docs/` 中的Markdown。

页面每5秒检查相关数据。项目后端比较路径、修改时间和大小，有变化时后台重新解析；React更新受影响的内容，保留栏目、搜索、展开目录和媒体状态。已打开正文有变化时由公共文档组件提示“读取新版本”。同步失败时保留旧结果并记录日志；页面打开期间每隔30秒重试，新文件变化提前触发。相同错误只通知一次，恢复后再次失败可重新通知。

服务代码更新另由AppShell中的useAppUpdate每15秒检查 `/api/service`，回到页面也检查。前端版本由package.json在构建时注入，后端启动时读取同一来源；构建的release.json与后端版本匹配才返回ready。新版本在未编辑、没有未保存意见、音视频未播放且弹窗关闭时再次确认服务并自动刷新。底栏显示页面版本与等待提示；HTML入口要求缓存重新验证。refreshPosition通过sessionStorage一次性恢复当前标签页的栏目、集场段、画质／版本、文字页签及滚动位置；不保存文本或写项目资料，普通导航不复用该恢复状态。详见[W080](开发记录/W080-统一版本与页面自动刷新.md)。

上述检查由网页请求项目status触发，后端以3秒为同一项目文件扫描的最小间隔；并非持续扫描ComfyUI服务器。首次访问解析本地项目并缓存，文件变化时后台生成完整新结果，成功后增加revision，网页下一次检查发现新revision再请求当前栏目。同步期间保留上一份完整数据，读取失败通过现有状态接口提示。

视频资料由后台上传后、POST前冻结并写入输入映射generation_contexts；网页按EP/C/P/R/阶段读取同一份来源资料。任务成功后后台按显式目标保存最终成果，Agent负责业务记录、审核及采用，不进行运行中取回或收尾替换。

## 4. 如何统一而不重复建组件

1. 新页面先复用AppShell与PageHeader。顶部操作区只有一处容器。风格库把原筛选栏、项目页把原TabNav通过React Portal放入该容器，输入状态和回调仍由原页面管理，不复制第二份控件。
2. 选择栏目用TabNav，搜索用SearchField，翻页用Pagination。标签名称、条目数据、筛选规则由业务页传入；按钮及输入框外观由公共层维护。
3. 项目Markdown与开发Markdown都交给Document，文件层级交给FileTree，模态窗口交给Dialog。改变这些公共组件后，各使用处一起生效。
4. 新增人物、场景、道具浏览内容继续使用Assets与AssetMedia；有具体字段差异时处理数据，不另造功能相同的资产详情页。
5. 颜色、字体、间距、按钮、输入框、正文和状态标记共用 `frontend/src/style.css`。主色、边框、次要文字有统一变量。状态标记当前由后端解析成HTML，通过Rich展示；还没有独立的React StatusBadge组件。
6. 同一用途只保留一份实现。新增组件前检查本文清单和源码；需要布局差异时优先为已有组件增加明确的布局选项，不复制后改名。只在出现实际复用需求时提取，不提前创建未使用的组件。

入口卡片、资产卡片和风格卡片用途不同，保留各自业务内容。入口卡片用于跳转；资产卡片包含编号、审核状态、候选与正式参考信息；风格卡片展示风格预览、来源和分类。参考图要完整保留画面，使用contain；风格列表使用固定比例缩略图，详情再展示完整预览。可以共用颜色、边框和按钮规则，不应为了相同外框把三种内容塞进带大量判断的万能卡片。

原生按钮、选择框及details折叠控件目前依靠统一CSS；尚未引入额外UI组件库。更新管理仍是Krea2业务组件，不把“检查、准备、应用、恢复”写进通用Dialog。

## 6. 项目定位输入与展示

## 7. 共用头部与消息通知

正式内容模板统一六项头部，填写规则维护于主技能开发流程的“正式内容文档的共用头部”。document_header将标题至第一章之间的完整文字生成headerHtml，不限制字段数量，不从正文抽取同名字段。DocumentInformation默认折叠，主旨、大纲、资料卡及文档预览复用；通用预览的contentHtml去掉重复头部，原始html供原文预览和既有读取方使用。记录型模板保留专用结构，旧项目源文件不自动改写。

Notifications位于AppShell外层，全站只挂载一份；多条消息同时纵向显示，不互相覆盖。useNotify默认3秒关闭、可手动关闭，计时与清理均只作用于本条；打开或关闭阅读弹窗不重新计时。FloatingMessage将Document／Preview的“读取新版本”及AppShell的待刷新提示接到同一框体，按原条件更新、消失，不额外添加关闭按钮或自动关闭时间。SyncNotification按后台稳定的retryAt显示逐秒倒计时，等待期间不自动关闭；同次轮询不重新调用通知，手动关闭后不反复弹出。后台将读取期间的源文件变化标为source_changed，用普通提示“资料正在更新，X秒后重试。”；其他错误标为read_failed，红色提示“资料更新失败，X秒后重试。”。到点Project主动查询status触发重试，不因最近一次文件扫描不足3秒再延后；文件再次变化仍可提前重试。重试中使用“正在同步资料…”，成功或离开项目清理对应消息，清理不误关闭其他通知。通用Result固定使用“资料读取失败，请点击重新读取。”。首次读取仍使用Loading。后台保留真实error，日志保留具体原因，源文件变化记INFO，真正读取错误记录调用栈。业务规则详见[W081](开发记录/W081-同步倒计时与固定错误提示.md)，公共显示层见[W256](开发记录/W256-左下角公共消息组件.md)。AppShell底栏同一行左对齐显示运行状态、版本与开发记录链接、上次同步时间；Project通过FooterSyncContext和Portal提供现有同步时间，不新增常规轮询。非项目页面显示“上次同步：—”，切页移除原项目时间。底栏固定44像素，正文预留空间；公共消息栈距底栏16像素，返回顶部让出整个消息栈的高度。手机缩小底栏间距和文字，保持单行，极窄屏可在底栏内部横向滚动。后台更新时仍保持上次同步时间。

Result的读取失败提示统一使用左下角FloatingMessage，固定文字为“资料读取失败，请点击重新读取。”，正文不再重复显示错误条，也不另发3秒通知。“重新读取”按钮及原错误／加载状态逻辑保留；错误状态保留的后台重读期间，按钮禁用并显示“正在读取…”。消息不参与普通通知的3秒倒计时，随Result的原错误状态清理；首次读取失败后重读仍回到Loading。项目页状态／概览及开发记录列表／正文的组合Result重读实际报错的一项，仍有另一项失败时保留入口；其他Result直接重读自己的Query，只清理自己的消息，不误关其他来源。统一status／revision、打开正文冻结阅读版本及原定时检查均保留。原重读规则见[W082](开发记录/W082-统一读取失败重试入口.md)，本次显示层调整见[W275](开发记录/W275-读取失败迁入公共消息组件.md)。

## 项目页面的共用展示规则

- 封面资料由`backend/parsers/covers.py`读取项目封面索引与制作记录，`CoverLibrary`归入“相关资料”下拉，当前采用图及历史候选复用`AssetMediaCard`和`asset-media-grid`，卡片仅保留通用字段，通过“查看详情”打开额外规格、原图／成品下载及批准／处理记录；移除重复的登记版本。具体候选批准与规格分别核对。候选和历史默认折叠，按需加载预览，不为其他项目创建空栏目。
- 网页服务展示正式项目定位的“视觉规格”时，隐藏“画风正文版本、验证范围、画风确认依据、画幅待确认事项、画幅确认依据”五个列表字段，保留风格名称、正式画幅及两项确认状态。过滤仅作用于该章节的页面显示，不删除源文件字段，不修改其他章节、文档或历史版本；原文件入口仍提供完整内容。正文模板继续保留这些字段。
- 顶部显示项目名称、当前阶段、待处理事项、页面更新时间及项目进度入口。数据来自当前项目的实际记录；多个进行中／待确认阶段并列，不擅自选一个代表全部工作。待处理事项保留记录中的待决事项与下一步，不自行改写其含义。

### 统一文件预览与原文件入口

所有过程文件列表及目录文件入口共用预览分支，不因文件扩展名直接替换浏览页。Markdown在弹窗排版阅读；JSON／TXT／LOG以原始纯文本显示，不执行脚本、解析为HTML或改写文件；图片使用图片预览，音视频使用手动播放控件。暂不支持的类型、不可解码的文本或媒体加载失败，在页内明确提示并保留原文件入口，不自动跳转。JSON即使语法不完整也按原文展示，不擅自修复。

所有标为“原文件”“原始Markdown”或“原图”的入口均设置新标签页打开及noopener隔离，不被页内文档预览事件拦截、不替换当前浏览页；文件名负责预览，原文件入口负责直接访问。是否内联显示或下载仍取决于浏览器对文件格式的支持。

场次分镜的“分段 P编号”三级标题在阅读弹窗中作为独立折叠区块，默认收起；点击标题或通过键盘展开／收起。标题使用比字段正文更大的字号、强调色及边框，与段内参数区分。正文完整保留原镜头、顺序与锚点；完整EP-C-P标题的分段时间表保持展开。从索引、分段或镜号链接跳转到区块内内容时，先自动展开所属区块，再定位目标。此展示由共用阅读逻辑处理，所有采用相同模板的场次生效，不在Markdown另存折叠副本。

JSON／TXT／LOG以UTF-8（可带BOM）文本快照预览，每份最多256 KiB，超出时标明仅截取预览并引导打开完整原文件；截断不破坏末尾UTF-8字符。非UTF-8文本显示不支持提示，不因此中止整个项目读取。媒体仅保存项目内路径，不嵌入二进制；历史图片预览不代表当前批准。浏览服务按需返回预览并检测源文件变化。

页面展示的确认状态来自该文档自身的记录，关联审阅依据保留实际链接；不凭文件存在、最新日期或其他资产获批推断批准，不把全阶段状态代替单份文件状态。

### 分集大纲标签

列表使用每行一个的紧凑横条：集号与阶段同行，概要、原确认状态及文件路径在左侧紧凑排列。分集大纲整卡点击打开原文，整卡可聚焦并通过Enter／空格打开；返回后焦点回到原卡。悬停时边框高亮、背景变浅绿，竖排“阅读原文”提示从右边框向内滑入，移开后收回，默认不显示。滑入区只是装饰文字，不设独立按钮、焦点或点击处理，点击由整卡承接；背景继承卡片当前背景，内缩2px，不覆盖高亮边框。卡片右侧预留提示宽度，不遮挡文字或引起内容跳动。键盘焦点进入卡片时同样展开并保留清晰焦点轮廓，无悬停能力的触屏设备保留可见提示，减少动态效果偏好下取消动画。保留完整概要与状态，窄屏自然换行；原文中已有链接仍按链接行为处理，过程资料等非分集条目保留普通入口。此样式仅用于分集大纲标签，不改变其他标签的卡片、搜索、筛选、分页或阅读行为。

读取 `06-分集大纲/分集索引.md` 的集号、所属故事阶段、原有一句话概要及正式入口，支持关键词搜索与故事阶段筛选；文档状态来自各集大纲，不代表本集视频制作完成。进入后显示完整大纲、版本、原确认状态、原文件及章节导航。索引已登记但文件缺失时明确提示，不以草稿顶替。过程资料与未登记文件另列，保留索引入口，不改写概要或自动补齐集数。

本标签筛选文字固定为“阶段”，其他具有分类的素材标签仍显示“分类”。阶段来自源索引，不由页面补造；空值、未记录、待确认、不适用或未划分等占位不生成阶段选项。没有可用阶段时隐藏筛选，仍展示所有条目并支持搜索、分页；兼容缺少“所属故事阶段”列的旧索引，不因此丢失大纲入口。此兼容仅限浏览，不取消开发流程与分集模板的固定字段要求，也不自动改写原索引。

### 参考音频与参考视频标签

两库分别按各自索引展示RA／RV编号、名称、分类、参考用途、来源及授权说明、索引实测时长、审核／采用及版本依据。固定三类来自[参考音视频管理规范](../../.agents/skills/nora-drama-assets/references/参考音视频管理规范.md)，沿用原分类并支持筛选、搜索。未登记／其他文件另列供核对，不自行推断其入库资格或批准。两库 `其他资料/` 的工作稿、历史版本和执行附件按真实目录单独展示，不混入未登记媒体，不作为RA／RV素材卡；支持既有文件预览及原文件入口。

用户点击后才打开原生音频／视频播放器，无自动播放；关闭弹窗停止播放。音频使用 `preload=none`；所有视频预览使用 `preload=auto`，在打开弹窗后加载尺寸及首帧，保持暂停。尺寸尚未返回时只显示加载提示，不使用固定比例占位；收到有效画面尺寸后才显示播放区域，按视频实际宽高比完整容纳画面且高度不超过视口65%，不拉伸、不裁切。无法读取画面尺寸时明确提示并保留原文件入口。首帧由浏览器原生解码显示，不另生成封面文件；未打开的媒体不预载。浏览器不支持格式或无法播放时提供原文件入口，不转码、不提取音轨、不分析内容。只加载项目内可读取的对应类型文件，外部URL、越界路径及缺失文件提示核对。时长以索引原文展示，不为填表另行测算；未记录授权／审核不补写。空库保留分类与空状态，不建空索引、不生成素材。

### 剧集制作标签

进度图标使用PointerTooltip组件替代原生title：默认距指针右侧12px、上方12px，随鼠标移动，靠近视口边缘时限制在8px安全留白内，上方空间不足时移至下方。提示通过portal放在document.body，并用manual popover进入浏览器顶层，避免共同滚动容器裁切，也能显示在阅读弹窗之上；不参与布局，也不接收指针事件。组件直接衔接触发元素原有事件，不增加包裹元素，保留原有布局层级。键盘聚焦时以图标右上角为锚点，使用role=tooltip与aria-describedby关联，Esc、离开、失焦、滚动、窗口大小变化或窗口失焦均会隐藏旧提示。滚动后新的图标进入鼠标位置，可显示对应的新提示。图标占位20×24px、字号20px，每格上下留白8px，状态行含底边约41px，不随列宽缩放；浏览器缩放仍影响整体显示尺寸。详见[W175](开发记录/W175-分段状态悬停提示组件.md)。

所有顶层标签及其详情页均显示路径导航，普通与悬浮导航统一带“当前路径：”前缀，前缀与首项紧邻，仅留约2px间距：顶层显示当前标签名，人物／场景／道具详情追加资产编号及名称，目录详情显示实际浏览层级；祖先路径可点击返回，当前位置不可重复点击。路径在左、“返回上一级”按钮在右，桌面同行、窄屏允许自然换行；仅非顶层路径显示返回按钮。原路径栏完全滚出视口上方后，左上角显示相同路径及适用的返回按钮，紧接当前阶段浮框右侧，组间距10px，同排两组上下边缘对齐、保持等高；仅当两组按内容宽度无法在视口内排下时，路径组换到下一行。两组使用同一个可换行的悬浮容器，各自继续按原区域的滚出条件显示；容器空白处不阻挡正文点击；原栏重新可见时隐藏浮框，保留原位置避免布局跳动。切换标签同步当前路径，打开阅读／媒体弹窗时隐藏主页面悬浮导航；弹窗保留原文件路径与关闭入口。按悬浮容器实际排布后的底边位置为章节跳转预留空间，避免窄屏遮挡标题。

上述五个目录标签复用搜索及分类筛选（有分类时）。分页固定在视口左下角，依次为“上一页”按钮、“第 X 页 · 起止范围 · 共 Y 页 · 共 Z 项”、“下一页”按钮及“每页显示”选项；选项紧跟下一页，保留少量间距。仅在适用的目录列表页显示，进入正文详情或切换到其他标签后随列表隐藏；打开阅读／媒体弹窗时隐藏悬浮条。窄屏允许自然换行，按悬浮条实际高度预留页面底部空间，并将左下角返回顶部按钮上移，避免互相重叠或遮挡末尾内容。默认每页20项，可选10／20／50／全部；“全部”展示当前搜索／筛选结果的所有条目，非空时为1页，不清除筛选。搜索、筛选或改变每页数量后回到第一页，先过滤后分页。空列表显示“第 0 页 · 0-0 · 共 0 页 · 共 0 项”，两侧按钮禁用；首尾页禁用对应按钮。进入详情保留父层页码、每页数量、搜索与筛选及滚动位置，返回恢复；不同标签和目录层级各自保留本次浏览状态，不写入项目记录。关键词查询可检索当前节点子树，结果仍指向原文件。

当前层级按进入时渲染。服务按项目及栏目返回数据，文档预览单独读取，不把完整项目文本塞进首页。图片及音视频只保存路径，不将媒体二进制嵌入HTML。所有播放、原图查看、历史阅读不改变正式资料或审批。自动化数据／语法／导航逻辑检查不等于真实浏览器排版和媒体兼容性验收，受限项交付时明确说明。

### 状态展示配色

状态只使用以下五套“浅色底＋深色文字”标签，不为同类词新增颜色；配色不改变业务状态定义。

| 颜色 | 状态文字 |
| --- | --- |
| 绿色 | 已完成、已确认、已定稿、通过、批准采用、成功／success |
| 蓝色 | 进行中、运行中／running |
| 橙色 | 待确认、部分确认、待审核、修改后再审、状态不明／unknown |
| 红色 | 失败／failed、不通过 |
| 灰色 | 未开始、排队中／queued、不采用、未记录、不适用、既有记录中的待完成，以及未识别状态 |

仅用于明确的状态字段、阶段状态和表格状态列，不将创作正文、剧情状态或普通说明中的相同词语自动染色。保留原始状态文字及附加说明，不凭子串匹配将“尚未通过”“已完成部分”等判为绿色；模板中未选定的多项枚举不当作真实结论。执行成功、文件核对和用户批准分别保留字段与含义，历史技术／内容审查结论照原文展示；不因为着色改变审批事实。阶段进度仍只有未开始／进行中／待确认／已完成四种，不新增“待完成”业务状态。当前已接入的首页、定位确认字段及页内文档使用这套样式，后续资产视图沿用。

### 分阶段整集资源下载

SceneDownloads在加载及错误状态只显示Result，隐藏阶段章节；视频数量以小字放在标题旁，按钮统一样式并简写为“打包下载”。导演包下载用原生details默认折叠，展开后导演包和画布每行一个。DownloadButton由本集入口、视频包、导演包与画布共用。各自显示真实准备／接收状态及旋转动画，准备期间只禁用本按钮；完整收到Blob后按服务端文件名交给浏览器保存并释放对象URL。每次操作保留时间与状态：顶部本集入口显示在按钮左侧，资源区显示在按钮右侧，各按钮互不覆盖，失败用role=alert显示实际错误；交给浏览器不代表保存成功。新流程见[W158](开发记录/W158-下载准备状态与局域网保存.md)。下载完成验证须取得浏览器保存路径并核对文件，HTTP发送完成只用于服务端临时包清理。布局见[W156](开发记录/W156-资源下载布局与操作提示.md)，当前视频命名见[W157](开发记录/W157-视频下载包按实际顺序命名.md)。
