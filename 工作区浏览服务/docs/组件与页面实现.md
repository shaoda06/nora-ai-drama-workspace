## 1. 页面怎样生成

当前服务采用 React＋TypeScript 前端、FastAPI 后端。Vite将前端打包，FastAPI同时提供前端文件和数据接口；React Router使用 `#/` 路由切换页面。项目、风格库、开发记录按需加载，TanStack Query负责请求、缓存和定时检查。

浏览器读取数据接口后，由React组件渲染。项目资料仍保存在原目录，后端共用 `backend/parsers/project.py` 解析Markdown、资产记录和素材路径，不另建内容数据库。API按当前栏目、资产和文档返回数据；项目首次打开仍需完整解析一次。Krea2通过适配层沿用原资源及更新程序。开发记录直接读取本服务 `docs/` 中的Markdown。

页面每5秒检查相关数据。项目后端比较路径、修改时间和大小，有变化时后台重新解析；React更新受影响的内容，保留栏目、搜索、展开目录和媒体状态。已打开正文有变化时由公共文档组件提示“读取新版本”。同步失败时保留旧结果并记录日志；页面打开期间每隔30秒重试，新文件变化提前触发。相同错误只通知一次，恢复后再次失败可重新通知。

服务代码更新另由AppShell中的useAppUpdate每15秒检查 `/api/service`，回到页面也检查。前端版本由package.json在构建时注入，后端启动时读取同一来源；构建的release.json与后端版本匹配才返回ready。新版本在未编辑、没有未保存意见、音视频未播放且弹窗关闭时再次确认服务并自动刷新。底栏显示页面版本与等待提示；HTML入口要求缓存重新验证。refreshPosition通过sessionStorage一次性恢复当前标签页的栏目、集场段、画质／版本、文字页签及滚动位置；不保存文本或写项目资料，普通导航不复用该恢复状态。详见[W080](开发记录/W080-统一版本与页面自动刷新.md)。

上述检查由网页请求项目status触发，后端以3秒为同一项目文件扫描的最小间隔；并非持续扫描ComfyUI服务器。首次访问解析本地项目并缓存，文件变化时后台生成完整新结果，成功后增加revision，网页下一次检查发现新revision再请求当前栏目。同步期间保留上一份完整数据，读取失败通过现有状态接口提示。

视频生成资料由统一提交入口在POST前自动冻结并写入输入映射的generation_contexts，后端按完整EP/C/P/R/阶段身份关联本地视频与当次分镜、提示词及参考素材。生成完成后，Agent仍须依据真实任务结果取回视频、按既有目录命名保存并维护执行状态；用户批准采用后才维护采用记录。浏览服务自动发现本地文件与记录变化，不负责查询或下载ComfyUI结果、不推断审批，也不需要另执行网页资料关联或HTML重建命令。

## 4. 如何统一而不重复建组件

1. 新页面先复用AppShell与PageHeader。顶部操作区只有一处容器。风格库把原筛选栏、项目页把原TabNav通过React Portal放入该容器，输入状态和回调仍由原页面管理，不复制第二份控件。
2. 选择栏目用TabNav，搜索用SearchField，翻页用Pagination。标签名称、条目数据、筛选规则由业务页传入；按钮及输入框外观由公共层维护。
3. 项目Markdown与开发Markdown都交给Document，文件层级交给FileTree，模态窗口交给Dialog。改变这些公共组件后，各使用处一起生效。
4. 新增人物、场景、道具浏览内容继续使用Assets与AssetMedia；有具体字段差异时处理数据，不另造功能相同的资产详情页。
5. 颜色、字体、间距、按钮、输入框、正文和状态标记共用 `frontend/src/style.css`。主色、边框、次要文字有统一变量。状态标记当前由后端解析成HTML，通过Rich展示；还没有独立的React StatusBadge组件。
6. 同一用途只保留一份实现。新增组件前检查本文清单和源码；需要布局差异时优先为已有组件增加明确的布局选项，不复制后改名。只在出现实际复用需求时提取，不提前创建未使用的组件。

入口卡片、资产卡片和风格卡片用途不同，保留各自业务内容。入口卡片用于跳转；资产卡片包含编号、审核状态、候选与正式参考信息；风格卡片展示风格预览、来源和分类。参考图要完整保留画面，使用contain；风格列表使用固定比例缩略图，详情再展示完整预览。可以共用颜色、边框和按钮规则，不应为了相同外框把三种内容塞进带大量判断的万能卡片。

原生按钮、选择框及details折叠控件目前依靠统一CSS；尚未引入额外UI组件库。更新管理仍是Krea2业务组件，不把“检查、准备、应用、恢复”写进通用Dialog。

## 7. 共用头部与消息通知

正式内容模板统一六项头部，填写规则维护于主技能开发流程的“正式内容文档的共用头部”。document_header将标题至第一章之间的完整文字生成headerHtml，不限制字段数量，不从正文抽取同名字段。DocumentInformation默认折叠，主旨、大纲、资料卡及文档预览复用；通用预览的contentHtml去掉重复头部，原始html供原文预览和既有读取方使用。记录型模板保留专用结构，旧项目源文件不自动改写。

Notifications位于AppShell外层，全站只挂载一份，新消息替换当前消息，默认3秒关闭。SyncNotification按后台稳定的retryAt显示逐秒倒计时，等待期间不自动关闭；同次轮询不重新调用通知，手动关闭后不反复弹出。后台将读取期间的源文件变化标为source_changed，用普通提示“资料正在更新，X秒后重试。”；其他错误标为read_failed，红色提示“资料更新失败，X秒后重试。”。到点Project主动查询status触发重试，不因最近一次文件扫描不足3秒再延后；文件再次变化仍可提前重试。重试中使用“正在同步资料…”，成功或离开项目清理对应消息，清理不误关闭后出现的其他通知。通用Result固定使用“资料读取失败，请点击重新读取。”。首次读取仍使用Loading。后台保留真实error，日志保留具体原因，源文件变化记INFO，真正读取错误记录调用栈。详见[W081](开发记录/W081-同步倒计时与固定错误提示.md)。AppShell底栏同一行左对齐显示运行状态、版本与开发记录链接、上次同步时间；Project通过FooterSyncContext和Portal提供现有同步时间，不新增常规轮询。非项目页面显示“上次同步：—”，切页移除原项目时间。底栏固定44像素，正文预留空间；Notifications、document-update和返回顶部均在底栏上方留16像素间距。手机缩小间距和文字，保持单行，极窄屏可在底栏内部横向滚动。后台更新时仍保持上次同步时间。

- 网页服务的“当前阶段”框位于项目主标题下方、路径上方；标题、阶段框、路径依次排列，上次同步时间放在全站底部常驻栏。长文档共用元信息行，按“确认状态、文档版本、更新日期、原文件”排列；完整头部使用独立的“文档信息”组件，默认折叠。组件展示原有六项信息及额外字段、旧说明和实际链接，不限制字段数量，不另外写摘要。状态仍使用源文件标签与颜色，旧状态附带说明保留在完整头部中。窄屏空间不足时自然换行，不删去字段。项目各栏目共用路径组件，从栏目开始，不显示项目代号前缀；顶层只显示当前栏目，单集详情显示“剧集制作 / EP编号 · 题名”，题名沿用当前选集数据，缺少题名仍显示“题名未记录”。当前位置使用22px加粗强调色，前面的路径保持15px加粗并作为可点击链接，不加下划线，悬停颜色稍浅；剧集制作前缀返回选集列表。标题距下方阶段框20px；路径距上方阶段框与下方正文框均为20px。各栏目正文框不再重复页面栏目标题，文档章节和具体资料详情标题保留。
