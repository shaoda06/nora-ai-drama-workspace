# 组件与页面实现

核对日期：2026-10-06。本文记录当前源码以及本轮公共组件整理后的实际结构，供后续开发复用。

## 1. 页面怎样生成

当前服务采用 React＋TypeScript 前端、FastAPI 后端。Vite将前端打包，FastAPI同时提供前端文件和数据接口；React Router使用 `#/` 路由切换页面。项目、风格库、开发记录按需加载，TanStack Query负责请求、缓存和定时检查。

浏览器读取数据接口后，由React组件渲染。项目资料仍保存在原目录，后端共用 `backend/parsers/project.py` 解析Markdown、资产记录和素材路径，不另建内容数据库。API按当前栏目、资产和文档返回数据；项目首次打开仍需完整解析一次。Krea2通过适配层沿用原资源及更新程序。开发记录直接读取本服务 `docs/` 中的Markdown。

页面每5秒检查相关数据。项目后端比较路径、修改时间和大小，有变化时后台重新解析；React更新受影响的内容，保留栏目、搜索、展开目录和媒体状态。已打开正文有变化时由公共文档组件提示“读取新版本”。这不同于原 `项目总览.html`：原离线页面仍是脚本导出的快照，未改造成React组件，也不会自动继承本服务的界面调整。

## 2. 页面与业务组件

| 页面 | 入口文件 | 业务组成 | 复用的公共组件 |
| --- | --- | --- | --- |
| 工作区首页 `#/` | `frontend/src/main.tsx` 的 Home | 项目列表、共用工具入口 | AppShell、EntryCard、Result |
| 项目 `#/projects/:name` | `frontend/src/Project.tsx` | 简短阶段条、SectionPane栏目、Section分派、Catalogue目录、Assets资产、AssetMedia媒体分组 | PageHeader、TabNav、SearchField、Pagination、Document、Rich、FileTree、Groups、Original、Preview、Result |
| 风格库 `#/krea2` | `frontend/src/Krea.tsx` | 风格筛选列表、Style详情、UpdateManagement更新管理 | PageHeader、SearchField、Pagination、Dialog、CopyButton、Original、Result |
| 开发记录 `#/history` | `frontend/src/History.tsx` | 文档选择和当前文档读取 | PageHeader、TabNav、Document、Result |

AppShell在路由外层只挂载一次，因此所有页面使用同一份顶部外壳、品牌、页脚和返回顶部行为。顶部不再显示工作区／风格库／开发记录全局导航；通过品牌返回首页，首页入口卡片负责进入风格库和项目，开发记录通过右上角“服务运行中”下方的小链接进入。主入口的PageBoundary处理页面渲染失败，Suspense显示按需加载状态；它们是全站基础设施，不在各页面重复设置。

Assets已同时用于人物、场景和道具，不存在三套独立的资产列表／详情实现。Catalogue用于剧集、分集及其他目录资料；具体内容由API数据决定。

## 3. 公共组件清单

### 布局与操作组件

以下组件各自保存在 `frontend/src/components/同名组件.tsx`，页面直接导入所需文件。

| 组件 | 负责什么 | 实际使用处及统一范围 |
| --- | --- | --- |
| AppShell | 品牌、服务状态及开发记录链接、当前页面操作区、正文容器、页脚、返回顶部、路由切换滚动 | 全站；当前品牌为 **Nora工作台**，字号、字重和颜色一致 |
| PageHeader | 栏目小标题、页面标题、说明、右侧操作区 | 项目、风格库与开发记录页面；统一标题层级、说明字号与间距，风格库通过eyebrowInline选项把小字放到标题右侧 |
| EntryCard | 带标题、说明、箭头的页面入口 | 首页项目与共用工具；图标可选，布局与交互相同 |
| TabNav | 列表项选择、可选分组下拉、选中样式、可访问名称 | 项目栏目、资产详情、开发文档；项目传入groups合并相关资料与参考素材，其他使用处仍为原按钮；横排／竖排及小屏共用实现 |
| SearchField | 搜索输入框及输入回调 | 目录、资产、风格库；尺寸、边框、焦点样式一致，筛选逻辑由页面负责 |
| Pagination | 上一页、页码／总数、下一页 | 项目目录和风格库；统一每页36项、首尾禁用和不足一页时隐藏 |
| CopyButton | 复制文字及成功／失败反馈、局域网手动复制入口 | 风格详情中的发给AI、正面和负面提示词；沿用同一实现 |

### 内容与预览组件

以下组件沿用 `frontend/src/components.tsx` 中现有的唯一实现。本轮没有另外创建第二套阅读器或弹窗。

| 组件 | 负责什么 | 实际复用关系 |
| --- | --- | --- |
| Result | 请求加载状态和错误提示 | 各页面、详情与预览 |
| Rich | 正文HTML排版与文档链接处理 | 文档正文、状态说明、资产字段；共用prose样式 |
| Document | 正文、元信息、章节导航、附属资料、新版本提示 | 项目正文／资料卡、文档预览、开发记录 |
| Original | 原文件／原图／下载入口 | 项目文件、资产媒体、风格详情 |
| FileLink | 文件名称预览按钮及原文件入口 | FileTree中的文件项 |
| FileTree | 可展开的递归文件目录 | 项目目录、资产记录、附属资料 |
| Folder | 单个目录的展开状态 | FileTree与Groups内部共用；不单独导出 |
| Groups | 其他资料分组 | 文档、目录、资产相关资料；实际复用Folder和FileTree |
| Dialog | 弹窗外壳、标题、关闭、Esc及背景点击 | 项目Preview、风格Style、更新管理UpdateManagement |
| Preview | 文档、图片、视频、音频或其他文件的预览内容 | 项目内文件与资产；套用Dialog，文档套用Document |

PreviewContext负责把“打开这个文件”的请求交给当前页面：项目页打开Preview，开发记录页切换所选文档。它是行为连接，不是另一种可见组件。

## 4. 如何统一而不重复建组件

1. 新页面先复用AppShell与PageHeader。顶部操作区只有一处容器。风格库把原筛选栏、项目页把原TabNav通过React Portal放入该容器，输入状态和回调仍由原页面管理，不复制第二份控件。
2. 选择栏目用TabNav，搜索用SearchField，翻页用Pagination。标签名称、条目数据、筛选规则由业务页传入；按钮及输入框外观由公共层维护。
3. 项目Markdown与开发Markdown都交给Document，文件层级交给FileTree，模态窗口交给Dialog。改变这些公共组件后，各使用处一起生效。
4. 新增人物、场景、道具浏览内容继续使用Assets与AssetMedia；有具体字段差异时处理数据，不另造功能相同的资产详情页。
5. 颜色、字体、间距、按钮、输入框、正文和状态标记共用 `frontend/src/style.css`。主色、边框、次要文字有统一变量。状态标记当前由后端解析成HTML，通过Rich展示；还没有独立的React StatusBadge组件。
6. 同一用途只保留一份实现。新增组件前检查本文清单和源码；需要布局差异时优先为已有组件增加明确的布局选项，不复制后改名。只在出现实际复用需求时提取，不提前创建未使用的组件。

入口卡片、资产卡片和风格卡片用途不同，保留各自业务内容。入口卡片用于跳转；资产卡片包含编号、审核状态、候选与正式参考信息；风格卡片展示风格预览、来源和分类。参考图要完整保留画面，使用contain；风格列表使用固定比例缩略图，详情再展示完整预览。可以共用颜色、边框和按钮规则，不应为了相同外框把三种内容塞进带大量判断的万能卡片。

原生按钮、选择框及details折叠控件目前依靠统一CSS；尚未引入额外UI组件库。更新管理仍是Krea2业务组件，不把“检查、准备、应用、恢复”写进通用Dialog。

## 5. 本轮实际处理

- 顶部品牌及浏览器标题改成 `Nora workspace`，去掉原中文副标题的不同字重和字号。
- 提取以上七个布局／操作组件并替换原页面内重复结构。
- 分页从Project移至公共层；Krea不再导入Project页面文件，保留按需加载边界。
- 文档阅读、文件树、弹窗以及人物／场景／道具资产实现继续共用，没有创建功能重复的替代组件。
- 预览验证发现正式参考图显示名称不带扩展名时被误判为不支持格式；改为依据真实文件路径识别媒体格式。

本轮不改变项目内容、审核状态、资源更新执行流程或后端数据接口。顶部“服务运行中”仍为既有静态展示文本，不等同于实时健康检测；后续若增加检测，继续由AppShell统一承载。
