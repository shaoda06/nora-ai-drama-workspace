## 具体改动

### 复查结论与调整

范围是图片／超分提交前和正常生成后的技术执行。按nora-ai-short-drama及skill-creator维护源规则、入口与模板，使用stop-that-shit的职责与真实失败检查方法缩小重复工作；不改项目创作、用户批准决定或已有任务的生成范围。规则修改前完整备份到技能历史目录。

| 发现 | 处理 |
| --- | --- |
| 读取入口仍要求Agent重读种子表；执行说明仍列人工核对清单；人物模板仍要求保存后再查网页 | 共用规范明确图片执行分工，相关入口改为引用；已备内容的纯执行只提交并读报告展示，不加载无变化的创作资料和技术映射 |
| 固定RTX检查散在逐项CLI、清单装配入口，后台纯API准备没有同一责任入口 | 收归共用准备fixed_checks；装配和CLI不再执行，新任务一次准备检查，原历史恢复边界保持 |
| 同批多个任务使用同一输入时分别解码 | 同一次Documents装配按实际文件复用尺寸读取；不跨阶段复用，后续实际文件变化核验仍保留 |
| 部分新记录的模型、反向提示词、缓存／预处理字段被默认填为不适用 | 在工作流完成装配后，从实际API填写模型名、采样参数、反向提示词、缓存与预处理；不让Agent事后抄写 |
| 实际上传绑定只存在通信附件，普通图片工作稿缺真实路径；超分收尾重复读同一上传响应 | 收尾单次读取上传凭据并复用，自动填真实路径、槽位及凭据链接；这些凭据同时纳入既有恢复文件变化检查 |
| 报告重复展开状态及收尾内容，Agent仍需拼项目根路径和审核URL | 通知前保存delivery展示数据；CLI正常图片只返回绝对路径、实际规格、数量及审核链接，异常自动返回完整报告，--details显式读取完整报告 |

准备配对／格式检查、上传后真实返回值核对、开工及恢复时文件变化检查、实际输出解码与下载凭据核对、批准后正式替换及历史保留，分别保护不同阶段，继续由脚本执行。未增加视觉初审、自动重生成、Agent补核验或新的审批流程。已有报告无delivery时保留原读取格式，不重做收尾或迁移项目资料。
