# W427：自动同步取回事实与汇总整轮结果

日期：2026-10-27
状态：待发布
关联版本：未发布

## 修改原因

视频取回已有技术收尾，但业务交接仍笼统要求Agent核对三个摘要；多次通知只列当次任务，整轮数量和缺项需手工拼接。本次仅落实取回事实同步与原任务清单范围的整轮汇总，不扩展图片采用、文本批准或复盘工具。

## 具体改动

1. 取回后自动维护生成说明工作稿的“当前执行事实”，总表和正式说明引用该事实入口。正式说明只能更新这一条链接，接口拒绝改写其创作正文或批准；已有制作完成决定保持不变。混合待办、非标准状态及来源缺项保留原文，`business_sync.actions`返回具体文件、字段、原因及责任方。
2. 统一视频装配为任务保存原清单关联；报告沿原清单、装配记录、输入映射和整集轮次计算`rounds`。列出预期任务／分段、取回／可审数量、未提交、失败、取消、停止和沿用身份；跨场、分批返回及部分提交不再靠Agent数文件。原来源改变、身份重复或轮次不符时明确返回原因。
3. 原通知报告可接收同一清单后续结果；接收回执继续用现有任务状态保存，重启后不重复通知。`review_ready`不代表采用，`received`不代表已交付，工具返回`delivered_to_user=null`，实际对话交付仍在原共同记录注明。没有原清单关联的历史任务不猜测合批或批量回填，多份独立清单不因同轮号合并。
4. 更新既有技术记录分工、监控规则、固定工具说明及两个相关模板；保留图片、文本批准及复盘原流程。旧规则5份归档于主技能`references/历史版本/`，后缀`归档-20261027-173006.md`。代码回退依据为本次提交父版本`2b8c14b0`，不改历史提交。

关键实现：[事实收尾](../../backend/services/result_registration.py)、[清单范围汇总](../../backend/services/round_results.py)、[通知接收](../../backend/services/task_notifications.py)、[统一装配](../../backend/services/submission_plans.py)。
