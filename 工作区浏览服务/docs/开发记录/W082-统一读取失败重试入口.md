# W082：统一读取失败重试入口

日期：2026-10-08

关联版本：原记录未单列，以正文为准

## 修改原因

### 用户要求与现状核对

用户同意后台资料更新失败继续自动重试、主动打开内容失败提供“重新读取”按钮，并询问为什么部分页面定时检查、项目资料更新是否统一。

项目资料变化依据统一的status和revision。项目页每5秒查询状态，后端读到完整新结果后递增revision，页面按需取回栏目、资料卡等内容；打开的文档保留阅读版本，用户选择后读取新版。内容请求通常不各自定时检查，避免重复请求和打断阅读。之前遗漏的是取回内容失败后的手动重试入口，并非项目资料各自独立同步。

| 定时请求 | 间隔 | 用途 |
| --- | --- | --- |
| 首页 /api/projects | 5秒 | 发现新增／移除的项目目录 |
| 项目 /api/projects/{name}/status | 5秒 | 统一检查项目资料变化、后台同步结果 |
| 风格库 /api/krea2/state | 5秒 | 查询独立风格库版本和更新任务进度 |
| 开发记录 /api/history、/api/history/document | 5秒 | 读取开发记录目录及当前记录正文 |
| AppShell /api/service | 15秒及回到页面 | 检查浏览服务代码版本并按既有保护自动刷新 |

除AppShell外，均在相应页面挂载期间使用，后台标签页受浏览器及React Query原有调度影响。各接口负责不同内容，不将项目同步重复扩展到每个栏目。

## 具体改动

Result要求传入retry和retrying。失败时通知及内容区统一“资料读取失败，请点击重新读取。”；失败内容旁的按钮持续保留，3秒通知关闭不影响操作。点击只调用原Query的refetch，不重载整页。读取过程中使用既有Loading或禁用按钮，避免重复点击；成功移除错误区及对应通知，清理不误关其他消息。

接入：首页项目列表、项目状态／概览、栏目、资料卡、文档预览、场次分镜、开发记录列表／正文、风格目录／详情／管理状态。组合Result按当前实际报错请求重读；另一项仍报错时保留入口。删除场次分镜重复错误段落。意见保存、媒体缓存、复制和风格更新动作保留各自既有处理，本次只补通用读取请求。

同步服务README、组件说明及待发布记录。使用vercel-react-best-practices及frontend-testing-debugging，继续复用现有Query，不新增依赖。未改后端、项目内容、主技能、模板或创作规则。
