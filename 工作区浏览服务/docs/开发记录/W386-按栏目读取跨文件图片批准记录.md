# W386：按栏目读取跨文件图片批准记录

日期：2026-10-25
状态：已完成
关联版本：v0.8.86（运行核对发现旧缓存）；v0.8.87（已发布）

## 修改原因

人物图片的批准记录通过链接保存在另一份工作稿中。网页按栏目加载资料时，该记录尚未加入正文缓存，批准检查把未加载内容当成未记录，造成已批准图片出现资料警告。

## 具体改动

批准检查复用现有受目录范围和项目边界约束的读取入口，按链接读取具体审阅章节；保留现有候选身份、章节锚点和批准判断。将现有解析缓存版本从13递增至14，使磁盘旧解析结果在重启后重新计算。新增按栏目读取人物、场景、道具审阅记录，以及人物共享工作稿／定位工作稿的批准、不采用、错误锚点、缺少锚点回归测试。

## 验证结果

已在临时目录复现：相同记录完整读取能识别批准，按栏目读取显示未记录；新增测试在修复前出现5个失败子用例，修复后通过。

解析器116项测试全部通过。完整服务回归执行957项（3项跳过），4项在图片任务命名及formal路径检查处失败；同样4项在未修复的HEAD解析器代码下也复现（1失败、3错误），属于既有失败；本次不扩大修改图片任务执行逻辑。macOS临时目录使用真实路径TMPDIR=/private/tmp；按tests模块名加载避免既有同名测试模块导入冲突。

直接读取真实角色工坊资料：11张正式人物图全部识别为批准采用，资料警告为0。v0.8.86运行核对发现磁盘缓存仍保留11条旧误报，因此同步递增既有解析缓存版本；最终发布v0.8.87后，/api/service返回ready=true；角色工坊人物栏目warnings为空，11个角色的formalCount均为1，项目status无错误且未处于更新中。真实网页已刷新核对：资料提示消失，11项人物各显示正式参考图1；已保存本轮页面截图。
