# W357：自动检查字号继承与手机越界

日期：2026-10-23
状态：已完成
关联版本：v0.8.46（已发布）

## 修改原因

用户要求将W356发现的宽屏字号继承和手机容器越界纳入自动检查，后续修改公共组件时一起执行。

## 具体改动

- 提交前静态检查之后增加浏览器检查：从Git暂存区导出前端快照，在独立临时目录构建真实组件，以临时回环端口运行Chromium；结束后关闭浏览器和服务、删除快照。缺少依赖／浏览器或检查失败会阻止提交，不回退到正式页面，也不自动安装。
- `frontend/tests/shared-layout/fixture.tsx`直接使用ComponentShowcase和SegmentWorkspace及所有现有CSS，只有模拟候选和本地选择状态，不复制公共控件。请求仅允许临时服务的静态GET／HEAD，禁止API、外部网络及业务写入。
- 覆盖1362px桌面、390px与320px手机；分别切换普通／宽屏、旧／最新候选，对比展示页同规格的字号、行高、内边距、高度和圆角；检查可见选择项与父容器边界、整页横向越界及菜单屏幕边界。关闭的浮层不参与边界比较，打开的菜单单独按屏幕判断；允许1px几何取整差，不保存样式快照或baseline。
- `check:shared`与Git钩子均执行两部分；`check:shared-layout`仅执行浏览器检查，`test:shared-layout`另外注入两类已知故障，确认断言能失败并在恢复后通过。钩子覆盖前端src、检查脚本、布局夹具和依赖变动；纯文档／后端提交不启动浏览器。
- 新检查实际发现320px宽屏下视频列过窄，候选和最新状态挤出容器。SegmentLayout的手机操作区改为使用视频与分段侧栏合计宽度，按钮继续使用公共尺寸；展示规则与覆盖说明同步更新。发布v0.8.46。
- 新增Playwright1.62.1开发依赖及锁定文件，复用本机已有同版本Chromium；README写明其他设备的初始化命令。AGENTS与README明确新增场景需补真实组件用例；现有用例不代表所有页面或所有公共组件已被浏览器自动覆盖。

## 验证结果

- Browser plugin not available；使用项目Playwright，在隔离构建中验证“真实展示页工具栏下拉框→分段普通／宽屏切换→同规格样式与手机边界一致”。3种视口、2种布局、2种候选状态均通过，菜单交互有效，无页面／控制台错误或意外网络请求。
- `test:shared-layout`反向验证：强制按钮继承父级字号、取消容器宽度限制并禁止换行，两次分别被同一组断言拦截；移除注入后通过。截图检查390px宽屏操作区正常换行。
- 使用独立临时Git索引删除候选下拉框的toolbar规格，保留真实工作区正确代码；实际浏览器执行器仍拒绝错误暂存代码，证明没有读取未暂存的修复冒充通过。未改动正式索引或源码。
- 静态规则与Git钩子5组测试通过，补充浏览器检查被调用及其失败阻止提交的连接测试。该钩子测试用替身执行器验证退出码传递，真实浏览器结果由上述隔离用例验证。
- 初次运行修正macOS临时路径符号链接导致的构建路径差异，并排除关闭的popover零尺寸节点；随后真实320px溢出被检查发现并修正，未通过缩小检查范围解决。
- TypeScript与Vite生产构建通过；统一启动器重启后`/api/service`返回v0.8.46及ready=true。正式8782项目页面在320px下的普通／宽屏样式及选择栏边界检查通过，截图确认文字在操作区内换行，没有业务写入。最终执行真实提交前钩子：静态检查2个暂存源码文件，0项需修正、0项待人工判断；暂存快照的3种视口浏览器检查全部通过。W357编号唯一、标题与新增引用有效，暂存区仅包含本次修改。
- 公共组件复用检查：本次仅新增验证夹具、检查执行器及公共SegmentLayout手机空间分配，不新增重复控件或页面样式覆盖；展示仍调用真实SegmentLayout。人工核对了浮层边界与可见节点判定、暂存快照读取、临时资源清理以及当前覆盖范围，其他场景按规则继续补例或人工检查。
