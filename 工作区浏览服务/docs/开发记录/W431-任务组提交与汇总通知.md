# W431：任务组提交与汇总通知

日期：2026-10-27
状态：已完成
关联版本：v0.8.138，已发布至8782

## 修改原因

同一次授权包含多个后台任务时，逐任务完成通知反复唤醒Agent。用户确认引入明确的任务组，按组提交和汇总通知；远端排队、执行、恢复和网页任务卡保持单任务粒度。

## 具体改动

- 新后台清单经过全部准备检查后，在同一数据库事务中登记固定成员及任务组，返回真实group_id和子任务ID。允许单成员组；旧单项提交入口自动创建单成员组。重复原清单及装配回执中断后恢复沿用原组、原ID，不重复生成或改组。
- 组状态汇总成员完成收尾数、成果取回数、缺项及异常。Agent可用`browser_tasks.py status --group-id`查询，`report`返回完整groups和成员成果，包含此前异常报告已读的成员；图片和视频混合组保留两类成果。
- 正常成功等待全组技术收尾后只通知一次。需处理异常提前按组通知，其余成员继续；失败、取消及结案形成终态汇总。修复后可发送新的完成结果，服务重启保留组和通知记录；读取异常报告不把仍运行的成员误记为结果已接收。全组正常超分继续静默。
- 网页排队、运行和历史仍为单任务卡；组成员可打开详情查看全组进度，并切换成员详情。详情只在组未终结时定期读取本地状态，不新增远端轮询。
- 同步执行技能、提交规范、监控与结果处理规范、CLI说明、监控提示词模板和服务说明。规则原文按维护规范归档。旧无组任务、旧图片批次及旧partial清单保留兼容；不按会话、轮号或标题追溯合组。同步本地规格处理不加入异步后台组。

## 默认提交入口补查（2026-10-27）

用户要求再次确认其他会话无需提醒即可按任务组提交。沿主技能、执行技能、固定工具调用、图片专项、H3专项、阶段返修及CLI帮助逐项核对，补齐以下入口歧义：

- 删除“已有完整资料可用旧式入口”的无条件口径。旧单项参数限原任务接续或明确独立的单项提交；同一组不能通过循环调用旧入口拆开。
- 任务组范围作为唯一规则真源，明确同次授权、同项目及来源会话、可同时提交的任务默认使用同一清单，无需再次询问。素材容量、不同缓存来源或工作流拆分只产生组内多个远端任务；跨场次及逐段准备不构成拆组理由。前置依赖、不同项目／来源或用户明确分组按其实际边界接续。
- 主技能路由、执行技能、固定工具入口、图生图及视频专项和脚本说明链接该规则；CLI帮助首先提示--plan整组提交。图片通知中的“新制作优先”残留改为统一规则引用，并将历史批次说明明确标为历史无组兼容。

复查结果：两个主入口技能quick_validate通过；受影响新增／改动本地链接及锚点全部通过；任务组与清单70项、CLI17项回归通过，覆盖默认多任务清单只登记一组、单项兼容及原ID恢复。现行文本再次检索，逐段提交相关剩余命中为禁止拆分、历史兼容或真实执行分批，不再存在无条件旧入口推荐。规则修改前已归档。未更改后台运行逻辑或前端，不生成真实媒体，不涉及新的服务发布；本次无公共组件变更，复用已发布v0.8.138。
