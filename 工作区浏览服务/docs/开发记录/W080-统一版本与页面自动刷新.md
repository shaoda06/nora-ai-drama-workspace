# W080 统一版本与页面自动刷新

日期：2026-10-08。版本：0.2.0。

## 用户要求与实现

原前后端版本从创建起一直为0.1.0，网页只在打开时读取服务信息，发布后要手动刷新。本次在main落实统一版本、自动检查、编辑／播放保护与刷新位置恢复。

- frontend/package.json是版本唯一来源。本次为0.2.0；Vite向页面代码注入版本并生成dist/release.json，后端启动时读取同一来源。/api/service对比构建版本与已启动后端版本，只有一致才ready=true。尚未构建、构建与后端不一致、网络失败均不触发刷新。正式发布新代码须递增版本、构建并重启；普通提交、项目资料更新及同版本重启不递增。
- AppShell每15秒检查版本，回到页面也检查。比较页面构建版本而非首次接口响应，能识别发布前遗留的旧页面。检测到不同且就绪的版本后，空闲时再次查询确认，再刷新。
- 正在文字输入、意见等待保存／保存中／保存失败、音视频播放中或弹窗打开均暂缓。底部显示等待提示；复用revisionNotes现有草稿状态判断，不新建草稿副本或写真实项目。连续播放复选框焦点不视为文字编辑。
- refreshPosition只在自动刷新前向当前标签页sessionStorage保存选择与滚动位置。组件提交后消费恢复值，避免并发渲染在提交前丢失恢复值；普通导航及手动刷新不重复恢复。恢复栏目、集数、场次、分段、画质、视频版本、场次和右侧页签、语言及分镜模式。视频保持暂停；已移除单集回到入口，已移除场次／分段／视频使用现有可用项。
- HTML入口设置no-cache以便刷新重新验证；API继续no-store，构建资源沿用Vite文件名。底栏显示当前页面版本。

## 规则与范围

同步浏览服务AGENTS.md、README、组件说明与版本记录，不修改主技能、模板、项目资料或生成流程。统一版本发布包含后端重启，前端单独改动也需要加载新后端版本。首次启用前已打开的旧页面没有检测代码，需要手动刷新一次。

使用fastapi核对服务接口与前端缓存响应，使用vercel-react-best-practices将版本检查集中在AppShell并复用查询缓存和既有草稿状态，按frontend-testing-debugging做隔离浏览器交互验证。
