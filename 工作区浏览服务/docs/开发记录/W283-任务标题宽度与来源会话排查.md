## 具体改动

### 标题跳动修复

用户反馈任务标题被右侧逐秒变化的时长反复挤到下一行。TaskCard原来使用自动宽度的flex时间列及非等宽数字；实测旧时间列为153.14像素，会随文字变化重新分配标题宽度。

仅调整TaskCard.css：电脑端改为剩余空间标题列＋固定182像素时间列，时长启用tabular-nums等宽数字；标题完整换行，不截断。700像素及以下改为单列，时间保持在标题与来源会话下方。未新增轮询、定时器或状态逻辑。

### 来源会话只读排查

当前任务c3dccaab-c037-42d3-8022-7605063348c5属于“小序和禾禾”，来源会话ID为01a159f6-50e0-7993-8d26-769da8175f6b。通过当前桌面只读工具确认真实标题为“小序和禾禾｜EP002 制作”，并非会话未命名，也不是当前正在浏览的项目。

公开任务接口和SQLite任务状态中source_session_name均为空。后台日志两次记录该任务source session lookup failed: Codex连接不可用。按该任务保存的桌面配置只读重放read操作，桥接进程退出1；仅在内存中展开原错误后，确认为tools/list阶段返回-32603、Codex app tools pipe closed，尚未进入read_thread。记录的node、server与pipe路径存在，pipe路径与本会话环境相同；“路径存在”不代表桥接连接可用。

读取名称的后台代码只在提交／恢复时尝试一次，失败只记警告，不写入名称；网页对空值显示“会话名称暂不可用”。所以刷新页面不能补出名字。已证实失败边界是后台桌面桥接；没有证据将更深层原因归为某个桌面版本或权限设置。

本次对名称按用户“查一下”要求只读诊断，不修改任务、数据库、提交流程、消息投递或桌面工具。后续修复应在受支持的提交入口记录真实会话名称，并单独处理桥接读名称失败，不能用项目名猜会话名或仅改占位文字。
