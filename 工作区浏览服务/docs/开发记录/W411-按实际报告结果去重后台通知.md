# W411：按实际报告结果去重后台通知

日期：2026-10-26
状态：已完成
关联版本：v0.8.116（统一发布进程已加载，实际接口验证通过）

## 修改原因

旧失败通知的report会返回后台最新的成功结果，但原实现只确认旧通知ID；同一成功结果的另一条通知随后到达时，接收方无法判断已经读取过该结果。用户授权修复，并要求保留失败后真正恢复成功的首次通知。

## 具体改动

已实现：将通知接收与具体任务结果的读取回执区分，持久保存实际已读结果，发送前去重，延迟通知返回静默标识；不以任务ID单独屏蔽后续新结果。

## 验证结果

隔离回归65项通过，覆盖旧失败通知读取最新成功后取消待发通知、已经排入会话的成功通知静默、读取回执重启保留、首次恢复和新失败不被任务ID屏蔽、发送前连接检查期间的读取竞态及现有收尾流程。真实服务v0.8.116、ready=true；用既有两条通知核对，旧通知读取成功结果返回should_notify_user=true，随后读取迟到成功通知返回false、new_task_ids为空。该验证未重新生成、下载或登记媒体。

- 公共组件复用检查：本次只改后台通知与CLI报告字段，不改前端组件、样式或交互；最终差异仅涉及后台、CLI、隔离测试及恢复规则，不涉及UI组件、样式或交互。

维护自动复查：核对实际结果回执、通知ID确认和用户汇报标识的职责；同步唯一监控规则与结果处理入口，保留正常超分静默和真实新结果通知。未改公共版本号或重启服务，与统一发布进程共用v0.8.116。
