# W237 视频执行职责复查与技术记录自动维护

## 范围与发现

按用户授权，以图片执行相同标准复查一采、二采、后处理及其返修的提交前和正常生成后流程。沿用nora-ai-short-drama与skill-creator维护规则真源、固定模板及脚本，按stop-that-shit区分必要执行边界与重复工作。规则修改前完整备份；不修改项目正文、用户批准、已有任务或来源工作流。

发现：旧执行规范仍要求Agent整理部分帧数／技术字段，通知后仍有“维护业务记录”的指令；后台虽冻结生成资料，结果登记仍要求提前手建各P阶段章节；中文参考和依据原文在四项语义核对及各组中重复读／计算指纹；视频报告仍展开完整状态；实际媒体规格此前没有统一由后台填入模板。

## 实现

- 共用规范定义视频执行职责，H3入口、逐集目录、分段模板及通知模板引用同一分工。内容已经备好的执行轮只提交、读取入队结果和最终报告；不再手建技术条目、抄参数／指纹、计算路径／数量或在通知后维护网页。创作判断和用户批准仍是输入，不由脚本生成通过结论。
- 清单提交自动建立或补空白的P／R／阶段执行条目，记录实际API参数、种子、请求秒数、计划帧数、来源及动态证据入口。已有非空说明、历史参数、反馈和决定保持。授权依据引用原任务清单，纯准备后补授权无需改写一批阶段条目。
- 新一采显式sync_timing从已核定durationSec装配17k+5帧数、起点、长度、总帧数及编辑区，输出到新执行副本。二采及带历史来源的任务不改原帧数和缓存身份。标准单段MP4后处理可由唯一VHS保存节点及选中P／R派生输出目标。
- 新content_review注释仅提供实际判断、摘录和路径，工具填写既有输入／中文／依据指纹，不生成passed，不重新绑定已带指纹的旧审查。一次审查中同一中文／来源文件只读一次并复用指纹，视频上传映射复用已解析的导演台时间线。
- 清单视频的video_plan在通知前用ffprobe读取一次stream／container事实：尺寸、帧率、时长、视频轨与文件总码率、编码和音轨，保存在既有结果收尾报告并自动填写工作稿。未提供的值保持未知，不拿请求值或CRF当实测。网页重试复用未变化的测量，视频变化停止复用；不扫描帧、不重算文件哈希、不做ASR或质量评价。
- 持久报告保存video delivery。正常CLI只返回完成数量、视频身份、绝对文件／记录路径、实测信息及可直接打开的审核链接；读取自动确认收到，不再登记、探测媒体、拼接入口或写项目记录。异常自动返回完整报告，--details支持显式追溯。旧接受任务与缺展示清单的旧完成报告保持原路径，不追溯补测或改写历史。
