# W142：本地队列恢复与异常流程测试

日期：2026-10-10。浏览器检查使用正式端已有 v0.5.14 构建；本次仅新增测试和记录，没有修改业务代码、重新发布或重启正式服务。

## 结果

本地队列、任务监控、导演台取回及新增恢复检查共 55 项全部通过。其中新增 6 项使用临时 SQLite、项目目录、本机 HTTP／WebSocket 服务和原版 Agent CLI；桌面消息连接用测试替身。

| 场景 | 实际验证方式与结果 |
| --- | --- |
| 七段取回部分失败 | 测试 HTTP 服务前三段成功、后四段返回 503；记录为取回失败、3/7，保留四段具体下载错误。关闭并重新创建 TaskStore 后，Agent CLI 请求重试，达到 7/7。前三段只请求一次，文件修改时间不变，没有生成提交。 |
| 下载过程中连接断开 | TCP 服务声明 10 字节但只传 3 字节；后台记录下载失败，没有发布不完整候选文件，临时下载文件已清理。再次取回完整保存，没有重新生成。 |
| 后台重启接续取回 | SQLite 保存 collecting 状态和执行结果后重新创建后台；start 自动接续取回，沿用原远端 ID，没有生成提交。 |
| WebSocket 断连后已完成 | 本机测试服务实际关闭 WebSocket；后台按现有 5 秒间隔重连，以原 client_id、prompt_id 查询完成结果并保存成果，没有重新提交。 |
| WebSocket 断连后任务失踪 | 重连后队列、历史都无原任务；标记 needs_attention，未下载或重新生成。其他独立任务继续调度由已有回归用例覆盖。 |
| 通知不可连接、会话忙、结果不明 | 两项同源任务先遇连接异常，再遇会话忙，最后空闲时合并为一次发送；验证通知等待分支分别请求 30 秒、15 秒等待，测试中加速等待。模拟发送响应丢失后保存 delivery_unknown；后台重启不重发，通过原版 Agent CLI 确认通知，两项都更新 acknowledged。 |

## 已有真实成果复验

只读获取荒院暴富 EP003 已完成的七段 R002 一采成果。在独立后台和临时项目中，前三段走真实远端 GET /view，后四段注入取回错误；关闭、重建测试后台后，通过原版 browser_tasks.py retry-collection 补取四段。

结果：3/7 恢复到 7/7；前三段未重复下载；七段字节数和 SHA-256 均与原下载凭据一致；原候选素材修改时间不变；生成 POST 次数为零。临时成果已随测试目录清理。该测试没有再次唤醒实际来源会话。

此前 EP003 的实际生成链已完成且原通知已 acknowledged；本次故障测试验证恢复逻辑，不把模拟通信当作新的一次真实生成或真实 Agent 唤醒。

## 网页操作

使用正式端现有构建，连接单独的 FastAPI、数据库和测试任务。项目浏览资料仅通过只读 GET 转发，所有队列写操作都在测试后台。

Chrome 自动操作验证通过：

- 排队按钮为立即提交、插队、暂停、取消；暂停按钮为立即提交、插队、恢复、取消。
- 暂停移到暂停分类，恢复回排队末尾；暂停任务插队解除暂停并成为第一项。
- 排队及暂停任务的立即提交都登记立即提交请求；忽略繁忙节点的实际调度分支由已有回归用例覆盖。
- 取消移入历史；历史卡片不显示队列操作按钮。
- 从标题区域抓取整张卡片，拖动期间后台调度锁有效，放下后排序保存并释放锁；后台重新加载 SQLite 后顺序一致。
- 分类数量随操作变化，1414×914 桌面及 390×844 窄屏均可操作；无页面 JavaScript 错误。

测试 HTTP 服务未提供网站图标，首次浏览出现 favicon 404；在临时服务补空图标响应后重新完整执行，控制台无错误。这不是队列业务故障，也没有因此修改正式端。
