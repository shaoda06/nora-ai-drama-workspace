# W255：视频停帧自动恢复

日期：2026-10-22；版本：0.6.135。

## 问题与依据

用户报告打开页面后视频黑屏，播放能听到声音，需要刷新。当前内置浏览器中复现：P005 R006有576×1024视频尺寸、readyState=4、无media error或控制台错误，播放时间可从0走到结尾，画面仍黑。同一文件切走再切回后画面恢复，说明重建播放器可以恢复此次异常。尚无证据确定最初失去画面的浏览器内部原因，也不将其直接归因于其他会话的服务更新。

SegmentVideo原实现只处理媒体error事件，没有检测音频时钟推进而视频帧不再呈现的状态；报错后也仅显示提示，没有局部恢复。

## 修改

播放器使用requestVideoFrameCallback跟踪新呈现帧；不提供该能力时使用getVideoPlaybackQuality的帧计数。播放时间持续推进且3秒没有新视频帧，或媒体错误/等待状态持续3秒时，重建当前video节点。页面隐藏、正常暂停及正常出帧不触发恢复。不提供帧观测能力的浏览器仍处理明确的媒体中断，不用黑色像素猜测故障。

恢复保持当前文件、候选、播放时间、原播放/暂停状态、音量、静音及倍速。每次候选挂载最多自动尝试两次；失败后明确提示，并提供局部“重新加载视频”按钮。卸载时清理定时器、事件及帧回调，不改整页自动更新或连播片单。

仅修改播放器、回归测试及发布资料；没有修改项目资料、素材、生成参数或审批记录。使用investigate进行现场复现和原因定位，frontend-testing-debugging进行隔离浏览器验证，React工程规则用于稳定effect依赖、ref保存瞬时播放状态及卸载清理。

## 验证与发布

- 新增7项回归覆盖时钟前进但无呈现帧、正常出帧、暂停/后台、网络/媒体错误、帧计数兼容、卸载清理、同文件重建和状态恢复、自动重试上限。旧实现7项失败；修复后相关Node回归共33项全部通过。
- TypeScript检查、生产构建和3项发布检查通过。没有新增依赖或修改后端。
- Browser插件未提供；用CUA在用户当前内置浏览器复现并验证同文件重建恢复。独立Playwright用临时蓝色视频及响应夹具模拟丢失帧回调，实际验证自动重建、原时间/播放/音量/静音/倍速恢复、两次后停止及局部重试按钮；无页面/控制台错误，无非GET请求。夹具、脚本及桌面/手机截图位于`/tmp/nora-video-recovery-validation/`，没有向真实项目写入测试数据。
- 已通过统一启动器发布至8782，`/api/service`返回0.6.135、ready=true。当前内置页面自动升级至0.6.135，保留P005/候选六；实际画面恢复并可播放，无应用告警或错误。

## 结论边界

已复现并补上播放器缺少自动恢复的路径，模拟故障可恢复；浏览器内部最初为何停止显示帧仍未确定，未声称消除了所有硬件或浏览器黑屏原因。实际黑色视频仍是有效内容，不据像素颜色触发恢复。
