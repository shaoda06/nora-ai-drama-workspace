# W358：弹窗与公共消息自动检查

日期：2026-10-23
状态：已完成
关联版本：v0.8.47（已发布）

## 修改原因

用户要求补充弹窗和公共消息提示的长文字、错误提示、关闭按钮自动检查，覆盖桌面与手机，并修正可确定的问题。

## 具体改动

- 在现有暂存快照浏览器执行器内接入`check-shared-feedback.mjs`，测试夹具直接调用Dialog、Notifications、FloatingMessage和Switch。只有本地模拟状态及计数器，不读取或写入真实业务。
- 覆盖1362px、390px、320px：普通／紧凑弹窗的长标题、连续长串、多段正文、滚动后关闭入口、按钮／Esc／遮罩关闭以及禁止关闭；消息的长短自适应、520px上限、手机边界、错误样式、堆叠逐条关闭和弹窗内外保留。
- 使用浏览器虚拟时钟检查成功提示在2999毫秒时仍存在、到3000毫秒消失，错误提示推进10秒后仍保留；关闭持续提示后模拟操作继续推进，提示不会因进度更新重新出现。没有使用真实保存、下载、生成或同步任务作为测试。
- 检查发现公共弹窗正文中的连续英文长串产生横向溢出，统一为dialog-body增加任意位置换行；长标题会挤压默认关闭按钮，增加公共dialog-close样式使其不收缩、不换行。同步在静态规则登记dialog-close归属并增加断言，阻止页面复制关闭按钮或覆盖其内边距。没有修改各页面弹窗或复制演示样式；公共消息现有行为检查通过，无需修改其实现。
- 公共展示页新增长内容弹窗和长错误提示入口，沿用真实组件；自动用例也实际打开这两个入口。README、AGENTS和组件覆盖表同步更新。未增加依赖，原提交钩子与check:shared命令自动包含本组。

## 验证结果

- Browser plugin not available，使用现有Playwright在隔离临时构建运行；目标流程为“打开真实弹窗／触发真实消息→长文字排版与关闭／计时操作→内容在屏幕内且状态正确”。三种视口及上述状态全部通过；无浏览器错误、外部请求或业务写入。
- 初查确实抓到正文scrollWidth 2428px大于clientWidth 1078px，以及关闭按钮被挤为两行。两处修正后复查通过，手机截图确认标题、正文换行与关闭按钮正常。
- self-test额外注入弹窗正文不换行、关闭按钮收缩换行、消息超宽、消息关闭按钮不可见4种故障，均被同一断言拦截；恢复后通过。原有字号继承和手机容器越界反向测试继续通过。
- 消息边界检查包含正文实际scrollWidth、卡片与通知区的视口范围；关闭按钮检查文字单行、尺寸、父框范围及中心点击命中。已关闭浮层及允许纵向滚动的堆叠区域按实际可见状态验证，不将正常滚动误报成溢出。
- 静态规则与真实Git钩子5组测试通过；TypeScript与Vite生产构建通过。正式8782公共组件展示页在1362px、390px、320px下的长内容弹窗与长错误提示检查通过，关闭按钮有效、没有横向溢出或业务写入；`/api/service`返回v0.8.47及ready=true。最终真实提交前钩子通过：静态检查3个暂存源码文件为0项需修正、0项待人工判断，所有已登记浏览器场景通过。新增dialog-close静态归属规则及断言补验通过；W358编号唯一、标题和新增引用有效，未暂存其他会话的技能文档修改。
- 公共组件复用检查：新增夹具只提供模拟数据与操作状态，不复制弹窗或消息实现；仅公共Dialog默认关闭按钮及正文样式变更，展示入口同步，人工核对CSS作用域、计时断言和关闭不取消模拟操作的依据。当前已登记用例不代表所有业务内容及自定义弹窗操作区都被自动覆盖。
