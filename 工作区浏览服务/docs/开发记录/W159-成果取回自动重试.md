# W159：成果取回自动重试

日期：2026-10-11；正式版本：v0.6.16。

## 范围与规则

用户授权：为现有后台成果取回增加自动重试。任务整项生成成功后才取回全部预期成果；不重新生成、不恢复运行中取回，不增加网页手动重试按钮。

- 初次取回之外最多自动重试3次，依次等待10、30、60秒。HTTP 429的有效Retry-After要求更久时延长等待；支持秒数及HTTP日期，依据[RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after)。格式不合法明确记录并交给Agent核对响应。
- 暂时性网络／读取中断、超时、下载不完整及HTTP 408、429、500、502、503、504可重试。缺失预期输出、最终报告／映射不符、其他HTTP错误、本机权限／磁盘／文件或凭据冲突不自动重试；同轮包含不可重试问题时停止。
- 每轮复用已成功保存的文件及凭据，只处理未保存成果；成功文件的字节、修改时间及原下载事件保持。最终状态是全部保存成功或取回失败，后者保留成功成果与具体原因。
- 次数、UTC下次时间、逐轮原因和结构化错误存入原SQLite及执行附件JSON；服务重启接续原周期，已过期等待立即执行原定的一次重试，不重置次数。Agent原retry-collection仅接受collection_failed，开启新的取回周期（另有最多3次自动重试），累计轮数继续增加。
- 重试期间保持collecting，历史全部结果展示进度及下次时间；详情展示累计轮数、本轮次数、停止原因及时间线。只有最终成功／停止后生成结果通知，不逐轮唤醒Agent。生成完成时间不被重试时间覆盖；通知保留原消息合并及送达确认逻辑。

## 实现位置

collection_retry分类外部错误；comfy_tasks统一驱动图片等普通输出与导演台最终报告成果；comfy_segments保留成功下载检查点。comfyui_client保留HTTP Retry-After，并将网络读取失败与本机写文件失败区分，继续清理未完成临时文件、禁止覆盖。

task_history／task_details提供摘要字段及逐轮记录；LocalQueueCard／TaskDetailDialog沿原SSE更新。任务监控规范v1.16与统一脚本README同步自动周期及Agent再次取回入口。
