# W232：项目读取锁与运行诊断

日期：2026-10-19；发布版本：v0.6.96。

## 问题与范围

已确认原实现会在目录扫描、缓存读写和栏目解析期间持有项目状态锁；此时同项目状态查询及其他栏目也必须等待。此前服务无响应时没有保留线程堆栈，不能认定这一风险就是那次无响应的唯一原因，也不能仅凭远端ComfyUI断连认定网页故障原因。

本次只调整资料读取同步方式和运行诊断，不改任务执行、重试、通知、采用或审批逻辑，不重生成媒体，不写入项目审批记录。

## 读取同步

- 初始化单独串行，耗时读取在状态锁之外；只有第一次读取本项目的请求等待初始化，不占用全局项目锁。
- 同栏目使用独立锁合并并发读取，不同栏目互不等待；状态锁只用于缓存索引、状态和结果发布。
- 读取期间若源快照的相关依赖已变化，返回已有的资料变更错误，不发布旧数据；磁盘缓存保留其原始快照，不能冒充新资料。
- 原文件路径、审批解释、已完成判定和缓存格式保持；不引入第二套项目真源。

## 运行诊断

- HTTP请求超过2秒才返回响应头时，写入`runtime/request-diagnostics.jsonl`，包括带时区UTC时间、进程、请求编号、方法、路径、耗时和状态。不记录查询参数、请求体、认证头或凭证。
- 独立线程每秒检查一次。请求超过15秒未返回响应头，或事件循环心跳超过15秒未更新，记录`service_stalled`并向`runtime/request-stacks.log`追加当时的全部Python线程堆栈、线程名及ID。
- 同一连续停顿只抓取一次堆栈；恢复后记录`service_recovered`，以后再次停顿再抓取。诊断不会取消请求、重启服务或重发ComfyUI任务。
- 计时截止响应头，正常保持的SSE、WebSocket和较长媒体传输不会仅因连接未关闭而误报。
- 请求日志约2MiB轮转，保留2份旧日志；堆栈日志约2MiB轮转，保留1份旧日志。日志位于忽略的本机runtime，不随Git分发。进程退出前关闭监控线程及日志。
- HTTP测试使用临时诊断目录；生产任务服务和凭证不在测试中启动或覆盖。

## 验证入口

`tests/test_project_scanning.py`覆盖慢栏目时状态与其他栏目可读、同栏目只解析一次、并发源变化不能发布旧结果，以及初始化不持有项目状态锁。

`tests/test_request_diagnostics.py`覆盖慢请求字段、事件循环阻塞时实际抓栈、停顿只报一次及恢复、日志轮转、长连接、异常与取消清理、监控线程关闭，以及不记录查询参数。

完整后端回归665项通过；最后调整后，项目读取及候选上下文65项专项、运行诊断10项专项通过。日志目录不可写时也验证了请求仍正常结束、错误进入原服务日志。

正式发布继续使用统一启动器；发布前后核对原任务身份与已保存状态、第三集十五段批准、网页完成状态及媒体入口，不以测试结果代替生产页面核验。
