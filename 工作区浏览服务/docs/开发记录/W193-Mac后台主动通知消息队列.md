# W193 Mac后台主动通知消息队列

日期：2026-10-14。版本：0.6.56。

## 问题与改动

Mac私有桌面管道会拒绝后台调用者，完成任务因此停在waiting_connection。只验证命令存在或共享socket不存在不足以下结论；实际运行官方codex queue后，原桌面会话自动开始新轮次并回复了测试标记。

Mac后台改用CLI消息队列，跳过私有管道的空闲状态读取。CLI路径随任务登记，旧任务从服务环境CODEX_CLI_PATH或PATH读取。保留通知批次、同来源合并、ack以及送达不明不重发，增加CLI回执留档。其他平台继续使用原桌面适配器。没有关闭安全检查，没有创建定时会话跟进。

## 验证

- 原会话实投：CLI退出0，返回队列消息ID；桌面原会话产生新轮次并回复唯一标记。测试未调用发送消息插件替代CLI。
- 自动测试覆盖不调用私有管道、旧任务CLI解析、失败保留原因且不重发，以及原有通知合并、ack和Windows适配器路径。
- 51项任务、队列恢复及版本测试通过，前端类型检查和构建通过；8782返回0.6.56 / ready=true，页面显示服务运行中。
- 重启后的独立后台将积压通知按两个来源合并投递，两个来源均已返回ack。原短片会话投递时正在导出导演包，通知入队未打断该轮，随后自动处理并确认。
- 原会话空闲时的实投完成“queue → 桌面新轮次 → 唯一标记回复”；忙时的正式批次也完成“独立后台 → queue → 原会话接续 → ack”。数据库真实状态为acknowledged，未手工改写。

通知入队不等于已处理，以原会话ack为收件证据。CLI不可用或调用结果不明时保留错误，不自动换成其他会话或定时跟进。
