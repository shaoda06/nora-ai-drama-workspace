# 版本记录规范

`版本记录.md`记录发布摘要，详细原因、实现及验证写在对应W文件。新条目使用[版本记录模板](版本记录模板.md)，W文件遵循[开发记录规范](开发记录规范.md)。

## 固定顺序

1. 三级标题：`### v版本号：变化名称（YYYY-MM-DD）`，版本使用实际发布号，日期使用实际发布日期，最新版本放在最前面。
2. 标题下第一段固定为`开发记录：[W编号](开发记录/W编号-事项名称.md)。`；同版涉及多个事项时列出全部对应W链接，同一W可以对应多个版本。需要定位补充章节时保留章节锚点。
3. 空一行后写内容：用户可见的变化、适用范围及必要限制。简短改动用一段，同版多项工作可分段；不重复粘贴完整开发记录。原文中有明确归属作用的W引用可以继续保留。

## 事实与关联

- 先建立或更新真实W记录，再填写发布条目；不能仅因标题相似、编号相邻或当前运行版本相同就建立关联。
- 正式发布验证完成后才能写“已发布”“通过”。失败、跳过、未验证及范围限制如实保留。尚未发布的工作留在W记录中，不预先写成发布完成。
- 纯讨论、文档维护和未发布工作不强行分配软件版本；它们保留在`docs/开发记录/`目录，不为网页入口虚构版本关联。
- 历史条目保持原版本号、日期和事实。原来的“同版维护”“开发环境维护”等标题没有明确版本号时保留原题，不推定版本。
- 历史缺链接时先核对W正文及原提交。有对应文件就补链接；未找到可核实的独立记录时，可以按原版本摘要补录W文件，题名注明“历史补录”，记录补录日期、原条目及原摘要提交。只转录已知内容，明确本次没有重做历史测试或核验历史发布，不补造缺失过程。

## 提交前检查

- 每个条目均按“标题 → W链接 → 内容”排列，内容非空；每个链接的文件存在，W编号与文件名一致，章节锚点存在。
- 内容与对应W记录的事项相符；整理旧条目时核对原说明、限制和有效引用没有遗漏。
- 同一版本的多项改动优先合并在该版本下；不因文档整理重复发布或递增版本。历史“随某版本发布”条目可以保留，避免改写历史归属。
- 网页侧栏只列版本记录、规范、模板等总入口，不逐个列出W文件。取消“全部开发记录”入口及列表；W记录通过版本链接在公共页内弹窗阅读，关闭后保留原页面位置，新增W文件无需手工维护另一个索引。
