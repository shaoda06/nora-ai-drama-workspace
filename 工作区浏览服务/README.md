# Nora 工作区浏览服务

当前版本见 `frontend/package.json`，网页底栏显示已加载的版本。项目浏览、Krea2风格库和开发记录共用一个入口，源文件仍是内容依据。

## 日常启动

Windows双击本目录的 `启动工作区浏览服务.bat`，后台运行并自动打开 http://127.0.0.1:8782/ 。重复双击复用已经运行的本工作区服务。关闭网页不停止后台；双击 `停止工作区浏览服务.bat` 停止，关机后需再次启动，不设开机自启。日志位于 `runtime/server.log`。端口被其他程序占用时明确报错，不终止其他进程。

同一局域网设备访问 `http://本机局域网IP:8782/`。当前机器地址为 `http://192.168.10.15:8782/`，地址随网络可能变化。只读浏览无需登录；用户视频修改意见可自动保存，仅接受本机及局域网IP的同源请求。风格库更新、应用和恢复允许本机及局域网IP访问，仍校验客户端地址、访问地址、同源请求和操作凭证。局域网HTTP可能无法使用自动剪贴板，页面提供可选中的文本供手动复制。

## 内置工作流

首页共用工具提供“内置工作流”入口，以列表卡片分组展示主技能工作流目录根部的正式工作流，以及“非正式工作流”子目录中的备用工作流，分别下载画布/API原文件。去油版仅用户明确指定时使用。此页面不提交生成任务。项目页不显示根目录“历史版本”栏目，其磁盘资料保留，各阶段辅助资料及任务历史不受影响。

项目顶部导航只识别现有的正式栏目：00项目定位至09剧集制作对应的十个规定目录；参考音频和参考视频仍归入“参考素材”菜单。其他目录、嵌套projects、综合资料及历史版本不会成为导航按钮，其文件不因导航筛选而删除。入队路径的填写与校验见[统一提交说明](../.agents/skills/nora-ai-short-drama/references/comfyui-scripts/README.md#浏览服务监控接入)。

剧集分段条第二集起提供固定宽度的“上集末段”回看入口，宽屏时在分段导航顶部；第一集不显示。格内仅显示名称和秒数，下方为一采、二采、后处理状态条。按直接上一集的剧本及分镜顺序取末段，默认打开最新可播放版本，点击本集分段返回；缺少资料或视频时入口禁用并提示缺项。首次勾选连续播放时，按当前画质为上集末段及本场各段固定最新可播放候选和剧情顺序；上集末段播完接到本场第一段，再沿用本轮固定版本接续。取消连播仍保留本轮，再勾选恢复；点击“开始新一轮”才重新选取。下一段缺少本轮视频时停止并提示，不跨画质或换用新版本。回看不计入本场下载范围，本轮规则见[W191](docs/开发记录/W191-本轮连播版本与意见导出.md)，回看入口原始实现见[W182](docs/开发记录/W182-上集末段回看.md)。

未固定本轮时，视频准备名单包含上集末段最新可播放版本及本场每段的最新视频；固定本轮后，准备名单采用本轮相同版本。上集末段先准备并计入进度，提示标注“含上集末段”；缺少该视频时不增加计数。预加载只读取现成文件到浏览器内存，不需要全部准备完成才能播放，原始准备机制见[W184](docs/开发记录/W184-上集末段视频准备.md)，本轮接续见[W191](docs/开发记录/W191-本轮连播版本与意见导出.md)。

分镜标签支持点击及键盘操作，跳转到当前视频关联分镜的开始秒数，并同步播放对齐正文和进度；保留视频原来的播放／暂停状态。时间按当前候选的生成资料计算，不混用其他候选或最新分镜；普通、宽屏和上集末段均适用，详见[W186](docs/开发记录/W186-分镜标签跳转视频.md)。

修改意见的“插入时间”直接写入编辑框：未聚焦时在全文末尾另起一行；正在编辑时在当前光标／选区处另起一行，保留选区替换行为。空文本或光标已在行首时不添加多余空行；插入后光标位于时间及镜号后，继续输入并沿用自动保存。时间格式仍为“00.01.0秒，SH001：”，详见[W192](docs/开发记录/W192-意见时间换行与焦点.md)。

## 剧集资源下载

单集详情的“当前位置”行右侧显示“本集打包下载”：项目进度中的本集制作已完成，且本集所有场次、所有索引分段各有唯一批准的后处理正式版、文件齐备且没有制作资料问题时才显示。点击按剧本场次顺序和分镜索引顺序打包整集；切换当前场次不改变下载范围。本集视频包命名为`项目名-第几集-正式版视频.zip`，包内平铺`第几场-第几段-正式版.原扩展名`，场号取剧本顺序，段号按本场分镜索引顺序从1计数，不取C/P数字。源文件名称与字节不变。当前范围见[W162](docs/开发记录/W162-本场与本集视频下载范围.md)，整集完成条件见[W152](docs/开发记录/W152-整集后处理正式视频打包下载.md)。

场次的“资源下载”按后处理、二采、一采展示，每个阶段的“本场打包下载”只打包当前选中场次、该阶段用户已批准采用的正式版片段，不包含其他场次、其他阶段、候选或历史版本；切换场次后，数量和入口随之更新。本场视频包命名为`项目名-第几集-C编号-阶段-正式版视频.zip`，包内沿用该场次在整集中的实际场号及本场分镜索引段号。导演包、画布列表也按当前场次筛选，直接下载该阶段 `06-阶段采用视频/阶段目录/C编号-场次/导演包/` 内已有的原文件，不再套包；多个文件逐个列出入口，缺少文件时按钮不可用，不拿其他阶段替代。既有未指定scene的阶段资源API继续提供整集范围；网页场次入口始终显式传入scene。

本场及本集视频ZIP同时包含`draft_content.json`与`draft_meta_info.json`，与视频平铺在同一目录。解压后的目录可作为剪映草稿，素材使用剪映固定草稿目录占位符引用同包视频，不写项目源视频或打包临时目录的绝对路径。时间线沿用包内真实顺序，各段完整原时长、速度1、原声音量1，不加转场、配乐、字幕或其他效果。画布尺寸与时间线帧率取首段媒体信息；包内原视频不转码、不裁剪。读取媒体信息或生成草稿失败会报错，不交付缺素材的草稿。素材库另在`draft_meta_info.json`登记，使用`./同包文件名`引用，支持独立预览与拖入；素材库修正见[W165](docs/开发记录/W165-剪映草稿素材库登记.md)。路径机制已在Windows剪映11.5验证，接入与检查见[W163](docs/开发记录/W163-视频下载包附带剪映草稿.md)。

视频打包接口按需在本服务 `runtime/downloads/` 中生成 `videos-*.zip`，以标准文件响应交给浏览器保存；资源区各阶段与本集下载均使用上述平铺命名，保留原始字节，不转码、不写入项目目录。未批准的视频不入包，但后续段号仍按索引位置计数，不填补缺口。同段有多个正式版导致包内重名时拒绝下载，提示核对采用记录。服务端发送完成、失败或请求取消后立即删除本次临时包，不以浏览器保存回执为清理条件；服务启动时仅清理该目录内本服务遗留的 `videos-*.zip`，不设置长期下载缓存或定时删除正在发送的文件。导演包和画布原文件不进入临时目录，也不参与此清理。详情见[W154](docs/开发记录/W154-原文件下载与视频临时包清理.md)。

资源下载的导演包列表默认折叠，展开后原文件每行一个。视频数量在标题旁显示。本集和资源下载按钮共用真实准备状态：点击即时显示旋转动画和打包／文件准备消息，完整收到文件后交给浏览器保存；各按钮各次操作的消息独立，准备期间只禁用当前按钮，失败明确提示。页面不把交接当作保存成功，仍以浏览器下载列表为准。布局见[W156](docs/开发记录/W156-资源下载布局与操作提示.md)，视频命名见[W157](docs/开发记录/W157-视频下载包按实际顺序命名.md)，准备及保存流程见[W158](docs/开发记录/W158-下载准备状态与局域网保存.md)。新流程通过同源请求完整接收Blob后发起保存；本机ZIP及局域网画布JSON保存完成，局域网ZIP仍在字节收齐后停留.crdownload，尚未解决。未取得明确拦截原因，不把浏览器交接消息当作保存完成，不放宽浏览器安全策略。

## 安装与构建

草稿生成依赖[pyJianYingDraft](https://github.com/GuanYixuan/pyJianYingDraft) 0.3.0（Apache-2.0）及[pymediainfo](https://github.com/sbraz/pymediainfo) 7.0.1（MIT），版本固定在requirements.txt；只使用文件生成和媒体信息读取，不调用剪映UI自动化。Windows的pymediainfo wheel包含MediaInfo运行库；其他平台按该库说明准备libmediainfo。固定目录占位符参考[ZenStory实现](https://github.com/zenstory-ai/video-recap-skills/blob/539168622918e058bd250c793b82f043eced31e0/skills/video-assemble/scripts/jianying/writer.py#L14)，未安装整套技能。

当前工作区已安装依赖并构建。其他电脑首次使用，在本目录执行以下命令；Python 3.10＋、Node.js 22＋、pnpm 11为开发环境要求，普通浏览启动仅使用 `.venv` 和已构建前端；ComfyUI后台的Codex会话通知在macOS需要支持queue的Codex CLI，其他平台需要本机Node及已安装的桌面适配器，见下方后台任务说明。

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
pnpm --dir frontend install --frozen-lockfile
pnpm --dir frontend build
```

日常代码修改默认在主线目录进行；仅在用户明确要求或双方另行约定时使用开发分支。正式发布统一递增版本、构建前端并停止再启动后端；仅前端改动也需让后端加载新版本。代码修改和提交不等于发布，正式构建及重启按本次授权范围执行。项目Markdown、素材和记录变化不需要重启或执行生成脚本。macOS／Linux在创建 `.venv`、安装依赖及构建后，可手动执行 `.venv/bin/python -m uvicorn backend.main:app --host 0.0.0.0 --port 8782`，本版双击入口为Windows提供。

## 换电脑与工作区迁移

本服务默认从所在目录定位工作区，不依赖盘符、用户名、项目名称或Codex安装位置。GitHub仅同步共用代码、规则、模板和风格库；真实`projects/`、`综合资料/`、`.venv`、`frontend/node_modules`、`frontend/dist`、`runtime`按根目录.gitignore排除。另一台设备拉取仓库后，先按“安装与构建”安装本机依赖及构建前端，再在`projects/`放入自己的项目；没有ComfyUI配置时仍可浏览项目，生成任务需单独配置该项目的节点及本机Codex连接。

整份工作区换位置前停止浏览服务，完整复制真实项目、执行附件、素材和`runtime/comfy-tasks.sqlite`，核对复制结果后再启动新位置的服务；不让两份后台同时处理同一队列。虚拟环境须在新位置重新创建并安装requirements.txt；Node、FFmpeg及Codex属于本机环境，按README配置，不把另一台设备的可执行文件路径作为通用配置。若有runtime/service.json或NORA_WORKSPACE覆盖默认目录，需要改为本机实际资料目录；没有覆盖时不用填写工作区路径。项目缓存绑定旧根目录，迁移后自动重建。

新入队的上传file、成果path和分段目标path以项目根目录解析，后台持久化项目名及项目内相对路径；执行时才解析为本机绝对路径。旧任务数据库及项目内旧凭据、输入映射中的`.../projects/项目名/...`路径在读取时对应到当前项目。重试仍核对真实远端文件、字节数和原下载凭据，不重生成、不覆盖成果；原始请求、响应、过程记录和通知正文不批量改写。Codex原会话工作目录和项目登记需要在Codex中另行接续，不由浏览服务修改。按[官方项目说明](https://learn.chatgpt.com/docs/projects?surface=app)，在项目菜单选择“Edit project”，添加新文件夹并设为“Make primary”，之后新会话从新目录开始；仅移动磁盘文件不会自动更新项目登记。

项目文件可以在设备间复制或另行同步；运行中的SQLite任务库、桌面连接与登录信息不作为多机共享队列。测试使用临时项目和模拟远端，不会通过迁移验证生成新素材。

## 开发环境与正式环境

默认在原工作区main分支修改，正式端口为8782。2026-10-08起，原codex/browser-dev分支同步主线后停用，其开发worktree归档；8783保持关闭。只有用户明确要求或说明需要并约定后，才另行使用分支／worktree，不因旧会话关联自动恢复开发环境。运行 `git worktree list` 可以核对当前实际目录。

若另行使用开发环境，两套目录各有自己的代码、规则、frontend/dist、Python虚拟环境、node_modules和runtime日志。Git管理的代码与规则通过合并同步，不是实时共享。开发服务可直接读取原工作区projects，不复制项目资料或视频。代码修改、合并与正式发布分别按当次任务约定执行。

### 本机开发配置与启动

以下为另行约定开发环境时的配置方法，不是默认日常流程。恢复旧开发目录后，应先同步主线，再安装依赖和构建。

在开发目录的 `工作区浏览服务/runtime/service.json` 保存以下配置，workspace填写原正式工作区的绝对路径：

```json
{
  "workspace": "C:/原工作区路径/nora-ai-drama-workspace",
  "port": 8783,
  "environment": "development"
}
```

runtime已被Git忽略，因此开发配置不会跟着合并进入正式目录。正式目录没有此文件时，默认使用自身父目录资料、8782端口及production环境。后端通过NORA_WORKSPACE与NORA_SERVICE_ENV接收启动器配置；代码目录、文档和静态资源始终来自当前服务目录。`/api/service` 返回资料目录workspace、代码目录tool、进程pid和environment，启动／停止同时核对代码与资料目录，不能因两套环境共用资料而误认服务。

初次在开发目录安装依赖并构建，执行上方“安装与构建”的命令；然后双击**开发目录内**原有启动脚本。停止时也使用该开发目录的停止脚本。两套目录脚本名称相同，由所在目录和本机配置决定目标，开发页底栏显示“开发环境 · 共用正式资料”。

```powershell
# 当前目录为开发工作目录的工作区浏览服务
pnpm --dir frontend build
.venv/Scripts/python.exe scripts/launcher.py start
.venv/Scripts/python.exe scripts/launcher.py stop
```

开发代码重启只影响8783。修改前端后重新构建并刷新开发页；修改后端后停止／启动开发服务。现有Vite前端热更新命令仍可用，但它默认代理8781，使用时须另起指向相同资料目录的8781开发后端；已经配置好的8783使用构建后前端，无需再起Vite。

开发页保存／清空意见会写入正式项目同一文件，不是测试副本。自动化保存与素材更新验证使用临时数据，不在正式项目中制造测试记录。两个服务的修改意见锁目前各自位于进程内，因此不要同时在两套服务里编辑同一场次的意见文件；两个页面同时修改可能互相覆盖。Krea2资源及其更新暂存仍属于各自代码目录，不自动同步到另一环境。

### 合并与正式发布

默认在main核对差异、运行相关检查并提交。代码修改和Git提交不等于发布，这一边界防止仅因提交、合并或同步分支就擅自发布。用户在8782交办的网页功能、样式或修复任务，默认交付到8782：Agent验证并提交后，说明短暂重启，继续正式构建、重启和页面核对，无需另问一次发布确认。用户明确只讨论、暂不发布、只改代码／规则，或约定开发环境、发布时间时，按该范围执行。另行使用开发分支时，发布步骤如下：

1. 检查开发目录及原工作区的未提交改动，确认本次差异范围；不能覆盖其他会话修改。
2. 在原工作区main上合并本次约定的开发分支，不在运行中的正式目录切换到开发分支。
3. 先完成检查与隔离构建验证；在约定更新时段递增统一版本、构建正式前端并使用正式目录停止／启动脚本。核对 `/api/service` 的version为本次版本、ready为true。正式发布仍可能短暂打断使用。
4. 验证8782的项目、媒体与保存功能；用户浏览器刷新加载新界面。开发端口不替代8782，任务完成后按约定停用开发环境，后续修改仍默认在main进行。

正式更新之前，应先保存正在编辑的意见。Git仅回退代码，不回退用户已写入的项目资料。本次开发环境配置、依赖和构建产物均留在本机，换电脑或恢复工作目录时需按以上步骤重新配置。

### 版本与页面自动更新

`frontend/package.json` 的version是唯一维护来源。修复和小调整递增末位，增加一批功能递增中间位，不兼容大改另行确定。每次正式使用新代码都递增并记录版本；普通Git提交、项目资料更新、同版本重启不算发布。后端启动时读取该版本，前端构建将版本写入页面代码和 `dist/release.json`。`/api/service` 只有在前端构建版本与当前后端版本一致时才返回ready=true，不把服务进程存在等同于发布就绪。

网页每15秒检查服务版本，回到页面时也检查；与页面代码自带版本比较，发布就绪且版本不同才准备刷新。意见未保存（包括保存失败）、输入区仍有焦点、音视频播放中或弹窗打开时暂缓，底部显示等待提示；空闲后再次查询确认服务就绪再刷新。暂时断网、重启期间、构建与后端版本不一致均不触发刷新。项目资料继续使用原5秒检查，不因资料变化刷新整页。

自动刷新前只把当前位置写入当前标签页sessionStorage，重新打开后消费一次：恢复项目栏目、集数、场次、分段、画质、视频版本、场次及右侧标签、提示词语言、分镜显示方式和滚动位置；视频保持暂停。已删除的选择回到可用入口或当前默认项，不恢复未保存文本，不写项目资料。普通手动刷新／导航不读取自动刷新位置。HTML入口要求缓存重新验证，构建资源使用Vite文件名。

首次启用该功能时，之前已打开的旧页面需要手动刷新一次；此后发布可自动更新。统一版本要求每次发布构建并重启，恢复旧版本时也须恢复匹配的前端与后端。

## 模块与数据

### ComfyUI后台任务与全局进度栏

Agent通过[统一入口](../.agents/skills/nora-ai-short-drama/references/comfyui-scripts/README.md#nora统一分配与提交)登记持久化本地队列；后台上传、按主节点空闲调度、提交、监听和完成后取回，备用节点只读观察。远端节点常驻WS连接，首次连接、重连、队列事件及每30秒读取queue，正式提交前再读取一次。“立即提交”忽略远端数量，仍检查资料和连接；其他来源抢先提交时，本任务正常进入远端队列，不重发。

网页每次进入默认收起，窄栏只显示本地队列中、暂停中和历史数量。展开后远端显示实际进行中与队列任务；本地排队／暂停／历史分开。按钮和拖拽调用同源写接口，后台保存顺序；拖拽期间暂缓取出下一项，断开15秒后释放租约。历史包含取回中、成功、各种失败、状态待核对和已取消，不能操作已提交远端任务。

运行与顺序保存在runtime/comfy-tasks.sqlite，Agent内部凭证保存在runtime/task-service.json，不分发、不提供给网页。内部接口要求回环地址、无浏览器Origin及凭证；网页写接口要求同源和本机／局域网来源。项目执行附件保存后台任务状态.json、后台过程记录.json和上传、提交、终态及下载证据，后台不写人工审批。

断线重连先核对原ID的queue/history，任务失踪进入历史待核对，不自动重提；主节点确认空闲后其他独立任务继续。后台重启恢复排队顺序、暂停及原ID监控，取回失败可由Agent按原ID请求只重试下载。生成失败不自动重新生成。所有媒体完成后取回，导演台按最终报告对应Agent指定的本机文件名和路径，不再逐段运行中取回。

同一任务中，相同本地文件上传到同一执行端及目录时只传一次，返回路径复用到各槽位，每个槽位保留独立凭据。恢复准备先核对已有凭据和文件内容，包含列表后方已完成的上传；文件变化、执行端不符或上传失败时停止，不跨任务或目标目录复用。导演台根时间线与编辑区同步绑定，详见[W194](docs/开发记录/W194-共用素材上传去重.md)。

后台支持统一入口的`--prepare-only`：准备阶段生成执行检查报告。授权入队只确认身份、实际路径范围、后台登记记录占用及重复任务，不检查映射格式或文件名称，不读取准备报告、不重跑固定技术检查；上传映射字段／类型／json-path、源文件与证据名称、基础JSON结构、配对和绑定等统一在准备时检查，开工资料未变直接复用；无报告旧任务在实际开工时补查一次并标明实际检查时点；自定义上传凭据在上传恢复时核对，终态／下载凭据在提交时拦截，目录不因准备资料或已有上传凭据而被拒绝；三份提交证据存在性检查与独占保护集中到底层，拦截返回未发送，保留已有结果及错误；轮到执行时统一比较一次准备依据及文件状态，未变复用、变化停止。上传后只核对实际素材槽位及根时间线／编辑区对应字段并保存实际输入映射与冻结资料，不重建整张工作流；绑定未变时不读取或改写API／画布。正常准备和提交不查询远端能力清单；远端节点／模型／参数错误保留详情返回Agent，普通同端H3任务仍核对阶段缓存。恢复上传每个唯一文件核验一次，新上传复用传输时的指纹；Agent不人工重复技术检查或抄写共同执行报告。调用见[准备检查与提交复用](../.agents/skills/nora-ai-short-drama/references/comfyui-scripts/README.md#准备检查与提交复用)。

后台仅通知完成或需要处理的问题，同一来源会话的未发送结果合并。macOS通过官方 `codex queue` 向来源会话投递，由Codex安排后续轮次，不先读取私有桌面管道。提交时登记 `CODEX_CLI_PATH`（或PATH中的codex）；旧任务使用服务启动环境中的CLI路径或PATH。其他平台保留原桌面适配器，忙时每15秒检查、不可连接时每30秒重试。CLI回执记入过程记录；入队成功不等于Agent确认，结果不明等待通知ack，不盲目重复发送。收到消息的Agent先确认，再依据阶段记录复查和维护业务。关闭网页不停止队列，历史旧定时器不因本次发布自动修改。具体规则读取[任务监控规范](../.agents/skills/nora-ai-short-drama/references/流程规范/ComfyUI-任务监控规范.md)。

├── 停止工作区浏览服务.bat

│   └── services/              # 项目变化检测、修改意见保存、Krea2更新适配

- 首页每5秒发现项目目录，项目页每5秒查询变化。后端比较文件路径、修改时间和大小；有变化时后台重新解析，失败保留上次完整结果，30秒后重试，文件再次变化时可提前重试。状态接口提供重试时间，页面逐秒显示倒计时并在到点时查询触发重试；普通轮询也能触发重试。读取期间文件被修改用普通提示“资料正在更新，X秒后重试。”，其他同步错误用红色“资料更新失败，X秒后重试。”；重试中显示“正在同步资料…”，成功清除提示。倒计时保持显示，可手动关闭，同一次等待不因轮询重新弹出；其他通知仍3秒关闭。并发修改记普通日志，真正读取错误保留原因与调用栈。通用读取错误通知统一“资料读取失败，请点击重新读取。”，不直接展示接口原文。首次打开大项目需要一次完整解析；不是逐栏目只读取磁盘。API按当前栏目、资料卡、文档分别发送，首页不含全部项目正文。
- 自动更新保持选中的栏目、搜索、展开目录及已打开的媒体。已打开正文有变化时提示“读取新版本”，用户选择后切换，不重载整页。没有打开页面时不运行项目扫描；下次进入检查变化。项目资料通过统一status和revision传递变化，栏目／资料卡按该版本读取，不各自定时扫描。通用读取失败时在失败内容旁保留“重新读取”按钮，只重读对应请求、不刷新整页；全局通知统一为“资料读取失败，请点击重新读取。”，成功后清除。
- 执行附件／执行记录中的`后台任务状态.json`和`后台过程记录.json`仅按文件存在性参加变化扫描，进度内容变化不触发整项目重读。这两类文本预览在打开时读取磁盘最新内容，仍使用原有路径边界、UTF-8与256 KiB预览限制；新增、删除或改名仍更新资料列表。队列进度由后台任务接口提供。剧本、分镜、输入映射、请求、审批等其他资料继续校验读取期间的一致性，不因后台进度写入阻塞待审核稿同步。离线生成沿用完整读取与检查。
- 变化扫描只遍历项目内可见资料，跳过隐藏及根目录综合资料子树，复用目录项的修改时间和大小，保留项目路径边界。网页首次解析仍读取完整项目；附件及历史Markdown保留原文、状态及链接，不提前排版正文，点击文档时通过既有预览接口排版。常用正文及离线生成保持原方式，不因按需排版漏掉资料更新。
- 完整解析结果保存在本服务`runtime/project-cache/`。重启后核对当前工作区、服务版本和项目文件快照（上述两类后台记录核对存在性，其他文件核对路径、修改时间及大小）；一致才复用缓存，否则重新解析。更新成功后原子替换缓存，失败不覆盖上次完整结果。缓存由服务生成，不存入项目、不分发；删掉缓存只会使下次打开重新解析。第一次打开项目或版本升级后仍需一次完整解析。
- 人物、场景、道具及剧集目录沿用已有解析规则和审核原文，不迁移创作文件、不补造采用事实。媒体按路径提供，支持Range读取，视频与音频手动播放。
- 剧集中的“查看本集剧本”、场次分镜和分段计划读取正式稿与当前工作稿的最新版本，包括待审核稿；同版按文件更新时间选择。版本与审批状态保留原文，历史视频的生成资料仍按对应执行记录读取。
- Krea2从本服务“风格库”进入，路由为 `/#/krea2`。后端通过 `backend/services/krea2.py` 调用 `Krea2风格库/Krea2_更新工具/updater.py`，保留Clio／Ray独立检查、准备差异、应用、放弃与恢复上一版。更新由用户手动触发，不自动升级。资源、`catalog.json`、`versions.json` 和 `work/` 路径保持不变；暂存及上一版不入Git。具体操作见[风格库使用说明](Krea2风格库/使用说明.md)，旧独立入口归档见[W083](docs/开发记录/W083-风格库统一入口与独立工具归档.md)。
- 项目静态HTML已退出日常流程，不再生成或维护。旧源码可从Git历史恢复，两个项目的旧页面按浏览入口规范归档到各自99-综合资料；这些快照不会自动更新，也不替代源文件和素材备份。
- 视频修改意见按场次独立保存到单集 `其他资料/工作稿/EP编号-C编号-视频修改意见.json`，身份为P／阶段／R；停笔约1秒或离开编辑区保存，失败保留草稿并允许重试。导出默认仅包含本轮固定审看版本的意见，不补入旧版本；可切换“全部历史意见”汇总本场次全部已填写版本。两个范围的临时编辑稿独立保留，可编辑并复制；导出不清空记录、不改审批或执行事实，存放结构以逐集目录规范为准。
- 开发记录使用Markdown源文档，网页只读显示；Git保存代码修改，`docs/开发记录/` 说明原因、实现、检查和剩余事项，`docs/版本记录.md` 跟踪发布功能。不把开发记录写入短剧项目进度。

页面和公共组件的实际组成、复用关系及样式约定见[组件与页面实现](docs/组件与页面实现.md)。项目栏目、预览与交互要求在该文档的“项目页面展示要求”维护；日常项目写入按[交付前同步检查](../.agents/skills/nora-ai-short-drama/references/流程规范/项目浏览入口规范.md#交付前同步检查)核验。新增页面先检查此清单，同用途优先复用已有组件。

## 开发与验证

### 网页反馈与规则同步

- 调整工作区浏览服务时，用户的网页意见也可能涉及创作文件的写法、主技能、工作流规则和模板。先结合反馈判断影响范围，说明是否需要同步，以及具体涉及哪些规则或模板、为什么；不默认所有反馈都只修改网页。
- 纯展示或交互调整只修改网页。涉及字段含义、文件结构、填写要求、阶段流程或生成规格时，在已授权范围内同步相应规则、模板、读取逻辑和受影响的现有项目文件，避免Agent填写要求与网页展示依据不一致。
- 规则修改维护在对应的既有真源，模板引用该规则；需要新模板时按既有命名和存放规范创建，不在网页代码或服务说明中另写一套业务规则。
- 完成时分别说明网页调整、规则／模板同步及现有文件校正的结果；没有必要同步的，也简要说明原因。格式整理不改变已确认创作内容或改写历史执行记录。
